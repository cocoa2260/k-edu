# 세 형식이 열리는 것과 수업 준비가 끝나는 것은 다르다

K2-14.U06 · L9 마지막 단원 자료. 선수는 [문서 등록](intake.md), [보고서 출력](report.md), [Provider 제어](provider.md), [React와 Streaming](streaming.md)이다. 이번 목표는 형식별 원본·구조·근거·실패·출력·비용을 비교하고 최종 채택 기준을 적용하는 것이다.

이 강의 다음 [실제 결과](../../reports/KEDU-PRODUCTION-017/RESULT.md)를 읽으면 된다. 전체 L9의 독립 품질·실제 운영 승인은 여전히 미완료다. 마지막 단원이라는 이름만으로 이전의 미통과 항목을 통과로 바꾸지 않는다.

## 파일 형식을 늘릴 때 유지할 계약

이전에는 PDF와 UTF-8 텍스트를 받았다. 이번에는 본문 문단과 병합 없는 표를 가진 DOCX를 실제 등록 경로에 추가했다. 세 형식 모두 원본 사본·SHA256·내부 버전·Parser 버전·Element ID·Locator를 이어간다.

| 입력 | 이번 실제 지원 | 원본 위치 | 주요 제한 |
|---|---|---|---|
| PDF | 이전 합성 디지털 PDF의 텍스트/표 | 물리 페이지·사각형 | 일반 Layout 품질은 미채택. 스캔은 L8 OCR 준비가 별도로 필요 |
| UTF-8 TXT | 문단과 실제 줄 번호 | 원본 줄 | 표처럼 보이는 문자열도 자동 표 구조로 판정하지 않음 |
| DOCX | 본문 문단·직사각형의 병합 없는 표·표 셀 | 본문 블록·표·행·열 | 그림·각주·변경 추적·필드·외부 관계 등 거부 |
| HWPX | 이번 입력 경로 미지원 | 미구현 | 구역/문단/표 어댑터와 실제 한글 프로그램 대조 필요 |
| HWP | 이번 입력 경로 미지원 | 미구현 | 변환기·실행 장비·라이선스·변환 손실 검증 필요 |

DOCX 출력 기능을 만들었다는 사실과 DOCX 입력을 읽는 기능은 다르다. 이번에는 입력 어댑터를 추가했고 기존 Registry와 보고서의 위치 설명도 확장했다. [Microsoft 문서 구조 설명](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)과 [표 설명](https://learn.microsoft.com/en-us/office/open-xml/word/working-with-wordprocessingml-tables)을 기준으로 본문의 문단·Run·텍스트, 표의 행·셀을 구분했다.

Word의 페이지는 글꼴·용지·앱에서 다시 배치될 수 있다. 따라서 DOCX의 첫 번째 문단이나 표 1의 3행 3열을 PDF 1쪽이라고 표시하지 않는다. 이번 보고서는 DOCX의 구조적 위치를 설명하며 클릭해서 Word의 해당 셀로 이동하는 UI까지 만든 것은 아니다.

HWPX는 XML 기반이고 HWP는 바이너리 형식이라는 [한컴 안내](https://www.hancom.co.kr/support/faqCenter/faq/detail/2784)를 참고한다. 확장자를 바꾸거나 ZIP 안의 텍스트를 전부 합쳤다는 이유로 변환/구조 보존이 끝났다고 부르지 않는다. 실제 지원 형식 세 가지는 PDF·TXT·DOCX이며 HWP/HWPX까지 지원한 결과가 아니다.

## 지원하지 않는 내용을 없었던 것처럼 만들지 않기

DOCX에는 화면에 보이는 글자가 본문 외 부분에도 있을 수 있다. 이번 좁은 경로는 머리말/꼬리말·각주/미주·주석·그림·임베디드 객체·변경 추적·병합/중첩 표·필드·외부 링크 등 감지한 미지원 구조를 거부한다. 적용 스타일에서 물려받는 숨김/번호 매기기도 확인한다. 문서 전체의 모든 OOXML 기능을 검증하는 스키마 검사기나 악성 파일 격리 Sandbox는 아니다.

압축 전 용량만으로 충분하지 않아 ZIP 항목 수·중복 이름·경로·압축 해제 예상 크기/비율, XML 크기와 DTD/Entity도 제한했다. 임의 경로로 파일을 압축 해제하거나 외부 관계의 주소를 열지 않는다. 직접 지원하는 간단한 문단·표 외의 서식·메타데이터를 모두 보존하지는 않는다. 이름이 올바른 DOCX라도 지원 범위 밖이면 실패할 수 있다.

이번 표는 3행×3열이다. 표 Element에 행렬과 명시된 머리글 행을 남기고, 검색/인용용 셀 Element에는 같은 표 ID와 행·열을 연결했다. ‘15000원’만 발견했다고 의미가 맞는 것은 아니다. 사람이 원본에서 ‘사용 이력’ 행과 ‘부담금’ 열의 교차점인지 확인해야 한다.

## Golden 문서를 어떻게 비교할까

Golden 문서는 작은 정답 세트다. 이번에는 교육용 DOCX와 TXT, 이전 PDF를 사용했다. PDF/DOCX의 표 값은 같은 9개 값이지만 두 파일의 전체 문서 구성·레이아웃은 같지 않다. TXT는 사람이 행/조건을 풀어 쓴 예제다. 같은 문서를 모든 앱에서 완전히 동일하게 변환한 실험이 아니다.

| 평가 층 | 확인할 증거 | 이번 결과 |
|---|---|---|
| 원본 식별 | 저장한 원본과 SHA256 일치 | 세 형식에서 확인 |
| 추출 | 지정한 문단·셀 값이 정답과 일치 | PDF/DOCX 표 각 9개 셀 일치 |
| 구조 | 행렬·표 ID·셀 위치·머리글 보존 | DOCX 행 3·열 3의 15000원 확인 |
| 검색/문맥 | 현재 버전의 Element를 다시 읽음 | 문자열 검색 후 세 형식의 위치 연결 |
| 근거/검토 | Claim별 인용·내용 해시·고정 결정 | 세 주장/세 인용의 시연. 독립 의미 평가 아님 |
| 문서 출력 | 같은 명세의 DOCX/PDF 내용·화면 | 실제 파일 생성·문자 비교·한글/표시 확인 |
| 변경 이후 | 권한 변경 뒤 과거 명세 재사용 금지 | DOCX 제한 후 새 출력 승인 거부 |

채점용 정답은 Parser에 주입하지 않는다. 정답을 읽어 구조를 만드는 Parser라면 추출을 시험한 것이 아니기 때문이다. 작은 예제 하나의 일치율을 전체 업무 문서 정확도라고 발표하지 않는다. 다음 평가에는 다른 출처·형식·레이아웃과 애매한 실패 사례를 넣고 교사와 교육생이 별도로 대조해야 한다.

## 형식과 계약이 바뀌면 과거 승인은 어떻게 할까

DOCX 위치와 출력 설명을 추가하면서 보고서 템플릿 계약을 v2로 올렸다. 이전 v1 보고서 파일은 당시 결과로 보존한다. 과거 명세를 현재 템플릿의 승인으로 조용히 재사용하지 않고 새 명세·검토를 요구한다.

실습은 세 형식의 Claim을 한 보고서에 담은 뒤 DOCX 원문을 restricted로 바꾼다. 같은 명세로 새 출력을 승인하는 시도는 거부된다. 이미 디스크에 생성하거나 다른 곳에 복사한 보고서까지 자동 삭제되는 것은 아니다. 최종 평가에서는 ‘재출력 차단’과 ‘발행물 회수’를 따로 채점해야 한다.

## 시간과 비용의 비교

각 형식에서 입력 바이트·추출 시간·색인 시간을 실제 기록했다. 하지만 파일 구성·문서 길이·내부 스타일 정보와 캐시가 달라 한 번의 수치로 어느 형식이 더 빠르다고 결론 내리지 않는다. 정답을 보존하면서 여러 문서·반복 실행의 분포를 비교해야 한다.

모델을 호출하지 않아 모델 Token 수와 청구액은 측정하지 않았다. 기록의 빈 값은 0원이나 무료 운영을 뜻하지 않는다. 장비 CPU·메모리·저장·렌더링 비용도 별도다. OCR/Vision·실제 생성 비용은 실행 범위를 정하고 같은 조건으로 평가해야 한다.

## 최종 채택은 별도의 판단이다

| 게이트 | 이번 판정 | 통과에 필요한 다음 증거 |
|---|---|---|
| 합성 입력·상태·보고서의 소프트웨어 계약 | 이번 범위 통과 | 범위 변경 때 관련 회귀 유지 |
| 일반 문서/복잡한 표·OCR 품질 | 채택 보류 | 대표 문서와 실패 사례의 독립 대조 |
| 실제 모델의 답변·Agent·튜닝 효과 | 기존 미통과 유지 | 기존 실패 수정·고정 평가 세트의 재평가 |
| 실제 모델 Streaming·강제 중단·인증·운영 연결 | 미검증 | 실제 Backend/장비에서 실행과 비용·상태 확인 |
| HWP/HWPX | 미지원 | 지원 또는 변환 범위 확정·정답/위치/손실 대조 |
| 독립 강사/교육생·교육장 장비 | 미실행 | 설명·설치·실습·채점·동시 실행 검증 |
| 전체 자료 작성 | 54/70 작성 | 남은 시작 안내·기초 16개 단원 |

따라서 이번 실행의 최종 채택은 **보류**다. 자동 검사 통과 수와 수업 가능성을 같은 수로 세지 않는다. 한 항목을 통과시켰다고 QLoRA·RAG/Agent 품질·실제 인증 같은 다른 게이트가 해소되지 않는다.

**최종 제출물:** 지원/미지원 명세, 세 형식의 원본→IR→Claim→보고서 연결표, 문단·표·위치의 오류표, 형식별 시간/측정하지 않은 비용, 채택 보류 사유를 제출한다. 강사는 표의 조건을 읽는지, 미지원 내용을 누락한 성공으로 바꾸지 않았는지, 단순 출력 완료를 의미 품질·운영 승인으로 설명하지 않는지 확인한다.

이 단원으로 K2-14의 여섯 단원 자료를 작성했다. L9의 독립 품질·운영 승인까지 끝났다는 뜻은 아니다. 다음은 남은 시작 안내·기초 16개 중 K2-00 시작 안내 세 단원이다.
