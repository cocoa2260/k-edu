## 파일 1 · 원본 계보 분리 예제

[split-examples.csv](../../practice/data-evaluation/data/split-examples.csv)는 12원본 × 원문/수동 변형 2개 = 24행이다. Train 12행/6그룹, Dev 6행/3그룹, Test 6행/3그룹이다. Label 1/0은 Train 8/4, Dev 4/2, Test 4/2다. 이 비율과 수량을 권장하지 않는다.

| 열 | 역할 |
|---|---|
| sample_id | 고유 사례 ID. 입력 Feature 제외 |
| root_group | 원문과 변형의 계보. 같은 그룹은 같은 분리에 둔다. 입력 Feature 제외 |
| variant | original 또는 human_paraphrase. 실제 모델 증강 결과가 아니다 |
| split | Train/Dev/Test의 분리 배치. 관리용이며 입력 Feature 제외 |
| text | 질문 본문. 예측 입력 후보 |
| policy_context | A-v2-public-only; B-body-unavailable. 모든 행에 공통인 합성 규정 맥락 식별자이며 B 본문이 아니다 |
| needs_escalation | 정답 Label 0/1. 예측 입력 금지 |
| label_basis | 강의 지침에 따른 정답 이유. 예측 입력 금지 |

수동 변형은 의미·Label을 유지하도록 작성했고 원본 계보를 잇는다. 파일의 Dev/Test 변형은 그룹 분리 원리를 설명하는 고정 연습 자료다. 학습 증강 절차에서는 그룹을 정해 분리한 후 Train만 추가하고 Dev/Test는 고정한다.

이 분리는 같은 A v2에 대한 문의 그룹을 나눈다. **새 문서 계열의 성능 평가가 아니다.** G05와 G11에는 기간/미사용 조건을 묻는 비슷한 질문이 남아 있다. 알려진 부모 계보만으로 의미상 독립 평가를 보장하지 않는 반례로 검토한다. 새 문서 일반화를 평가하려면 문서·개정본을 같은 그룹으로 묶고, 새 문의 유형 평가를 강화하려면 유사 질문을 검토·병합/제외한 뒤 분리를 다시 고정해야 한다. 실제 모델 학습·Test 성능 평가는 실행하지 않았다.

## 파일 2 · 독립된 계산용 Dev 가상 점수

[metric-examples.csv](../../practice/data-evaluation/data/metric-examples.csv)는 위 24행에서 모델로 예측한 결과가 아니다. 별개의 20개 행에 정답 1을 4개, 정답 0을 16개 두고 제작자가 계산용 점수를 직접 부여했다. 행 ID는 D01~D20이며 모두 Dev다. 확률 보정·실제 모델 품질·새 Test 결과를 뜻하지 않는다.

| 열 | 역할 |
|---|---|
| case_id | 계산용 사례 ID |
| split | 모두 dev. 임계값 선택 연습을 최종 평가와 구분한다 |
| needs_escalation | 계산용 정답 0/1 |
| illustrative_score | 0~1 범위의 가상 점수. ≥ 임계값이면 예측 1 |
| score_origin | authored_arithmetic_example_not_model_output. 출처 혼동을 막기 위한 표시 |

검사기는 고정 자료의 계보·수량·형식과 혼동행렬/지표를 재계산한다. B 본문 권한 통제나 실제 분류기, 상담 시스템을 구현·검증한 코드가 아니다.

## 품질 검사와 변경/제외 원칙

현재 확인 범위는 필수 열·ID·Label/점수 범위·알려진 그룹의 분리·지표 계산, 그리고 같은 세션의 문장/라벨 검토다. 원본 그룹을 가로질러 변형을 이동한 반례와 라벨 모순·계산 자료 오류를 검사기가 검출하는지도 확인한다. 실제 라벨러 일치도·의미 중복 탐지 성능·업무 품질·수업 이해도는 미검증이다.

오류 제보는 sample_id와 기준 버전·오류 이유로 추적한다. 문제가 있는 행은 평가/학습 사용을 보류하고 원본·변형·관련 분리까지 영향 범위를 확인한다. 변경 후 기존 성적과 무조건 직접 비교하지 않는다. 나중에 외부 자료를 추가한다면 사용 범위·권한/철회·보관·담당자를 별도 확인하며, 이번 합성 자료의 출처 설명으로 대신하지 않는다.

Dataset Card 형식의 취지는 [Hugging Face 공식 안내](https://huggingface.co/docs/hub/en/datasets-cards)를 참고했다. 공식 문서 확인일은 2026-11-02이며 고정 발행일은 미확인이다. 구체적인 예제·분리·라벨 정책은 이번 수업을 위한 설계다.
