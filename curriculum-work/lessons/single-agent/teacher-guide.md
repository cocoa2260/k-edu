# 도구 요청과 실행 경계의 해설

[강의](lesson.md)와 [실습](../../practice/document-assistant/L5.md)에 대응한다. 같은 작성자의 설명/실행 대조이며 독립 수업 검증은 아니다.

## 장별 확인 질문 해설

### 1장

1. 문자열은 요청 데이터다. Runtime이 행동을 파싱하고 Registry가 등록 이름·Schema·승인 등 조건을 검사한 뒤 함수를 호출한다. 이름을 썼다고 Python이 자동 실행되지 않는다.
2. Workflow는 정해 둔 단계, Agent는 관찰과 상태에 따른 다음 행동 선택이다. 선택을 모델에 맡겨도 실제 실행·정책·상한은 실행기 책임이다. 고정 스크립트의 완주는 모델의 계획 능력 증거가 아니다.
3. MCP는 도구 발견/호출 등의 연결 규약이다. 사용자 승인·업무 정책·모델 선택/종료는 별도 책임이다. 이번 로컬 JSON/Registry를 MCP 통신으로 부르지 않는다.

### 2장

1. k=true는 엄격한 정수 Schema 위반, approved=true는 허용하지 않은 추가 필드다. 승인 상태는 모델 인자에서 읽지 않는다. 추가 필드를 제거해도 실제 승인 없이는 모의 저장이 거부된다.
2. 미발견 ID는 read_evidence 함수 내부에서 거부된다. 따라서 함수 진입은 있었지만 원문 반환은 없다. 함수 진입 전 거부와 다른 경계다.
3. 승인값은 실행 ID·도구·인자에 묶여 같은 Registry에서 한 번 사용한다. 다른 인자는 거부하지만 지속 저장/다른 프로세스의 재사용 방지는 검증하지 않았다. 메모리는 외부 작업이 아니다.

### 3장

1. 네 번째 행동은 파싱돼 기록됐지만 전체 도구 상한을 이미 써서 처리 시도/dispatch가 증가하기 전에 멈췄다. action_selected 수와 tool_attempts는 같지 않을 수 있다.
2. 고정 검색→읽기→제출은 결정 3/도구 2다. 검색 첫 오류를 Runtime이 한 번 재시도하면 결정 3/도구 3이다. 같은 인수 재시도는 새 모델 결정이 아니지만 전체 도구 예산은 쓴다.
3. 최종 근거는 실제 읽은 출처만 사용한다. 발견만 했거나 추측한 ID는 불충분하다. 읽었어도 현재성·인용 존재와 별개로 주장 지지/조건 누락을 대조해야 한다.

### 4장

1. 아니다. 실제 A03은 검색을 반복해 없는 도구 검사 지점을 지나지 않았다. 고정 요청으로 해당 경계를 별도 검증한다.
2. 오류 주입 경로·한정된 재시도는 확인됐지만 읽기/최종 답변·과제 품질은 미완료다. fault_injected가 false인 실행은 오류 복구 증거가 아니다.
3. invoke는 감싼 도구 API와 Registry 연결 확인이다. Framework Agent 전체 Loop·안팎 예산·MCP 서버/전송·인증은 별도 검증이다.

## 활동 판정 근거

| 활동 | 충분한 설명 | 보완할 답 |
|---|---|---|
| 고정/실제 A02 | 고정 3/2/2·원문 1·초안과 실제 검색 반복/원문 0/초안없음을 구분 | 고정 완주를 모델 성공으로 표시 |
| 직접 코드 | 정상 3/2/2, 잘못된 정수 2/2/0, 미발견 출처 2/2/2·원문 0 | dispatch를 읽기 성공으로 표시 |
| 승인/재시도 | 이름·인자·승인·발견 경계를 나누고 같은 요청의 예산 소비 설명 | 모델의 승인문장 신뢰, 재시도마다 예산 초기화 |
| State/종료 | 발견/읽기/최근관찰·전체 예산·기술 중단과 과제 완료 구분 | 검색 반복을 답변 완료로 표시 |
| 포팅 범위 | 같은 계약과 평가를 유지하고 실제 invoke/전체Loop/MCP 범위를 구분 | 라이브러리 호출만으로 전체 Agent 완료 주장 |

실습 추가 과제에서 읽기를 생략하면 검색 후 final은 제공되지 않은 ‘읽은 출처’를 인용해 실패한다. 그 뒤 stop을 준비하면 model_stop으로 종료되며 근거 초안은 없다. 고정 응답 소진으로 생긴 IndexError를 모델의 실제 실패로 해석하지 않게 한다.

현재 프롬프트의 상태별 예시는 첫 발견 ID를 보여 주는 등 가이드가 있다. 실제 선택을 자동 실행하는 것은 아니지만 자유 계획 능력 평가도 아니다. 최근 관찰·읽은 원문만 넣고 전체 Trace/숨은 추론을 다음 입력으로 복사하지 않는다.

현재 추가 제어 검사는 Python3.12/Pydantic2.14.1 보조 환경이며 고정 요구 2.14.2·전체 Pytest/HTTP 환경과 다르다. 실제 모델/Framework/MCP를 새로 실행한 근거로 쓰지 않는다. 과거 StructuredTool 결과와 미완료 품질 판정을 보존한다.
