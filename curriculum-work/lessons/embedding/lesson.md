# 검색용 Embedding — 질문과 문서를 비교할 표현 만들기

K2-07 · 학생용 강의 제작본 v0.1 · 2026-10-31

**목표는 숫자 벡터를 만드는 데서 멈추지 않고, 무엇을 표현한 벡터인지 구분하고 실제 검색 결과로 평가하는 것이다.** [L3 실습](../../practice/document-assistant/L3.md)에서 같은 가상 문서와 질문을 사용한다. 실행 코드는 별도 Python 파일에 있다.

이번 실습은 E5-small의 실제 가중치를 CPU에 불러와 문서·질문을 인코딩했다. 답변 생성 모델은 실행하지 않았다. 문서를 찾았다는 사실과 그 문서로 올바르게 답했다는 사실은 따로 확인한다.

## K2-07.U01 ID·내부 표현·검색 표현

Embedding이라는 말은 여러 위치에 쓰인다. Tokenizer가 내놓는 정수 ID는 사전 항목을 가리킨다. 그 ID를 언어 모델의 입력 Embedding 표에서 조회하면 Token별 벡터를 얻는다. Transformer를 통과한 Token 표현은 주변 문맥을 반영한다. 문서 검색에 쓸 고정 길이 표현은 이런 Token 표현을 어떻게 모으고 어떤 목표로 학습했는지까지 확인해야 한다.

| 대상 | 입력 → 출력 | 확인할 것 |
|---|---|---|
| Token ID | 문자열 → 정수 ID 목록 | Tokenizer·특수 Token·분절 |
| 입력 Token Embedding | ID → Token별 벡터 | 모델의 학습된 표·차원 |
| 문맥 표현 | Token별 벡터와 문맥 → 위치별 표현 | 같은 단어도 문맥에 따라 달라짐 |
| 검색용 표현 | 질문/문서 → 비교용 벡터 | 검색 학습 목표·Pooling·접두어·정규화 |

ID의 숫자 차이가 단어 의미의 거리가 되는 것은 아니다. 생성 LLM의 임의 위치 벡터를 평균했다고 해서 적합한 검색 모델이 된다고 보장할 수도 없다. 검색용 모델의 Model Card를 먼저 읽는다.

이번 모델은 intfloat/multilingual-e5-small이고 출력은 384차원이다. 질문에는 query 접두어, 문서에는 passage 접두어를 붙인다. 패딩을 제외한 Token 표현의 평균을 구하고 길이 1로 정규화한다. 모델 리비전뿐 아니라 이 처리 방식도 Index 설정으로 저장한다. 모델 파일은 고정 리비전의 Safetensors를 읽으며 모델 저장소의 Python 코드를 실행하지 않는다.

**활동:** [Tokenizer 강의](../huggingface/README.md)의 ID와 L3 Manifest의 dimension을 비교한다. 같은 384차원이라는 이유만으로 다른 모델의 벡터를 섞을 수 있는지 토론한다.

**제출:** 위 네 대상의 입력·출력·역할 표와 실제 모델 설정. **확인 질문:** 문장 A가 20 Token이고 벡터가 384차원이라면 “384개의 Token으로 바뀌었다”고 설명해도 되는가?

## K2-07.U02 Dense·Sparse·BM25

Dense 검색은 학습한 실수 벡터를 비교한다. Sparse 검색은 단어·특징별로 대부분 비어 있는 표현을 사용한다. BM25는 질의 단어가 문서에 얼마나 등장하는지, 얼마나 드문 단어인지, 문서가 얼마나 긴지 등을 반영하는 전통적인 어휘 검색 점수다. Sparse라는 범주가 BM25만을 뜻하지는 않는다.

이번 BM25는 공백 주변의 어절·영문·숫자를 단순 분절한다. 한국어 형태소 분석기나 학습된 Sparse 모델은 사용하지 않는다. 따라서 ‘식비’와 ‘밥값’을 같은 뜻으로 묶거나, ‘교육비’와 ‘교육비를’의 조사 차이를 자동으로 해소하지 않는다. Dense도 언어·도메인·질문에 따라 관련 자료를 놓칠 수 있다. 둘 중 하나가 항상 우수하다는 전제 없이 같은 질문-정답 문서 쌍으로 비교한다.

평가 정답은 별도 파일의 문서 ID이며 검색 입력에 넣지 않는다. 고정 질문 12개 중 필요한 문서가 정의된 8개를 문서 회수 평가에 사용한다. 상위 3개 Chunk에 들어온 문서 ID를 모으고, 필요한 문서 중 몇 개가 포함됐는지 사례별로 계산한 뒤 평균한다. C09는 DOC-A와 DOC-B가 모두 필요해서 하나만 찾으면 0.5다. 자료 부족·제한 자료·공백·가용 자료 제한 사례는 이 평균과 별도로 검사한다.

| 실제 실행 방식 | 필요한 문서 포함 비율 평균, 상위 3 Chunk | 첫 Chunk의 관련 문서 적중 비율 |
|---|---|---|
| BM25 | 93.75% | 50% |
| Dense | 87.5% | 75% |
| Hybrid | 100% | 75% |

이 값은 작은 가상 자료 8개 평가 사례의 관찰이다. 답변 정답률·실서비스 성능이 아니다. C07에서 Dense는 공격 메모 DOC-I를 먼저 찾고 DOC-A를 상위 3개에서 놓쳤다. C08의 바꿔 말한 질문도 BM25가 DOC-A를 찾았으므로 “Dense만 동의 표현을 찾았다”는 시나리오로 꾸미지 않는다.

**활동:** C07·C08·C09의 세 방식 결과를 비교한다. 어떤 단어와 문서가 순위를 바꿨는지 원문과 대조한다. 필요한 문서가 있어도 답에 필요한 문장까지 들어왔는지도 따로 본다.

**제출:** 질문·관련 문서·검색 순위·누락·해석 한계 표. **확인 질문:** 상위 결과가 3개 나왔다면 자료에 답이 존재한다고 판단해도 되는가?

## K2-07.U03 유사도·정규화·차원

Dot Product는 성분별 곱의 합이다. Cosine은 두 벡터의 길이 영향을 나눠 방향을 비교한다. L2 거리는 두 점 사이 거리다. 정규화하지 않은 벡터에서는 Dot 순위와 Cosine 순위가 달라질 수 있다.

작은 계산 예로 질문 q=(1,0), 후보 A=(0.8,0.6), B=(2,2)를 사용한다. A와의 Dot은 0.8, B와의 Dot은 2다. Cosine은 A가 0.8, B가 약 0.7071이다. 길이가 큰 B가 Dot에서 유리해졌지만 방향은 A가 더 가깝다. 실제 계산값은 선택 ANN 실습 기록의 vector_math에 있다.

단위 벡터끼리는 Dot과 Cosine이 같고, 제곱 L2 거리는 2에서 Cosine의 두 배를 뺀 값이다. 따라서 같은 벡터와 같은 조건이면 Dot이 큰 순서와 L2 거리가 작은 순서가 일치한다. 이번 Exact 검색은 단위 벡터의 Dot을 사용한다. 길이가 0이거나 차원이 맞지 않거나 유한하지 않은 값은 거부한다.

차원이 맞아도 모델이나 리비전·Pooling·접두어가 다르면 좌표의 의미가 같다는 보장이 없다. 차원 검사만 통과시켜 옛 문서 벡터와 새 질문 벡터를 섞지 않는다. 유사도 점수 0.8 역시 답의 정확도 80%나 신뢰도 80%가 아니다. 자료 없음 판단의 임계값은 별도 평가로 정해야 한다.

**활동:** 위 두 후보의 Dot·Cosine·제곱 거리를 직접 계산하고 정규화 전후 순위를 적는다. Manifest의 normalized와 dimension이 계산 방식과 맞는지 확인한다.

**제출:** 손계산과 실행 계산의 비교표. **확인 질문:** 서로 다른 두 모델이 모두 384차원이면 같은 Index에 추가해도 안전한가?

## K2-07.U04 Hybrid·Reranking·모델 교체

Hybrid는 서로 다른 검색 신호를 함께 이용한다. 이번 실습은 Dense 순위와 BM25 순위를 Reciprocal Rank Fusion으로 합친다. 서로 단위가 다른 원점수를 그대로 더하지 않고, 각 목록에서 몇 번째인지로 점수를 만든다. 순위가 r이면 1/(60+r)을 더하는 고정 설정이다. 두 목록은 같은 권한·현행·가용 자료 필터를 거친다.

Reranking은 먼저 찾은 후보를 다시 평가해 순서를 바꾸는 단계다. 질문과 후보 문장을 함께 읽는 Cross-Encoder 등이 여기에 쓰일 수 있다. 처음 후보에서 빠진 문서를 Reranker가 저절로 가져오지는 못한다. 이번에는 학습된 Reranker를 실행하지 않았다. Hybrid의 결과를 Reranker 실험 결과라고 부르지 않는다.

모델 교체는 검색 설정의 변경이다. 문서 벡터를 새 설정으로 다시 만들고, 새 Index에서 같은 평가를 실행하고, 채택하거나 복구할 준비를 한다. 모델 ID·리비전·차원·Pooling·정규화·질문/문서 접두어·Token 상한을 함께 비교한다. 기존 Index와 설정이 다르면 재사용을 거부한다.

이번 실제 재색인 실험은 같은 E5 가중치의 Token 상한을 512에서 128로 바꾼 것이다. 같은 차원이어도 기존 Index를 열지 못하고 새 Index를 만들게 했다. 서로 다른 가중치의 두 검색 모델을 비교한 실험은 아니다. 작은 자료는 두 상한 안에 들어가므로 이 변경 자체가 검색 개선을 의미하지도 않는다.

**활동:** C07에서 Hybrid가 DOC-A를 후보에 되살려도 공격 메모가 첫 번째에 남는지 확인한다. 모델 교체 계획에 새 Index 생성·고정 평가·권한/삭제 회귀·전환·복구 순서를 적는다.

**제출:** 검색 방식 비교와 모델 교체·복구 계획. **확인 질문:** Hybrid의 회수 비율이 100%라면 Reranker나 답변 근거 검토를 생략해도 되는가?
