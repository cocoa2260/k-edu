# 검색 표현 수업의 해설과 관찰 기준

학생용 [강의](lesson.md)와 [연결 실습](../../practice/document-assistant/L3.md#embedding-활동)에 대응한다. 같은 작성자가 설명과 실제 파일을 대조한 해설이며 독립 강사·교육생 수업 검증은 아니다. 정답 문구를 암기했는지보다 어떤 입력·계산·원문을 근거로 설명하는지 확인한다.

## 1장: 번호·위치별 표현·검색 벡터

1. **20과 384:** 20은 해당 예에서 접두어/특수 Token을 포함한 입력 위치 수다. 384는 위치별 또는 최종 검색 벡터의 실수 성분 수다. 배치 B×T×384에서 T축을 평균한 뒤 B×384가 된다는 설명이 핵심이다. 실제 이 문장이 20 Token이라는 관측은 아니다.
2. **패딩 변경:** 올바른 마스크 평균은 바뀌지 않는다. 세 번째 위치에 0을 곱하고 실제 두 위치로 나누기 때문이다. 평균 후 정규화도 같다. `(9,9)`와 `(900,900)`은 원리를 확인하기 위한 가상 값이다.
3. **임의 평균:** 그 자체로 좋은 검색 표현이라는 보장이 없다. 모델의 학습 목표와 지정된 Pooling/역할 접두어/정규화·길이 제한을 함께 확인하고 고정 질문으로 평가해야 한다. ‘생성용 벡터는 절대 검색에 못 쓴다’는 식의 과도한 금지도 정답이 아니다.

## 2장: 어휘 일치·의미 표현·평가

1. **밥값 질문:** 현재 분절기로는 출장 규정 첫 줄의 ‘당일’이 일치한다. 그 사실만으로 동의어 학습을 주장할 수 없다. 이 과거 질문의 BM25 기록은 규정 첫 줄 하나이고, Dense는 표의 식비/영수증 행을 먼저 찾는다. ‘Dense가 항상 더 좋다’는 결론은 근거가 없다.
2. **중복 조각:** 정답 문서가 두 개이고 결과가 그중 한 문서의 조각들뿐이면 1/2이다. 결과가 정답 두 문서 모두와 무관하면 0이다. 세 조각이니 3/2 또는 100%라는 답은 잘못된 분모를 쓴 것이다.
3. **숙박비:** 결과가 나왔어도 원문에 상한이 없다. 숫자를 추정하지 않고 자료 부족·기준 없음으로 구분해야 한다. 해당 경계 사례는 문서 회수 평균의 8개에 포함하지 않는다. None을 회수 0점으로 바꾸어 기존 평균을 재계산하지 않는다.

## 3장: 내적·Cosine·거리

1. **B=(20,20):** 길이는 √800, 내적은 20, Cosine은 20/√800≈0.7071이다. 양수 배율은 방향을 유지하지만 내적 크기는 바꾼다. 정규화한 B도 이전과 같다.
2. **단위 벡터:** 제곱 L2는 2−2×0.8=0.4다. L2 거리는 √0.4≈0.6325이고 작은 쪽이 가깝다. 원래 거리·정규화 후 거리·제곱 거리를 구분한다.
3. **서로 다른 모델:** 정규화는 벡터의 길이를 맞출 뿐 좌표 의미를 맞추지 않는다. 모델/리비전·표현 처리 계약이 다르면 같은 차원이라도 재사용을 거부하고 자료 벡터를 새로 준비한다.

## 4장: RRF·후보 재평가·전환

1. **BM25에 A 없음:** BM25의 남은 전체 목록은 B→C이고 Dense는 A→B→C다. A는 1/61≈0.01639344만 받는다. B≈0.03252247, C≈0.03200205이므로 B→C→A다. 목록에 없는 A에 임의의 낮은 순위를 주어 기여를 더하지 않는다.
2. **공격 메모와 규정:** 관련도와 지시 권한은 다르다. Hybrid에서 규정을 회수했어도 메모가 첫째에 남았다. 문서 속 명령을 시스템 지시로 올려서는 안 된다. Reranker도 후보 관련도의 추가 판단일 뿐 현행성·권한·주장 근거를 모두 대신하지 못한다. 이번에는 학습된 Reranker 실행 자체가 없다.
3. **모델 교체:** 같은 차원이어도 좌표계가 달라질 수 있다. 자료를 새 설정으로 재인코딩하고 새 Index를 준비한다. 고정 평가·필터/갱신/삭제 회귀, 채택 판단, 이전 모델+Index 쌍으로의 복구를 포함한다. 기존의 512→128 시험은 같은 모델 길이 설정 변경이지 다른 가중치 모델의 품질 검증이 아니다.

## 연결 실습에서 받을 설명과 피드백

| 활동 | 충분한 관찰·해석 | 보완해야 할 답 |
|---|---|---|
| 손계산 | A/B 길이·내적/Cosine 순위·단위 제곱 거리, 패딩 평균, RRF B→A→C를 입력과 연결 | 숫자만 복사, 가상 계산을 E5 관측으로 표시 |
| 분절 | ‘당일’ 일치와 조사 차이, 단일 ‘밥값’은 무일치임을 현재 함수로 확인 | BM25가 밥값=식비 의미를 배웠다고 주장 |
| 기록 읽기 | 저장된 과거 실행과 지금 도구 실행을 구분, 규정 조건/예외를 원문에서 지목 | 화면에 출력됐으니 지금 모델을 돌렸다고 주장 |
| 근거 구분 | 공격문, 두 문서/필요한 줄의 차이, 기준 없음과 None의 의미 | 문서 회수 1.0을 답 정확도나 공격 방어로 표시 |
| 교체 계획 | 설정·문서/벡터 재생성·같은 평가·복구, 실제 교체 미실행 표시 | 차원만 같으면 질문 모델만 교체, 계획 제출을 실행 완료로 표시 |

분절 소예제의 BM25 양수 크기를 암기시킬 필요는 없다. 어떤 검색어가 어떤 문장에서 정확히 일치해 0 또는 양수가 되는지를 설명하게 한다. 새 실제 모델 결과가 과거와 다르면 환경·소스·고정 리비전·입력·설정/필터부터 대조한다. 임의로 점수를 과거 값에 맞추지 않는다. 벡터가 비슷한 것과 해당 문장이 상한·조건을 지지하는 것은 별도 질문으로 묻는다.

## 과거 설정 기록 불일치를 설명할 때

과거 `manifest_before_mutation.profile`과 삭제 후 Manifest의 profile은 인코더의 설정 사전을 그대로 참조했다. 실행 후반에 `max_tokens`를 128로 바꾸자 앞서 만든 기록의 표시값도 바뀌었다. 당시 `profile_sha256`는 문자열로 계산해 둔 값이라 512 설정의 해시가 유지됐다. 새 코드는 Manifest를 만들 때 설정을 깊은 복사하므로 이후 변경의 영향을 받지 않는다. 반환한 Manifest를 독자가 변경해도 인코더 설정이 바뀌지 않는다.

이 오류를 별도 경계 검사로 재현/수정 검증했고 과거 파일은 보존한다. 검색 순위·점수·호출은 이 설정 사전 값의 사후 변경과 별개다. 모델을 새로 실행한 것처럼 과거 JSON을 고쳐 쓰거나, 과거 표시값 128을 최초 실행 설정으로 인용하지 않는다. 현재 새 모델 전체 실행은 이번 수정에서 미실행이다.

| 기존 단원 | 학생용 장 | 직접 연결 활동 |
|---|---|---|
| K2-07.U01 ID·내부 표현·검색 표현 | 1. 문장에서 검색 벡터까지 | 활동1의 패딩 평균·활동3의 표현표·활동5의 코드 확인 |
| K2-07.U02 Dense·Sparse·BM25 | 2. 글자가 맞는 자료와 의미가 가까운 자료 | 활동2~4의 분절·같은 질문 비교·문서/문장 평가 |
| K2-07.U03 유사도·정규화·차원 | 3. 벡터의 길이와 방향 | 활동1의 계산과 입력 변경 |
| K2-07.U04 Hybrid·Reranking·모델 교체 | 4. 두 검색 결과를 합치고 다시 판단 | 활동1의 RRF·활동4 공격문·활동5 교체/복구 |
