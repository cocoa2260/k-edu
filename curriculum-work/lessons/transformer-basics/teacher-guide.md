# K2-02 강사용 해설과 검토 기준

교육생의 기본 경로는 [강의](lesson.md)와 [활동지](worksheet.md)다. 별도 JSON과 계산 코드는 검증/재현용이며 선행 독해가 필요하지 않다. 수치는 합성이다. 실제 학습된 모델·언어 생성·수업 검증 결과가 아니다.

## 진행에서 지킬 구분

먼저 행벡터와 Shape를 확인한다. U01의 한 층, U02의 한 Head, U03의 여러 구성 요소, U04의 4차원 위치 예시는 서로 다른 작은 계산임을 설명한다. 그 숫자를 하나의 학습된 모델의 층별 실행 기록으로 해석하지 않게 한다.

값을 맞힌 뒤 “무엇을 보장하지 않는가”도 말하게 한다. Attention 가중치와 어휘 확률, Causal Mask와 권한, Cache와 영구 기억, 형상/수치 일치와 업무 품질을 구분하면 좋다. 아래 답과 문구가 달라도 조건·의미가 맞으면 인정한다.

## A · Forward

xW=[4,-1], Bias를 더하면 [3,-1], ReLU 후 [3,0]이다. Bias가 0이면 [4,0]이다. 입력은 1×2, W는 2×2, 출력은 1×2다. 입력 1×2와 W 3×2는 안쪽 차원 2/3이 달라 곱할 수 없다.

행렬의 저장 방향을 다르게 쓰는 구현을 언급해도, xW+b라는 이번 약속에 맞추어 변환하면 인정한다. Activation 없는 가중합/Bias의 합성은 하나의 affine 변환으로 정리된다. 이 계산은 고정 Weight의 Forward이며 학습으로 Weight를 갱신한 것이 아니다.

## B · 한 Head의 Attention

Q=K=X이고 V의 세 행은 [2,0], [0,4], [2,4]다. T3 Query의 내적은 [1,1,2], √2로 나누면 [0.70710678,0.70710678,1.41421356]이다.

| 항목 | 결과 |
|---|---|
| 가중치 | [0.2482550783, 0.2482550783, 0.5034898435] |
| 출력 | [1.5034898435, 3.0069796870] |
| X/Q/K/V Shape | 각각 3×2 |
| Kᵀ Shape | 2×3 |
| 점수/가중치 Shape | 3×3 |
| 출력 Shape | 3×2 |

소수 넷째 자리 답은 절대 오차 0.0002 정도를 허용하고 반올림 누적을 설명하게 한다. 원 계산 검사는 더 높은 정밀도에서 비교한다. Softmax는 Key 방향의 한 행씩 계산한다. 최댓값을 빼면 수치 폭주를 줄이면서 같은 가중치를 얻지만, 점수에 상수를 곱하는 것은 일반적으로 같은 결과가 아니다.

가중치가 큰 위치를 ‘정답 문서’나 ‘인과적 설명’으로 곧바로 판정하지 않는다. U02에서는 다음 Token의 어휘 확률을 계산하지 않는다. Q=K인 것은 이번 Weight 선택의 결과다.

## C · Block 구성 요소

두 Head의 Q/K/V는 각각 3×2, 가중치는 3×3, 출력은 3×2, 연결 후 3×4, 4×4 W_O 적용 후 3×4다. 한 Token의 연결은 [1,2,3,4], 투영은 [4,6,3,4], 지정한 Residual을 더하면 [5,6,4,4]다.

LayerNorm [1,3]의 평균은 2, 모집단 분산은 1이다. (성분-2)/√(1+0.00001) 결과는 약 [-0.9999950000,0.9999950000]이다. 각 Token의 특성 축 정규화와 Batch 또는 Token 전체 평균을 혼동하면 보완한다. γ·β를 생략한 일반 정의로 오해하지 않게 한다. 여기서만 γ=1, β=0이다.

FFN은 [1,2] → [1,-1,3] → [1,0,3] → [4,-3]이다. Shape는 1×2 → 1×3 → 1×3 → 1×2다. 각 Token에 같은 가중치로 적용하지만, Token 사이 조회는 Attention 쪽 계산과 구분한다.

Post-LN은 잔차 덧셈 뒤 정규화, 예시 Pre-LN은 하위 계산에 들어가기 전 정규화다. 어느 모델이든 하나의 형태라고 주장하면 실제 사양을 확인하게 한다. 요소를 제거한 영향은 표현·정보/기울기 경로·규모/학습 조건이 바뀐다고 설명하면 된다. 항상 즉시 실패한다고 단정할 필요는 없다. 별도 작은 예시들을 전체 Block 실행 성적으로 묶지 않는다.

## D · 위치·구조·Mask

위치/Mask 없는 Self-Attention에 행 순열을 주면 출력도 같은 순열로 바뀐다. 순열된 출력을 평균으로 모으면 같은 값이 나와 순서 정보를 구분하기 어렵다. Causal 구조에도 순서 단서가 있을 수 있으므로 모든 위치 표현 없는 모델에 이 결론을 확대하지 않는다.

4차원 Sinusoidal은 p=0에서 [0,1,0,1], p=1에서 약 [0.8414709848,0.5403023059,0.0099998333,0.9999500004]다. RoPE 단순 쌍 [1,0]의 90도 회전은 [0,1]이다. 같은 벡터 두 개의 내적 1은 하나만 회전하면 약 0, 둘 다 같은 회전이면 1로 유지된다. 실제 RoPE의 주파수·차원·길이 확장 설정은 모델 사양을 확인한다.

| 유효 Query | Encoder: T1/T2/T3/PAD | Causal+Padding: T1/T2/T3/PAD |
|---|---|---|
| T1 | 1/1/1/0 | 1/0/0/0 |
| T2 | 1/1/1/0 | 1/1/0/0 |
| T3 | 1/1/1/0 | 1/1/1/0 |

T2의 Causal 점수는 [0,1/√2,-∞], 가중치는 [0.3302384507,0.6697615493,0], 출력은 [0.6604769013,2.6790461973]이다. Mask가 없으면 가중치는 [0.1977758146,0.4011120927,0.4011120927], 출력은 [1.1977758146,3.2088967414]다.

Softmax 뒤 T3 가중치만 0으로 만들고 재정규화하지 않으면 합은 약 0.5988879073이다. 올바른 Mask 계산과 다르다. 모든 Key 차단은 별도 처리가 필요하고, 예제는 오류로 거부한다. PAD Key를 막는 것과 PAD Query 출력/손실을 무시하는 처리를 구분한다.

분류용 Encoder는 유효 입력 전체를 보는 예가 가능하고, 다음 Token 생성에는 미래 입력 차단이 필요하다. Cross-Attention은 Query가 Decoder, K/V가 Encoder 출력에서 온다. 문서를 Decoder-only의 프롬프트에 넣는 것은 그 자체로 별도 Encoder-Cross-Attention의 증거가 아니다. 문서 권한은 입력 전후의 시스템 경계로 별도 검토한다.

## E · 학습·생성·Cache

Teacher Forcing의 목표는 차례로 T1·T2·T3다. 미래를 차단하고 목표를 한 칸 이동하므로 여러 위치의 손실을 병렬 계산할 수 있다. 일반 자기회귀 생성은 아직 고르지 않은 Token을 모르는 조건에서 다음 선택으로 이어진다.

Prefill의 입력 T1~T3는 Cache 길이 3에서 T4 선택에 쓰인다. T4를 입력하면 길이 4에서 T5를 고르고, T5를 입력하면 길이 5에서 T6를 고른다. T6를 선택하고 멈추면 T6의 K/V는 아직 만들지 않았으므로 길이 5다. 모든 생성 API 내부 상태가 항상 이 시점으로 반환된다고 단정하지 않는다.

Cache는 층별 과거 K/V이며 학습된 Weight나 사용자 간 공유 가능한 무제한 기억이 아니다. 같은 Prefix·모델/Adapter·위치/Mask·수치 조건을 확인한다. 입력이 바뀌면 유효 구간을 다시 판단하고 재계산해야 한다. Cache를 써도 저장 공간과 과거 Key를 조회하는 계산은 남는다.

| 가상 설정 | 계산 | 결과 |
|---|---|---|
| 기본 | 2×1×4×128×4×8×2 | 65,536 byte / 64 KiB |
| T=256 | 2×1×4×256×4×8×2 | 131,072 byte / 128 KiB |
| B=2 | 2×2×4×128×4×8×2 | 131,072 byte / 128 KiB |
| Hq=4·Hkv=1 | 2×1×4×128×1×8×2 | 16,384 byte / 16 KiB |

GQA에서 Query Head 수를 KV Head 수 대신 곱하면 이 예시의 Cache 데이터를 과대 계산한다. Weight 양자화와 Cache 자료형은 별도다. 모델 Weight·Activation·작업 공간·관리 비용과 실제 serving 방식을 더 확인해야 하므로 장비 적합성이나 속도를 이 표만으로 채택하지 않는다.

합성 Attention Cache 검사는 위치/정규화/FFN/언어 출력층 없는 계산이다. 세 Prefix 길이 3·4·5에서 전체 재계산과 증분 K/V 결과를 비교한다. 실제 모델 생성·벤치마크를 수행했다고 답하면 보완한다.

## 평가와 후속 수업 검증

각 항목을 **충족 / 보완 / 미제출**과 근거로 기록한다. 반올림 허용 범위 내의 수치뿐 아니라 Shape·적용 조건을 본다.

| 단원 | 충족 기준 | 필수 보완 사례 |
|---|---|---|
| U01 | 가중합·Bias·Activation·Shape를 추적함 | 곱셈 방향/차원 오류, Forward를 학습 완료로 주장 |
| U02 | Q/K/V·√dₖ·행별 Softmax·Value 합과 크기를 설명함 | 다른 축 정규화, 가중치를 다음 Token 확률/사실성 보장으로 해석 |
| U03 | Head 연결·출력 투영·Residual·정규화 축·FFN 입출력을 구분함 | 모든 Head/모델이 같은 역할/구조라고 단정, 별도 예시를 전체 Block 실행으로 주장 |
| U04 | 위치 표현·구조별 Q/K/V 출처·두 Mask·조회 표가 맞음 | 미래 Token 노출, Mask를 문서 권한 대체로 사용, PAD/전부 차단 처리 누락 |
| U05 | 이동한 목표·병렬 학습/순차 생성·Cache 상태·바이트 요인을 구분함 | 마지막 선택 Token의 Cache 시점 혼동, Weight 형식=Cache 형식 가정, 계산 표로 실제 장비/품질 채택 |

독립 수업에서는 Shape·Softmax·정규화 축·생성 시점 중 막힌 지점, 계산/설명 시간, 강사 도움과 판정 불일치를 기록한다. 현재는 같은 제작 세션의 내용 검토와 합성 계산 검사이며 독립 강사 검토·실제 학습자 수업은 미실행이다.
