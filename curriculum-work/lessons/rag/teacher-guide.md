# 검색·생성·근거 검토 수업의 해설

[학생 강의](lesson.md)와 [연결 활동](../../practice/document-assistant/L4.md)에 대응한다. 같은 작성자가 문서·코드·저장된 모델 관찰을 대조한 해설이며 독립 강사/교육생 수업 검증은 아니다. 과거 실제 응답·이번 검사 반례·학생의 새 실행을 구분한다.

## 1장: 사전 준비와 한 질문의 호출

1. **Offline/Online:** 여기서 Offline은 문서 식별·분할·Embedding/Metadata 저장이라는 사전 처리다. 네트워크 연결 유무가 아니다. Online은 질문 검사·검색·Context·생성·검토라는 요청 처리다. 로컬 캐시만 사용하는 CPU 실행도 요청 처리 구간이 있다.
2. **보완과 미완료:** 첫 실제 JSON에는 claims가 없다. 금액이 맞아도 출력 계약을 어겨 보완했다. 두 번째는 출처/인용을 얻었지만 답변의 사전 승인·식사 제공 예외가 빠졌다. 인용문에 승인 조건이 있어도 최종 사용자 답변의 조건/예외가 완전하다고 하지 않는다. 524/46과 552/133은 당시 Template 포함 입력/새 출력 Token이다.
3. **원문과 Index 불일치:** 먼저 현재 원본/버전과 인덱싱된 본문·벡터·상태를 대조하고 필요한 갱신을 한다. 모델만 다시 호출해도 옛 근거가 새 규정으로 바뀌지 않는다. 현재성 검사는 저장소 기준이므로 저장소에 반영하지 않은 외부 원문 변경을 자동으로 알아내는 체계가 아니다.

## 2장: 재작성과 인접 줄 확장

1. **원 질문:** 검색어는 규정 중심으로 바뀌어도 생성 입력의 원 질문에는 999999원 요구가 남는다. 실제 v2 비교에서 공격 메모가 빠져도 잘못된 금액을 답했다. 재작성으로 검색 후보가 바뀐 사실과 생성의 공격 유도 대응을 구분한다. 교사 지정 질의이며 자동 Rewrite 모델은 없다.
2. **문서와 줄:** 기본 C09에는 DOC-B@v1:L2가 있었지만 200000원·시작 7일 전 승인 등의 근거는 L1이다. 문서 회수는 성공해도 필요한 줄은 없다. 인접 확장은 이미 찾은 문서의 주변 줄을 같은 접근/현행/가용 자료 조건으로 추가한다. 정답 ID 주입이 아니다.
3. **개선의 범위:** 확장 후 두 금액이 맞아져도 영수증 표 인용이 금액을 지지하지 않는다. 조건·예외 누락도 따로 본다. 실제 구현은 조각ID 순으로 자료를 모아 내용/길이/순서가 함께 바뀌므로 추가한 한 문장의 인과 효과로 단정하지 않는다. 문자 889→1202와 Token을 혼동하지 않는다.

## 3장: 주장·인용·상태

1. **맞는 인용/틀린 주장:** 현재 검사기는 제공 source_id와 quote의 원문 포함 여부를 확인한다. 50000원 주장에 실제 30000원 인용을 붙이면 통과할 수 있다. 의미상 모순·조건/부정·주장 지지는 원문 대조가 필요하다. 이 시연 JSON은 교사가 만든 반례이고 모델 출력이 아니다.
2. **답변 전체:** answer가 두 금액을 말하지만 claims에 영수증 표뿐이면 금액 주장들이 적절한 근거와 연결되지 않는다. 현재 검사기는 모든 답변 사실의 포괄/일치를 보장하지 않는다. 인용이 있는지, 인용이 주장을 지지하는지, 중요한 사실이 누락되지 않았는지 각각 본다.
3. **행동 구분:** 숙박비 기준 없음은 수치 추측 없이 보류, 지급 조건 불명확은 필요한 조건을 되묻기, 제한 자료는 허용되지 않은 내용 반환을 거부해야 한다. 공백 사전 거부는 모델의 정상 보류 응답이 아니다. outcome 이름이 맞아도 answer에서 사실을 단정하거나 무관한 내용을 지어내면 통과시키지 않는다.

## 4장: 원인 구간과 비교

1. **누락 위치:** 후보/실제 입력을 나누어 교육비 첫 줄이 어디서 빠졌는지 확인한다. 첫 줄을 추가해도 틀리면 원응답·지시/모델/설정과 주장/인용을 확인한다. 데이터 부족과 생성 실패를 한 원인으로 묶지 않는다.
2. **기술 중단:** 두 번 형식 실패 뒤 repair_limit로 초안 없이 종료한 것은 제어상의 거부다. 사용자에게 적절한 정상 보류 메시지를 얻은 것은 아니다. 기술적 failure_stage=None인 초안도 의미 오류가 있을 수 있다.
3. **채택:** C01 v2의 출처/인용은 부분 개선이지만 조건 누락, 다른 질문의 틀린 금액·공격 요청 추종·정상 보류 회귀가 남았다. 기존 사실 6개/경계 6개 평가와 비교 사례의 범위를 유지하고 두 버전의 채택 보류를 보존한다. 자동 검사 통과 수로 품질 완료나 독립 수업 통과를 표시하지 않는다.

## 활동별 관찰과 보완

| 활동 | 충분한 근거 | 보완이 필요한 답 |
|---|---|---|
| 식비 호출 읽기 | 세 전달 자료·claims 누락·실패 ID·보완 후 인용·조건/예외 누락을 연결 | 금액 또는 JSON 통과만으로 완성 판정 |
| 검색/확장 비교 | 원 질문 유지, 질의 변경, 추가/제외/재배치된 실제 줄·문자 길이·답/인용 비교 | 공격 메모 제외=공격 방어, 인접 줄 추가=품질 완료 |
| 검사 반례 | 같은 50000원 주장에 실제 인용/없는 인용/없는 ID의 통과·실패를 구분 | 반례를 실제 모델 생성으로 표시하거나 자동 통과를 사실성으로 해석 |
| 행동 구분 | 정상 보류·되묻기·제한 거부·공백 사전 거부·형식 실패 종료를 분리 | 초안 없음과 적절한 보류 응답을 동일 취급 |
| 지시 비교/진단 | 한 조건과 유지 조건, 실제 개선·회귀·미완료를 근거로 다음 실험을 계획 | 여러 변경을 한꺼번에 적용하고 특정 기법 성공으로 일반화 |

실습 전체 코드의 세 출력은 첫째 `True / None`, 둘째 `False / QUOTE_NOT_IN_SOURCE`, 셋째 `False / CITATION_NOT_SUPPLIED`다. 첫째가 의미상 틀린 주장을 통과시킨다는 점을 먼저 말하게 한다. 필드의 정확한 띄어쓰기·키는 프로그램 계약이고, 관리용 코드값을 외우는 과제가 아니다. 영문 실패 이름은 실제 검사 결과를 추적할 때 사용한다.

## 실행 근거를 다룰 때

- 기본 읽기 도구는 표준 라이브러리로 합본 기록을 읽는다. 현재 검사 반례만 Pydantic을 포함한 앱 환경을 사용한다. 모델을 불러오지 않는다. 본인의 새 rag_lab 사례 파일과 합본 형식을 구분한다.
- `--input`은 prepared_message와 Trace의 실패 ID로 호출 문자열을 재구성해 모든 call_started 해시와 대조한다. Chat Template 적용 전 문자열이며 입력 Token ID/내부 추론 복원이 아니다. 해시 불일치면 표시를 중단한다. 원응답은 저장 관찰 그대로다.
- 현재 실제 제어 검사는 고정 인코더/응답과 실제 LocalIndex/run_rag/check_grounding을 사용한다. 이 실행을 새 E5/Qwen 답변 품질로 표현하지 않는다. 새 Tokenizer/모델 환경·원래 전체 Pytest/HTTP·독립 수업은 별도다.
- Provider의 1536/512와 기존 2000문자, Harness 호출/재시도/보완 상한은 서로 다른 위치의 검사다. 시간 상한은 호출 전후 확인이며 실행 중 강제 취소를 검증한 것은 아니다.
- 새 실제 모델 결과가 다르면 고정 리비전·입력·자료·Template/생성 설정·패키지·재개 여부부터 대조한다. 기존 관찰을 맞추려고 출력을 고치지 않는다. 재개 설정은 모든 소스/환경을 완전히 고정하는 Lock이 아니다.
