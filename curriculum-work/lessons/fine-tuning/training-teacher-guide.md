# LoRA 훈련·평가·재현 수업 해설

[학생 본문](training.md)과 [연결 실습](../../practice/document-assistant/L7.md)의 개념 질문과 활동을 해설한다. 같은 작성자의 문서 검수이며 독립 강사·교육생 수업 검증은 아니다. 과거 실제 훈련 기록을 현재 실행으로 바꿔 보고하지 않는다.

## 작은 갱신과 한 Step

1. **8,192는 1024×1024 Weight 하나에 r=4로 추가한 두 행렬의 수다.** 실제 모델에는 여러 크기의 투영·Layer·Embedding이 있고 적용 대상도 선택한다. 학습 가능 수와 Base를 포함한 전체 수를 따로 확인한다. 기존 실제 수는 573,440/596,623,360이며 약 0.0961%다. 학생이 ‘모델 전체를 8,192개로 압축했다’고 설명하면 Layer 하나와 전체 모델을 다시 구분한다.
2. **갱신이 B(Ax)이므로 B=0이면 첫 Step에서 A 변화에 대한 출력 민감도는 0일 수 있다.** B에 대한 Gradient에는 Ax가 있어 0이 아닐 수 있다. B가 바뀐 뒤 A도 배울 수 있다. 모든 Tensor의 첫 Gradient가 0이 아니어야 한다고 요구하지 않는다. trainable 대상·유한한 Loss·Gradient·Optimizer 뒤 Adapter 실제 변화·Base 동결을 함께 확인한다. 동결 앞 16개 표본을 전체 Weight 불변 해시로 확대하지 않는다.
3. **rank는 갱신 표현의 중간 차원, alpha는 출력에 더할 배율, Learning rate는 Optimizer의 갱신 크기와 관계된다.** 기본 배율 alpha/r에서 r만 바꾸면 배율도 바뀐다. 큰 rank가 불량 정답·누수·부적절한 목표를 해결하지 않는다. 변경 전에 가설과 평가 조건을 적게 한다.

가상 2×2 예제는 [2,1]→Ax=2→BAx=[0.2,0.4]→배율 적용 [0.4,0.8]→[2.4,1.8]이다. 작은 예에서 추가 수가 원래와 같음을 함께 설명한다. 가상 스칼라 활동은 A=1/B=0에서 dA=0, dB=-4, 단순 SGD 뒤 B=0.4·예측 3.6·Loss 0.18이다. Qwen/AdamW/SFT Loss가 아닌 작동 원리 계산이다.

## QLoRA와 자원

1. **양자화 추론 성공은 학습 성공을 증명하지 않는다.** Gradient/Optimizer·저장·새 프로세스 재로드까지 별도다. 여기서 실행한 것은 CPU float32 LoRA다. bitsandbytes 지원 문서에 CPU가 있다고 현재 설치에서 QLoRA가 통과했다고도 쓰지 않는다.
2. **24억/3억 바이트 예제는 6억 Weight의 float32/4-bit 코드 저장량 산술이다.** 실제 메모리에는 양자화 상수·고정밀도 부분·Adapter/Gradient·Optimizer·활성값·임시값 등이 남는다. double quantization은 양자화 상수의 저장 부담을 줄인다. compute dtype과 저장 비트를 구분한다. 약 4.65 GiB는 기존 전체 프로세스 RSS 기록이며 GPU VRAM이나 훈련 한 Step 값이 아니다.
3. **Gradient 누적은 한 번의 Microbatch 부담을 줄이는 구성과 연결되지만 너무 긴 단일 예제의 메모리 문제를 반드시 해결하지 않는다.** 길이·Microbatch·checkpointing·rank/대상·backend를 확인하고 변경 조건과 실제 최고 메모리·시간을 기록한다. 장비명·지원 표만으로 3GB 교육생 PC 전체 실행을 승인하지 않는다. checkpointing은 메모리와 재계산 시간의 교환이다.

QLoRA의 개념·자원 판단 활동과 실제 실행 과제를 구분한다. 미검증 장비에 옵션만 붙여 ‘재현 명령’이라고 제시하지 않는다. 실제 QLoRA 실행은 지원/환경을 고정한 후 별도 결과가 필요하다.

## 결과를 읽는 기준

1. **같은 28 Step이어도 원본은 20행+8행 반복, 증강은 28행 한 번이다.** 정답 Token 노출량도 1,727/1,947이다. 같은 초기 Adapter는 비교의 한 조건일 뿐 증강의 인과적 효과를 분리하는 충분조건이 아니다. 다음 비교에서는 통제할 축과 측정할 축을 명시한다.
2. **abstain과 빈 claims는 계약을 통과하지만 answer의 ‘0’은 기준 부재를 설명하지 않는다.** 보상금 원문에 없는 수치를 답했으므로 의미 검토가 필요하다. 또한 첫 한도 질문의 seed 답변은 사실 내용이 있어도 claims가 비어 계약 실패다. 학생이 ‘형식은 의미보다 중요하지 않다’로 단순화하면 사용자 답의 정확성과 근거 전달 계약을 모두 충족해야 함을 짚는다.
3. **호출 감소는 조기 실패일 수 있다.** 기존 18개 회귀의 최종 초안은 세 조건 모두 0이다. 원본 조건의 되묻기 증가·종료 이유·도구 입력을 봐야 하며 효율 개선으로 채택할 수 없다. SFT 정답 작성과 Agent의 action/tool 계약도 다르다.

Validation의 seed 선택은 Test 지표를 읽기 전에 고정한 프로그램 순서다. 이미 공개·열람한 Test라는 한계는 남는다. Test를 보고 설정을 조정하면 독립 평가 자료를 새로 마련한다. 예제별 평균 Loss의 평균과 전체 Token 가중 평균을 혼동하지 않는지도 확인한다. 낮은 Loss만으로 수렴·일반화·업무 품질을 선언하지 않는다.

## 저장과 재현

1. **Base Revision·Tokenizer/Template이 달라지면 같은 Adapter라도 Weight/입력 기준이 달라진다.** adapter_config와 Weight 파일, Base·자료·설정·환경·평가를 연결해 보관한다. Adapter만으로 완전한 모델이 있다고 가정하지 않는다.
2. **동일 Token ID는 그 입력에서 같은 동작을 재현했다는 뜻이다.** seed의 첫 한도 질문은 claims가 비어 OUTPUT_CONTRACT 실패인데 새 프로세스에서도 같은 Token열이 나왔다. 재현 통과가 품질 통과가 아닌 실제 반례다. 저장 JSON을 읽는 활동과 새로 바이너리를 로딩해 실행하는 활동도 구분한다.
3. **Optimizer·난수·행 순서·완료 Step이 없으면 같은 상태의 훈련 재개가 아니다.** Adapter만 읽고 새 Optimizer를 만드는 것은 새 시작 조건이다. 현행 Runner는 Step 파일들을 쓰고 완료 포인터를 옮기며 설정·코드·자료/환경 변경을 거부한다. 구 실행과 게시 코드 해시가 다르므로 과거 관측 폴더 재개 거부는 정상이다. 무작위 작은 모델의 중단 검사를 실제 Qwen 중단 실험으로 확대하지 않는다.

## 실습 피드백과 제출 판단

| 활동 | 충분한 근거 | 보완이 필요한 답 |
|---|---|---|
| 작은 계산/실제 로그 | 가상 값과 실제 Step/Gradient/Adapter 변화의 차이 설명 | 가상 Loss를 실제 Qwen 훈련 성공으로 표시 |
| 자원 계획 | 저장 비트·계산 dtype·잔여 메모리·장비/실측 여부 기록 | 파일만 작으면 3GB에서 가능하다고 단정 |
| 평가/반례 | 선택 규칙과 보상금/claims 실패를 분리해 설명 | 8/10을 의미 정답률이라고 보고 |
| Agent 회귀 | 호출 수와 종료/최종 초안 함께 확인 | 호출 감소를 그대로 효율 향상으로 보고 |
| 재현/Card | 저장 Token 대조와 직접 재로드를 구분하고 제한 기재 | 같은 잘못된 답 재현을 성능 승인으로 사용 |

학생이 직접 재실행했다면 사용한 폴더·설정·환경과 관찰 파일을 받고, 기록만 읽었다면 그 범위로 제출하게 한다. 모델 바이너리·훈련 실행 없이도 계산·실패 분석 활동은 가능하지만 실제 훈련/재로드 과제의 완료로 세지 않는다. 훈련 설정을 바꾸려면 새 폴더에서 원인 가설 하나와 동일 평가를 유지한다.
