# 데이터 준비 수업의 해설과 진행 기준

이 자료는 학생용 본문의 질문에 답하고 연결 실습의 판단 근거를 설명한다. 실행 성공과 설명 이해, 모델 품질을 따로 확인한다. 같은 작성자가 문서를 검토한 기록이며 독립 강사·교육생 수업 검증은 아니다.

## 행동 목표와 변경 방법

1. **SFT는 교사 응답을 예측하게 하는 학습 방식이고 LoRA는 갱신할 Parameter의 구조다.** SFT를 Full fine-tuning으로 할 수도 LoRA로 할 수도 있다. “LoRA를 쓰겠다”만으로 목표 행동·좋은 정답·평가 기준은 정해지지 않는다. 학생이 회의실 예제에서 ‘근거가 있으면 조건을 포함해 답하기’ 같은 관찰 가능한 목표를 말하도록 한다.
2. **검색에 없는 규정과 빠진 권한 검사는 먼저 입력·실행기를 고쳐야 한다.** 학습에 예전 금액을 넣어도 현행 규정이 제공되지 않는 문제는 남는다. 거부 문장을 잘 생성해도 실행기에서 승인 없이 도구를 실행하면 권한 통제가 아니다. 반복 보류 사례도 실제 근거·Prompt·설정을 확인한 뒤 학습 가설을 세워야 한다.
3. **Soft Prompt는 사람이 읽는 지시 문장을 자동 작성하는 기능이 아니라 학습 가능한 연속 벡터를 조정한다.** 양자화 추론은 답변 생성이며 QLoRA는 양자화한 동결 Base 위 LoRA Parameter를 학습하는 구성이다. 훈련에는 Gradient·Optimizer·활성값 등 추가 자원이 필요하다. 메뉴 이름을 외운 답보다 선택 이유와 확인할 자원을 말하는지 본다.

## 원문과 다섯 행동, 가족 분리

1. **원문은 사실의 근거, 훈련 예제는 그 입력에서 바라는 행동, 평가 문항은 갱신 뒤 행동 확인에 쓰인다.** 같은 원문이라도 예약 상태가 없으면 되묻고 보상 기준이 없으면 보류한다. 숫자 정답 하나만 말하면 질문과 조건이 달라질 때의 행동을 다시 묻는다.
2. **질문 표현만 바꾼 같은 규정은 같은 원문 가족으로 묶는다.** 먼저 가족을 Train/Validation/Test로 나누고 파생도 부모 쪽에 둔다. 여기서는 4/2/2가 20/10/10행이 된다. 서로 다른 가족이어도 문장 틀이 비슷하므로 이 숫자를 완전한 의미 누수 방지나 충분한 일반화 평가로 설명하지 않는다.
3. **거부 예제에 비밀 원문을 넣으면 답변 거부 이전에 모델 입력으로 이미 노출된다.** permitted는 실행기가 제공한 모의 신뢰 값이며 사용자 주장으로 바꾸지 않는다. 이 데이터의 거부 정답과 실제 서비스의 인증·도구 권한 통제는 별도다. deny의 sources와 claims가 비어 있는지 직접 확인한다.

## 증강의 채택과 기각

1. **2시간을 정확히 인용하면서 답은 20시간이라고 해도 잘못된 정답이다.** 인용 문자열 포함 검사는 답변의 모든 주장이 참인지 판단하지 않는다. 현재 바꿔쓰기 채택기는 부모 target 변경을 거부한다. 해시까지 다시 승인하면 의미가 참이 되는 것도 아니다. 정답 재작성은 별도 검수 작업이다.
2. **Validation 파생을 Train에 넣으면 설정 선택에 사용할 내용을 학습에 노출한다.** 후보의 split만 train으로 바꿔도 부모가 validation이면 거부해야 한다. 부모 계보와 가족 분리를 함께 확인하는 이유다.
3. **행 수 증가와 성능 증가 사이에는 보장된 비례 관계가 없다.** 반복된 보류 표현만 늘리면 과잉 보류를 학습할 수도 있다. 학습 Step이 같아도 길이·반복 횟수에 따라 정답 Token 노출량이 달라진다. 원본/증강의 같은 시작 상태·Step·평가 조건과 행동별 결과를 함께 비교한다.

## Token과 정답 범위

1. **실제 응답 끝 EOS는 정답 Token이고 길이 맞춤 Padding은 -100이다.** 같은 ID를 써도 attention_mask의 1/0과 위치에 따라 구별한다. ID가 EOS와 같다는 이유로 전부 무시하면 종료를 배우는 정답까지 지운다.
2. **Prompt의 label=-100은 Prompt를 입력에서 지운다는 뜻이 아니다.** Prompt는 attention_mask=1로 읽고 그 뒤 응답을 예측하는 Context다. 이번 Loss에서 Prompt 위치를 직접 정답으로 채점하지 않는다는 뜻이며 실제 Transformer의 간접 Gradient까지 0이라는 주장은 아니다.
3. **Token/label 저장은 학습 준비다.** Optimizer Step과 Parameter 변화·평가·저장/재로드는 후속 확인이다. 가상 Token 예나 가짜 17분류 Logit 수치는 Qwen 학습 결과가 아니다. Causal LM의 다음 Token 정렬을 준비 코드와 모델이 중복 적용하지 않는지도 확인한다.

## 연결 실습 피드백

| 활동 | 충분한 설명의 예 | 다시 확인할 지점 |
|---|---|---|
| 실패 원인 고르기 | “2시간 자료는 입력에 있는데 보류했으므로 지시와 응답을 비교하고 행동 학습을 가설로 둔다.” | 모델 문제라고 단정하거나 모든 실패를 튜닝으로 보내는가 |
| 한 가족 읽기 | S01의 근거 답변과 S03의 예약 질문, S04의 보상 보류를 구분한다 | clarify와 abstain을 모두 자료 부족이라고 부르는가 |
| 현재 검수 실행 | 원본 40행, Train 파생 8개 채택·4개 기각이며 Train 28/Validation 10/Test 10이다 | 48행 전체를 훈련에 넣는가, 기각 ID를 외우고 이유는 모르는가 |
| 정답 범위 대조 | 저장된 첫 예제의 250~355 위치와 실제 EOS, 가상 Padding의 -100을 설명한다 | 지금 Tokenizer를 실행했다고 쓰거나 Prompt를 읽지 않는다고 말하는가 |
| 선택 실행/제출 | 새 출력 폴더·고정 리비전·관찰 근거와 실제 실행 여부를 남긴다 | 과거 파일을 자기 실행/품질 통과로 표시하는가 |

현재 데이터의 검수자는 같은 Work의 AI 작성자다. 학생이 새로운 예제를 만들면 의미·권한·출처·분리·검수 이유를 다시 확인한다. 기존 정답이나 review 해시를 복사해 자동 채택되게 하는 활동으로 바꾸지 않는다. 실제 모델이 이 행동을 배웠는지는 후속 훈련 비교에서 판단한다.
