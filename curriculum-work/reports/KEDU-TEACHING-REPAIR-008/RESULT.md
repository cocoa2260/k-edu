# RAG 교안·연결 실습 수정 결과

**RAG 네 단원과 연결 실습을 수정하고 같은 작성자가 설명·예제·실행 근거를 재검수했다.** 독립 강사/교육생 수업 검증은 아니다. 이번까지 이 기준의 설명 검수 범위는 25개이며 나머지 45개 단원 정비와 별도 실제 품질·수업 게이트는 남아 있다. 파일 작성 수 70/70과 구분한다.

[학생 강의](../../lessons/rag/lesson.md) · [연결 실습](../../practice/document-assistant/L4.md) · [강사 해설](../../lessons/rag/teacher-guide.md)

## 수정한 학습 흐름

- 한 식비 질문의 실제 검색 자료·입력 역할·원응답·형식 실패/보완·주장/인용·누락 조건을 이어 설명했다. 첫 응답의 claims 누락과 보완 후 인용을 실제 JSON으로 보여 주고 524/46, 552/133 Token을 당시 관찰로 구분했다.
- 사전 자료 처리와 요청 처리, 검색용 질의와 원 질문을 풀어 설명했다. 공격 메모가 빠져도 원 질문의 잘못된 금액을 따르는 실제 실패를 보존했다.
- 인접 줄 확장 전 교육비 문서/필요한 줄의 차이와 추가된 실제 문장을 제시했다. 확장은 내용뿐 아니라 조각ID 순서와 길이도 바꾸므로 새 문장 하나의 단독 효과로 단정하지 않았다. 금액 개선 뒤에도 인용 근거가 맞지 않는 문제를 연결했다.
- 자동 형식/출처/부분 인용 검사와 의미상 주장 지지·답변 전체의 근거 범위를 구분했다. 교사가 만든 50000원 주장+실제 30000원 인용 반례를 현재 검사기에 넣고, 정상 보류·되묻기·제한 거부·공백 거부·형식 중단을 나누어 판단하게 했다.
- 장별 질문 12개·강사 해설과 다섯 연결 활동, 실제 모델 준비/재개/개별 사례 읽기·오류 안내를 정비했다. 새 도구는 필요한 합본 사례/비교만 읽고 전체 호출 문자열은 선택적으로 보여 준다. 긴 JSON을 먼저 전부 읽게 하지 않는다.

## 이번 실제 확인과 근거 수준

보조 환경은 Python 3.12.14/Pydantic 2.14.1이다. 학생용 고정 요구 2.14.2와 다르며 새 E5/Qwen·Tokenizer·전체 Pytest/HTTP 환경을 실행하지 않았다.

| 근거 | 확인한 내용 | 해석 한계 |
|---|---|---|
| 저장된 실제 E5/Qwen 합본 | 28조건의 29호출 문자열 재구성/저장 해시 일치, 29원응답의 현재 형식/출처/인용 검사 결과 일치 | 새 모델 추론·Tokenizer 실행이 아님. 내부 추론/입력 Token ID 복원이 아님 |
| 저장된 선택 재생+현재 입력 구성 | 원문 DB에서 같은 자료를 다시 읽고 모든 기록의 메시지/계약과 대조, 인접 줄 확장/배치 순서 확인 | 저장 검색 선택을 재생했으며 새 의미 검색 실행이 아님 |
| 실제 현재 RAG/Index/Harness+고정 인코더/응답 | 입력→검색/Context→출력 검사, 공유 재시도/보완 3호출, 없는 출처/인용 실패, 공백 0호출, 빈 Context 보류, 호출 중 변경 시 초안 폐기 | 의미 없는 고정 벡터/응답으로 제어를 확인. 실제 모델 답변 품질이 아님 |
| 길이·입력 구분 | 원 질문/검색어 분리, 인접 줄/필터, 긴 가상 자료의 문자 예산 중단 | 실제 Tokenizer의 Token 길이 검사는 이번에 미실행 |
| 교사 반례 | 올바른 출처/실제 인용인데 50000원 모순 주장이 자동 통과 | 현재 검사의 한계 확인. 실제 모델 생성으로 표시하지 않음 |
| 교안/도구 실행 | 새 전체 코드 두 개·실제 JSON 두 개/검사기 발췌 대조, 합본 사례/비교/입력/반례 CLI와 오류/변조 해시 거부 | 개별 새 모델 사례 파일 읽기 코드는 과거 실제 사례를 격리 폴더에 복사해 확인. 새 모델 파일 생성이 아님 |

기존 구조 통과/최초 통과 수는 기록으로 재계산했고 기존 의미 평가의 집계는 과거 evaluation.json과 일치함을 확인했다. 의미 품질 점수는 기존 동일 세션의 수동 원문 대조를 보존한 것이며 새 자동/독립 채점으로 만들지 않았다. 사실 6개와 경계 6개, 별도 비교 사례의 분모를 유지한다. 두 지시 버전의 채택 보류도 그대로다.

직접 검사와 CLI 자식 프로세스에 연결 시도 거부 가드를 두었고 시도를 관찰하지 않았다. OS 차원의 네트워크 격리 검증은 아니다. 현재 검증에서 유료 API·새 모델 생성은 없고 어떤 소스나 평가 정답을 생성 입력에 새로 주입하지 않았다.

## 보존·한계·다음 작업

기존 RAG·Harness·Index·Provider·모델/생성 설정·실제 실험/테스트·원본 자료/질문/정답·API·과거 보고서와 이전 정비 교안은 변경하지 않았다. 입력 문자열 재구성도 기존 동작과 저장 해시를 대조할 뿐 실행기를 바꾸지 않는다. 모델/Tokenizer·캐시/전체 Pytest/HTTP·교육장/UI·독립 수업·실제 인증/승인 품질은 별도 미완료다.

재개 설정은 모델 프로필·자료·RAG 코드/지시를 대조하지만 모든 실행 코드/패키지의 완전한 Lock은 아니다. 시간 상한은 호출 전후 검사이며 실제 실행 중 강제 중단을 검증한 것이 아니다. 합본 읽기와 새 rag_lab 개별 사례 파일을 구분하고, 과거 생성 기록을 새 결과로 고쳐 쓰지 않는다. 상세 기준과 범위는 [validation.json](validation.json)에 남긴다.

다음은 Single-Agent 네 단원과 L5 연결 실습이다. 모델 도구 선택과 실행기의 인자/권한 검사, 상태·관찰·종료를 한 요청으로 설명하고 Workflow/Tool/MCP/Framework와 미실행 범위를 구분한다. 추천 추론 강도는 **High**다.

공식 [고정 Qwen Model Card](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md)에서 non-thinking과 샘플링 권장을 확인하고 현재 Greedy 실험과 구분했다. Phase1의 상황→원리→중간값→실행/해석 전개는 현재 프롬프트의 고정 참고를 재사용했으며 Phase1 전체를 재분석하지 않았다.
