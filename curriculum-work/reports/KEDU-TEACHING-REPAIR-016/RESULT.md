# 시작 안내 세 단원과 활동·해설 수정

**기존 사례와 설명 범위를 유지하면서 시작 안내 세 단원·활동지·강사 해설을 수정하고 같은 작성자가 설명을 검수했다.** 누적 54개 설명 검수, 나머지 16개 정비가 남았다. 실제 모델 품질·운영 채택·독립 강사/학습자의 수업 검증은 별도 미완료다.

[강의](../../lessons/orientation/lesson.md) · [활동지](../../lessons/orientation/worksheet.md) · [강사 해설](../../lessons/orientation/teacher-guide.md)

## 기존 내용에서 유지한 것과 보완한 것

기존 합성 A v2/v1·비공개 B 카드, 문제 정의 여덟 항목, 서로 다른 세 실패, Lifecycle 단계/책임표·규정 변경/노출 대응, 기술 분류·자기회귀/Diffusion 비교·출처 날짜 판단은 이미 유용한 전개였다. 전수 검사에서 정한 대로 이 범위를 보존했다. 관리용 단원·실패 코드를 교육생의 설명 출발점으로 쓰는 부분은 자연어로 바꾸고 교사용 매핑으로 옮겼다.

환불 질문의 두 가상 초안을 먼저 풀어 읽으며 기간·사용 여부로 확인한 조건과 근거 없는 금액 확정을 구분한다. 6일을 10일로 바꿔 학습자가 초안을 수정하고 예외까지 단정하지 않았는지 설명하게 했다. 합성 12문항/실패 0건은 종전의 설계 예시이며 이번 실행 성적이 아니다.

규정의 등록일과 발효일이 다를 때 문서 소유자·개발/업무 검토자·책임자가 각각 무엇을 결정하고 증거로 남기는지 풀었다. 새 v3 본문/금액을 주지 않았으므로 답변 내용은 추측하지 않게 했다. 버전 칸의 존재와 질문 시점에 맞는 근거인지의 검토도 구분했다.

가상 제품 소개 한 문장에서 모델 범주·구조·실행 도구·RAG 구성의 역할을 나누고, 빠진 모델/호출 경로를 찾게 했다. 자기회귀의 다음 Token과 Diffusion의 변화 과정은 원문 범위 안에서 풀되 실제 Token 분할·모델 출력으로 오인하지 않게 했다. 새 기술/Adapter 전체 이름을 외우는 활동으로 바꾸지 않았다.

단원마다 개념별 이해 확인 3개, 총 9개와 판단 근거 해설을 추가했다. 활동지 A·B·C에도 같은 질문 변화·적용일·가상 구성을 연결했다. 뒤 실습의 식비·회의실 등은 다른 합성 업무이므로 오늘의 환불 규정을 복사하지 않고 같은 판단 방법을 옮겨 쓴다고 안내했다. 기술 실행 준비는 기준 앱 강의로 연결한다.

## 이번에 확인한 것

고정 부모 커밋의 대상 세 문서와 제작 프롬프트·진행 정보가 로컬과 Git blob 해시로 일치함을 확인했다. Phase1의 배송비 규칙 설명→코드/결과 해석과 현재 프롬프트의 확인 구간, 기존 기준 앱 준비·누적 실습 안내를 참고했다. Phase1 전체를 재분석하거나 실습을 재실행한 것은 아니다.

같은 작성자가 설명→예제→활동→해석·질문/해설을 읽고, 금액/권한/폐기 규정·두 날짜·모델 범주/구조/생성/도구를 대조했다. Transformer·DDPM·DiT 원 논문의 제목/초록/최초 제출일, PEFT·Transformers·Model Card·Ollama 공식 문서의 해당 설명을 2026-11-03에 확인했다. 페이지 확인은 특정 모델의 라이선스·실측 성능·전송 경로 확인이 아니다. 학습자는 자신의 직접 확인 여부/날짜를 별도로 남긴다.

변경 문서의 상대 경로·활동지 제목 앵커·표 구조와 관리 단원 매핑·54/16 집계를 검사했다. 실행 코드·데이터·과거 결과와 기존 단원의 runtime 상태·전체 품질 게이트는 보존한다. 이 정적 검사는 설명의 충분성을 자동으로 증명하지 않으며 본문을 읽은 자체 설명 검수와 구분한다.

## 미실행과 다음 작업

이번 활동은 프로그램 실행이 없는 작성·판단 연습이다. 실제 모델/Tokenizer/API·훈련·검색/권한 구현·브라우저·독립 교사/학습자 수업을 새로 실행하지 않았다. 가상 초안·예시 문장을 실제 모델 결과나 검증 완료로 기록하지 않는다. 기존 독립 미완료를 해소했다고 주장하지 않는다.

현재 추천은 범위가 정해진 시작 안내 정비에 **Medium**이었다. 다음은 데이터·평가 네 단원과 활동/해설 정비이며 **High**를 추천한다. 예측 시점·원문 가족별 분리/누수·일반화와 실험 조건·지표 산술 및 오류 영향을 실제 예제와 함께 판단해야 한다.

세부 검수 근거·원문 버전·정적 검사·게시 확인은 [validation.json](validation.json)에 별도로 남긴다. 교육생의 필수 읽기 문서는 강의와 활동지다.
