# 전체 Train 학습과 회귀 검증 결과

**원본 20개·증강 28개 전체를 포함해 조건별 28 Step을 실행했다. 기존 Single-Agent 18개 사례도 세 조건에서 모두 다시 실행했다. 품질 채택과 수렴 판정은 별도다.**

| 조건 | 학습 예제/Step | Validation Loss | Test Loss | Test 계약 통과 | 계약+행동 이름 일치 |
|---|---|---|---|---|---|
| base | 0/0 | 1.707224 | 1.706630 | 0/10 | 0/10 |
| seed | 20/28 | 0.375139 | 0.349665 | 8/10 | 4/10 |
| augmented | 28/28 | 0.459348 | 0.444199 | 8/10 | 3/10 |

Validation으로 고정한 후보는 **seed**다. 선택 기록을 Test 실행 전에 저장했고 Test 결과로 설정을 다시 고르지 않았다. 고정 설정·한 Seed·28 Step이며 최적 설정이나 충분한 수렴을 확인한 실험은 아니다.

계약은 기존 JSON/인용 검사다. 행동 이름 일치도 의미적 정답률이 아니다. 숫자·조건·예외·불필요한 거부는 원문과 별도로 대조해야 한다. 이 Test는 이전 4 Step 실험에서도 이미 확인한 공개 자료다. 이번 선택 알고리즘이 Test 지표를 쓰지 않았어도 블라인드 최종 평가가 되지는 않는다. 같은 AI 작성/검수라는 한계도 유지한다.

원본은 20개 전체를 한 번 본 뒤 8개를 반복하고, 증강은 28개를 한 번씩 본다. 양쪽 모두 28 Step이지만 Token 노출량·행동 분포가 달라 증강의 인과적 효과로 단정하지 않는다. 동일 초기 Adapter 해시도 확인했다.

## 지표와 별개로 확인한 의미 오류

원본 학습 모델은 보상금 기준이 없는 질문에 outcome=abstain을 쓰면서 answer를 0으로 출력한 사례가 있었다. JSON 계약과 행동 이름은 맞아도 없는 금액을 만든 셈이다. 교정 질문에 clarify를 선택하거나 권한 제한 질문을 되돌려 묻는 오류도 있었다. 증강 모델에서는 원문에 없는 5000원 보상금을 만들거나, 45분 한도를 이용 불가로 바꿔 설명한 사례도 있었다. 같은 Work의 대조이며 독립 정답률을 매긴 것은 아니다.

## 새 프로세스·검사·한계

두 Adapter 모두 별도의 새 Python 프로세스에서 Base를 다시 읽어 Test 첫 사례의 Token ID가 일치했다. 캐시 전용 요청 가드에서는 HTTP 시도 0회였다. 모델 병합·다른 Runtime 변환·GTX 1060 3GB 실측은 하지 않았다.

278개 테스트 통과. 작은 무작위 모델의 체크포인트 중단/재개 최종 Weight 일치는 실제 Qwen 중단 실험과 다르다. 프로세스가 겹친 초기 시도 하나가 메모리 한도로 종료됐고 기존 단일 실행이 계속됐다. 이 실패를 성공 수치에 포함하지 않았다.

관측 실행의 원본 소스 해시는 configuration과 실행 소스 기록으로 확인한다. 게시 Runner는 체크포인트를 Step별 디렉터리에 저장한 뒤 완료 포인터를 옮기도록 보완했다. 모델 학습/평가 로직은 같지만 소스 해시가 달라 기존 관측 폴더에 현재 Runner로 resume하면 거부되는 것이 정상이다. 새 폴더에서 실행한다.

QLoRA·IA3/DoRA·다중 Seed·독립 강사/교육생 검수·교육장 동시 실행은 미완료다. 이번에는 새로운 강의 단원을 더하지 않아 자료 작성 수는 **44/70**으로 유지한다. 후속 제작은 PDF/OCR/L8로 진행하면서 품질·QLoRA·독립 검증 미완료를 별도로 추적한다.
