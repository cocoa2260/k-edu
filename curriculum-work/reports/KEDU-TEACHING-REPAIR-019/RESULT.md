## 수정한 설명과 연결 활동

기존 Sinusoidal·회전·조회 허용표·T2 가중합·학습 목표 이동·Prefill/Decode·Cache 메모리 예제를 유지했다. 단원 관리 코드는 교육생 제목에서 자연어로 바꾸고 교사용 매핑으로 분리했다. 별도의 작은 계산을 하나의 실제 모델 실행처럼 이어 붙이지 않는다.

위치 표시값과 Token 내용, 입력에 더하는 방식과 Q/K를 회전하는 방식을 구분했다. 조회표의 두 번째 행에서 미래 위치와 PAD를 각각 제외하는 이유를 읽고, Softmax 뒤 가중치만 지운 합 약 0.5989와 허용된 대상에서 다시 정규화한 값을 비교한다. Decoder-only 문서 입력과 Encoder-Decoder Cross-Attention, Causal Mask와 문서 권한 경계를 구분한다.

학습 위치 2의 입력 T1·목표 T2·허용 BOS/T1을 풀고, 생성에서는 입력 처리→K/V 추가→다음 Token 선택 순서로 시점을 나눴다. T6 선택 후 길이5는 설명용 Token 흐름이며 실제 생성 기록이 아니다. 한 위치·한 층의 128 byte에서 128개 위치·4개 층의 65,536 byte로 확장하고 동시 시퀀스 수와 가입자 수를 구분했다. 기존 Hkv=1 행은 단일 KV Head인 MQA 한계 경우라는 설명을 추가해 중간 KV Head의 GQA와 구분한다.

두 단원에 각 3개 총 6개 개념 확인과 해설·활동 피드백을 연결했다. 기존 선택 명령에서 이번에 볼 JSON 항목·예상 값·실패 의미를 설명했다. 프로그램 실행 없이도 손계산/판단으로 필수 활동을 수행할 수 있다.

## 이번 검증의 범위

부모 커밋의 원문9개와 로컬을 Git blob 해시로 대조했다. 현재 제작 프롬프트와 기존 전수 검사 근거를 적용하고 이미 확인한 Phase1의 설명/예제/활동 전개 기준을 재사용했다. 원본 전체를 새로 분석한 것은 아니다.

기존 표준 라이브러리 공유 계산기를 현재 자료로 다시 실행했다. 위치0/1·회전·위치/Mask 없는 순서 성질, Mask와 미래 입력 변경 경계, Cache 길이3/4/5에서 전체·증분 계산의 마지막 출력 일치, 네 설정의64/128/128/16KiB, 잘못된 입력8종의 거부가 통과했다. 교안에 연결된 폴더에서 실제 `python check_examples.py`도 종료코드0이었다. 한 위치·한 층128byte→한 층16,384byte→네 층65,536byte와 T2 미래 가중치0·행 합1을 별도로 대조했다.

현재 실행은 실제 모델·위치/정규화/FFN/언어 출력층을 포함한 전체 Block 또는 Token 생성이 아니다. 앞 세 단원도 공유 계산기로 함께 확인했지만 그 실행을 새 설명 수정으로 중복 집계하지 않았다. Python 버전·자료 해시·실행 값과 미실행은 [상세 검증](validation.json)에 기록한다.

2026-11-03에 원 Transformer 논문의 구조/미래 차단, RoPE·GQA 원 논문, Hugging Face의 다음 Token 학습/Cache 공식 안내의 해당 내용을 확인했다. 문서/논문의 관련 범위를 읽은 것이며 라이브러리·모델을 실행하거나 실제 성능을 측정한 증거는 아니다. 링크·표·질문/해설·63/7집계 검사는 자체 설명 검수를 보조한다.

## 보존·한계와 다음 작업

앞 세 단원 본문·활동은 원문 그대로다. 교사 해설의 앞 세 단원 설명·질문/답도 보존했으며 ‘뒤 단원은 다음 정비’라는 지난 행정 안내 한 문장만 현재 상태로 갱신했다. 기존 계산 코드·JSON·과거 증거·다른 단원 runtime 상태와 전체 품질 게이트는 보존했다.

실제 모델 추론/훈련·Token 선택·속도/전체VRAM 측정·긴 문맥/업무 품질·독립 강사/학습자 수업은 미실행이다. 이번 추천 강도는 High였다. 다음은 언어 모델 기초의 앞 네 단원이며 High를 추천한다. 학습/Token 선택·정보 저장 위치와 시스템 평가를 구체적 예제 및 기존 실습 근거에 맞춰 함께 검토해야 한다. 이후 Hugging Face 첫 방문·Model Card·Tokenizer 세 단원을 정비한다.
