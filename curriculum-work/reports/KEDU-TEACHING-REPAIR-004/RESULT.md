# Context 교안·연결 실습 수정 결과

**Context 네 단원과 연결 실습을 수정하고 동일 작성자의 설명 검수를 마쳤다.** 기존 Prompt 대표본의 설명·예제 연결 원칙을 적용하되, 자료의 출처·선택·길이·현재 전달이라는 이번 주제에 맞게 구성했다.

학생이 먼저 볼 자료는 **[수정한 Context 강의](../../lessons/context/lesson.md)**와 **[연결 실습](../../practice/document-assistant/CONTEXT.md)**이다. **[강사용 해설](../../lessons/context/teacher-guide.md)**은 개념별 질문·활동 판정·기존 단원 매핑을 담는다. 공통 실습의 Context 연결 부분에서 이 안내로 이어지며, 기존 Prompt 활동은 보존했다.

| 수정한 내용 | 구체적인 학습 예 |
|---|---|
| 출처·신뢰 | 읽을 수 있는 이전 문서와 현행 근거의 차이, 문서의 공격 명령과 실제 권한, 제한 문서의 이름/본문 구분 |
| 선택·순서·형식 | 식비 질문의 다섯 자료→현행 규정 하나, 식비/교육비 비교의 두 문서, 같은 본문을 유지한 순서 변경과 예외 손실 반례 |
| Token 예산 | 기존 실측 657/264 + 출력 여유 256 → 합계 913/520·잔여 1135/1528. 가상 1900 입력은 108 초과 |
| 현재 전달 | 과거 문서 목록이 남아 있어도 현재 사용할 수 없으면 제외. 현재 문서가 있는 경우 ID/v1까지 대조 |

각 장에 다른 이해 질문과 교사 해설을 붙였다. 강의의 핵심 코드에는 실행 가능한 코드/발췌/설명용 예의 종류와 역할을 명시했다. 학생에게 관리 보고서와 JSON 전체를 먼저 읽게 하지 않는다.

## 실행과 재검수

새 `tools.context_steps`는 기존 입력 준비 함수와 자료를 재사용하는 학습 관찰 도구다. 선택·순서·과거 관찰 예산 계산·일회성 전달 자료를 확인한다. 기존 입력 생성 코드·자료·API·Prompt 본문/해설·이전 실행 증거는 변경하지 않았다.

- 문서 선택, 식비/교육비 질문, 제한/공격 자료의 준비 상태, 현재 가용 문서/버전과 오류 종료를 확인했다.
- 순서를 바꾼 실제 입력에서 같은 문서·본문·지시·질문과 문자 1151이 보존됐고 문자열의 순서는 달라졌다. 새 입력의 Token 수나 생성 품질은 측정하지 않았다.
- 예산 계산의 입력 파일 해시가 기존 Token 관찰 대상과 같았다. 입력을 바꾸는 반례에서는 과거 수치를 출력하기 전에 계산이 거부됐다. 913/520·잔여 1135/1528·가상 초과 108을 계산 대조했다.
- 교안의 실행 가능한 Python 세 블록을 실행하고, 핵심 발췌를 실제 입력 생성 소스와 대조했다. 기준별 설명 검수 근거와 실행 범위는 [검증 기록](validation.json)에 있다.

**보조 실행 환경은 Python 3.12.14/Pydantic 2.14.1**이다. 학생용 고정 요구 Pydantic 2.14.2와 다르므로 전체 고정 환경 재검증으로 표시하지 않는다. 검사 중 네트워크 연결/주소 조회 시도를 감시했고 0회였으며 새 모델 생성도 0회다.

현재 Tokenizer와 캐시는 준비돼 있지 않아 새 Tokenizer 실행은 하지 않았다. 657/264는 기존 고정 리비전·Template 관찰을 재사용한 값이다. Token 예산 계산이 실제 Provider의 출력 상한을 설정하거나 모델 최대 문맥·전체 메모리·답변 품질을 보장하지 않는다.

실제 검색·지속 Memory·문서 삭제/권한 서비스·Handoff 검증기 구현, Prompt/Context 조건의 실제 생성·의미 평가, 독립 강사/교육생 수업·교육장 실행은 이번 완료 범위가 아니다. 기존 품질·QLoRA·통합 미완료도 유지한다.

## 현재 위치와 다음 작업

이번 판정은 **설명·실습 연결의 동일 작성자 검수 통과**다. 교실 수업이나 독립 의미 평가의 통과가 아니다. Prompt/Context 8개 단원 정비를 기록했고 나머지 62개 단원은 검사 결과에 따라 정비해야 한다.

다음은 **Harness 다섯 단원과 연결 실습 수정·재검수**, 추천 추론 강도는 **High**다. 한 호출의 검사·재시도/보완·종료를 실제 Trace로 풀고, 기존 입력/제어 코드의 책임과 실패 경계를 정확히 연결해야 한다.
