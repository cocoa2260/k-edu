# 교육자료 제작·검수 프롬프트 수정 결과

**1단계인 제작·검수 프롬프트 수정을 마쳤다. 기존 70개 교안과 실습의 전체 검사·수정은 아직 하지 않았다.** 자료 작성 70/70은 유지하지만 교육자료의 설명 품질 통과나 수업 준비 완료를 뜻하지 않는다.

실제 적용할 문서는 [제작·검수·수정 지시](../../loop/prompts.md)다. 과거 분석 시범 지시는 그 문서 맨 아래에 원문을 보존했다. 이번 변경은 교육생용 교안과 실습 코드를 수정한 작업이 아니다.

## Phase1 원문에서 가져온 기준

‘일반 프로그램과 AI의 차이’ 교안은 상황·개념·집값 표를 설명한 뒤 같은 데이터를 코드로 연결하고, fit/predict의 줄별 의미와 출력값을 해설한다. 이어서 입력을 바꾸기 전에 예상하고 실행·해석하게 한다.

‘Transformers로 모델 직접 실행하기’의 확인 구간은 생성 옵션을 설명하고 반환 ID·문자열·입력과 새 생성 구간을 구분한다. 비교 실습에는 관찰할 값과 정상 변동을, 오류 활동에는 실패 위치와 해설을 붙인다. 원문 경로·고정 커밋과 확인 위치는 [프롬프트의 참조 표](../../loop/prompts.md)에 연결했다.

이 작성 방식을 Phase2의 내용·목표에 적용한다. 원문 분량 맞추기나 기술 사양 무검증 복사는 기준으로 삼지 않았다. 실제 모델 실습을 이번 작업에서 다시 실행하지 않았다.

## 바꾼 제작·검수 지시

| 항목 | 적용한 기준 |
|---|---|
| Phase1의 역할 | 설명 깊이·전개·예제/실습 연결의 참고 교안으로 명시. 중복 검토를 임의 축약의 허가로 사용하지 않음 |
| 강의 설명 | 새 개념의 뜻·필요성·과정/원리를 예제로 풀어 쓰고 활동과 결과 해석으로 연결. 단원 표를 짧은 요약으로 옮기는 방식은 보완 대상 |
| 식별자·코드 | 관리 ID를 교육생의 설명 출발점으로 쓰지 않음. 필요한 변수·수식·프로그래밍 코드·실제 파일/설정 이름은 맥락과 함께 사용 |
| 실습 검사 | 교육적 연결과 실제 코드/입출력·환경의 일치를 함께 검사. 실습을 검사 범위에 포함 |
| 판정 | 실제 문장·예제·활동의 근거로 설명 검수 통과/보완 필요/확인 불가를 판정. 테스트 수·분량·표의 항목 유무로 대체하지 않음 |
| 확장·수정 | 대표 교안과 연결 실습을 수정·재검수한 뒤 해당 결함이 있는 나머지에 적용. 코드값 삭제·문장 늘리기만으로 완료하지 않음 |
| 비용·재사용 | 검사 범위를 이어서 기록하고 고정 원문·유효한 실행 증거를 재사용. 관련 없는 코드/데이터 재작성·전체 재실행을 요구하지 않음 |
| 추론 강도 | 기준 재설계/다과목 교차 검토 Extra High, 기준이 정해진 설명/실습 수정 High, 제한된 표기/링크 정리 Medium을 출발점으로 작업별 판단 |

## 기준이 기존 문제를 잡는지 확인한 범위

같은 작성자가 새 기준을 아래 구간과 대조했다. 이는 기준의 적용 예시이며 전체 교안 검사나 독립 교육 효과 검증이 아니다.

| 대조한 구간/반례 | 판정과 이유 |
|---|---|
| [기존 Prompt 강의의 첫 단원](../../lessons/prompt/lesson.md)과 [연결 실습](../../practice/document-assistant/L1.md) | **보완 필요.** 실습의 비교 표와 사례별 기대 행동은 있으나, 강의는 실제 질문/변경 전후 지시를 풀어 보여주기 전에 C01·baseline/instruction의 비교를 요구한다. 링크가 있다는 사실과 학습 대상의 설명이 충분하다는 판단을 구분한다 |
| 같은 강의의 추론 기법 단원 | **보완 필요.** Self-Consistency·ReAct의 짧은 언급에서 바로 호출/실행 책임 분류로 넘어간다. 해당 전략의 과정과 구체적 예제·관찰을 설명하고 질문을 개념에 맞게 바꿀 필요가 있다. 네 단원의 동일 확인 질문만으로 이해를 판정하지 않는다 |
| Phase1 집값 예제의 설명·코드·해석 구간 | **확인한 설명 연결은 충족.** 앞서 설명한 데이터가 코드에 이어지고 fit/predict와 출력값을 해석한다. 코드가 있다는 이유로 탈락시키지 않는다. 전체 수업/환경을 통과시킨 판정은 아님 |
| ‘내부 ID만 자연어로 바꾸면 수정 완료’라는 처리 | **불충분.** 이름을 바꾸어도 원리·풀어쓴 예제·실습의 관찰/해석이 빠지면 보완 필요가 유지된다 |
| ‘기존 코드 테스트가 통과했으니 설명도 통과’라는 처리 | **불충분.** 코드 증거는 유효한 범위에서 재사용하되 설명 품질·실제 수업의 증거로 승격하지 않는다 |

이 대조에서는 기존 교안/실습을 편집하지 않았다. 코드·모델 호출·훈련·전체 회귀 테스트도 실행하지 않았다. 정적 링크·기록 일치 검사와 변경 범위/보존 확인은 [검사 기록](validation.json)에 남겼다.

## 다음 작업

**2단계: 기존 교육자료와 연결 실습 검사. 추천 추론 강도 Extra High.** 70개 단원을 과목별로 이어서 읽고 설명 결함·실습 불일치·재사용 가능한 자산·필요한 재검증을 위치와 함께 정리한다. 그 검사 결과를 근거로 3단계의 대표 교안 수정 범위를 잡는다. 이번 프롬프트 수정만으로 기존 교안이 좋아졌다고 표시하지 않는다.
