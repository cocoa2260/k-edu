# Single-Agent 교안·연결 실습 수정

**네 단원과 연결 실습을 수정하고 같은 작성자가 설명·예제·제어 동작을 재검수했다.** 독립 수업 검증은 아니다. 누적 설명 검수29개와 나머지41개 정비, 실제 품질 게이트를 구분한다.

[강의](../../lessons/single-agent/lesson.md) · [실습](../../practice/document-assistant/L5.md) · [해설](../../lessons/single-agent/teacher-guide.md)

## 바꾼 설명

모델의 요청과 실행기의 검사/호출을 검색→읽기→최종 제출의 고정 사례로 연결했다. 이름·엄격한 정수·추가 승인 필드·모의 승인·미발견 출처의 서로 다른 거부 지점을 설명했다. 함수 진입과 원문 반환, 네 번째 선택과 전체 처리3회, Runtime 재시도와 모델 결정, 발견/읽기 상태를 구분했다.

실제 모델은 검색 반복이나 미발견 출처로 실패한 기록을 그대로 보여 준다. 모델이 특정 요청을 하지 않았다면 해당 거부 검증으로 세지 않는다. 가이드 예시와 원문/최근 관찰이 다음 입력에 들어가는 범위, 인용의 의미 검토, 내부 상태 복원과 외부 부작용 취소의 차이도 설명했다. 질문12개와 해설·다섯 활동·직접 실행 코드·별도 모델/Framework 준비를 연결했다.

## 실제 확인

Python3.12.14/Pydantic2.14.1 보조 환경에서 직접 코드의 정상3/2/2·읽은원문1, 인자실패2/2/0, 미발견출처2/2/2·원문0을 확인했다. 현재 Registry로 이름/인자/승인/미발견 출처와 실행/인자에 묶인 모의 승인1회 사용·재사용 거부를 확인했다.

과거 실제18사례의 원응답을 고정 Provider로 재생하고 비의미 고정 벡터의 실제 LocalIndex/Runtime에서 종료·결정·처리/함수 진입·재시도 카운터가 일치함을 확인했다. 이는 새 모델/의미 검색이 아니라 현재 제어 검증이다. 저장 기록의 결정60·dispatch46(검색42/읽기4)·읽은출처0·근거초안0도 대조했다. 읽기 도구26사례와 잘못된 경로/키를 확인했다.

직접 검사 프로세스의 연결 시도 거부 가드에서는 시도가 없었다. CLI 자식 전체의 네트워크 격리나 OS 차단을 검증한 것은 아니다. 고정 요구Pydantic2.14.2·전체 Pytest/HTTP·새 E5/Qwen·Tokenizer·LangChain/Framework·MCP·독립 수업은 미실행이다. 기존 Framework 증거를 새 실행으로 표시하지 않는다. 공식 MCP 도구 명세는 확인했고 StructuredTool 공식 API URL은 검색 도구가 markdown 타입을 읽지 못해 본문 재확인은 하지 못했다. 기존 로컬 코드/과거 실제 API 증거 범위만 재사용했다.

## 보존과 다음

기존 Agent/Registry/정책·검색·Provider·자료·실험·보고서와 이전 정비 교안은 보존했다. 새 도구는 합본 읽기 전용이며 모델/Framework를 실행하거나 파일을 수정하지 않는다. 품질 채택 보류·실제 인증/지속 승인/강제 중단·교육장/UI/독립 수업 미완료를 유지한다. [검증 기록](validation.json)에 범위를 남긴다.

다음은 Multi-Agent 네 단원과 L6다. 같은 요청의 역할 전달·원문/상태·전체 예산·실패 전파를 풀고 역할 증가와 품질 개선을 구분한다. 추천 추론 강도는 **High**다.
