# Multi-Agent 교안·연결 실습 수정

**네 단원과 연결 실습을 수정하고 같은 작성자가 설명·예제·제어 동작을 재검수했다.** 독립 수업 검증은 아니다. 누적33개 설명 검수와 나머지37개 정비·별도 품질 게이트를 구분한다.

[강의](../../lessons/multi-agent/lesson.md) · [실습](../../practice/document-assistant/L6.md) · [해설](../../lessons/multi-agent/teacher-guide.md)

## 바꾼 학습 흐름

고정 Control의 모델5/도구2를 검색3·작성1·검토1로 풀고, 전달 요청JSON과 실행기가 만든Handoff 기록을 구분했다. 수신 범위M01, 공통보완/재진입M02, 부분/최종 초안M03, 전체/역할예산과 늦은출력M04를 같은 흐름으로 연결했다. 모델검토 pass와 사용자 승인/독립 의미 검증은 다르다.

실제 C01의 조기 되묻기, A02의 원문 전달 후 부적절한 보류/검토기각을 설명했다.42역할호출·부분6/최종0을 역할 수의 성공이나 비용 개선으로 해석하지 않았다. 예산/Prompt 차이·18사례 분모·별도 Role Probe를 통합 성공과 분리했다. 질문12개·해설과5활동·직접코드·선택적 실제모델 실행을 연결하고 긴JSON 전체를 필수 읽기로 만들지 않았다.

## 실제 검사와 한계

Python3.12.14/Pydantic2.14.1 보조 환경에서 기존 probes를 현재 Runtime/임시 SQLite/비의미 벡터/고정응답으로 실행했다. Control·M01~M03·M04의 전체모델/일시오류/가짜시계 하위 결과가 기존 기록과 종료·예산·초안/부분초안·승인/의미 상태에서 일치했다. M01 writer0, M02 모델7/도구2/보완1, M03 부분초안만 남음, M04 늦은 전달 차단을 확인했다.

writer 검색 도구 거부(처리1/함수진입0), 전체 JSON 코드블록 포장만 허용하는 파서와 Python/설명/다중JSON 거부를 확인했다. 새 전체 실습 코드를 실행하고 읽기 도구25사례·잘못된경로/키를 검사했다. 과거 실제18사례의42역할 입력 문자열 해시, 검색30/작성6/검토6, 함수진입 검색8/읽기6·부분6/최종0을 대조했다. 이것은 저장 관찰 검산이며 새 모델 실행이 아니다.

직접 검사 프로세스의 연결 시도 가드에서는 시도가 없었다. CLI 자식 전체나 OS 네트워크 격리 검증은 아니다. 고정 요구Pydantic2.14.2·전체 Pytest/HTTP·새 E5/Qwen/Tokenizer·교육장/독립 수업을 실행하지 않았다. 가짜시계 시험을 실제240초 장애 성능 시험으로 표시하지 않는다. 의미 품질 채택 보류도 그대로다.

## 보존과 다음

기존 MultiRuntime/Registry/정책·검색·Provider·자료·실험·과거보고서와 이전 정비 교안은 보존했다. 새 도구는 합본 읽기 전용이며 실행/파일수정을 하지 않는다. 별도 역할Probe는 실행기가 근거를 준비한 개별 호출이고 통합 성공이 아니다. 초기 되묻기의 짧은 시간·모델 검토/형식 통과·부분 초안은 과제 완료를 증명하지 못한다. [검증 기록](validation.json)에 범위를 남긴다.

다음은 Fine-tuning 앞 네 단원과L7 준비 활동이다. 목표/PEFT 선택·Dataset 설계/증강·학습입력 범위를 실제 예제로 풀고 기존 훈련/Reload/회귀 증거를 보존한다. 추천 추론 강도는 **High**다. Phase1의 설명 깊이·예제/실습 연결은 현재 제작 프롬프트의 고정 기준을 재사용했다.
