**후반 네 단원과 훈련 연결 활동을 수정하고 같은 작성자가 설명·예제·코드를 재검수했다.** 누적 41개 설명 검수, 나머지 29개 정비와 독립 품질/수업 검증을 구분한다. 코드/기록 검사는 수업 품질의 대체 증거가 아니다.

## 바꾼 설명과 교육적 연결

이전 본문의 짧은 정의·설정·제출 지시를 작은 갱신 계산부터 결과 판단까지 풀었다. W/A/B의 모양과 출력 합산, 2×2 가상 계산과 1024×1024 Parameter 산술, 실제 학습 가능/전체 수, 첫 B=0일 때 Gradient, Forward/Backward/Optimizer와 동결 표본의 한계를 설명했다. QLoRA는 양자화 코드/상수·계산 dtype·남는 메모리와 자원 선택으로 연결하고 CPU/3GB 장비의 미검증을 남겼다.

같은 초기 Adapter·28 Step이라도 행/Token 노출이 다른 실제 비교를 보여주고, Loss·JSON/인용·행동·의미·Agent 과제를 나눴다. 계약 통과 abstain의 answer=0, 사실을 말해도 claims가 없어 계약 실패한 첫 응답, Agent 호출 감소와 최종 초안 0개를 직접 해석했다. 잘못된 응답도 재로드 후 동일하게 재현된 실제 사례로 저장 재현과 품질을 구분했다. 추론 재로드·훈련 재개·병합/Runtime 변환, 결과 Card에 적을 한계까지 연결했다.

12개 질문과 개념별 해설, 네 활동의 예측·실행·관찰·제출 기준을 추가했다. 앞 준비 활동은 원문 그대로 보존하고 후속 훈련 안내를 읽기 계산/과거 관찰/선택적 실제 실행으로 구분했다. 실제 프로그램 ID·설정은 의미를 설명하고 단원 관리 매핑은 교사용으로 분리했다. Phase1의 설명 깊이와 예제/실습 연결을 참고하는 현재 제작 기준을 적용했다.

## 현재 실행·저장 관찰 검증

Python 3.12.14/Pydantic 2.14.1 보조 환경에서 새 읽기 도구의 여섯 모드·Test 10개·잘못된 인자, 실습 Bash 블록 3개를 실행했다. 가상 스칼라 SGD·2×2 Forward·Parameter/메모리 산술을 확인했다. 현행 Runner에서 schedule_ids/verify_config와 read/save의 함수 AST만 그대로 추출해 실행했다. 원본/증강의 28 Step 순서·전체 행 노출과 빈/중복/부족 Step 거부, 동일 설정 재사용·변경 거부를 확인했다. Torch 훈련이나 실제 체크포인트 저장/재개 실행은 아니다.

저장된 30개 실제 Test 원응답을 현재 계약 검사로 다시 확인해 0/8/8 계약 통과와 0/4/3 계약+행동 일치를 재계산했다. 예제별 Loss 평균, 선택 후보 seed, 학습 로그의 28 Step·20/28고유행·1,727/1,947정답 Token 노출·같은 초기 Adapter 해시, 두 새 프로세스 재로드의 저장 Token열 일치를 대조했다. 54개 Agent 회귀 기록의 생성 60/42/40·Handler 진입 46/22/33·최종 초안 0과 종료 분포를 검산했다. 이 값은 과거 실제 실행 기록의 대조이며 현재 새 모델 실행이 아니다.

원본 데이터 해시는 당시와 같았다. 현재 lora_full_lab.py는 과거 실행 후 체크포인트 디렉터리/완료 포인터 방식이 보완됐고 실행 원문은 executed-runner.py로 보존돼 있다. retrieval/index.py도 이전 Embedding 정비에서 Manifest의 profile을 deepcopy로 반환하도록 바뀌었다. 구 Index 원문과 비교해 이 변경을 확인했다. 다른 관련 코드 해시는 당시 값과 같았다. 따라서 과거 관측 전체를 현행 코드 전체의 재실행 증거로 표시하지 않는다. 원본/게시 소스 차이는 검증 기록에 남긴다.

## 한계와 보존

보조 Pydantic 2.14.1은 고정 요구 2.14.2와 다르다. 현재 환경에는 Torch/PEFT/Transformers가 없으며 설치·모델/Tokenizer·훈련·실제 Adapter 바이너리 재로드·QLoRA/IA3/DoRA·전체 Pytest/HTTP·독립 품질/수업·교육생 장비를 새로 실행하지 않았다. 기록의 SHA256을 읽는 것과 현재 바이너리를 재해시하는 것도 구분한다. 직접 검증 프로세스의 연결 시도는 없었으며 OS 네트워크 격리 검증은 아니다.

기존 학습기·검수 코드·의존성·데이터·과거 결과를 보존했다. 새 도구는 표준 라이브러리의 가상 계산/로컬 기록 읽기만 수행한다. 기존 품질 채택 보류와 QLoRA/독립 검증 미완료를 유지한다. [상세 검증](validation.json)을 참고한다.
