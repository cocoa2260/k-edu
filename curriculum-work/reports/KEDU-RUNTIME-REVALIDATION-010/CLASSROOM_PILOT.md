# 독립 강사용 Phase2 대표 수업 파일럿

이 문서는 진행안과 기록지다. 파일럿을 진행한 날짜, 참여자, 장비와 결과는 시행 후 채운다. 아래 인원·시간·통과 기준은 제안값이므로 사전 점검에서 확정하고 시행 중에는 바꾸지 않는다. 정답과 판정표는 강사가 채점할 때 사용한다.

## 강사가 수업 전에 준비할 것

1. **검토자와 참여자.** 교안 작성에 참여하지 않은 강사 1명, 교육생 2~4명을 첫 파일럿의 제안 규모로 잡는다. 강사는 먼저 학생용 [수강 안내](../../STUDY_GUIDE.md)와 아래 네 실습을 안내서만 보고 따라가고, 빠진 설명이나 다른 경로를 찾아야 했던 지점을 남긴다.
2. **기준 버전과 자료.** 수업에서 사용할 커밋 SHA를 기록한다. 해당 커밋의 강의·실습·가상 원본과 고정 출력 기록을 준비한다. 제출에는 참가자 코드와 가상 입력만 쓴다.
3. **장비별 확인.** 각 장비에서 OS·아키텍처·RAM·여유 디스크·Python·Node 버전, 설치와 한글 PDF 열람 가능 여부를 확인한다. Python 활동은 [Backend 준비 안내](../../practice/document-assistant/backend/README.md)와 [PDF 의존성 안내](../../practice/document-assistant/L8.md)를 따른다. Node 활동은 [Streaming 실습](../../practice/document-assistant/L9.md)의 메모리 예제로 시작한다. 모델 파일·GPU·유료 API가 필요 없는 활동을 필수 경로로 삼는다.
4. **직접 실행 전환 기준.** 수업 전 강사는 아래 네 활동의 입력·출력과 대체 자료를 확보한다. 학생이 장비 문제로 한 활동을 10분 안에 시작할 수 없으면 해당 활동의 저장 결과로 전환한다. 원래 실행 상태는 `장비 차단`으로 남기고 개념 판정과 분리한다. 여러 장비에서 동시에 실행했다면 인원·오류·복구 시간도 적는다.
5. **별도 선택 시험.** 실제 모델 실행을 포함할 때는 사용할 장비에서 모델/Tokenizer 리비전과 캐시, 시작 시간, 실행 종료와 실패 복구를 먼저 관찰한다. GTX 1060 3GB와 다른 OS의 재현은 실측 전까지 미확인으로 둔다. 운영 인증이 없는 실습 서버는 각 장비의 loopback에서 가상 자료로만 다룬다.

## 독립 강사 사전 실행

학생에게는 [대표 실습 제출지](PILOT_WORKSHEET.md)를 먼저 준다. 아래 판정표는 첫 제출을 받은 뒤 사용한다. 모델을 내려받기 전에 다음 경로를 별도 작업 폴더에서 점검한다.

1. 저장소를 열고 `git rev-parse HEAD`로 교안 커밋을 기록한다. Python 3.12 가상환경을 만든다. 예시 명령의 `python`은 그 가상환경에서 실행한다. 수업의 네 필수 활동에 사용하는 패키지는 Backend 폴더에서 `python -m pip install pydantic==2.14.2 -r requirements-document.txt`로 준비한다. Node는 `node --version`으로 기록한다. D의 메모리 예제에는 npm 설치와 브라우저가 필요 없다.
2. A는 벡터 계산 도구, B는 아래 Harness 명령 두 개, C는 L8의 2절 디지털 PDF 코드, D는 L9의 메모리 SSE 코드를 실행한다. A~C는 Backend 폴더, D는 `stream-ui` 폴더에서 시작한다. C는 PDF를 직접 열어 한글과 표도 확인한다.
3. 각 활동에서 처음 시도한 명령, 실제 관찰, 중단 또는 재시도 이유를 아래 표에 한 줄씩 적는다. 설치 안내가 빠졌는지, 명령은 실행됐지만 설명이 모호했는지, 장비 자체가 부족했는지 구분한다. 저장 결과로 전환했다면 해당 장비의 직접 실행 상태는 미확인으로 둔다.
4. 학생 파일럿 전에 시간과 점수 기준을 확정한다. 사전 실행이 막힌 필수 활동은 안내를 수정해 재시도하거나 이번 파일럿에서 직접 실행 대신 기록 관찰로 분류한다.

| B · 고정 응답 검토 | | | | |

## 수업 진행 · 총 105분 제안

오리엔테이션·환경 확인 15분, 아래 네 활동 각각 20분, 개별 제출·회고 10분이다. 학습자는 활동마다 **예상 → 실제 관찰 → 판정 이유**를 적는다. 강사는 시간과 도움 요청을 기록하고, 정답을 알려 준 경우에도 그 지점을 표시한다.

| 활동 | 학생이 할 일과 제출물 | 장비가 막혔을 때 |
|---|---|---|
| A · 입력과 검색 | [L3의 손계산](../../practice/document-assistant/L3.md)에서 벡터 비교를 먼저 예측하고 `python -m tools.embedding_steps --math`로 대조한다. 검색에 잡힌 결과가 규정의 정확한 답이라는 판단에 왜 추가 근거가 필요한지 설명한다. | 같은 예제의 계산을 종이로 풀고 저장 검색 결과를 읽는다. Python 실행은 미실행으로 남긴다. |
| B · 형식과 사실 | [L2의 틀린 사실이 형식을 통과한 사례](../../practice/document-assistant/L2.md)를 실행하고, [RAG 식비 사례](../KEDU-RUNTIME-REVALIDATION-006/RESULT.md)의 답을 원문 조건과 대조한다. 값·조건·예외 중 무엇이 맞고 빠졌는지 한 줄씩 적는다. | 005와 006 보고서의 고정된 관찰을 사용한다. 새 Harness나 모델 실행으로 집계하지 않는다. |
| C · 금액과 원문 위치 | [L8의 디지털 PDF 표 실습](../../practice/document-assistant/L8.md)을 따라 미사용 행과 사용 이력 행의 부담금을 각각 적는다. 인용으로 사용할 페이지와 행·열을 지목하고 [복잡한 스캔 결과](../KEDU-RUNTIME-REVALIDATION-008/RESULT.md)에서 같은 금액 문자열이 다른 위치에 나타날 수 있는 이유를 설명한다. | 저장 PDF와 보고서의 표를 대조한다. 직접 추출·OCR은 각각 실행 여부를 적는다. |
| D · 부분 응답과 확정 | [L9의 메모리 SSE 예제](../../practice/document-assistant/L9.md)를 실행해 정상 final과 final 누락을 비교한다. 화면에 초안이 보여도 어느 경우 답변을 확정하면 안 되는지 설명한다. [실제 모델 중단 기록](../KEDU-RUNTIME-REVALIDATION-009/RESULT.md)으로 취소 요청과 워커 종료의 증거도 비교한다. | 저장 예시의 두 이벤트 흐름을 순서대로 읽는다. 브라우저·실제 모델 실행은 미실행이다. |

A~C의 Python 명령은 `practice/document-assistant/backend`에서, D의 Node 예제는 `practice/document-assistant/stream-ui`에서 실행한다. B는 기존 교안의 두 명령을 그대로 사용한다.

```sh
python -m tools.harness_demo --output runs/harness-01.json
python -m tools.harness_steps --input runs/harness-01.json --scenario wrong_fact_shape_passes
```

출력 경로가 이미 있으면 새 이름을 사용하고 두 번째 명령도 같은 이름으로 맞춘다. 각 활동에 필요한 파일과 실행 명령은 위 링크의 해당 절에서 찾는다.

## 독립 강사 판정 기준

활동별로 **2점**은 예상·관찰·판정 이유를 근거와 함께 독립 설명, **1점**은 설명 일부 누락 또는 힌트 후 판정, **0점**은 핵심 판단 오류 또는 제출 없음이다. 실제 실행 여부는 점수와 별도 열에 기록한다.

| 활동 | 핵심 판정 |
|---|---|
| A | 벡터 비교의 근거를 설명하고, 검색 순위와 답변 사실성 판정을 구분한다. |
| B | 식비의 최대 3만 원과 영수증은 맞았고 사전 승인과 식사 제공 시 미지급 예외는 빠졌음을 찾는다. 인용이나 형식 검사를 통과한 답도 보류할 수 있음을 설명한다. |
| C | 디지털 PDF 1쪽에서 미사용 0원, 사용 이력 15,000원을 올바른 행·열에 연결한다. 다른 행 또는 각주의 같은 금액은 해당 행의 근거로 쓰지 않는다. |
| D | final 누락 시 초안이 남아도 확정 답변이 없다고 판단한다. 취소 접수와 실제 프로세스 종료를 다른 관찰로 설명한다. |

**파일럿 수업 판정 제안.** 독립 강사가 네 활동을 사전 재현하고, 참가자가 각각 6/8점 이상이며 아래 핵심 오류를 최종 제출에서 남기지 않으면 해당 장비·활동 범위에서 재사용 후보로 기록한다. 한 명이라도 미충족이거나 안내만으로 진행하지 못한 단계가 있으면 그 활동을 보완하고 다시 시험한다. 대체 자료로 통과한 경우 개념 활동 범위만 판단한다. 이 소규모 파일럿으로 전체 70개 단원의 검증을 마감하지 않는다.

핵심 오류는 잘못된 금액·필수 예외 누락을 정답으로 채택하거나, 미검증 초안을 최종 답변으로 확정하거나, 저장 기록을 자신의 실제 실행으로 제출하는 경우다.
