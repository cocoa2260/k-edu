# L9 문서 등록·공통 구조·상태 검증 결과

**K2-14.U01~U02 자료와 실제 PDF/TXT 등록 경로를 작성했다. 검사 25개 통과, 전체 자료 작성은 50/70개다.** L9 여섯 단원 전체의 완료를 뜻하지 않는다.

[강의](../../lessons/document-ai/intake.md) 다음 이 결과를 읽으면 된다. 실행 담당자는 [L9 안내](../../practice/document-assistant/L9.md)를 본다. 코드·JSON은 문제 조사 때만 확인한다.

| 실제 수행 | 관찰 | 한계 |
|---|---|---|
| 디지털 합성 PDF 입력 | 이전 L8 추출기 재사용, IR Element 11개·표 행렬·페이지/영역 보존 | OCR 재실행·일반 Layout 모델 아님 |
| UTF-8 TXT 입력 | 문자와 원본 줄 번호를 보존한 공통 IR | DOCX/HWPX/HWP 미지원 |
| 원본 → IR → 검색 문맥 | PDF 영수증 문장과 TXT 금액 문장의 문서·버전·해시·Element·위치 연결 | 문자열 포함 검색. 의미 검색/순위/LLM 실험 아님 |
| 동일 요청 재전송 | 새 내부 버전·새 generation 없이 현재 상태 반환 | 새 키를 주면 새 버전으로 보는 실습 정책 |
| 새 버전 | 이전 Chunk 삭제, 이전 검색 선택 거부 | 새 버전 재추출·색인 전 검색 제외 |
| 권한 제한 | 해당 Chunk 제거·검색 제외·과거 요청 재전송 거부 | 고정 staff 실습. 실제 인증 아님 |
| 삭제 후 재시작 | SQLite를 다시 열어도 원문·IR이 비어 있고 검색 제외 | 백업·외부 원본 파일의 보안 삭제 아님 |

문서의 상태는 uploaded → parsed → indexed → review로 이어진다. review도 검토 필요 상태이며 발행 승인이 아니다. Parsing이 실패하면 uploaded 상태로 남고 검색에는 들어가지 않는다. 새 버전·권한 제한·삭제는 이미 얻은 검색 결과를 무효화한다.

검사는 실제 PDF 표/좌표, UTF-8 줄 번호, 원본 사본의 불변성, 요청 키 충돌, 과거 버전/삭제/권한 제한 후 재전송, 재색인 중복, 문맥 위조 문자열 무시, 재시작 후 삭제 유지, 미지원 Office 형식, 잘못된 인코딩·입력·상태 전이를 포함했다. 이전 L8의 44개 및 과거 ML 278개 전체는 이번에 재실행하지 않았다. 기존 파일 보존은 게시 트리의 Blob 해시 비교로 별도 확인한다.

**작성은 2개 단원만 완료로 추가했다.** 나머지 K2-14.U03~U06의 보고서 생성·Provider/예산·React/Streaming·다중 형식 최종 평가는 진행 전이다. 남은 기초/안내 16개도 별도 제작한다. 독립 수업·실제 인증·동시 Worker·백업/보안 삭제와 기존 RAG/Agent/LoRA 품질·QLoRA 게이트는 미완료다.

다음 작업은 **U03 근거·검토·문서 생성**이다. 추천 추론 강도 **High**. Claim별 출처·검토 상태를 실제 DOCX/PDF 보고서와 연결하고 내용·형식·화면을 대조해야 한다.
