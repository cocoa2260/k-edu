# 실제 CPU 모델과 기준 API 생성 검증

2026-11-04 · **기존 API에 실제 Qwen CPU Provider를 명시적으로 주입해 HTTP 생성 2회 성공. 답변 품질은 채택 보류.**

Ollama 실행 파일/서비스와 유료 API 자격 증명이 없는 환경에서 저장소의 HFCpuProvider를 재사용했다. 기본 Factory의 Ollama/OpenAI 선택 로직은 바꾸지 않았다. 기존 create_app(provider) 주입 기능으로 실제 loopback HTTP 서버를 열었다. 이 경로는 Ollama 실행 성공이나 기본 API의 자동 전환을 뜻하지 않는다.

## 실제 관찰

고정 Qwen/Qwen3-0.6B revision c1899de289a04d12100db370d81485cdf75e47ca를 내려받아 캐시로 로딩했다. Linux Python 3.12.14, Torch 2.15.0+cpu, float32, CPU 2 threads, greedy, thinking 비활성, 최대 출력 192 Token 조건이다. 생성용 별도 가상환경을 준비했다. 모델 로딩은 6.7444초, Linux 프로세스 최고 RSS는 4,867,944 KiB였다. 다운로드한 Weight는 1,503,300,328바이트다. 이 프로세스 측정값을 학생 PC의 필요 RAM이나 GPU 3GB 적합성으로 환산하지 않는다.

두 번째 실제 응답은 “국내 당일 출장 식비 상한: 30000원 / 필요한 자료: 영수증”이다. 원문은 사전 승인된 출장의 상한·영수증·식사 제공 예외를 함께 요구한다. 금액 하나가 맞아도 완전한 규정 안내로 채택하지 않는다. 첫 번째는 기관 규정이 주어지지 않았으므로 특정 금액을 확정할 근거 자체가 없다.

두 요청 모두 HTTP 200이지만 의미 품질 합격이 아니다. 첫 응답은 출력 길이 상한에 걸린 상태로 반환됐고, 현재 기본 API는 이 잘림 표시를 응답 Schema에 노출하지 않는다. Provider 관찰의 hit_output_limit을 함께 기록했다. 이 API를 완료/정답 보장 시스템으로 설명하지 않는다.

이번 비교에서는 지시와 제공 자료가 함께 달라졌다. Context만 바꾼 효과를 입증하는 통제 실험이나 Prompt 다섯 조건 전체 비교가 아니다. 같은 작성자의 두 출력 원문 대조이며 독립 품질 평가도 아니다.

## 실행 경계와 재현

health 200과 공백 입력 422에서는 모델을 호출하지 않았고, 두 정상 요청만 실제 생성했다. 서버는 종료 후 정리했다. 입력 문자열·해시·응답·Token·시간·실행 설정은 [observed.json](observed.json), 실행 명령/환경은 [execution.json](execution.json), 재현 코드는 [probe.py](probe.py)에 있다. Backend를 PYTHONPATH로 지정하고 준비된 HF_HOME 및 HF_HUB_OFFLINE=1 / TRANSFORMERS_OFFLINE=1을 사용했다. 다른 장비에서는 execution의 절대 경로를 실제 위치로 바꾸고 새 output을 지정한다. OS 전체 네트워크 차단 실험은 아니다.

[모델 파일 목록/해시](model-files.json), [설치 버전](requirements-observed.txt), [환경](environment.json)을 보존했다. 모델 바이너리는 Git에 올리지 않았다. 새 훈련·검색·Agent·유료 API 호출은 없었다.

최초 로딩은 다운로드가 끝나기 전에 시작해 safetensors 파일 부재로 실패했다. [실패 기록](initial-incomplete-cache.json)을 보존하고, SDK 다운로드 완료를 확인한 뒤 같은 코드로 재실행했다. 파일 이름을 바꾸거나 안전 형식 조건을 완화하지 않았다. [다운로드 결과](download.json)의 완료 이후 기록이 최종 실행이다.
