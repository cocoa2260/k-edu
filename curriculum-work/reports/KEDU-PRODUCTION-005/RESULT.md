# Embedding·Index / L3 제작·검증 결과

**8개 단원과 L3 실습을 작성하고 실제 CPU Embedding·검색·Index 갱신/삭제를 실행했다. 기존 검사 포함 164개 테스트 통과. 작성 자료는 70개 중 24개이며 실제 답변 생성·RAG·품질 채점은 미실행이다.**

[Embedding 강의](../../lessons/embedding/lesson.md) → [Index 강의](../../lessons/vector-index/lesson.md) → [L3 실습](../../practice/document-assistant/L3.md)을 읽으면 된다. 아래 수치는 예상 예시가 아니라 저장한 실제 실행 기록이다.

## 실제로 구현·실행한 것

고정 E5-small 가중치를 CPU로 실행했다. 모델 ID는 intfloat/multilingual-e5-small, 리비전은 614241f622f53c4eeff9890bdc4f31cfecc418b3이다. 384차원, 패딩 제외 평균, 단위 정규화, 질문/문서 접두어를 설정에 기록했다. 설정한 Token 상한을 넘으면 자동 절단 대신 오류로 중단한다. 답변 생성 모델·유료 API 호출은 0회다.

원본 가상 문서 6개를 비어 있지 않은 줄 단위로 나눠 11 Chunk를 SQLite에 저장했다. 권한·현행 필터 뒤에는 기본 9 Chunk가 검색 대상이다. Doc ID/버전·Chunk ID·내부 줄·원문 해시·논리 위치·표현 설정을 보존한다. 제목과 줄 본문을 인코딩하며 모델은 저장소 Python 코드를 실행하지 않는 Safetensors 경로로 읽었다.

## 같은 질문의 실제 검색 비교

공통 12개 사례 × BM25/Dense/Hybrid를 실행했다. 별도 교사 라벨로 정의한 8개 사례만 문서 회수 지표의 평균에 사용했고, 정답·라벨은 인코더 입력에 넣지 않았다. Recall은 상위 3개 Chunk의 문서 ID에 필요한 문서가 얼마나 포함됐는지다. C09는 두 문서 중 하나면 0.5다.

| 검색 방식 | 문서 Recall 평균, 상위 3 Chunk | 첫 Chunk의 관련 문서 적중 |
|---|---|---|
| bm25 | 93.75% | 50.00% |
| dense | 87.50% | 75.00% |
| hybrid | 100.00% | 75.00% |

Dense는 C07의 공격 메모를 먼저 찾고 필요한 DOC-A를 상위 3개에서 놓쳤다. BM25는 C09의 두 관련 문서 중 하나만 찾았다. Hybrid는 8개 사례에서 필요한 문서를 포함했지만 C07의 첫 결과는 여전히 공격 메모다. C08에서는 BM25도 바꿔 말한 질문으로 DOC-A를 찾았다. 불리한 결과를 숨기거나 예시를 성공에 맞춰 바꾸지 않았다.

이 값은 아주 작은 학습 자료의 문서 회수 관찰이다. 답변 정답률·인용 타당성·공격 저항성·실서비스 검색 성능이 아니다. C03은 검색 결과가 있어도 숙박비 금액 근거가 없고, C06 결과에는 제한 문서가 없으며, C10은 인코딩 전에 거부했다. C12는 가용 목록에서 DOC-A를 제외한 실험으로 실제 삭제와 따로 기록했다.

## 실제 Index 변경·재실행

임시 SQLite에서 DOC-A를 v2 시험값 35000원으로 갱신했다. 갱신 전 선택은 Context 준비에서 거부됐고 새 검색에서는 새 버전·본문이 확인됐다. 이후 DOC-A를 실제 삭제해 벡터·본문을 제거하고 삭제 전 선택도 거부했다. 모든 적격 Chunk를 검색해도 DOC-A가 결과와 Context에 나타나지 않았다. 원본 documents-v1의 30000원과 과거 보고서는 변경하지 않았다.

같은 E5 가중치의 Token 상한을 512에서 128로 바꾸자 기존 Index 재사용을 거부했다. 원본 자료로 새 Index를 만들어 실제 검색을 재실행했다. 서로 다른 가중치 모델의 실제 전환은 미검증이고, 변경된 모델 ID/리비전·차원의 재사용 거부는 경계 테스트로 확인했다.

캐시만 읽는 새 실행에서 요청 전송 함수를 금지했고 HTTP 요청 시도는 0회였다. 36개 조건의 결과 순서와 평가값이 첫 실행과 같았다. 이는 local_files_only와 requests 요청 가드의 검증이며 OS 차원의 네트워크 격리는 아니다.

## 선택 실습: 실제 FAISS, 합성 벡터

32차원 정규화 합성 벡터 4096개·질의 128개·k=10을 고정했다. 아래 회수율은 Exact의 이웃을 되찾은 비율로 한국어 의미 검색 지표가 아니다. 지연은 한 스레드·따뜻한 검색 5회 배치 중앙값이며 인코딩·Index 구축·IVF 학습을 제외했다.

| 방식 | efSearch / nprobe | Exact 이웃 Recall@10 | 128질의 배치 ms |
|---|---|---|---|
| exact | 전체 | 100.00% | 2.302 |
| hnsw | 8 | 44.92% | 0.508 |
| hnsw | 64 | 92.81% | 3.075 |
| ivf | 1 | 16.64% | 0.149 |
| ivf | 16 | 81.72% | 1.125 |
| ivf | 64 | 100.00% | 3.867 |

폭을 늘리면 이웃 누락이 줄었지만 작은 자료에서는 Exact가 일부 ANN 설정보다 빨랐다. 전체 IVF 구역을 탐색했을 때 이 실험은 이웃 회수율 1이 됐다. FAISS HNSW의 삭제는 구현·검증하지 않았고 SQLite 삭제 결과와 혼동하지 않는다. 내부 그래프 경로 전체를 수집한 도구도 아니다.

## 검사·환경·한계

기존 136개와 L3 28개를 합쳐 164개 테스트를 통과했다. 테스트는 의미를 학습하지 않은 2차원 고정 벡터로 필터·지속 저장·갱신/삭제·ACL 변경·오래된 선택·위조 본문·모델 설정 불일치·잘못된 벡터/입력·덮어쓰기 거부를 검사한다. 실제 모델 검증은 별도 검색 실행 기록이다.

실행 환경은 Linux x86_64 Python 3.12.14, PyTorch 2.15.0+cpu, Transformers 4.57.1, NumPy 2.5.4, FAISS CPU 1.15.1다. 새 ML 가상환경을 만들었고 기존 L0 고정 환경 파일을 바꾸지 않았다. 설치 전체 스냅샷은 requirements-retrieval-tested.txt이며 다른 운영체제의 Lock이 아니다.

staff는 고정 학습 역할이고 실제 인증·다중 조직 권한 체계는 없다. 로컬 저장소에는 제한 자료도 있으므로 파일 접근 자체를 허용하는 서비스 구조가 아니다. 삭제는 조회 배제와 저장 필드/벡터 제거이며 디스크 잔여·백업의 안전 삭제를 뜻하지 않는다. 동시 분산 변경·교육장 처리량·GTX 1060 3GB·Windows/macOS·React UI·수업 검증은 미실행이다. 검토자는 같은 Work 세션이다.

다음은 K2-09/L4 RAG이며 추천 추론 강도는 High다. 검색·Context·실제 생성·근거 채점을 연결해야 한다. 현재 실제 검색 Gate와 과거 L0/L1/L2의 미완료 답변 생성 Gate를 구분해 유지한다.
