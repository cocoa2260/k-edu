# L4 실습 — 실제 검색에서 근거 답변까지

**[RAG 강의](../../lessons/rag/lesson.md) → [실제 실행 읽기](../../reports/KEDU-PRODUCTION-006/REVIEW.md) 순서로 보면 된다.** JSON 전체를 읽을 필요는 없다. 실행 읽기에서 출처 링크를 누르면 같은 실행의 원문을 확인할 수 있다.

L3의 실제 E5 검색과 L2의 제한된 재시도·출력 보완을 재사용한다. Qwen3-0.6B의 실제 가중치로 답변을 생성한다. 고정 응답·유료 API가 아니다. Linux x86_64 / Python 3.12 CPU에서 확인하며 학생 PC·GTX 1060 3GB·macOS·Windows·동시 수업 실행을 보장하지 않는다.

## 1. 준비와 실행

[L3 환경](L3.md)의 별도 CPU 가상환경과 패키지를 사용한다. PyTorch·Transformers를 새로 업그레이드하지 않는다. 생성 모델 가중치를 추가로 내려받을 디스크와 모델을 CPU에 올릴 RAM이 필요하다. 파일 다운로드와 모델 실행은 다른 단계다.

backend 폴더에서 아래를 실행한다. 표는 **입력할 명령**이며 관찰 결과가 아니다. 실제 대화 웹 API의 Provider 선택은 그대로이고 새 로컬 모델은 이 실습 CLI에서 명시적으로 불러온다.

| 목적 | 입력할 명령 |
|---|---|
| 기존·새 경계 검사 | `python -m pytest -q` |
| 최초 다운로드와 한 사례 실행 | `python -m tools.rag_lab --download --output l4-v2 --cases C01` |
| 같은 설정으로 나머지 사례·비교 이어서 실행 | `python -m tools.rag_lab --resume --output l4-v2 --comparisons` |
| 이전 지시 v1을 별도 폴더에 실행 | `python -m tools.rag_lab --prompt-revision v1 --output l4-v1 --comparisons` |

기본 실행은 캐시만 읽는다. 캐시가 없으면 실패하며 API나 고정 응답으로 전환하지 않는다. 매 사례가 끝날 때 결과를 저장하고 resume에서는 완료 사례를 재사용한다. 기록한 모델·자료·RAG 구성 코드·지시 설정이 바뀌면 이전 폴더의 재개를 거부하므로 새 폴더를 사용한다. v1/v2는 서로 다른 폴더에 기록한다. v2는 실패 분석용 기본 실험 조건이며 품질을 승인한 서비스 기본값이 아니다. 두 버전 모두 서비스 채택을 보류했다.

## 2. 한 사례의 결과 읽기

| 기록 | 볼 내용 |
|---|---|
| 검색 | 질문·Hybrid 순위·필터 뒤 Chunk·Index 변경 번호 |
| 실제 입력 | 검색 자료와 원 질문·출력 지시; 평가 정답 제외 |
| 생성 관찰 | 매 호출의 실제 입력/출력 Token·원응답·시간 |
| L2 Trace | 시도 수·실패 ID·보완·종료 이유 |
| 초안 | 상태·답변·주장별 Source ID·부분 인용 |
| 출처 대조 | 같은 실행의 문서 버전·내부 줄·실제 본문 |

기본 입력 예산은 Chat Template 포함 1536 Token, 신규 출력은 최대 512 Token이다. Context를 조립한 뒤 기존 2000문자 계약도 검사한다. 두 제한은 별개다. 초과하면 원문을 몰래 자르지 않는다. L2의 총 시도 3회·재시도 1회·보완 1회와 호출 전후 시간 검사도 유지한다.

이번 로컬 Provider의 실제 Token 관찰은 별도 생성 기록에 있다. 기존 공통 Harness의 사용량 칸이 미확인으로 남아 있는 것을 0 Token으로 해석하지 않는다. 생성 시간은 이번 실험의 경과시간이며 최적화한 성능이나 교육장 처리량이 아니다.

## 3. 비교 실험

출력 지시 v1은 첫 실행에서 발견한 실패를 보존한 기준이다. v2는 사실을 답할 때 answer 상태·주장·정확한 부분 인용을 요구하도록 지시만 바꿨다. 같은 질문·검색·모델·검사기를 유지한다. 구조 통과 수와 원문 대조 결과를 따로 적는다.

C07-rewrite는 검색 질의만 바꾸고 사용자 질문을 유지한다. C09-neighbors는 같은 질의의 후보 주변 줄을 확장한다. 자동 Rewrite 모델이나 평가 정답 문서 주입은 사용하지 않는다. 이 비교가 출력 지시 변경과 섞이지 않도록 같은 지시 버전 안에서 비교한다.

검색된 문서가 관련 있어도 금액·조건이 있는 줄이 입력에 없을 수 있다. 반대로 필요한 줄을 넣었어도 모델이 답을 보류하거나 예외를 빠뜨릴 수 있다. 결과를 보고 원인을 분리한다.

## 4. 제출·채점

정상 사실 사례 C01/C02/C05/C08/C09/C11은 금액·조건·예외·현재 버전·근거를 원문과 대조한다. C03/C04/C06/C07/C10/C12는 자료 부족·되묻기·제한 자료·공격 지시·공백·가용 자료 변경의 행동을 별도로 평가한다. 자료가 부족하다는 상태를 붙이고 사실을 말하는 모순도 확인한다.

| 사례·버전 | 검색/Context에 필요한 근거 | 최초·보완 출력 | 주장과 부분 인용 일치 | 누락·잘못된 값·상태 | 원인 구간·다음 변경 |
|---|---|---|---|---|---|
| 각 사례 | 직접 확인 | 실제 관찰 | 원문과 대조 | 직접 기록 | 한 조건 선택 |

자동 검사는 출력 구조·제공한 Source ID·원문 안의 부분 인용까지다. 정확한 문장을 인용하고도 틀린 주장을 할 수 있어 의미적 근거 검증 완료로 표시하지 않는다. 현재 결과는 모두 사람 검토가 필요한 초안이며 실제 인증·승인·외부 Tool 실행은 없다.

제출물은 원문→검색→Context→생성 Trace, Chunk/질의 비교, 주장별 출처 대조, 보류·실패 이유, 같은 사례의 수정 전후 평가다. 읽기용 기록은 같은 Work 세션의 검토이며 독립 강사·교육생 수업 검증이 아니다. 아직 남은 품질 문제를 수업용 실패 분석 자료로 함께 제출한다.
