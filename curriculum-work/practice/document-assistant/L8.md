# L8 · PDF 입력에서 원본 페이지까지

먼저 [강의](../../lessons/document-parsing/lesson.md)를 읽고 [실행 결과](../../reports/KEDU-PRODUCTION-012/RESULT.md)를 확인한다. 코드 검토는 교육생의 필수 읽기 경로가 아니다.

## 이번에 바꾸는 것

L3의 줄 단위 검색 입력 앞에 PDF 추출 경로를 붙이는 CLI 실험이다. 기존 문서 JSON·L4~L7 모델·웹 API는 유지한다. 합성 PDF 네 개와 원문 좌표를 별도로 보존한다. 실제 사용자 업로드 화면은 추가하지 않았다.

| 순서 | 실행 담당자의 행동 | 확인할 결과 |
|---|---|---|
| 1 | Python 3.12 별도 환경에 requirements-document.txt 설치 | 설치 버전, pdftoppm과 Tesseract 실행 가능 |
| 2 | tools.document_assets에 새 output 폴더 지정 | 한글/영어 인식 데이터와 글꼴의 SHA256 검사 |
| 3 | 저장된 data/document-v1의 네 PDF·gold.json 확인 | 원본 PDF는 이미 Git에 있어 재생성 불필요 |
| 4 | tools.document_lab의 specimens·tessdata-dir·output 지정 | 페이지별 직접 추출/OCR, OCR 오류·표·순서·원문 연결 |
| 5 | L8_SPECIMENS와 L8_TESSDATA를 위 폴더로 지정하고 document_tests만 실행 | 현재 범위의 경계 검사. 이전 ML 전체 테스트 재실행과 구분 |
| 6 | PDF 화면과 결과를 함께 대조 | 글자·숫자·표의 관계·출처 검토 |

정확한 CLI 인수는 각 [실행 파일](backend/tools/document_lab.py)과 [데이터 준비 파일](backend/tools/document_assets.py)의 첫 설명에 있다. 본문에 실행 코드·JSON을 섞지 않았다. Backend 폴더에서 모듈로 실행하며 모든 output은 기존 결과를 덮어쓰지 않는 새 폴더를 사용한다.

## 비교 조건

OCR는 Tesseract 5.3.4, kor+eng, LSTM 엔진, PSM 6, 216dpi 렌더링이다. 단일 블록 가정이 있는 PSM 6을 모든 실제 레이아웃에 그대로 적용하지 않는다. 전처리 비교는 열화 스캔에 같은 크기의 임계값 175 흑백화만 적용한다. 자동 Deskew·표 모델·Vision은 실행하지 않는다.

OCR 평가의 정답은 네 줄이다. 평가 영역을 페이지 상단 700point 미만으로 고정해 합성 표시를 제외한다. 정답은 평가에만 쓰며 OCR 입력에 주지 않는다. 공백 제외 CER와 공백 토큰 WER를 함께 보고, 주요 필드는 공백 제거 후 문자열 존재만 검사한다. 이 점수는 문서 의미와 답변 품질의 점수가 아니다.

레이아웃 비교는 digital.pdf의 사람이 지정한 두 열 영역만 대상으로 한다. 표는 경계선이 있는 3×3 한 개다. 줄 정규화는 두 열을 합칠 수 있고 표의 관계는 별도 기록에 있으므로 일반 Layout-aware 검색으로 확대하지 않는다.

## 거부와 검토

restricted·current가 아닌 문서·삭제 문서는 읽기 전에 거부한다. 8MB 초과, 6쪽 초과, 지원하지 않는 페이지 크기·회전·Crop·원점·UserUnit, 암호 PDF, 언어 데이터 부재, OCR 실패·시간초과·빈 결과는 거부한다. 정상 결과도 검토 필요 상태로 남긴다. 예외가 나면 해당 실행 결과 전체를 채택하지 않는다.

이 제한은 실습 장비의 일반적인 실수를 줄이는 경계다. PDF 라이브러리는 프로세스 안에서 실행되므로 악성 압축 해제·메모리 고갈을 격리하는 보안 Sandbox가 아니다. 인터넷에서 받은 임의 PDF 업로드 서비스를 이 코드만으로 운영하지 않는다.

실제 인증·파일 보관·변경 감지와 지속 권한 관리, 재실행 재색인 자동화, 원본 뷰어 하이라이트 UI는 미구현이다. 기존 RAG/Agent/LoRA 품질 보류도 유지한다.
