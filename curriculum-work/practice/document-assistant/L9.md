# L9 첫 묶음 · 문서 등록·공통 구조·무효화

[강의](../../lessons/document-ai/intake.md) → [결과](../../reports/KEDU-PRODUCTION-013/RESULT.md) 순서로 읽는다. L9 전체가 아니라 K2-14.U01~U02의 첫 구현이다.

| 구성 | 역할 |
|---|---|
| backend/app/document_registry.py | PDF/TXT → IR, SQLite 원본 사본·버전·요청 키·상태·검색/문맥·삭제 |
| backend/tools/registry_lab.py | 저장된 합성 PDF와 직접 쓴 UTF-8 텍스트로 실제 순차 실행 |
| backend/registry_tests/test_registry.py | 상태·권한·재전송·잘못된 입력·원본 위치의 25개 unittest 검사 |
| backend/app/document_ingest.py | 이전 L8 PDF 추출기. 이번에 변경하지 않음 |

Backend 폴더에서 tools.registry_lab를 모듈로 실행하고 새 output 디렉터리를 지정한다. 정확한 CLI는 [실행 파일](backend/tools/registry_lab.py) 첫 설명에서 본다. 검사에는 Python 표준 unittest의 discover로 registry_tests를 지정한다. requirements-document.txt의 PDF 라이브러리가 필요하며 이번 검사에는 pytest·Torch가 필요하지 않다.

출력 observed.json에는 PDF/TXT IR·실제 문맥·원본 Locator·재전송과 무효화 결과가 있다. SQLite와 생성한 텍스트는 로컬 실행 자료다. 새 디렉터리를 써서 과거 결과를 보존한다. 원본 PDF는 이전 data/document-v1/digital.pdf를 사용하므로 다시 만들 필요가 없다.

이번에는 PDF 디지털 문서와 TXT 두 형식만 실행했다. DOCX/HWPX/HWP는 명시적으로 거부하며 변환을 시도하지 않는다. PDF 스캔 OCR는 L8 인식 데이터 준비가 별도로 필요하고 이번에는 실행하지 않았다.

기존 LocalIndex·웹 API·Provider·모델·데이터는 변경하지 않았다. Registry 검색은 문자열 포함 검사이며 실제 RAG 생성이나 의미 검색 성능 실험이 아니다. report 생성·UI·동시 Worker·실제 인증·보안 삭제/백업·독립 수업 검증은 남아 있다.

## U03 보고서 확장

[보고서 강의](../../lessons/document-ai/report.md) → [결과](../../reports/KEDU-PRODUCTION-014/RESULT.md)를 읽는다. requirements-report.txt 환경에서 tools.report_lab에 새 output 디렉터리와 NotoSansKR-Regular.ttf 경로를 지정한다. CLI는 [실행 파일](backend/tools/report_lab.py) 첫 설명을 본다. report_tests와 기존 registry_tests는 표준 unittest discover로 각각 실행한다.

app/report_spec.py는 명세·현재 원문·검토 기록을 연결하고 tools/report_export.py는 동일한 문단에서 DOCX/PDF를 출력한다. 단일 고정 검토자 시연이며 실제 인증·독립 승인은 아니다. 검토 결정은 같은 명세에 한 번 저장하고 정정·철회 기능은 미구현이다. 템플릿 구현 변경 때는 버전도 바꿔야 한다.

PDF는 글꼴 파일을 사용하고 DOCX는 Noto Sans KR 설치가 필요하다. render_docx.py는 임시 HOME을 사용하므로 해당 렌더러가 찾을 수 있는 글꼴 경로에 준비한다. 실제로 한글이 보이는지 모든 페이지를 확인한다. 성공적으로 저장됐다는 검사만으로 배포하지 않는다.

## U04 Provider 제어

[Provider 강의](../../lessons/document-ai/provider.md) → [결과](../../reports/KEDU-PRODUCTION-015/RESULT.md)를 읽는다. tools.provider_lab를 모듈로 실행하고 새 output 디렉터리를 지정한다. 정확한 CLI는 [실행 파일](backend/tools/provider_lab.py) 첫 설명을 본다. 로컬 127.0.0.1 임시 포트의 표준 라이브러리 HTTP 서버가 필요하다. 모델 다운로드·유료 API·새 Python 패키지는 필요하지 않다.

router_tests는 표준 unittest discover로 실행한다. Registry/보고서 회귀는 각각 registry_tests/report_tests를 지정한다. 실제 결과의 Token 수는 Unicode 코드 포인트 기반 Fixture이며 실제 모델 Token이 아니다.

app/provider_router.py는 기존 웹 Factory에 연결되지 않은 별도 경로다. hf_cpu_endpoint는 이미 준비한 HFCpuProvider 객체를 명시적으로 받아 Chat Template·고정 출력 상한·프로필/사용량을 연결한다. 이번 검사는 가짜 Provider 계약이며 실제 HF 가중치 실행은 아니다. 기존 문자열 Provider를 그대로 예산 지원 경로라고 등록하지 않는다. 실제 Token 계수·출력 상한·오류 분류·준비 상태를 보장하는 어댑터가 필요하다.

Timeout/취소는 동기 호출 전후 검사이고 강제 중단은 미구현이다. Trace는 질문/예외 원문을 제외하지만 최종 응답 answer를 저장하면 답변 내용이 남는다는 점은 별개다. Provider/모델 전환·실제 외부 전송·React/Streaming·금액 예산·독립 수업은 이번 범위가 아니다.

## U05 React와 SSE

[Streaming 강의](../../lessons/document-ai/streaming.md) → [결과](../../reports/KEDU-PRODUCTION-016/RESULT.md)를 읽는다. [실행 화면 안내](stream-ui/README.md)에 설치·빌드·로컬 서버·검사 순서를 적었다. 기존 FastAPI API에 자동 연결하지 않고 별도 loopback 서버에서 U04 Router의 고정 답변을 SSE로 나눈다. 실제 모델 Token Streaming은 미검증이다.

공통 Parser를 Node와 React가 함께 사용한다. 최종 판정 없이 끝나면 실패, 취소 뒤에는 부분 응답을 확정하지 않는다. 실제 Chromium에서 취소/새 실행의 늦은 확인 경합·오류·중간 종료·기능 거부·시간 한도와 모바일 크기를 확인했다. 실제 사용자 인증·운영 Proxy·다른 브라우저·교실 장비는 미검증이다.
