# 자료를 고르고 현재 입력을 확인하는 실습

[Context 강의](../../lessons/context/lesson.md)를 읽고 아래 활동을 진행한다. 같은 대화 앱과 같은 가상 규정·질문을 사용한다. 새 앱을 만들거나 모델을 다운로드하지 않는다. 이 안내의 작성 표를 복사해 관찰과 해석을 남긴다.

## 준비와 실행 위치

[기준 대화 앱](../../lessons/baseline/lesson.md)의 Python 3.12 가상환경과 `requirements-dev.txt` 설치를 준비한다. 터미널을 `curriculum-work/practice/document-assistant/backend` 폴더에서 연다. 아래 `python`은 그 가상환경의 실행기를 뜻한다. 가상환경을 활성화하지 않았다면 해당 실행기의 경로로 바꾸어 사용한다.

이번 명령은 입력 준비·자료 순서·기존 관찰을 이용한 계산·일회성 전달 자료를 확인한다. 모델 가중치·API Key·GPU가 필요하지 않다. Tokenizer를 새로 실행하는 선택 활동은 뒤에서 따로 안내한다.

## 활동 1. 같은 질문에서 자료 묶음만 바꾸기

다음은 **터미널에 입력할 명령**이다.

```bash
python -m tools.context_steps
```

기본 질문은 “국내 당일 출장 식비 상한과 필요한 자료는?”이다. 같은 지시와 예시 0개를 유지하면서 기본 제공 자료와 교사 선택 자료를 비교한다. 출력에는 문서 제목·실제 ID·버전·현행 표시와 문자 수가 나온다.

현재 자료에서 기본 조건은 다섯 자료·1151문자이고, 선택 조건은 현행 출장 규정 하나·398문자다. `DOC-A`가 그 현행 출장 규정이다. 현행 표시가 거짓인 이전 문서가 기본 목록에 남아 있는지도 읽는다. 허용된 자료라는 것과 현재 질문의 적절한 근거라는 것은 다르다.

전체 입력이 궁금하면 기존 표시 도구를 사용한다. 다음 역시 **터미널 명령**이며 출력은 답변이 아니라 준비 입력이다.

```bash
python -m tools.prompt_inputs --case C01 --variant instruction
python -m tools.prompt_inputs --case C01 --variant focused
```

`C01`은 식비 문의, `instruction`은 기본 다섯 자료, `focused`는 교사가 정한 선택 조건이다. 두 입력의 첫 작성 지시와 마지막 질문이 같고 자료 묶음만 다른지 확인한다. Prompt 실습에서 자신이 임시로 추가한 지시 문장이 이 고정 조건에 자동 반영되지는 않는다.

다음 질문으로 바꾸어 실행한다.

```bash
python -m tools.context_steps --case C09
```

`C09`는 “출장 식비도 교육비처럼 20만원까지 받을 수 있어?”라는 비교 질문이다. 교사 선택 결과에는 출장·교육비 규정 두 개가 나온다. 자료 하나가 항상 최선이라면 이 질문에서 무엇을 놓칠 수 있을까? 두 숫자의 적용 대상을 원문과 연결해 설명한다.

| 관찰 | 내 기록 |
|---|---|
| 식비 문의에 선택한 문서와 보존해야 할 조건·예외 | [문서·원문 근거] |
| 식비/교육비 비교 질문에 필요한 문서가 달라진 이유 | [두 규정의 역할] |
| 같은 지시·질문·예시 수를 유지한 근거 | [입력에서 찾은 위치] |
| 짧아졌다는 관찰로 아직 말할 수 없는 것 | [검색/생성/품질의 상태] |

## 활동 2. 자료의 지시와 접근 범위를 구분하기

다음 두 명령은 서로 다른 경계를 읽기 위한 것이다. 두 사례의 출력 길이를 비교해 성능 차이를 주장하는 실험이 아니다.

```bash
python -m tools.context_steps --case C06
python -m tools.prompt_inputs --case C07 --variant focused
```

첫 번째의 `C06`은 제한 문서 내용을 요구하는 질문이다. 질문에 제한 문서 이름이 있어도 제공 문서 목록에는 제한 자료가 없어야 한다. 기본 다섯 자료와 선택 조건의 빈 목록을 읽고, 질문의 이름과 문서 본문 제공을 구분한다.

두 번째의 `C07`은 첨부 메모가 잘못된 식비를 답하라고 지시하는 질문이다. 출력에는 현행 규정과 공격 실험 메모가 자료로 들어 있다. 메모의 문장을 읽고도 왜 이를 규정이나 실행 권한으로 받아들이면 안 되는지 설명한다. 현재 명령은 실제 모델이 공격을 무시하는지 평가하지 않는다.

| 정보 | 출처·허용 여부 | 이번 질문의 근거/제외 판단 | 실제로 확인한 범위 |
|---|---|---|---|
| 현행 출장 규정 | [ ] | [ ] | [ ] |
| 이전 출장 규정 | [ ] | [ ] | [ ] |
| 공격 실험 메모 | [ ] | [ ] | [ ] |
| 제한 자료 | [ ] | [ ] | [입력 제외와 실제 모델 응답을 구분] |

## 활동 3. 문서 내용은 유지하고 순서만 바꾸기

```bash
python -m tools.context_steps --part order
```

`--part order`는 기본 식비 입력의 같은 다섯 자료를 역순으로 놓는다. 출력의 문서 순서 전후, 동일 문서·본문 여부, 지시·질문 유지 여부, 문자 수를 읽는다. 현재 예제에서 본문과 지시·질문 유지가 `True`인 이유를 설명한다. `True`가 모델 품질 통과라는 뜻은 아니다.

문자 수가 같아도 입력의 순서는 달라졌다. 이 새 입력의 Token 수를 기존 657로 자동 채우지 않는다. 실제 Template을 적용해 다시 세어야 하며, 응답의 변화는 같은 생성 조건으로 별도 확인해야 한다. 현재 도구는 새 순서의 입력을 생성 모델에 보내지 않는다.

같은 사실을 표로 바꾸는 활동도 구분한다. “사전 승인 / 상한 30,000원 / 영수증 / 식사 제공 시 지급 없음”을 표로 옮겨 보고 원문과 대조한다. 이는 **학생이 작성할 형식 제안**이며 새 직렬화/Token 계산을 자동 실행한 결과가 아니다. 조건이나 부정 표현을 빠뜨리면 형식만 바꾼 것이 아니다.

| 변경 | 유지한 것과 확인 방법 | 바뀐 것 | 아직 미측정 |
|---|---|---|---|
| 같은 다섯 자료의 순서 뒤집기 | [목록·본문·지시·질문] | [순서] | [새 Token/생성] |
| 규정의 표 표현 제안 | [조건·예외·출처 대조] | [표현 형식] | [실제 직렬화/Token/생성] |

<details>
<summary>순서가 바뀐 실제 입력을 Python에서 읽으려면</summary>

Backend에서 Python 실행기를 열어 아래 **실행 가능한 Python 코드**를 입력한다. 첫 두 줄의 import/호출 뒤 반환값의 `after`가 새로 조립된 입력이다. `quit()`으로 실행기를 종료할 수 있다.

```python
from tools.context_steps import reorder
before, after = reorder("C01")
print(after)
```

긴 실행 도구 전체를 외우지 않아도 된다. 실제 조립은 기존 입력에서 자료 부분을 읽어 같은 목록을 역순으로 직렬화하고, 기존 `ChatRequest`의 공백·2000문자 검사를 적용한다. 지시·자료 본문·질문은 새 값으로 만들어내지 않는다.

</details>

## 활동 4. 출력 여유를 포함해 예산 계산하기

```bash
python -m tools.context_steps --part budget
```

이 명령은 **기존 고정 Tokenizer 관찰을 재사용한 산술 계산**이다. 현재 식비 입력 다섯 조건의 파일 해시가 기존 관찰 대상과 같은지 먼저 확인한다. 달라지면 계산을 거부한다. Tokenizer를 새로 실행하거나 모델을 호출하지 않는다.

| 조건 | 기존 Template 포함 입력 | 출력 여유 | 합계 | 기준 2048에서 남는 공간 |
|---|---|---|---|---|
| 다섯 자료 | 657 | 256 | 913 | 1135 |
| 현행 출장 규정 하나 | 264 | 256 | 520 | 1528 |

출력의 가상 입력 1900 사례도 읽는다. 1900+256=2156이므로 108을 초과한다. 1900은 실측이 아니라 초과 판단을 위한 가정이다. 문서에서 중요한 예외를 잘라 맞추기보다 중복·불필요한 자료를 먼저 살펴야 하는 이유를 쓴다.

| 기록할 것 | 내 계산/판단 |
|---|---|
| 입력과 출력 여유의 합·기준·잔여 공간 | [두 조건 계산] |
| 2000문자 계약과 2048 Token 기준의 차이 | [단위·검사 대상] |
| 가상 초과 입력에서 줄일 것·보존할 것·중단 기준 | [조건/예외/출처 포함] |
| 기준 계산을 통과해도 실제 Provider에서 확인할 것 | [모델/Template·출력 설정·실행 자원] |

<details>
<summary>실제 Tokenizer로 다시 세는 선택 활동</summary>

앞의 Tokenizer 실습 환경과 고정 Qwen Tokenizer 캐시가 준비된 경우에만 진행한다. 아래는 Backend 폴더의 **터미널 명령**이다. 두 번째 명령의 `python`은 Tokenizer 환경의 실행기여야 한다.

```bash
python -m tools.prepare_l1 --output runs/context-inputs-01
python -m tools.count_l1_tokens --input runs/context-inputs-01/samples.json --output runs/context-tokens-01.json
```

두 번째 도구는 로컬 캐시만 사용한다. 설치/캐시가 없으면 준비 필요로 기록하고 과거 수치를 자신의 새 측정값으로 복사하지 않는다. 기존 결과가 있으면 새 폴더/파일 이름을 쓴다. 첫 명령은 입력 준비이며 Token 계산 성공과 다르다.

여기서 재계산하는 것은 기존 다섯 조건의 입력이다. 순서를 바꾼 `after`나 자신의 표 표현은 이 파일에 자동 저장되지 않는다. 새 입력을 측정하려면 그 실제 입력을 기록하고 해당 Template의 전체 Token을 별도로 세어야 한다.

</details>

## 활동 5. 과거 상태와 현재 전달 자료를 비교하기

```bash
python -m tools.context_steps --part handoff
```

기본값은 현재 제공 목록에 출장 규정이 없는 `C12` 사례다. 출력의 과거 문서 목록은 **설명을 위한 가상 상태**다. 현재 선택 문서·버전은 실제 준비 결과로 만든다. 과거 상태에는 출장 규정이 있었지만 현재 선택 목록은 비어 있다. 과거 답의 숫자를 복사하면 어떤 근거 확인을 건너뛰는지 설명한다.

다음은 현재 출장 규정을 사용할 수 있는 식비 문의로 바꾼 실행이다.

```bash
python -m tools.context_steps --part handoff --case C01
```

이 경우 현재 선택 문서·버전에는 `DOC-A`·`v1`이 나온다. “과거에 있었으니 사용한다”와 “현재 제공 가능한 원문을 선택하고 버전을 확인했다”의 차이를 읽는다. 데이터 묶음 버전과 문서 한 개의 버전도 구분한다.

| 전달 후보 | 이번에 포함/제외할 이유 | 확인할 현재 기준 |
|---|---|---|
| 현재 질문 | [ ] | [ ] |
| 현재 문서 ID·버전·선택 방식 | [ ] | [ ] |
| 과거 모델 답변 | [자동 복사하지 않을 이유] | [ ] |
| 디버그 기록·제한 자료 | [ ] | [ ] |
| 저장된 언어 선호 | [보관/선택/실제 입력 반영을 구분] | [ ] |

도구는 일회성 전달 자료를 보여준다. 대화를 저장하거나 지속 Memory·실제 문서 삭제·권한 서비스·전달 검증기를 만든 것이 아니다. 현재 준비 문자열과 내부 전달 딕셔너리도 서로 다른 자료다.

## 실패를 읽는 방법과 제출

| 증상 | 먼저 확인할 것 |
|---|---|
| `No module named app` 또는 `tools` | Backend 폴더와 가상환경 Python |
| 데이터 파일을 못 찾음 | 같은 브랜치의 전체 폴더 구조를 받았는지 |
| 공백/없는 사례로 입력 관찰 실패 | `C10` 공백은 의도한 거부다. 성공 결과로 채우지 않음 |
| 예산 단계가 입력 불일치를 알림 | 현재 입력이 과거 관찰과 달라짐. 새 실제 Token 계산 필요 |
| 예산에 다른 사례를 지정해 거부 | 기존 Token 관찰은 식비 입력뿐. 다른 질문에 재사용하지 않음 |
| Tokenizer 선택 활동이 설치/캐시 오류 | 입력·산술 활동과 실제 Tokenizer 실행 상태를 별도로 기록 |

다섯 활동의 관찰 표, 강의의 장별 질문에 대한 답, 선택/제외·축소/중단 이유를 제출한다. **실제 입력 준비 / 기존 관찰의 재계산 / 새 Tokenizer 실행 / 모델 생성**을 따로 표시한다. 같은 작성자의 시연 결과를 학생 자신의 실행이나 독립 수업 검증으로 제출하지 않는다.
