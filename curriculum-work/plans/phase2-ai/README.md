## 공통 원칙

1. Phase1은 개편하거나 전수 분석하지 않으며, Phase2 작성 시 중복 개념·예제만 확인한다.
2. 기존 Phase2 교안 및 실습의 유효한 설명과 코드는 재사용하되, 교육용 폴더 구조는 새로 설계한다.
3. 학생이 Obsidian 교안을 따라 하나의 애플리케이션에 코드를 붙여넣고 수정하며 각 단원에서 직접 결과를 확인해야 한다.
4. Chunking → Embedding → Retrieval → RAG → Tool Calling → Single-Agent → Multi-Agent를 단계별로 누적 구현한다.
5. 기존 `academy/` 아래 교육자료는 이번 문서 반영으로 변경하지 않는다.

> 이 인덱스는 실제 승인·확보 상태를 기록한다. 기존 분석 및 설계 문서의 작성 당시 상태 표현보다 이 표의 승인·파일 확보 상태가 최신이다.

## 학생용 문서 표기 원칙 (2026-11-07 승인)

- 수업용 목차·교안·실습 절차·검사표에는 내부 단계 식별자나 임의 검사 번호를 노출하지 않는다.
- 각 단계는 ‘기존 대화 앱 실행’, ‘Embedding 생성’, ‘근거 있는 RAG 답변 확인’처럼 배우는 내용과 실제 행동으로 설명한다.
- 실제 프로그램 실행에 필요한 API 속성·자료 식별자는 기술적 의미를 설명하면서 정확하게 유지한다. 이 규칙을 위해 기능 구현 조건이나 검증 범위를 삭제하지 않는다.
