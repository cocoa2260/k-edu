## 1. 오늘의 목표와 이미 알고 있어야 할 것

여기서는 Python·React 문법이나 Transformer 내부 계산을 다시 처음부터 설명하지 않습니다. Python 함수와 가상환경, HTTP·JSON, React 컴포넌트·상태, FastAPI 요청/응답의 기본 사용은 앞 과정에서 배웠다고 가정합니다. 모르는 부분이 생기면 해당 개념만 이전 자료에서 확인합니다.

수업이 끝나면 다음을 할 수 있어야 합니다.

- React에서 입력한 질문이 **어떤 HTTP 요청**으로 전달되는지 설명한다.
- FastAPI의 요청 검사, 서비스 코드, Ollama 모델 호출, 응답 반환의 **각 책임을 실제 파일에서 찾는다**.
- 서버 설정 확인(`/health`), 실제 모델의 답변(`/ai/chat`), 고정 테스트 결과를 서로 구별한다.
- 교육용 가상 규정에 관해 **정답처럼 보이는 모델 답변도 아직 문서 근거가 없을 수 있음**을 관찰한다.
- 기본 대화 앱의 예시 질문을 직접 수정하고, 브라우저에서 달라진 동작을 확인한다.
- 오류가 나면 무작정 코드를 고치기 전에 **입력·서버·모델의 어느 구간에서 발생했는지** 좁혀 본다.

**실습 원칙:** 이번 단원에서 새 프로젝트를 만들지 않습니다. 이후 단원에서도 지금 사용하는 `실습앱/`의 파일을 계속 확장합니다.

## 2. 왜 일반 LLM 대화만으로는 문서 도우미를 완성할 수 없을까?

우리가 만들 프로그램의 사용자는 “국내 당일 출장 식비 상한과 필요한 자료는?”처럼 조직의 규정을 질문합니다. 일반 Chat 화면은 질문을 모델에 전달하고 모델이 작성한 문장을 받아 보여줄 수 있습니다. 하지만 그 문장이 **실제로 제공한 규정 문서에서 확인된 사실인지**는 별개의 문제입니다.

### 2.1 자연스러운 문장과 검증된 사실은 다르다

예를 들어 다음 두 질문을 생각해 봅니다.

> 국내 당일 출장 식비 상한과 필요한 자료는?  
> 해외 출장 숙박비 상한은 얼마야?

수업 자료에는 첫 번째 질문과 관련된 **가상의 출장 규정**이 있지만, 해외 출장 숙박비 상한은 명시되어 있지 않습니다. 모델은 두 질문 모두에 문장 형태로 답할 수 있습니다. 그러나 그 문장이 그럴듯하다고 해서 교육용 규정과 일치한다는 뜻은 아닙니다.

| 관찰한 현상 | 판단할 수 있는 것 | 아직 판단할 수 없는 것 |
|---|---|---|
| 화면에 답변이 나타남 | 요청이 처리되어 문자열이 반환됨 | 규정과 일치하는 답인지 |
| 답변에 금액이 포함됨 | 모델이 금액을 문장에 사용함 | 금액의 실제 출처가 무엇인지 |
| 모델이 “규정에 따르면”이라고 말함 | 모델이 그런 표현을 선택함 | 해당 규정을 검색·열람했는지 |
| 정답과 같은 숫자가 나옴 | 해당 문장은 우연히 또는 학습된 정보로 숫자가 맞을 수 있음 | 이후 질문에도 같은 기준으로 정확할지 |

이 과정에서는 이 문제를 해결하기 위해 **문서 원문 → 단락 분할 → Embedding → 검색 → 근거를 포함한 모델 답변**을 뒤 단원에서 직접 연결합니다. 지금은 그 기능이 없는 상태를 기준으로 남겨 둡니다.

### 2.2 모델의 역할과 프로그램의 역할을 분리한다

모델은 주어진 입력에 대해 텍스트를 생성합니다. 반면 **어떤 자료를 제공할지, 어떤 도구를 허용할지, 어느 결과를 신뢰할지, 오류를 어떻게 처리할지**는 애플리케이션이 결정해야 합니다.

- **모델:** 입력을 받아 답변 문장을 생성합니다.
- **Provider 연결 코드:** 모델 호출 방식의 차이를 감춥니다. 현재 시작본에서는 Ollama 또는 선택형 OpenAI 경로를 사용합니다.
- **FastAPI:** 요청을 검사하고 응답 형식과 오류 상태를 정합니다.
- **React:** 사용자가 질문하고 답변 및 상태를 확인하게 합니다.
- **문서 검색·Agent:** **아직 구현하지 않았습니다.** 이후 학생이 같은 프로젝트에 추가합니다.

따라서 “모델이 답했다”와 “문서 도우미가 근거를 찾아 검증한 답을 제시했다”는 다릅니다.

### 2.3 오늘 사용할 가상 규정

`실습앱/backend/data/fixtures/documents-v1.json`에는 가상의 출장·교육비 규정과 이전 버전, 제한 자료, 신뢰할 수 없는 메모, 텍스트 표 등 **교육용 문서 6개**가 있습니다. `core-v1.json`에는 이 문서에 연결된 질문 사례 **12개**가 있습니다.

오늘은 이 파일을 열어 내용을 읽지만, **일반 Chat은 이 JSON 파일을 자동으로 모델에 전달하지 않습니다.** 이 차이가 다음 단원에서 입력 자료를 조합하고, 나중에 검색 기능을 구현해야 하는 이유입니다. 이 자료들은 실제 회사 규정이 아닙니다.

## 3. 우리 앱에서 질문 하나가 이동하는 경로

다음 경로는 제공된 **시작본 소스에서 확인할 수 있는 구조**입니다.

```text
브라우저: React 화면 (http://127.0.0.1:5173)
   │ 질문 작성·전송
   ▼
frontend/src/App.jsx
   │ askChat(question)
   ▼
frontend/src/api.js
   │ POST /ai/chat  {"message":"질문"}
   ▼
Vite 개발 서버 → FastAPI 프록시 (http://127.0.0.1:8000)
   │
   ▼
backend/app/main.py
   │ ChatRequest 입력 검사 → AIService.chat()
   ▼
backend/app/service.py
   │ Provider.generate(message)
   ▼
backend/app/providers/ollama_provider.py
   │ POST /api/chat
   ▼
Ollama (http://127.0.0.1:11434) → 설치된 생성 모델
   │ 생성된 문자열
   ▼
FastAPI → JSON {provider, model, answer} → React 답변 표시
```

이 흐름에서 **Ollama**는 모델을 실행·제공하는 로컬 서비스이고, **모델**은 `qwen3:1.7b`처럼 실제로 설치되는 생성 모델입니다. FastAPI와 React는 Ollama 자체가 아니라 우리가 만드는 애플리케이션 구성요소입니다.

> **중요:** 이 경로에는 문서 검색 단계가 없습니다. `fixtures/`에 규정 파일이 존재해도, 지금 질문을 보낼 때 그 문서가 자동으로 추가되지는 않습니다.

### 3.1 코드에서 책임 찾기

| 파일 | 학생이 직접 찾을 위치 | 역할 |
|---|---|---|
| `frontend/src/App.jsx` | `submit()` | 질문 입력, 로딩·답변·오류 상태 변경 |
| `frontend/src/api.js` | `askChat()` | 실제 HTTP 요청 생성 |
| `frontend/vite.config.js` | `proxy` | 브라우저의 `/ai`·`/health` 요청을 FastAPI에 전달 |
| `backend/app/main.py` | `create_app()`, `chat()` | HTTP 경로, 예외를 상태 코드로 변환 |
| `backend/app/schemas.py` | `ChatRequest`, `ChatResponse` | 요청 검증과 답변 형식 |
| `backend/app/service.py` | `AIService.chat()` | Provider에 독립적인 Chat 호출 |
| `backend/app/providers/factory.py` | `create_provider()` | 설정에서 호출할 Provider 선택 |
| `backend/app/providers/ollama_provider.py` | `OllamaProvider.generate()` | Ollama HTTP 호출과 응답 읽기 |
| `backend/app/config.py` | `required_env()` | 필수 환경설정 확인 |
| `backend/app/experiments.py` | `prepare()` | **미리 준비한 가상 사례를 조합**할 뿐, 모델을 생성·검색하지 않음 |

이 표를 외우는 것이 목표가 아닙니다. 실제로 파일을 열고 해당 함수를 찾는 것이 목표입니다.

### 3.2 서버가 설정을 확인하는 것과 답을 만드는 것은 다르다

시작본은 다음 경로를 구분합니다.

- `GET /health`: 현재 선택된 Provider와 모델 **설정값을 알려 줍니다**. 실제 모델에 질문하지 않습니다.
- `POST /ai/chat`: `message`를 검증하고 **Provider를 통해 실제 모델 생성 요청**을 시도합니다.
- `POST /ai/prepare`: 기존 고정 사례에서 Prompt 입력을 **준비만 합니다**. 생성이나 문서 검색이 아닙니다. 이 API는 다음 단원에서 다시 살펴봅니다.

`/health`가 정상이라고 해서 Ollama 모델이 로드되었거나 답변 품질이 검증됐다고 판단하지 마세요.

### 3.3 이 시작본의 HTTP 계약

설명용 요청 JSON 예시는 다음과 같습니다.

```json
{"message":"안녕하세요"}
```

정상 생성 시 **응답 구조**는 다음과 같습니다. 답변 문장은 모델마다 달라집니다.

```json
{
  "provider": "ollama",
  "model": "qwen3:1.7b",
  "answer": "실제 모델이 생성한 문장"
}
```

질문은 공백만으로 구성될 수 없고, 최대 **2000자**입니다. 여기서 2000은 **문자 수**이지 토큰 수가 아닙니다. 올바른 입력의 양쪽 공백은 서버에서 제거됩니다. 서버 설정으로 Provider를 선택하므로 브라우저에서 임의로 Provider 이름을 보낸다고 변경되지 않습니다.

## 4. 수업 준비: 하나의 실습앱 열기

### 4.1 파일 확인

배포받은 `03. Phase2_AI_수업용` 안에서 다음을 확인합니다.

```text
03. Phase2_AI_수업용/
├── 교안/
│   ├── 시작하기.md
│   ├── 부록. Python 가상환경 만들기.md
│   └── 01. LLM 심화와 AI 프로젝트 출발.md  ← 현재 읽는 교안
└── 실습앱/
    ├── README.md
    ├── backend/
    │   ├── .env.example

```

Obsidian에서 `교안/`을 보관함(Vault)으로 열고, VS Code에서는 옆의 `실습앱/`을 엽니다. **`backend/`와 `frontend/`를 따로 다운로드하여 별도의 프로젝트로 만들지 않습니다.**

[환경 설치 부록](<부록. Python 가상환경 만들기.md>)을 참고하며 필요한 프로그램은 Python 3.11 이상(권장 3.11/3.12), Node.js 20.19 이상(권장 22), npm, Ollama와 실제 생성 모델입니다. 실제 설치 가능 여부는 사용 중인 PC에서 확인해야 합니다. 수업에 사용하는 모델의 메모리 요구량과 생성 속도는 PC 사양에 따라 다를 수 있습니다.

### 4.2 Ollama 모델 준비

수업의 기본 생성 모델은 **`qwen3:1.7b`** 입니다. Ollama 설치 및 서비스 실행 상태를 확인합니다.

```bash
ollama --version
ollama list
```

모델이 없다면 인터넷이 되는 환경에서 한 번 설치합니다.

```bash
ollama pull qwen3:1.7b
ollama list
```

Ollama 서버가 실행되지 않았다면 시스템에 맞는 방법으로 실행합니다. GUI 앱이 이미 서비스를 실행하는 환경에서는 두 번째 `ollama serve`를 무조건 시작하지 않습니다. 별도 서버가 필요한 환경이라면 전용 터미널에서 `ollama serve`를 실행할 수 있습니다.

> `ollama list`에 모델이 보인다는 것만으로 **현재 모델의 추론이 성공했다는 뜻은 아닙니다.** 실제 생성은 아래 Chat 요청으로 확인합니다.

### 4.3 Backend 시작 — macOS/Linux

**터미널의 시작 위치:** VS Code에서 연 `실습앱/` 폴더.

```bash
cd backend
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
```

처음 한 번 설치하는 명령입니다. 다음 수업에서 이미 생성한 `.venv`를 다시 사용하면 됩니다. `backend/.env`를 열어 다음 부분을 확인합니다. **아래는 파일 전체가 아니라 수정할 설정 부분**입니다.

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:1.7b
```

다음 명령을 **`backend/` 폴더에서** 실행하고 터미널을 닫지 않습니다.

```bash
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

**확인:** 브라우저에서 `http://127.0.0.1:8000/health`를 엽니다. 정상이라면 `status`가 `ok`이고, 설정한 모델명이 표시됩니다. 이것은 아직 실제 생성 테스트가 아닙니다.

### 4.4 Backend 시작 — Windows PowerShell

**터미널의 시작 위치:** `실습앱/` 폴더.

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

`backend/.env`를 열어 `OLLAMA_MODEL=qwen3:1.7b`로 수정합니다. 그 뒤 같은 폴더에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

이렇게 가상환경의 Python을 **직접 지정**하면 PowerShell의 스크립트 실행 정책 때문에 활성화 명령이 차단되는 문제를 피할 수 있습니다. 설치된 Python 버전이 3.11 이상인지도 확인합니다.

### 4.5 Frontend 시작 — 운영체제 공통

Backend는 그대로 실행해 둡니다. **새 터미널**에서 `실습앱/frontend/`로 이동합니다.

```bash
cd frontend
npm install
npm run dev
```

새 터미널이 이미 `frontend/`에서 열려 있다면 `cd frontend`는 다시 입력하지 않습니다. 브라우저에서 `http://127.0.0.1:5173`을 엽니다. 최초 `npm install`에는 네트워크가 필요할 수 있습니다.

**정상적으로 기대하는 화면:** 왼쪽에 질문 입력창과 ‘질문 보내기’ 버튼, 오른쪽에 답변과 서버/Provider/Model 상태가 표시됩니다. 화면의 ‘설정 확인’은 **FastAPI 설정 응답을 받았다는 뜻**입니다.

> **화면이 열리지 않으면** `frontend/` 터미널의 Vite 오류부터 확인하세요. **화면은 열리지만 질문이 실패하면** Backend·Ollama 상태를 순서대로 확인합니다. 두 오류를 혼동하지 않습니다.

## 5. 실습: 질문 한 번의 실제 이동 확인

### 5.1 일반 대화 실행

1. 브라우저의 질문창에 `안녕하세요. 간단히 자기소개해 주세요.`를 입력합니다.
2. **질문 보내기**를 클릭합니다.
3. 버튼이 ‘응답 기다리는 중…’으로 바뀌고, 상태가 ‘생성 중’이 되는지 확인합니다.
4. 정상이라면 답변 영역에 **실제 모델이 생성한 문자열**이 나타나고 ‘응답 수신’으로 바뀝니다.
5. 오른쪽 아래의 Provider 및 Model 이름을 확인합니다.

**기록할 내용:** 사용한 질문, 설정된 모델, 응답 성공 또는 오류, 화면에서 관찰한 상태. 답변 문장은 학생 PC에서 실제로 생성된 값을 적어야 합니다. 다른 사람이 만든 예시 문장을 ‘실측’으로 복사하지 않습니다.

### 5.2 개발자 도구로 HTTP 요청 확인

브라우저에서 개발자 도구를 열고 **Network(네트워크)** 탭을 선택합니다. 질문을 다시 한 번 보냅니다.

- `POST /ai/chat` 요청이 생겼는지 확인합니다.
- Request Payload(요청 본문)의 `message` 필드를 확인합니다.
- Response(응답)에 `provider`, `model`, `answer`가 있는지 확인합니다.
- Status가 `200`인지 또는 `422/502/503/504` 같은 오류인지 확인합니다.

브라우저에는 `127.0.0.1:5173`으로 보이는 요청이 있을 수 있습니다. Vite의 `frontend/vite.config.js`가 **`/ai` 요청을 FastAPI의 `127.0.0.1:8000`으로 프록시**하므로 정상입니다. 프록시를 거친 뒤 FastAPI가 Ollama를 호출합니다.

**직접 파일에서 확인하기:** `frontend/src/App.jsx`의 `submit()` 안에 `await askChat(question)`이 있습니다. `frontend/src/api.js`의 `askChat(message)`가 `POST /ai/chat` 요청 본문을 만듭니다. 이 함수들이 위 네트워크 요청과 어떻게 연결되는지 설명해 봅니다.

### 5.3 API를 화면 없이 직접 호출하기

Backend 터미널은 켜 둡니다. **세 번째 터미널**에서 다음 중 운영체제에 맞는 명령을 실행합니다.

macOS/Linux:

```bash
curl -sS -X POST http://127.0.0.1:8000/ai/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"안녕하세요"}'
```

Windows PowerShell:

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/ai/chat' `
  -Method Post -ContentType 'application/json' `
  -Body '{"message":"안녕하세요"}'
```

화면 없이도 같은 API를 호출할 수 있어야 합니다. **React는 답변을 표현하는 사용자 인터페이스이고, 실제 AI 호출 책임은 Backend에 있습니다.**

## 6. 실습: 직접 코드 바꾸고 화면에서 확인하기

이번 변경은 전체 프로그램을 새로 만드는 작업이 아니라, 이미 존재하는 코드에서 **실제 값을 찾아 수정하는 첫 연습**입니다.

### 6.1 React의 기본 질문 변경

VS Code에서 `실습앱/frontend/src/App.jsx`를 엽니다. 파일 윗부분의 다음 코드를 찾습니다.

**수정 전:**

```jsx
const SAMPLE = '국내 당일 출장 식비 상한과 필요한 자료는?';
```

**수정 후:**

```jsx
const SAMPLE = '해외 출장 숙박비 상한은 얼마야?';
```

저장하고 브라우저를 새로 고침합니다. 질문 입력창에 **새로운 기본 질문이 표시되는지** 확인합니다. 이 변경이 동작하는 이유는 `App.jsx`에서 `useState(SAMPLE)`로 질문의 최초 값을 만들기 때문입니다. ‘예시 질문 다시 넣기’ 버튼도 같은 값을 사용합니다.

이제 질문을 전송합니다. 모델이 금액을 제시할 수도 있고 모르겠다고 말할 수도 있습니다. **어느 쪽이든 바로 정답 처리하지 않습니다.** 해당 교육용 규정에 해외 숙박비 상한이 명시되어 있는지 `backend/data/fixtures/documents-v1.json`을 직접 열어 확인합니다.

**실험이 끝나면** `SAMPLE`을 원래의 국내 당일 출장 질문으로 되돌리고 저장합니다. 이후 단원에서 동일 질문을 기준 사례로 사용하기 위해서입니다.

### 6.2 요청 형식과 입력 검사 확인

`backend/app/schemas.py`에서 다음 두 부분을 찾습니다.

```python
message: str = Field(min_length=1, max_length=2000)
```

```python
if not value.strip():
    raise ValueError("공백만 있는 질문은 허용하지 않습니다.")
```

이 부분은 **모델에 보내기 전** 입력을 검사합니다. 모델이 틀린 금액을 답했는지 판단하는 코드가 아닙니다.

**최신 React 시작본에서는 공백만 입력하면 ‘질문 보내기’ 버튼이 비활성화됩니다.** 따라서 화면에서 공백을 전송해 `422` 응답을 관찰하라고 안내하면 진행할 수 없습니다. 이 버튼 비활성화는 **화면의 첫 번째 입력 검사**입니다.

서버에서도 입력을 검증한다는 사실을 확인하려면, 브라우저에서 `F12`(또는 개발자 도구 열기) → **Console(콘솔)**로 이동한 다음 다음 JavaScript를 실행합니다. 반드시 React 개발 서버(`http://127.0.0.1:5173`)가 열린 탭에서 실행하세요.

```javascript
fetch('/ai/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: '   ' }),
}).then(response => console.log('서버 응답 코드:', response.status));
```

콘솔에 **`서버 응답 코드: 422`**가 나타나면 FastAPI의 `ChatRequest` 입력 검증이 동작한 것입니다. 이 요청은 정상이라면 실제 모델을 호출하지 않습니다. `422`가 보이지 않으면 개발자 도구의 Network 탭과 FastAPI 서버 로그를 확인합니다.

> **구분:** React에서 버튼을 막는 것은 사용자 편의를 위한 첫 검사이고, FastAPI에서 `422`로 거부하는 것은 서버의 별도 입력 검사입니다. 서버 검사는 API를 직접 호출하는 경우에도 반드시 필요합니다.

### 6.3 Backend의 오류 책임 확인

`backend/app/main.py`의 `chat()`을 열고 다음 예외 변환을 찾아보세요.

| 상태 | 뜻 | 먼저 점검할 것 |
|---|---|---|
| `422` | 잘못된 질문 또는 요청 형식 | 공백 질문, 글자 수, JSON 필드 |
| `503` | Provider 연결 실패 | Ollama 서버 실행, 주소·포트 |
| `504` | Provider 응답 시간 초과 | 모델 실행 상태, 장시간 추론 |
| `502` | Provider 쪽 오류·잘못된 응답 | 모델명, 서버 로그, 응답 형식 |

**연습:** Backend를 실행한 상태에서 Ollama를 종료하고 질문을 전송해 봅니다. 환경에 따라 `503` 또는 다른 실제 상태가 나타날 수 있으므로 **표에 맞는 숫자가 나오는지 억지로 맞추지 말고, 관찰한 상태와 서버 로그를 기록**합니다. 수업이 끝나면 Ollama를 다시 켜서 정상 상태로 되돌립니다.

> **주의:** 학생 PC의 실제 응답 시간을 재지 않은 채 “이 모델은 항상 몇 초 안에 답한다”고 기록하지 마세요. 입력 길이와 하드웨어에 따라 달라집니다.

## 7. 실습: 문서가 있는데도 왜 문서 근거가 아닌가?

다음은 이번 단원의 핵심 비교입니다.

1. `backend/data/fixtures/documents-v1.json`의 **가상 기관 출장 규정**을 직접 열어, 국내 당일 출장 식비 상한과 조건을 읽습니다.
2. React 화면에서 같은 질문을 보냅니다.
3. 화면이 반환한 문장과 **실제 파일의 내용**을 대조합니다.
4. 다음 두 가지를 구분해 적습니다.
   - **문서에 실제로 적힌 내용:** 원본에서 찾은 문장.
   - **모델이 생성한 내용:** Chat 응답에 나타난 문장.
5. `frontend/src/api.js`의 `askChat()`과 `backend/app/service.py`의 `chat()`을 다시 확인합니다. **이 두 함수는 `fixtures/`의 규정 파일을 읽어 전달하지 않습니다.**

현재 교육용 문서에는 국내 당일 출장 식비 상한이 **30,000원**이라고 적혀 있으며, 사전 승인·영수증·식사 제공 시 미지급 조건이 함께 있습니다. 반면 해외 출장 숙박비 상한은 해당 문서에서 제공하지 않습니다. 이는 **원본 파일을 읽어 확인한 교육용 사실**이며, Chat이 그 사실을 조회했다는 뜻은 아닙니다.

**관찰 기록 예시 (내용은 각자 실제 결과로 채우기):**

| 질문 | 문서에서 확인한 사실 | 모델이 실제로 답한 내용 | 지금의 결론 |
|---|---|---|---|
| 국내 당일 출장 식비 상한? | 30,000원, 사전 승인, 영수증, 식사 제공 시 미지급 | *직접 입력* | Chat 생성 결과와 문서 사실 비교만 가능 |
| 해외 출장 숙박비 상한? | 자료에 상한 없음 | *직접 입력* | 근거 없는 금액을 답했다면 오류 사례로 기록 |

이후 RAG 단원에서는 **문서를 찾아 모델에게 제공하고 답변과 출처를 연결**합니다. 그때 비로소 지금과 같은 질문을 근거 기반 흐름에서 다시 비교합니다. 문서를 읽고도 잘못 해석할 가능성이 있으므로 RAG 역시 무조건 정답을 보장하지는 않습니다.

## 9. 오류 해결 순서

오류가 발생했을 때 아래 순서대로 확인해 보세요.

1. **화면 자체가 안 열리는가?** `frontend/`에서 `npm install`, `npm run dev`를 실행했는지, `127.0.0.1:5173`인지 확인합니다.
2. **화면은 열리지만 서버 연결 확인 실패인가?** `backend/`에서 Uvicorn이 켜져 있는지, `http://127.0.0.1:8000/health`에 응답하는지 확인합니다.
3. **서버 실행부터 실패하는가?** 가상환경 Python이 맞는지, `backend/.env`를 만들었는지, `OLLAMA_MODEL`에 실제 모델명이 들어 있는지 확인합니다.
4. **서버 상태는 정상인데 질문에 실패하는가?** Ollama가 실행 중인지, `ollama list`에 같은 모델명이 있는지, 모델 서버의 에러 로그를 확인합니다.
5. **실행은 되지만 금액이 틀렸는가?** 지금은 RAG가 없으므로 규정 원문을 모델에게 제공했다고 가정하지 않습니다. 출처 검증이 없었다는 관찰로 남깁니다.
6. **테스트만 통과하고 실제 모델 호출은 실패하는가?** 테스트용 가짜 답변과 실제 생성 모델 실행은 별개의 과정이므로, 모델·네트워크·메모리를 따로 점검합니다.

설치 문제가 생기면 다른 버전의 전체 프로젝트를 새로 다운로드하기보다 **어느 파일·명령에서 실패했는지** 먼저 기록합니다. 이것이 다음 단원에 이어질 자신의 코드 상태를 유지하는 가장 쉬운 방법입니다.
