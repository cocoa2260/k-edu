# 부록. Python 가상환경 만들기

> 이 부록은 **AI 문서 도우미 실습을 시작하기 전에 그대로 따라 하는 환경 준비 안내**입니다. 먼저 수업용 Qwen3 모델을 다운로드·실행하고, Mac·Windows·Linux 중 **자신의 운영체제에 해당하는 Python 가상환경 절차만** 진행하세요. 이후 모든 수업에서는 **같은 가상환경과 생성 모델**을 계속 사용합니다.

## 오늘 할 일

**Ollama의 Qwen3 1.7B 모델을 설치하고 실제 한국어 응답을 확인**한 뒤, Python 가상환경을 만들고 필요한 패키지를 설치해 **가상환경의 Python으로 FastAPI를 실행**합니다. 가상환경은 이 프로젝트에서 사용하는 Python 패키지를 다른 프로젝트와 분리해 관리하는 폴더입니다. 새 프로젝트를 만들거나 Python을 컴퓨터에서 삭제하는 작업이 아닙니다.

실습이 끝난 뒤 폴더는 다음과 같습니다.

```text
03. Phase2_AI_수업용/
├── 교안/
│   ├── 시작하기.md
│   └── 부록. Python 가상환경 만들기.md   ← 지금 읽는 문서
└── 실습앱/                            ← VS Code에서 여는 폴더
    ├── backend/
    │   ├── .venv/                      ← 이번에 만들 가상환경 (공유하지 않음)
    │   ├── .env.example
    │   ├── .env                        ← 학생이 자신의 컴퓨터에서 생성
    │   ├── requirements.txt
    │   ├── requirements-dev.txt
    │   └── app/
    └── frontend/
```

**중요:** `.venv`는 항상 **`실습앱/backend/.venv`** 한 곳에 만듭니다. `frontend`용 Python 가상환경을 따로 만들지 않습니다. React는 이후에 `npm install`로 준비합니다.

## 시작 전 — 정확한 폴더 열기

1. 제공받은 **AI 문서 도우미 시작본 ZIP**을 압축 해제합니다.
2. VS Code를 실행해 `03. Phase2_AI_수업용` 아래의 **`실습앱` 폴더**를 엽니다. `backend`만 따로 열거나 이전 실습 프로젝트를 열지 마세요.
3. VS Code 메뉴에서 **터미널 → 새 터미널**을 클릭합니다.
4. 아래 명령을 실행해 터미널이 `실습앱` 폴더에 있는지 확인합니다.

**Mac / Linux**

```bash
pwd
ls
```

**Windows PowerShell**

```powershell
Get-Location
Get-ChildItem
```

**확인할 결과:** `backend`와 `frontend` 폴더가 모두 보여야 합니다. 보이지 않는다면 VS Code에서 연 폴더를 다시 확인합니다. 아래 명령은 **이 위치에서 시작한다는 전제**로 작성되어 있습니다.

## 학원 실습 AI 모델 준비 — Qwen3 1.7B

이번 과정에서는 **Qwen3 1.7B**를 기본 답변 생성 모델로 사용합니다. 첫 수업의 Chat부터 나중에 만들 RAG·Tool Calling·Single-Agent·Multi-Agent까지 **생성 모델은 동일하게 유지**합니다. 지금 준비할 것은 모델 설치와 기본 Chat 확인이고, 이후 기능의 코드는 해당 단원에서 직접 작성합니다.

| 항목 | 수업에서 사용할 값 또는 의미 |
|---|---|
| 모델 이름 | `qwen3:1.7b` |
| 양자화 | `Q4_K_M` (Ollama의 해당 기본 태그) |
| 모델 다운로드 크기 | 약 **1.4GB**. 디스크 다운로드 크기로, 실행 시 필요한 GPU 메모리와 동일하지 않습니다. |
| 주요 역할 | 한국어 Chat, RAG **답변 생성**, Agent의 다음 행동/역할별 응답 생성 |
| 도구 호출 | 모델과 Ollama API가 지원합니다. **현재 시작본에서는 구현되지 않았으며** 뒤의 도구 호출 단원에서 직접 작성합니다. |
| 학원 PC | GTX 1060 **3GB**를 대상으로 우선 시험할 후보입니다. GPU에 항상 전부 올라간다고 보장하지 않습니다. |

모델 크기와 양자화 및 Tool Calling 지원은 [Ollama Qwen3 공식 모델 페이지](https://ollama.com/library/qwen3:1.7b), [Ollama 공식 API 문서](https://docs.ollama.com/api/chat)를 기준으로 확인했습니다. **GTX 1060 3GB에서의 실제 속도·GPU 적재 여부·안정성은 아직 학원 PC에서 검증되지 않았습니다.** PC의 RAM, GPU 드라이버, Ollama 버전과 Context 크기에 따라 달라집니다.

### 1. Ollama 설치 여부 확인

**Mac / Linux / Windows PowerShell 모두** 다음을 실행합니다. 이 명령은 Python 가상환경을 켜기 전이나 켠 뒤 어디서나 실행할 수 있습니다.

```text
ollama --version
```

버전이 표시되면 다음 단계로 갑니다. `ollama` 명령을 찾을 수 없다면 [Ollama 공식 설치 페이지](https://ollama.com/download)에서 **자신의 운영체제에 맞게 설치**한 뒤 VS Code 터미널을 새로 열어 다시 확인합니다. Ollama를 이미 설치한 컴퓨터에서는 다시 설치할 필요가 없습니다.

### 2. 모델 다운로드

```text
ollama pull qwen3:1.7b
```

모델 다운로드에는 인터넷 연결과 디스크 여유 공간이 필요합니다. 다운로드가 끝나면 다음 명령으로 확인합니다.

```text
ollama list
```

**확인할 결과:** 목록에 `qwen3:1.7b`가 보입니다. 여기까지는 모델 다운로드를 확인한 것이지 실제 답변 생성이 성공했다는 뜻은 아닙니다.

### 3. 모델 직접 실행하고 한국어 질문하기

```text
ollama run qwen3:1.7b
```

모델 입력 프롬프트가 나타나면 다음 문장을 **직접 입력**하고 Enter를 누릅니다.

```text
안녕하세요. 지금은 AI 문서 도우미를 만드는 수업입니다. 한 문장으로 인사해 주세요.
```

**확인할 결과:** 한국어로 모델 응답이 나타나는지 직접 확인합니다. 모델이 처음 로딩되는 과정은 시간이 걸릴 수 있습니다. 답변의 문장은 PC와 실행 설정에 따라 달라지므로 예시 문장을 정답처럼 외우거나 복사하지 않습니다.

대화를 마치려면 다음을 입력합니다.

```text
/bye
```

> `ollama run`에서 나오는 것은 **Ollama 프로그램의 대화**입니다. 아직 React·FastAPI 프로그램과 연결한 것은 아닙니다. 뒤에서 FastAPI와 React를 실행한 뒤 **브라우저에서도 답을 받아야** 연결 실습이 끝납니다.

### 4. 이 수업 프로젝트에 Qwen3 연결하기

아래 Mac·Windows·Linux 가상환경 절차에서 `.env.example`을 `.env`로 복사한 다음, VS Code에서 **`실습앱/backend/.env`**를 열고 다음 값을 입력합니다. 이미 같은 이름의 설정이 있다면 그 값을 아래 값으로 변경하세요.

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:1.7b
```

`FRONTEND_ORIGINS` 등 기존 `.env.example`에 있는 **다른 설정은 삭제하지 않습니다.** `.env`는 개인 실행 설정이므로 다른 사람에게 공유하거나 Git에 올리지 않습니다.

그 뒤 이 부록의 운영체제별 절차대로 **가상환경 패키지 설치 → FastAPI 실행 → React 실행**을 진행합니다. `/health`에서 `model: qwen3:1.7b`가 보이는지는 설정 확인이고, **React에서 질문에 대한 실제 모델 답변을 받는 것이 생성 연결 확인**입니다.

### 5. GPU 사용과 메모리 확인 — 학원 PC에서 수행

실제 질문을 실행한 뒤 **다른 터미널**에서 다음을 입력합니다.

```text
ollama ps
```

**확인할 것:** Ollama 버전에 따라 `PROCESSOR` 등에 CPU 또는 GPU 적재 비율이 표시됩니다. 모델 파일 크기 약 1.4GB는 **GPU VRAM 사용량과 다릅니다.** Context(KV Cache), 런타임, 다른 프로그램이 추가 메모리를 사용하므로 **GTX 1060 3GB에 반드시 전체 적재된다고 단정할 수 없습니다.** 첫 수업은 PC 한 대당 모델 하나, 동시에 여러 요청을 보내지 않는 방식으로 진행합니다. 속도가 느리거나 메모리 부족 오류가 발생하면 강사에게 장비와 실행 상태를 기록해 전달합니다.

권장 Context 실습 시작 범위는 **2,048~4,096토큰**입니다. Qwen3의 모델 사양상 최대 Context와 교육장 PC에서 무리 없이 설정 가능한 Context는 다릅니다. **현재 EDU-08 시작본은 `.env`의 Context 설정 값을 읽어 모델 호출에 전달하지 않습니다.** 따라서 단순히 `.env`에 Context 변수 한 줄을 추가하는 것만으로 적용됐다고 말하면 안 됩니다. 강사가 모델 요청 코드를 준비할 때 `options.num_ctx`를 명시하고 실제 적용 여부를 확인해야 합니다.

### 6. Embedding은 나중에 별도의 모델을 사용합니다

| 모델 | 하는 일 | 어느 수업에서 사용하는가 |
|---|---|---|
| **Qwen3 1.7B** | 자연어 답변 생성, 검색된 자료를 바탕으로 답변 만들기, Agent의 행동 선택 | 기본 Chat부터 최종 Multi-Agent까지 |
| **`intfloat/multilingual-e5-small`** | 문서·질문을 **384차원 Embedding 벡터**로 변환해 비슷한 내용을 검색할 수 있게 함 | Embedding·벡터 검색·RAG 단원부터 |

`multilingual-e5-small`은 Ollama의 Qwen 모델과 **다른 모델**이며, 후속 Python 실습에서 CPU로 실행하도록 계획합니다. 문서는 `passage: `, 검색 질문은 `query: ` 접두어를 붙이는 방식으로 사용합니다. Embedding 모델 설치는 그 단원에서 안내하므로 **이번 Chat 시작 단계에서 다운로드하거나 패키지를 설치할 필요가 없습니다.** ([Embedding 모델 공식 안내](https://huggingface.co/intfloat/multilingual-e5-small))

**수업 완료 판단:** Ollama 터미널에서 한국어 답변을 받는 데 성공하면 **모델 단독 실행 확인**입니다. FastAPI와 React를 연결해 같은 모델로 질문에 응답받으면 **기본 Chat 연결 확인**입니다. 두 결과는 구분해 기록하세요. Tool Calling 및 Multi-Agent의 실제 정확도는 이후 수업에서 별도로 검증합니다.

## Mac에서 만들기 (macOS 터미널 / VS Code 터미널)

### 1. Python 버전 확인

```bash
python3.11 --version
```

**예상 출력 예시:** `Python 3.11.x`

- 이번 가이드는 Python **3.11**을 예로 듭니다. 수업에서 3.12를 지정했다면 아래 `python3.11`을 `python3.12`로 바꾸세요.
- `command not found`가 나오면 Python 3.11 실행 파일을 찾지 못한 것입니다. Python을 먼저 설치해야 합니다. Homebrew가 이미 설치된 Mac에서는 다음처럼 설치할 수 있습니다.

```bash
brew install python@3.11
```

- 설치 후에도 `python3.11`을 찾지 못하면 다음 명령으로 설치 경로를 확인할 수 있습니다.

```bash
"$(brew --prefix python@3.11)/bin/python3.11" --version
```

이 경우 아래의 `python3.11 -m venv .venv` 대신 **`"$(brew --prefix python@3.11)/bin/python3.11" -m venv .venv`**를 사용합니다. Mac 시스템에 원래 있는 Python을 삭제하거나 다른 프로젝트의 Python을 바꿀 필요는 없습니다.

### 2. Backend 폴더로 이동하고 가상환경 생성

```bash
cd backend
python3.11 -m venv .venv
```

**확인할 결과:** `backend` 안에 `.venv` 폴더가 만들어집니다. 성공할 때 메시지가 표시되지 않아도 정상입니다.

### 3. 가상환경 활성화

```bash
source .venv/bin/activate
```

터미널 왼쪽에 `(.venv)`가 나타날 수 있습니다. **표시가 없어도 다음 확인 명령으로 판단**하세요.

```bash
python --version
python -c "import sys; print(sys.executable); print('가상환경 사용 중:', sys.prefix != sys.base_prefix)"
```

**예상 결과:** Python 3.11.x, 경로에 `backend/.venv/bin/python`이 포함되며 `가상환경 사용 중: True`가 출력됩니다.

### 4. 패키지 설치 및 확인

```bash
python -m pip install -r requirements-dev.txt
python -m pip --version
python -m pytest -q
```

`pip` 경로에 `.venv`가 보이고 테스트가 실행되면 정상입니다. **테스트 통과는 코드의 기본 동작 확인이지 Ollama 모델의 실제 추론 성공이 아닙니다.** 다운로드에 실패하면 네트워크와 Python 버전을 확인합니다.

### 5. 실행 설정 복사

```bash
cp .env.example .env
```

VS Code에서 `backend/.env`를 열고 **`OLLAMA_MODEL=qwen3:1.7b`**로 설정합니다. 위 ‘학원 실습 AI 모델 준비’ 절차에서 모델 다운로드와 단독 실행을 먼저 확인하세요. `.env`는 GitHub나 학생 공유 ZIP에 올리지 않습니다.

### 6. FastAPI 실행

```bash
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

터미널을 **닫지 말고 유지**합니다. 브라우저에서 `http://127.0.0.1:8000/health`를 엽니다. JSON 형태의 `status`, `provider`, `model`이 표시되면 **Backend 설정·서버 실행 확인**입니다. `/health`만으로 실제 모델이 답했다고 판단하면 안 됩니다.

## Windows에서 만들기 (PowerShell)

> Windows에서는 **VS Code의 PowerShell 터미널**을 사용합니다. Mac 명령어인 `source`를 복사하면 실행되지 않습니다.

### 1. Python 버전 확인

```powershell
py -0p
py -3.11 --version
```

**예상 출력 예시:** `Python 3.11.x`

`py` 명령을 사용할 수 없다면 `python --version`으로 확인하세요. Python 3.11이 설치되지 않았다면 Python 설치 프로그램에서 **Python 3.11**을 설치한 뒤 VS Code 터미널을 다시 엽니다. 수업에서 3.12를 지정했다면 `py -3.11` 대신 `py -3.12`를 사용합니다.

### 2. Backend 폴더로 이동하고 가상환경 생성

```powershell
cd backend
py -3.11 -m venv .venv
```

**확인할 결과:** `backend/.venv` 폴더가 생성됩니다.

### 3. 가상환경 활성화

```powershell
.\.venv\Scripts\Activate.ps1
```

보안 정책 때문에 실행이 차단되면 **현재 터미널 프로세스에서만** 활성화를 허용할 수 있습니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

위 설정을 허용하지 않거나 회사 PC 정책으로 변경이 불가능하다면 **활성화 없이도 가상환경의 Python을 직접 호출**하면 됩니다. 아래 명령에서 `python` 대신 `.\.venv\Scripts\python.exe`를 사용하세요.

### 4. 가상환경 확인 및 패키지 설치

**활성화에 성공했다면** 다음 명령을 실행합니다.

```powershell
python --version
python -c "import sys; print(sys.executable); print('가상환경 사용 중:', sys.prefix != sys.base_prefix)"
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

**예상 결과:** `.venv\Scripts\python.exe` 경로, `가상환경 사용 중: True`, Backend 테스트 실행.

## Backend가 실행됐다면 React 화면 열기

가상환경을 활성화한 **Backend 터미널은 그대로 열어 둡니다.** VS Code에서 **새 터미널을 하나 더 열고** `실습앱` 폴더에서 다음 명령을 실행합니다.

```bash
cd frontend
npm install
npm run dev
```

Windows PowerShell에서도 위 명령은 같습니다. 브라우저에서 **`http://127.0.0.1:5173`**을 열고 질문을 전송합니다. React 개발 서버는 Python 가상환경 안에서 실행하는 프로그램이 아니므로 새 터미널에 `.venv`를 활성화할 필요는 없습니다.

**정상 확인을 두 가지로 구분하세요.**

- `/health`가 보임: FastAPI 서버와 Provider **설정 확인**.
- React에서 질문을 전송하고 모델 답변을 받음: **실제 Qwen3 1.7B 생성 호출 확인**. 단, 답변이 규정 문서에 근거한 결과인지는 아직 확인할 수 없습니다. 문서 검색과 RAG는 이후 수업에서 만듭니다.

## 다음 수업에서 다시 시작하는 방법

가상환경은 한 번 만든 뒤 **삭제하지 않고 계속 사용**합니다. 새로운 터미널을 열면 다시 활성화해야 합니다. VS Code에서 `실습앱` 폴더를 열었다는 전제입니다.

**Mac / Linux**

```bash
cd backend
source .venv/bin/activate
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

**Windows PowerShell**

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Windows에서 활성화가 막혀 있으면 위에서 소개한 `.\.venv\Scripts\python.exe -m uvicorn ...` 형태를 사용합니다. React는 **새 터미널**에서 `cd frontend` → `npm run dev`로 재시작합니다.

### 수업 종료 시

1. FastAPI가 실행 중인 터미널에서 **Ctrl+C**를 누릅니다.
2. React 개발 서버가 실행 중인 터미널에서도 **Ctrl+C**를 누릅니다.
3. 가상환경이 활성화된 터미널에서 다음 명령으로 종료할 수 있습니다.

```text
deactivate
```

`deactivate`는 **가상환경을 삭제하는 명령이 아닙니다.** 다음 수업에서 다시 활성화하면 됩니다.

## 자주 발생하는 문제

| 화면 또는 오류 | 확인 방법 |
|---|---|
| `python3.11: command not found` | 해당 Python 버전이 설치되었는지 확인. Mac에서는 Homebrew 설치 경로 점검 |
| `No module named venv` 또는 `ensurepip is not available` | 해당 OS의 Python `venv` 패키지 설치 필요. 운영체제별 방법으로 설치 |
| `Activate.ps1 cannot be loaded` | Windows 실행 정책 차단. `-Scope Process` 해결 또는 활성화 없이 `.venv` Python 직접 실행 |
| 가상환경을 켰는데 `False` 출력 | 가상환경이 아닌 Python이 선택된 상태. 실행 경로를 다시 확인 |
| `No module named fastapi` | 가상환경 활성화 상태에서 `python -m pip install -r requirements-dev.txt`를 실행했는지 확인 |
| `No module named uvicorn` | 역시 **같은 가상환경의 Python**으로 설치/실행했는지 확인 |
| `.env` 파일이 없음 | `backend` 폴더에서 OS에 맞는 `cp` 또는 `Copy-Item` 명령 실행 |
| `OLLAMA_MODEL` 설정 오류 | `.env`에 `OLLAMA_MODEL=qwen3:1.7b`가 들어 있고 `ollama list`에 같은 이름이 있는지 확인 |
| `/health`는 정상인데 질문에 답하지 않음 | `ollama list`에서 `qwen3:1.7b` 존재 여부, `ollama run qwen3:1.7b`로 단독 답변, 서버 상태 및 모델 메모리 확인. `/health`는 모델을 실행하지 않음 |
| `npm` 오류 | Python 가상환경 문제가 아님. Node.js/npm 설치·버전 및 네트워크 점검 |
| VS Code를 다시 열었더니 가상환경 표시가 사라짐 | 정상. 새 터미널에서 다시 `source ...` 또는 `Activate.ps1`을 실행 |

### 기억할 세 가지

1. 가상환경은 **`backend/.venv` 하나**만 만듭니다.
2. 패키지를 설치하거나 FastAPI를 실행할 때는 **반드시 그 가상환경의 Python**을 사용합니다.
3. 이후 수업에서 Embedding·RAG·Agent 기능을 추가하더라도 **같은 가상환경과 같은 실습앱을 유지**합니다. 생성 모델도 `qwen3:1.7b`를 유지하고, Embedding 단원에서만 별도 CPU 모델을 추가합니다. 필요한 패키지는 해당 수업의 안내에 따라 설치합니다.

> **검증 범위 안내:** 이 문서의 명령은 EDU-08 시작본의 실제 파일 구조를 기준으로 작성했습니다. Python 3.11/3.12를 사용하는 각 운영체제와 학원 PC의 GTX 1060 3GB에서 `qwen3:1.7b`의 전체 재현·GPU 메모리·응답 속도는 별도 검증이 필요합니다. 출력 문자열은 학생이 확인할 **예시**이지 학생 컴퓨터의 실행 결과를 미리 보장하는 값이 아닙니다.
