# 호출 실패와 출력 보완을 직접 구분하기

[Harness 강의](<../../01. Phase2_AI/05. 프롬프트 엔지니어링(Prompt Engineering)/Harness/강의용.md>)와 같은 가상 규정·질문·입력 준비 코드를 사용한다. 먼저 요청 하나의 전체 흐름을 읽고, 통신 재시도·출력 보완·반복 실패·회귀·취소를 비교한다. 실제 모델 대신 고정 응답을 주입한다. 코드가 실제로 실행된 것과 모델이 답을 생성한 것은 구분한다.

## 준비와 첫 실행

[기준 대화 앱](<../../01. Phase2_AI/12. AI Integration/강의용.md>)의 Python 3.12 가상환경과 설치 패키지를 사용한다. 터미널의 작업 폴더는 `academy/00. 교육과정(curriculum)/02. 실습/document-assistant/backend`다. 아래 `python`은 그 가상환경의 실행기를 뜻한다. API Key·모델 가중치·GPU는 필요 없다.

다음은 **터미널에 입력할 명령**이다.

```bash
python -m tools.harness_steps
```

이 명령은 교육용으로 작성한 충실한 식비 답안을 고정 반환하고 실제 Harness를 한 번 실행한다. 준비→호출→검사→종료가 보인다. Provider 시도 1회, 재시도 0회, 보완 0회이며 마지막은 사람 검토가 필요한 초안이다. 실제 모델 추론은 0회다.

| 볼 것 | 해석할 것 |
|---|---|
| 초안에 있는 금액·조건·예외·출처 | 원문과 맞는지 사람이 확인한다 |
| 구조 통과·사람 검토 필요 | 자동 내용 검증/업무 승인과 구분한다 |
| 내용 검증·승인·외부 작업 `False` | 실제 사실 검증기나 승인/실행 절차를 수행하지 않았다 |
| Token·비용 `None` | 사용량 미확인이다. 0 Token/0원을 측정한 것이 아니다 |

첫 명령은 새 단일 예제를 실행하며 파일을 만들지 않는다. 아래의 전체 실험 기록을 읽는 명령은 지정한 파일을 읽을 뿐 같은 실험을 다시 실행하지 않는다.

## 활동 1. 열 가지 제어 실험을 기록하고 읽기

먼저 **새 파일 이름**으로 기존 고정 응답 데모를 실행한다.

```bash
python -m tools.harness_demo --output runs/harness-01.json
```

이 파일에는 열 가지 제어 실험과 같은 12질문의 고정 출력 A/B가 들어간다. 이미 파일이 있으면 덮어쓰지 않고 실패한다. 다시 실행할 때는 `harness-02.json`처럼 새 이름을 쓴다. 기록의 응답은 교사가 정한 고정값이고 실제 모델·유료 API 호출은 없다.

정상 구조 실험부터 읽는다.

```bash
python -m tools.harness_steps --input runs/harness-01.json --scenario valid_shape
```

`--input`은 기록 파일, `--scenario`는 그 파일에서 읽을 실험을 고르는 옵션이다. `valid_shape`는 정상 구조 실험의 실제 이름이다. 첫 단일 식비 예제와 달리 이 기존 실험의 고정 답은 “자료를 확인한 뒤 사람이 사실과 조건을 검토해야 합니다”라는 일반 문장이다. 구조는 맞지만 식비 질문의 충실한 답이라는 뜻은 아니다.

| 사건의 담당 | 현재 사례에서 한 일 | 아직 남는 확인 |
|---|---|---|
| 입력 준비 함수·Harness | 자료 선택·출력 계약·최종 문자 검사 | 입력과 평가 정답의 역할 |
| 고정 응답 Provider | 정해 둔 문자열 반환 | 실제 모델 생성 아님 |
| 검사 함수 | 필드·형식·제공 문서 ID 확인 | 원문의 수치·조건·예외와 의미 대조 |
| 실행기·사람 | 초안 반환과 별도 내용 검토 | 수업/업무 채택·승인 |

위 표를 자신의 말로 채워 제출한다. Trace는 모델의 사고 과정이 아니라 앱이 관찰한 사건임을 설명한다.

## 활동 2. 같은 입력의 재시도와 달라진 보완 입력 비교

다음 두 기록을 차례로 읽는다.

```bash
python -m tools.harness_steps --input runs/harness-01.json --scenario timeout_then_success
python -m tools.harness_steps --input runs/harness-01.json --scenario repair_then_success
```

첫 실험은 시간 초과 뒤 정상 구조이고 두 번째는 `not json` 뒤 정상 구조다. 자연어 설명과 함께 출력되는 실제 실패 이름을 읽는다. 시간 초과는 `ProviderTimeoutError`, 출력 계약 실패는 `OUTPUT_CONTRACT`다.

재시도에서는 두 호출의 입력이 같다. 보완에서는 실패 이름을 알려 주는 문장을 추가하므로 달라진다. 표시 도구의 “첫 입력”과 “직전 호출” 기준을 구분한다. 보완 입력을 다시 재시도할 때는 처음 입력과 달라도 직전 입력과는 같을 수 있다.

다음은 Backend에서 Python 실행기를 열어 입력할 **실행 가능한 Python 코드**다. 보완으로 실제 추가되는 부분만 확인한다. `quit()`으로 실행기를 나올 수 있다.

```python
from app.harness import run_harness
from tools.harness_demo import ScriptedProvider, draft

provider = ScriptedProvider(["not json", draft()])
result = run_harness(provider, "C01")
print(provider.messages[1][len(provider.messages[0]):])
print(result["calls"], result["retries"], result["repairs"])
```

추가된 부분은 실패 이름과 “원래 질문과 자료는 유지하고 출력 계약만 보완하라”는 안내다. 실패한 응답 전문·정답 금액·평가 해설을 되돌려 준 것이 아니다. 두 번째 호출 뒤에도 같은 검사기가 실행됐는지 기록에서 찾는다.

| 구분 | 시작 실패 | 호출 전후 입력 관계 | 시도·재시도·보완 | 실제 확인/미확인 |

## 활동 3. 상한에 도달하거나 보완이 반복될 때

```bash
python -m tools.harness_steps --input runs/harness-01.json --scenario global_three_calls
python -m tools.harness_steps --input runs/harness-01.json --scenario repeated_invalid
```

첫 실험은 시간 초과→형식 오류→정상 구조다. 누적 3회 안에서 재시도 1회와 보완 1회를 사용하고 초안을 반환한다. 두 번째는 형식 실패→보완→다시 실패다. 누적 2회에서 보완 예산 소진으로 끝나고 초안은 없다.

호출 수가 3이 되면 무조건 실패하는 규칙이 아니다. 세 번째 응답을 검사할 수는 있지만 네 번째 호출을 추가하지 않는다. 반대로 총 호출 여유가 남아도 보완 예산을 이미 썼으면 종료할 수 있다. 각 기록의 실제 종료 이유를 읽는다.

| 실험 | 누적 호출 변화 | 재시도/보완 공유 상태 | 마지막 초안 여부 | 멈추거나 반환한 이유 |
|---|---|---|---|---|
| 세 호출의 혼합 실패/통과 | [ ] | [ ] | [ ] | [ ] |
| 보완 후 재실패 | [ ] | [ ] | [ ] | [ ] |

추가로 기록의 `retry_exhausted`와 `upstream_terminal`을 읽을 수 있다. 각각 통신 재시도 소진과 원격 오류 즉시 종료다. 현재 정책이 모든 오류를 똑같이 반복하지 않는 이유를 쓴다.

## 활동 4. 출처 이름과 내용의 판정을 나누기

```bash
python -m tools.harness_steps --input runs/harness-01.json --scenario wrong_fact_shape_passes
python -m tools.harness_steps --input runs/harness-01.json --scenario restricted_citation
```

첫 응답은 식비를 999999원이라고 쓰면서 현행 출장 규정 `DOC-A`를 붙인다. 구조·제공 ID 검사에는 통과하지만 원문의 상한 30,000원과 다르다. 두 번째는 제공하지 않은 제한 문서를 반복 인용해 초안 없이 종료한다.

원문에서 사전 승인·영수증·식사 제공 예외도 함께 읽는다. 출처 이름이 맞다는 이유로 의미를 통과시키지 않는다. 또한 출처 검사 실패가 실제 사용자 인증 체계 구현을 증명하지는 않는다.

## 활동 5. 전체 수와 회귀를 함께 읽기

```bash
python -m tools.harness_steps --input runs/harness-01.json --compare
```

이 비교는 같은 12사례의 고정 출력 A/B다. 구조 통과는 9건→10건, 호출 전 입력 거부는 양쪽 1건이다. 식비·교육비의 구조 실패가 없어지는 대신 첨부 메모 사례에는 승인 필드가 추가되어 실패한다.

개선/회귀는 이 고정 출력의 구조 기준이다. 자료가 충분한데 자료 부족으로 답해도 구조만 통과할 수 있으므로, 모델이나 Prompt의 정답률을 측정한 표로 제출하지 않는다. 최초 구조 검사를 비교하기 위해 이 A/B에는 최대 한 번의 시도와 재시도/보완 0회를 적용했다.

| 비교 항목 | 내 관찰과 판단 |
|---|---|
| 같은 질문·자료·규칙과 바꾼 고정 출력 | [ ] |
| 구조 기준 개선과 회귀 | [질문 이름·전후 결과] |
| 바로 채택하지 않을 이유 | [회귀·내용 검토와 연결] |
| 실제 모델 비교에서 추가할 증거 | [원응답·모델/설정·근거·조건/예외·재시도/보완] |

실제 생성이 준비되면 아래 표를 각 사례의 전후 조건마다 작성한다. 정상 사실 여섯 개와 경계 행동 여섯 개를 나누는 [Prompt 실습](L1.md)의 기준을 이어받는다. 미실행 칸에는 가상 답이나0점을 채우지 않는다.

| 사례·조건·모델/설정 | 최초/보완 구조 | 실제 답 또는 미실행 | 사람의 사실·근거/행동 판정 | 시도·지연·종료 | 채택/보류 이유 |
|---|---|---|---|---|---|
| [같은 사례의 전후 조건] | [ ] | [ ] | [ ] | [ ] | [ ] |

## 활동 6. 승인 위조·시간·취소의 경계 보기

승인됐다는 필드를 넣은 응답을 먼저 읽는다.

```bash
python -m tools.harness_steps --input runs/harness-01.json --scenario forged_approval
```

추가 `approved` 필드는 출력 계약에서 거부된다. 실제 승인이나 외부 작업은 실행하지 않는다. 이 사실을 로그인·승인 저장소·작업 도구를 만들었다는 결과로 바꾸지 않는다.

다음 명령은 **현재 가짜 시계·취소 신호를 주입해 실행기를 실행**한다. 기록 파일을 읽는 명령과 다르다.

```bash
python -m tools.harness_steps --boundaries
```

시간 예에서는 호출 중 시계를 91초로 바꾸고 정상 구조 응답을 돌려준다. 기본 90초 경과시간을 반환 뒤에 확인해 초안을 버린다. 실제로 91초를 기다리거나 실행 중 요청을 강제 중단하지 않는다. 취소 예에서는 호출 중 신호가 설정되어 반환 뒤 취소로 종료한다.

| 경계 | 실제 관찰 | 이 증거만으로 말할 수 없는 것 |
|---|---|---|
| 승인 필드 거부 | [구조 실패·미승인·초안 없음] | [실제 인증/승인 체계] |
| 늦은 응답 | [호출 수·종료 이유·초안] | [벽시계 측정·강제 중단] |
| 취소 신호 | [신호와 반환 후 종료] | [실제 Provider/분산 취소] |

## 오류를 읽고 결과를 제출하기

| 증상 | 확인할 것 |
|---|---|
| `No module named app`/`tools` | Backend 폴더와 가상환경 Python |
| 기존 기록 파일이 있어 생성 실패 | 과거 결과를 지우지 말고 새 파일 이름 사용 |
| 읽기 도구가 파일/실험을 못 찾음 | 실제 저장 경로·실험 이름 확인 |
| 읽기 도구가 고정 응답 기록이 아니라고 거부 | 이 도구는 실제 모델 기록을 고정 실험으로 바꿔 표시하지 않음 |
| 옵션을 함께 쓸 수 없다고 거부 | 파일의 개별 읽기·전체 비교·현재 시계/취소 시연을 각각 실행 |
| Provider의 예상 밖 프로그래밍 오류 | 정상 초안이나 모델 오답으로 포장하지 말고 코드 오류 조사 |

제출은 각 활동의 관찰·판단 표와 강의의 장별 질문 답이다. **고정 응답 실행 / 실제 모델 생성 / 사람의 의미 검토 / 수업 검증** 상태를 따로 적는다. 기본 Trace의 해시는 비교용이며 원문 보관이나 모든 산출물의 민감 내용 처리를 대신하지 않는다.
