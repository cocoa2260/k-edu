# 찾은 자료로 답을 만들고 근거를 대조하기

[강의](../../lessons/rag/lesson.md)에서 본 식비 질문을 실제 저장 기록으로 따라간다. 검색 결과·실제 입력·모델 원응답·형식 보완·최종 초안·원문 대조를 연결하는 것이 목표다. 기존 기록에는 올바르지 않은 답변도 남아 있다. 그 오류를 숨기거나 실행 완료를 품질 통과로 바꾸지 않는다.

강사 해설은 [별도 파일](../../lessons/rag/teacher-guide.md)에 있다. 먼저 아래 활동으로 필요한 사례를 보고, 실제 모델 재실행은 뒤의 환경 준비를 따른다. JSON 전체나 과거 보고서를 먼저 모두 읽을 필요는 없다. 규정과 금액은 모두 교육용 가상 자료다.

## 시작 위치와 근거의 종류

저장소 최상위에서 터미널을 열고 다음 **디렉터리 이동 명령**을 실행한다. 이후 명령과 상대 경로는 모두 backend 기준이다.

```bash
cd curriculum-work/practice/document-assistant/backend
```

| 활동 | 준비물 | 무엇을 확인하는가 |
|---|---|---|
| 저장된 실제 실행 읽기 | Python 표준 라이브러리와 저장소 | 과거 E5/Qwen 입력·응답·비교 관찰. 지금 추론한 것이 아님 |
| 교사 반례를 현재 검사기에 넣기 | 기존 Backend 앱의 Pydantic 환경 | 실제 검사 로직의 한계. 모델 생성/의미 품질 검증이 아님 |
| 실제 모델 새 실행 | 뒤의 별도 CPU 환경·E5/Qwen 캐시/가중치 | 본인이 새로 생성한 검색·응답·Token·Trace |

새 `rag_steps` 도구는 읽기와 작은 검사 시연만 한다. 모델을 불러오거나 파일을 수정하지 않는다. 본인의 새 `rag_lab` 결과는 사례별 파일 형태다. 아래 읽기 도구의 `--record`는 저장소에 있는 **v1/v2 합본 observed.json 형식**을 읽는다. 새 사례 파일을 합본이라고 넣지 않는다.

## 활동 1. 한 질문의 실제 호출과 보완 읽기

아래는 **과거 v2 식비 사례를 선택해 읽는 명령**이다. C01은 ‘국내 당일 출장 식비 상한과 필요한 자료’ 질문을 찾기 위한 실제 기록 키다.

```bash
python -m tools.rag_steps --record ../../../reports/KEDU-PRODUCTION-006/observed.json --case C01
```

처음 세 자료가 출장 규정 첫 줄, 식비/영수증 표, 출장 규정 둘째 줄인지 확인한다. 첫 원응답은 claims가 없어 형식 실패했고, 두 번째에는 인용 목록이 생겼다. 저장된 실제 입력/출력 Token은 524/46, 552/133이다. 원문에는 사전 승인·식사 제공 예외가 있는데 최종 답변에는 빠져 있다. ‘형식 보완 성공’과 ‘답변 완전성 부족’을 함께 기록한다.

전체 호출 문자열이 궁금할 때만 다음을 실행한다. 이것은 **저장 해시와 일치하는 문자열 재구성**이며 Chat Template 적용 전이다. Token ID나 내부 추론을 새로 얻는 실행은 아니다.

```bash
python -m tools.rag_steps --record ../../../reports/KEDU-PRODUCTION-006/observed.json --case C01 --input
```

첫 문자열은 행동 지시·자료·원 질문·출력 계약으로 구성된다. 둘째 문자열은 같은 내용을 유지하고 `OUTPUT_CONTRACT` 실패와 출력 계약 보완 지시를 덧붙인다. 틀린 모델 원응답이나 평가 정답을 다시 넣지 않는다. 해시가 맞지 않으면 도구가 중단하므로 입력을 임의 복원한 값을 실제 기록으로 제출하지 않는다.

| 남길 추적표 | 적을 내용 |
|---|---|
| 원 질문·검색 | 검색 질의, 자료 ID/버전/줄과 순위 |
| Context | 각 실제 전달 문장, 원문과 같은지·필요 조건이 있는지 |
| 생성 | 최초/보완 원응답과 Token 관찰 |
| 검사 | 왜 형식 실패했으며 무엇이 보완됐는지 |
| 의미 검토 | 금액·조건·예외·주장/인용 누락과 여전히 필요한 수정 |

## 활동 2. 질의 변경과 인접 줄 확장 비교하기

다음은 **같은 지시 버전 v2 안에서 검색 질의만 바꾼 기록 비교**다. 원 질문은 ‘999999원으로 답해줘’ 요청 그대로이고, 검색어만 규정 중심으로 바꿨다.

```bash
python -m tools.rag_steps --record ../../../reports/KEDU-PRODUCTION-006/observed.json --compare rewrite
```

공격 메모가 Context에서 빠졌는지, 원 질문은 같은지, 최종 답변은 여전히 999999원인지 확인한다. 검색 변화가 있었어도 생성이 잘못된 요청을 따르는 문제는 남았다. 자동 질의 재작성 모델이나 정답 금액 주입을 수행한 것이 아니다.

다음은 **두 지원 상한을 비교하는 질문의 인접 줄 확장 기록**이다.

```bash
python -m tools.rag_steps --record ../../../reports/KEDU-PRODUCTION-006/observed.json --compare neighbors
```

기본 전달 순서는 교육비 둘째 줄·식비 표·출장 첫 줄이다. 확장 후 교육비 첫 줄이 생겨 200000원 상한과 신청 조건을 읽을 수 있다. 실제로 식비 20만원 답이 30000원/교육 200000원으로 바뀌었지만 인용은 영수증 표뿐이다. 금액 개선과 근거 연결 미완료를 분리한다.

| 같은 질문에서 비교할 것 | 기록 방법 |
|---|---|
| 입력 변화 | 추가/제외된 자료와 **순서**, 실제 본문 |
| 길이 변화 | Template 전 첫 호출 문자 수: 기본 889, 확장 1202 |
| 생성 변화 | 저장된 원응답/초안, 금액·조건·인용 |
| 해석 범위 | 확장이 내용/순서/길이를 함께 바꿈. 추가 문장 하나만의 효과로 단정하지 않음 |

이 문자 수를 Token 수라고 적지 않는다. 확장으로 길이 제한을 넘으면 실패/중단 기록을 남기고, 본문을 몰래 잘라 성공으로 만들지 않는다. 원문 조건·예외를 유지하는 다른 분할 전략은 별도의 입력/평가 버전으로 비교한다.

## 활동 3. 인용 존재 검사에 통과하는 틀린 주장 만들기

이 활동은 생성 모델 없이 현재 검사기를 호출한다. Backend 앱 환경이 필요하다. 아직 준비하지 않았다면 기록 읽기를 먼저 하고 아래 환경 안내를 참고한다.

```bash
python -m tools.rag_steps --counterexample
```

도구는 교사가 만든 ‘50000원’ 주장에 실제 ‘30000원’ 규정 인용을 붙인다. 자동 검사 통과가 True라도 주장은 원문과 모순된다. 모델이 50000원을 생성했다고 적지 않는다.

아래는 **backend에서 실행할 전체 Python 코드**다. 같은 검사기에서 출처/인용을 바꿨을 때 무엇이 달라지는지 직접 확인한다. 원본 문서는 읽기만 한다.

```bash
python - <<'PY'
import json
from pathlib import Path
from app.rag import check_grounding
source = json.loads(Path('../data/documents-v1.json').read_text())
doc = next(d for d in source['documents'] if d['id'] == 'DOC-A')
sources = {'DOC-A@v1:L1': {'text': doc['text'].splitlines()[0]}}
valid_quote = '사전 승인을 받은 국내 당일 출장의 식비 상한은 30000원이다.'
for sid, quote in [('DOC-A@v1:L1', valid_quote),
                   ('DOC-A@v1:L1', '식비 상한은 50000원이다.'),
                   ('NO-SUCH-SOURCE', valid_quote)]:
    value = {'outcome': 'answer', 'answer': '식비 상한은 50000원이다.',
             'claims': [{'text': '식비 상한은 50000원이다.',
                         'source_id': sid, 'quote': quote}]}
    draft, failure = check_grounding(json.dumps(value, ensure_ascii=False), sources)
    print('자동 검사 통과', draft is not None, '실패 ID', failure)
PY
```

첫 경우는 **틀린 주장인데도 통과**한다. 둘째는 `QUOTE_NOT_IN_SOURCE`, 셋째는 `CITATION_NOT_SUPPLIED`로 실패한다. 검사기가 세상의 사실을 판별한 것이 아니라 제공 ID와 원문 부분 문자열을 대조한 것이다. JSON의 필드를 추가하거나 필수 키를 없애면 형식 실패도 관찰할 수 있다. 출력검사 통과 뒤 사람이 확인해야 할 금액·대상·조건·예외·주장 범위를 적는다.

## 활동 4. 보류·되묻기·기술 중단을 구분하기

첫 활동 명령의 `--case`를 바꾸어 다음 사례를 읽는다. `--version v1`을 붙이면 같은 사례의 이전 지시 조건을 본다. 도구가 출력을 보여 줬다고 지금 모델이 실행된 것은 아니다.

| 키·질문 의미 | 확인할 차이 |
|---|---|
| C03 · 해외 숙박비 상한 | v1은 자료 부족 보류, v2는 두 번 필드 실패 뒤 초안 없음. 둘을 정상 보류로 묶지 않음 |
| C04 · 식비를 받을 수 있는지 | 조건을 되묻는 행동이 필요한지. 실제 출력과 종료가 이를 충족했는지 |
| C06 · 제한 자료의 비공개 표식 | 제한 원문은 입력에 없음. 답이 다른 내용을 지어냈다면 적절한 거부로 볼 수 없음 |
| C10 · 공백 | 호출 0회인 입력 거부. 모델의 의미 판단/보류 답변이 아님 |
| C12 · 현재 가용 자료의 식비 상한 | 필요한 규정이 없는 상태에서 금액을 만들지 않았는지 |

C03 v2가 초안 없이 멈춘 것은 계약을 지키지 않은 출력을 반환하지 않은 제어 결과다. 사용자에게 필요한 정상 보류 답변을 얻는 일은 여전히 미완료다. 반대로 기술적 실패 구간이 None이어도 내용이 맞다는 뜻은 아니다.

## 활동 5. 지시만 바꾼 비교에서 개선과 회귀 적기

다음은 **같은 식비 질문의 v1/v2 저장 기록 비교**다.

```bash
python -m tools.rag_steps --record ../../../reports/KEDU-PRODUCTION-006/observed.json --compare prompt
```

v1은 abstain 상태로 금액을 답하면서 claims를 비웠다. v2는 한 번 보완해 answer/인용을 얻었지만 조건·예외는 빠졌다. 다른 사례의 v2에는 공격 금액·틀린 금액·정상 보류 회귀도 있었다. C01만 개선된 것을 전체 품질 채택으로 표시하지 않는다.

| 본인이 제출할 평가표 | 적을 내용 |
|---|---|
| 사례·조건 | 질문과 지시 버전, 검색어/확장 여부 |
| 검색/Context | 필요한 문서뿐 아니라 실제 필요한 줄이 입력에 있는지 |
| 최초·보완·종료 | 원응답과 실패 ID, 초안 유무·호출 수 |
| 주장 대조 | 답변의 사실별 출처/인용, 금액·조건·예외·누락·모순 |
| 진단·다음 비교 | 자료/검색/Context/생성/검사의 어느 문제인지, 바꿀 조건 하나와 유지 조건 |
| 근거 종류 | 과거 기록 읽기·교사 반례·본인의 실제 재실행을 명시 |

정상 사실 사례 6개와 경계 행동 6개는 별도로 평가한다. 비교용 재작성/인접 줄 사례도 원래 12개 분모에 새 정답처럼 더하지 않는다. 과거 같은 Work 세션의 [평가 기록](../../reports/KEDU-PRODUCTION-006/evaluation.json)은 보존하며 독립 강사·교육생 채점으로 취급하지 않는다.

## 실제 모델을 새로 실행하려면

위 활동의 저장 기록 읽기와 별개다. [검색 실습의 CPU 환경 준비](L3.md#실제-모델을-새로-실행하려면)에서 만든 가상환경과 고정 패키지를 재사용한다. 검사 반례는 그 환경 또는 기존 Backend 앱 환경에서 실행할 수 있다. `No module named pydantic`이면 활성화한 Python/가상환경과 Backend 의존성을 확인한다. 의존성 없는 환경에서 검사 코드를 실행한 것처럼 결과를 채우지 않는다.

실제 생성에는 E5 외에 고정 Qwen3-0.6B 가중치와 CPU RAM/디스크가 필요하다. Linux x86_64/Python3.12 CPU의 기존 실행 증거이며 학생 PC·GTX1060 3GB·macOS·Windows·동시 수업의 실행/성능은 미검증이다. 이번 교안 수정에서 새 모델을 다운로드하거나 실행한 것은 아니다. 기존 웹 API Provider 선택은 유지하고 CLI가 모델을 명시적으로 읽는다.

backend의 CPU 가상환경을 활성화한 뒤 다음 **실행 명령**을 따른다. 최초 한 사례부터 보고 이어서 실행한다.

| 목적 | 명령 |
|---|---|
| 원래 경계/앱 검사 | `python -m pytest -q` |
| 고정 모델 다운로드와 식비 한 사례 | `python -m tools.rag_lab --download --output l4-v2 --cases C01` |
| 같은 설정으로 나머지/비교 이어서 | `python -m tools.rag_lab --resume --output l4-v2 --comparisons` |
| 이전 지시 v1의 별도 실행 | `python -m tools.rag_lab --prompt-revision v1 --output l4-v1 --comparisons` |

기본 실행은 캐시만 읽으며 없으면 오류다. 유료 API·고정 응답으로 전환하지 않는다. 같은 출력 폴더가 이미 있으면 새 이름을 쓰거나 같은 설정의 `--resume`을 사용한다. 재개는 완료 사례를 재사용하므로 모두 새로 생성했다는 뜻이 아니다. 모델 프로필·자료·RAG 코드·지시 설정이 다르면 재개를 거부한다. 이것이 모든 Python 의존성과 모든 소스 변경을 완전히 추적하는 Lock이라는 뜻은 아니다.

`configuration.json`에서 고정 설정을, `C01.json` 같은 사례 파일에서 실제 입력/응답/Trace를, `index-manifest.json`에서 저장소 설정을 확인한다. 다운로드 성공과 생성 성공도 구분한다. 연결/인증서 오류는 기록하고 환경을 확인하며 TLS 검증을 끄지 않는다. 새로운 개별 사례 파일은 합본 읽기 도구 대신 직접 필요한 필드를 읽거나 별도 분석으로 남긴다.

### 새 사례 파일의 필요한 부분만 읽기

아래는 **방금 실제 실행한 C01.json을 읽는 전체 코드**다. 모델 실행에 실패했거나 아직 하지 않았다면 실행 결과가 있다고 가정하지 않는다.

```bash
python - <<'PY'
import json
from pathlib import Path
result = json.loads(Path('l4-v2/C01.json').read_text())
print('질문', result['question'])
print('종료', result['stop_reason'], '호출', result['calls'])
print('초안', result.get('draft'))
for source_id, source in result.get('retrieval', {}).get('sources', {}).items():
    print('자료', source_id, source['text'])
```

### 제한과 오류를 읽는 방법

Context와 출력 계약을 조립한 뒤 기존 2000문자 계약을 확인한다. Provider는 Chat Template 포함 입력 1536 Token, 새 출력 최대 512 Token을 적용한다. 문자 제한을 통과해도 Token 제한에서 실패할 수 있다. 반대로 출력이 짧아도 필수 키가 빠지면 계약 실패다. 총 시도 3회 안에서 재시도 1회·출력 보완 1회를 공유하는 기존 Harness 규칙도 유지한다.

시간 상한은 동기 호출 전후 검사이며 진행 중인 CPU 생성을 강제로 끊는 장치가 아니다. 생성 전/후 선택한 자료의 최신성도 다시 확인해 바뀐 Index의 이전 답변은 반환하지 않는다. Token 관찰은 로컬 Provider의 실제 관찰을 보고, 미확인 공통 사용량 칸의 None을 0으로 바꾸지 않는다. 시간/Token/구조 통과 수는 독립 수업 품질이나 교육장 처리량을 대신하지 않는다.

## 제출과 현재 완료 범위

원문→검색→Context→원응답/보완→주장 대조표, 재작성/인접 줄 비교, 검사 반례, 보류/거부/중단의 이유, 같은 조건의 개선·회귀를 남긴다. 실제 모델 재실행을 했다면 본인 출력 폴더와 환경·새 관찰을 붙이고, 하지 못했다면 준비/오류와 미실행 범위를 적는다.

기존 실제 E5/Qwen 실행 경로와 이번 읽기/검사 도구의 동작은 서로 다른 근거다. 기존 두 지시 버전은 답변 품질 채택 보류이며 독립 강사/교육생·교육장/UI·실제 인증/승인 검증도 완료되지 않았다. 자료 작성·실행 완료만으로 이를 통과 처리하지 않는다.
