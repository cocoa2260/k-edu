# 문서를 등록하고 현재 근거로 보고서 준비하기

[문서 입력·상태 강의](<../../01. Phase2_AI/13. Document AI/01. 문서 등록.md>)와 [근거 보고서 강의](<../../01. Phase2_AI/13. Document AI/02. 근거 보고서.md>)를 읽고 진행한다. 아래는 문서 도우미 통합의 앞 세 단원에 해당한다. Provider·React/Streaming·최종 평가 안내는 뒤에 별도로 보존한다.

## 준비와 실제 실행 범위

모든 명령은 `practice/document-assistant/backend`에서 입력한다. Python 3.12의 기존 환경에 `python -m pip install -r requirements-document.txt -r requirements-report.txt`로 고정 PDF·DOCX 의존성을 준비한다. 새 임시 실습에는 모델 Weight·GPU·한글 OCR 데이터·외부 API가 필요 없다.

`tools.document_ai_steps`의 intake/lifecycle/review는 **현재 코드와 원본 자료를 사용하는 실행**이다. 임시 SQLite·TXT를 만들고 끝나면 정리한다. 기존 자료/DB를 덮어쓰지 않고, DOCX/PDF 파일 생성·LLM 호출·독립 승인도 수행하지 않는다. history는 **저장 기록 읽기**다. 실습 전에 무엇이 달라질지 예상하고 실행 뒤 이유를 설명한다.

## 1. 같은 내용과 형식에 맞는 원문 위치

다음은 **실행 명령**이다. 실제 PDF/단순 DOCX와 임시 TXT를 읽어 IR로 바꾸고 검색 문맥을 확인한다. TXT에는 기한 문장·빈 줄·금액 문장이 있다. 금액의 원문 줄 번호가 2일지 3일지 먼저 예상한다.

```bash
python -m tools.document_ai_steps --mode intake
```

현재 예제의 예상 Element 수는 PDF 11/TXT 2/DOCX 16이다. 이 숫자를 외우는 대신 무엇을 센 것인지 본다. PDF는 텍스트 블록과 별도 표, TXT는 비어 있지 않은 원문 줄, DOCX는 본문 문단·표/셀 구조를 보존한다. parse 직후에는 대상 문서의 검색 결과가 0이고 index 뒤에 문맥이 나온다.

TXT 금액의 Locator는 원본 3줄, PDF 영수증 문장은 물리 1쪽의 영역, DOCX 금액은 본문 블록 6의 표 1·행 3·열 3이다. DOCX에 가짜 PDF 페이지를 붙이지 않는다. PDF 문맥에는 두 열의 문장이 합쳐진 한계가 남으며 DOCX 금액 셀도 숫자만 검색했다고 조건/머리글 관계를 이해한 것은 아니다.

원본 파일은 [디지털 PDF](backend/data/document-v1/digital.pdf)와 [단순 DOCX](backend/data/multiformat-v1/policy.docx)다. 현재 DOCX 지원은 단순 문단과 병합 없는 직사각 표의 좁은 범위다. HWP/HWPX는 거부한다. 최초 Registry 실험의 PDF/TXT 두 형식 기록과 이후 추가된 현재 기능을 구분한다. 스캔 OCR는 이 활동에서 실행하지 않는다.

제출은 원본/내부 버전/IR Element/검색 문장/Locator의 연결표와 형식별 지원 한계다.

## 2. 재전송·새 버전·권한·삭제 비교

첫 업로드의 기한은 7일이다. 같은 요청을 다시 보내면 버전이 늘어날지, PC 파일만 14일로 고치면 저장소도 바뀔지 예상한다. 아래는 **실행 명령**이다.

```bash
python -m tools.document_ai_steps --mode lifecycle
```

같은 키·같은 입력은 replayed=True이고 버전 1이다. 호출자가 검색 결과 문장을 ‘변조한 문장’으로 고쳐도 context는 저장된 금액 원문을 가져온다. PC 파일을 14일로 바꿔도 등록 사본은 7일이다. 같은 키로 바뀐 입력을 등록하면 충돌하고, 새 키면 버전 2·uploaded가 된다.

새 버전 등록 직후에는 검색이 비고 옛 문맥은 Stale selection으로 거부된다. parse/index/review를 다시 거친 다음 14일 문장을 확인한다. 권한을 restricted로 바꾸면 검색에서 사라지고 옛 요청 재전송도 거부된다. 삭제 후 DB를 다시 열어도 state=deleted·source=None·ir=None이며 같은 ID를 새 요청으로 등록할 수 없다.

코드가 기록한 현재 상태와 과거 selection의 사용 가능 여부를 나눠 적는다. 삭제는 임시 저장소 안의 자료 제거이며 사용자 PC 원본·백업·외부 사본의 보안 삭제가 아니다. 같은 요청 재전송을 위한 지문과 삭제 흔적은 남는다. staff는 고정 신뢰 측 시연 역할이며 실제 사용자 인증으로 취급하지 않는다.

제출은 재전송/입력 변경/새 버전/제한/삭제/재시작의 버전·상태·검색·옛 문맥 결과와 이유다.

## 3. 인용이 있어도 틀린 주장을 거부하기

원문은 ‘신청 기한 7일’이다. 보고서의 문장을 30일이라고 쓰면서 같은 인용을 달면 어디서 막혀야 할지 예상한다. 아래는 **실행 명령**이다.

```bash
python -m tools.document_ai_steps --mode review
```

문서가 indexed일 때는 보고서 명세를 만들 수 없고 review로 표시한 뒤 prepare가 가능하다. 그러나 이것만으로 출력은 허용되지 않는다. 승인 전 export는 차단되며 최종 폴더 존재는 False다. 이 거부는 실제 출력 함수의 승인 검사에서 일어나고 문서 렌더링은 실행되지 않는다.

7일 인용+30일 주장은 자동 연결 검사로 명세가 만들어질 수 있다. 도구 안의 고정 검토자가 ‘7일 근거는 30일을 지지하지 않음’이라는 이유로 reject를 기록한다. 올바른 7일 명세에는 별도의 approve를 기록하지만 실제 사람의 업무 승인이 아니다. 학생도 원문과 주장·조건을 대조해 결정 이유를 적는다.

승인한 명세의 문장을 바꾸면 내용 해시가 달라 과거 승인과 맞지 않는다. 같은 파일을 새 요청으로 등록해 버전만 늘려도 옛 출처는 무효다. 문서가 review 상태라는 것, 특정 내용의 approve가 있다는 것, 그 내용이 **현재** 원문과 맞는 것은 각각 확인해야 한다.

제출은 7일/30일 주장의 인용·의미 판단, 승인 전/문장 변경/출처 새 버전의 차단 이유다. “자동 검사가 통과해서 승인했다”는 이유로 의미 검토를 대신하지 않는다.

## 4. 과거 출력 파일과 현재 템플릿 구분

아래는 **저장 기록을 읽는 실행 명령**이다. 새 문서 출력·재승인은 아니다.

```bash
python -m tools.document_ai_steps --mode history
```

초기 두 Claim의 명세·검토는 템플릿 v1, 현재 템플릿은 v2다. 저장 내용 해시와 검토 연결이 True여도 과거 명세를 현재 승인으로 쓸 수 있다는 뜻은 아니다. DOCX Locator 지원을 더한 현재 템플릿으로 새 출력하려면 원문에서 명세를 새로 준비하고 검토해야 한다.

[기존 DOCX](backend/data/report-v1/evidence-report.docx)와 [기존 PDF](backend/data/report-v1/evidence-report.pdf)를 열어 주장 두 개·인용·원본 위치·해시를 확인한다. 두 파일은 같은 명세의 내용을 다른 형식으로 출력한 과거 예제다. 픽셀 배치가 동일해야 하는 요구는 없지만 주장의 내용과 근거는 같아야 한다.

DOCX의 문단/XML에 한글이 있어도 화면에서 빠질 수 있다. Word/렌더러가 찾는 Noto Sans KR 또는 호환 글꼴을 확인한다. PDF에는 당시 사용한 글꼴 일부가 들어 있지만 DOCX에는 글꼴을 내장하지 않았다. 내용 검사와 모든 페이지의 화면 대조를 분리한다. 현재 장비에서 렌더링하지 않았다면 과거 화면 확인 기록을 본 것으로만 남긴다.

제출은 한 주장에 대한 문장/인용/위치 연결과 저장·텍스트·화면 검사의 차이, 현재 실행과 과거 관찰의 구분이다. [강사용 해설](<../../01. Phase2_AI/13. Document AI/강사용.md>)을 함께 본다.

## 선택 실행과 출력·검사 경로

아래 표는 **실행할 명령**이다. 모든 output은 새 폴더이며 기존 실험을 덮어쓰지 않는다. registry_lab는 초기 PDF/TXT 순차 실험을 재현하는 도구라 출력의 remaining 문구에는 당시 미구현 사항이 들어 있다. 현재 DOCX 지원 판단은 위 지원 범위와 현재 코드로 한다.

| 목적 | backend에서 입력할 명령 |
|---|---|
| 기존 PDF/TXT 상태 실험을 새 폴더에 저장 | `python -m tools.registry_lab --output l9-registry-new` |
| 현재 상태·요청/삭제 경계 검사 | `python -m unittest discover -s registry_tests -v` |
| 현재 명세·검토/출력 차단 검사 | `python -m unittest discover -s report_tests -v` |
| 실제 DOCX/PDF 출력 | `python -m tools.report_lab --output l9-report-new --font assets-l8-new/NotoSansKR-Regular.ttf` |

실제 출력에는 앞 PDF 실습에서 준비한 글꼴이 필요하다. 없다면 [PDF/OCR 실습의 자산 준비](L8.md)를 따른다. 글꼴 경로를 실제 파일로 맞추고 출력 뒤 DOCX를 렌더링해 모든 페이지를 확인한다. 라이브러리가 저장에 성공했다는 사실만으로 화면을 확인했다고 보고하지 않는다. 단위 검사의 렌더링 실패/중간 삭제는 모의 경계 검사이며 실제 Office/ReportLab 화면 검사와 다르다.

출력 도구는 현재 v2 명세를 준비하고 고정 검토 결정을 기록한다. 이는 로컬 교육용 시연이며 실제 사용자의 승인 절차가 아니다. 생성된 artifacts 아래 document-spec.json은 공통 내용, review.json은 그 내용 해시에 묶인 결정, evidence-report.docx/pdf는 출력이다. 모델 생성 문장과 혼동하지 않는다.

임시 출력 뒤 원문/승인을 다시 확인하고 통과하면 최종 폴더로 옮긴다. 중간 삭제나 변환 실패는 최종 폴더 생성을 막지만 DB/파일시스템의 동시 발행·취소 전체 원자성, 이미 복사한 보고서의 회수까지 구현한 것은 아니다. 실제 인증·동시 Worker·보관/백업/보안 삭제·일반 문서 품질·독립 수업/업무 채택과 기존 모델 품질 보류는 남아 있다.

## Provider 활동: 실패 뒤에도 같은 예산을 적용하기

[Provider 강의](<../../01. Phase2_AI/13. Document AI/03. Provider.md>)를 읽고 시작한다. 아래는 **실행 명령**이다. backend에서 실행하면 임시 폴더와 loopback HTTP 서버를 열어 고정 응답 네 사례를 처리하고 종료한다. 인터넷 모델·유료 API·실제 Tokenizer는 호출하지 않는다.

```bash
python -m tools.delivery_steps --mode provider
```

입력 ‘정책 확인’의 가짜 문자 단위 수는 5, 최대 출력 여유는 16이다. 실행 전에 정상 대체에 필요한 예약과 41 한도에서 backup이 호출될지 예상한다. 출력에서 판정 순서·calls·reserved_tokens를 확인한다.

| 사례 | 예상 최종 상태 | 실제 HTTP 호출/예약 | 관찰할 이유 |
|---|---|---:|---|
| 주 경로 503 뒤 backup | completed | 2 / 42 | temporary_failure 뒤 completed |
| Vision 요청 | all_unavailable | 0 / 0 | text 기능만 선언돼 호출하지 않음 |
| 공유 호출 한도 1 | budget_exhausted | 1 / 21 | 실패 뒤에도 호출 수를 돌려주지 않음 |
| 공유 예약 한도 41 | budget_exhausted | 1 / 21 | 두 번째 21을 예약할 수 없음 |

네 사례의 실제 로컬 HTTP 요청 합계는 4다. 실패 응답의 실제 사용량을 모른다고 예약을 0으로 지우지 않는다. 문자 단위 Fixture는 모델 Token·청구액이 아니다. Context 초과·권한/범위·ready 관찰·출력 상한·늦은 응답도 다른 판정으로 구분한다. 별도 Router/HF 어댑터는 기존 FastAPI Factory를 자동 전환하지 않는다.

제출은 네 사례의 상태/호출/예약/Trace와 ‘Context 20·전체 예약 100’, ‘Context 100·전체 예약 41’의 차이다. Timeout은 동기 호출 전후 검사이며 강제 계산 중단과 다르다.

## Streaming 활동: final이 없는 답변 확정하지 않기

[Streaming 강의](<../../01. Phase2_AI/13. Document AI/04. Streaming.md>)의 이벤트 예를 본다. 아래는 stream-ui 폴더에서 실행하는 **완전한 코드**다. 네트워크 대신 메모리 Response를 만들고 각 바이트를 따로 전달한다. 현재 공통 consume 함수를 사용하지만 React 화면/실제 TCP·모델 생성 시험은 아니다.

```bash
node --input-type=module <<'JS'
import {consume} from './src/stream.mjs';
const id='demo', text='신청 기한은 7일';
const frame=(event,seq,extra)=>`event: ${event}\ndata: ${JSON.stringify({id,seq,...extra})}\n\n`;
const prefix=frame('start',0,{fixture:true})+frame('delta',1,{text});
for(const complete of [true,false]) {
  const bytes=new TextEncoder().encode(prefix+(complete?frame('final',2,{status:'completed',answer:text}):''));
  const body=new ReadableStream({start(controller){
    for(const byte of bytes)controller.enqueue(Uint8Array.of(byte));
    controller.close();
  }});
  const response=new Response(body,{headers:{'Content-Type':'text/event-stream'}});
  let last;
  try {
    const result=await consume(response,id,state=>{last=state;});
    console.log('final 있음:',result.phase,result.answer);
  } catch(error) {
    console.log('final 없음:',error.message,'부분:',last.draft,'확정:',last.answer);
  }
}
JS
```

예상 출력은 final이 있을 때 completed/7일 문장, 없을 때 missing_final/부분 문장/확정 null이다. 한글의 바이트를 나누어도 올바르게 합쳐야 하며 정상 SSE 프레임이 와도 최종 판정이 없으면 실패다. 한글 바이트·SSE 이벤트·모델 Token의 단위를 구분해 설명한다.

이제 [화면 실행 안내](stream-ui/README.md)의 정확한 명령으로 UI를 빌드하고 서버를 실행한다. 정상/오류/중간 종료/기능 미지원/시간 한도/느린 취소를 선택해 화면의 부분 문장·상태·확정 answer를 대조한다. 아래는 서버를 backend에서 실행할 **명령**이며 UI 빌드를 먼저 마쳐야 한다.

```bash
python -m tools.stream_lab --ui ../stream-ui/dist --port 8765
```

서버가 켜진 상태에서 http://127.0.0.1:8765 를 연다. 종료는 해당 터미널에서 Ctrl+C다. 실행 버튼을 누르면 완성된 고정 답변을 나누어 전송한다. 모델의 실시간 Token 생성·실제 인증·운영 Proxy 경로가 아니다.

부분 문장이 보이는 동안 취소하고 곧 정상 실행을 시작한다. 이전 취소 접수가 새 성공 화면을 덮어쓰지 않아야 한다. 서버 접수는 실제 모델 강제 중단과 구분한다. 한글이 네모로 보이면 브라우저가 사용하는 한글 지원 글꼴을 확인한다. DOM 문자열/자동 상태 검사만 통과한 상태를 화면 검수 통과로 표시하지 않는다.

과거 실제 Chromium 기록은 backend에서 다음 **명령**으로 읽을 수 있다. 지금 본인이 브라우저를 실행한 결과와 구분한다.

```bash
python -m tools.delivery_steps --mode history
```

저장된 서버 기록의 Router completed와 전송 failed/truncated/deadline_exceeded가 함께 존재한다. 생성 경로가 완료돼도 전송·화면은 실패할 수 있음을 설명한다. 제출은 서버 Router/전송 판정·화면 상태·확정 답변 유무와 취소 후 재실행의 ID/세대 이유다.

## 최종 평가 활동: 세 형식의 통과 범위와 채택 보류

[최종 평가 강의](<../../01. Phase2_AI/13. Document AI/05. 최종 평가.md>)를 읽고 backend에서 아래 **명령**을 실행한다. 저장된 PDF·TXT·DOCX를 현재 Registry/IR로 처리하고 세 주장/인용의 고정 검토 뒤 DOCX 권한 변경에 대한 재출력 차단을 확인한다. 임시 SQLite를 쓰며 새 DOCX/PDF 파일은 생성하지 않는다.

```bash
python -m tools.delivery_steps --mode formats
```

원본 해시가 맞아야 진행한다. 예상 Element/표 수는 PDF 11/1, TXT 5/0, DOCX 16/1이고 PDF/DOCX 표의 9셀 값이 정답과 같다. 앞 입력 활동의 임시 TXT 2개 Element와 이번 저장된 TXT 5개 Element는 입력 내용이 다르다. 모순된 집계라고 합치지 않는다.

DOCX 금액은 표 1·행 3·열 3이다. 원본에서 사용 이력/부담금 관계까지 확인한다. 세 주장/인용을 준비한 고정 approve는 독립 업무 승인이 아니다. 이후 DOCX를 restricted로 바꾸면 같은 명세의 출력 승인은 거부된다. 이미 생성/복사된 파일의 자동 회수와는 다른 기능이다.

| 평가할 항목 | 이번에 제출할 근거 | 남겨야 할 제한 |
|---|---|---|
| 형식·추출·위치 | 세 형식의 Element/표·원문 Locator | 좁은 합성 자료와 미지원 구조 |
| 의미와 검토 | 문장·인용·행/조건 대조 이유 | 고정 검토, 독립 의미 채점 아님 |
| 변경 이후 | restricted 뒤 과거 명세 거부 | 발행물 회수/실제 인증 미구현 |
| 시간·비용 | 원본/측정 조건·실행 여부 | 단일 파일 우열 금지, Token/청구액 미측정 |
| 최종 채택 | 통과/보류/미실행을 항목별 기록 | 일반 문서·실제 모델·독립 수업 별도 |

실제 파일 생성까지 확인하려면 새 output과 기존 한글 글꼴을 사용해 `python -m tools.multiformat_lab --output l9-three-new --font assets-l8-new/NotoSansKR-Regular.ttf`를 실행한다. 별도의 선택 과제이며 현재 실습 명령만으로 출력/화면을 확인했다고 쓰지 않는다. 생성 뒤 DOCX 렌더링과 PDF의 모든 페이지를 내용/화면으로 대조한다. 원본 재생성은 필수가 아니며 저장된 자료 해시를 기준으로 한다.

최종 제출에는 채택 보류의 구체적인 이유를 쓴다. 합성 소프트웨어 계약·실제 모델/Agent 품질·일반 OCR/복잡한 표·운영 연결·독립 강사/교육생 장비는 서로 다른 게이트다. 초안 작성 수와 현재 설명 정비 수는 [제작 현황](https://github.com/cocoa2260/k-edu/blob/work/curriculum-production-001/curriculum-work/PROGRESS.md)을 따른다. 과거 실험 보고서의 미작성 16개 같은 당시 상태를 현재 미완료 집계로 복사하지 않는다.

## 실행 검사 경로와 근거 구분

아래 표는 **검사 명령**이다. Python은 backend, Node는 stream-ui에서 실행한다. 서버 실행·실제 화면 관찰은 그와 별도로 진행한다.

| 위치 | 명령 | 범위 |
|---|---|---|
| backend | `python -m unittest discover -s router_tests -v` | 기능·준비·Context/예산·취소/오류·HF 가짜 어댑터 |
| backend | `python -m unittest discover -s stream_tests -v` | 실제 loopback HTTP/SSE 계약·취소 |
| backend | `python -m unittest discover -s multiformat_tests -v` | 좁은 DOCX 입력/미지원 구조·현재성 |
| stream-ui | `npm test` | UTF-8/SSE/앱 상태·메모리 수신 |
| stream-ui | `npm run build` | 고정 React 프로젝트 빌드 |

브라우저 자동 검사는 [화면 안내](stream-ui/README.md)의 Playwright/실행 파일 준비와 정확한 CLI를 따른다. 고정 응답 제어가 통과해도 실제 모델 Token Streaming·강제 중단·실제 인증/조직 권한·운영 배포/동시 사용자·독립 수업은 검증한 것이 아니다. [강사용 해설](<../../01. Phase2_AI/13. Document AI/수업 운영 안내.md>)에서 각 활동의 판단 근거를 확인한다.
