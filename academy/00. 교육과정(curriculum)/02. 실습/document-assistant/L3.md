# 질문으로 문서를 찾고 검색 결과를 검토하기

[Embedding 강의](<../../01. Phase2_AI/06. 임베딩(Embedding)/강의용.md>)에서 배운 숫자 표현을 같은 가상 규정과 질문으로 관찰한다. 목표는 도구를 한 번 실행하는 것이 아니라 **무엇을 비교했는지, 필요한 자료와 문장을 찾았는지, 이 결과로 어디까지 판단할 수 있는지 설명하는 것**이다. 앞에서 제공할 자료를 사람이 골랐다면 이번에는 검색기가 후보를 고른다. 아직 답변 생성 모델에는 보내지 않는다.

Embedding 활동을 먼저 진행한 뒤 [Index 운영 강의](<../../01. Phase2_AI/07. 벡터 데이터베이스(VectorDB)/강의용.md>)를 읽고 아래 Index 경계·선택 실습으로 넘어간다. 교사 해설은 [별도 파일](<../../01. Phase2_AI/06. 임베딩(Embedding)/강사용.md>)에 있다.

## 시작 위치와 두 가지 실행

저장소 최상위에서 터미널을 열고 아래 **디렉터리 이동 명령**을 입력한다. 이후 상대 경로와 명령은 모두 이 backend 폴더 기준이다.

```bash
cd "academy/00. 교육과정(curriculum)/02. 실습/document-assistant/backend"
```

| 지금 할 일 | 필요한 것 | 얻는 근거 |
|---|---|---|
| 계산·분절 관찰·저장된 기록 읽기 | Python 표준 라이브러리와 저장소 파일 | 지금 실행한 작은 계산/분절, 또는 과거 모델 결과의 해석 |
| 실제 검색 모델을 다시 실행하기 | 뒤의 별도 CPU 환경과 모델 파일 | 본인이 새로 만든 Embedding·검색·Index 변경 기록 |

기록을 읽는 도구가 출력했다고 지금 모델을 실행한 것은 아니다. 아래 도구는 모델을 불러오거나 다운로드하지 않는다. 저장된 실제 검색 기록은 보존하고, 새 모델 실행 결과는 새 폴더에 만든다. 출장 식비·교육비 금액은 모두 교육용 가상 규정이다.

## Embedding 활동

### 활동 1. 손계산과 실행값을 맞춰 보기

먼저 강의의 q=(1,0), A=(0.8,0.6), B=(2,2)에 대해 내적과 Cosine에서 누가 먼저일지 예상한다. 마스크 평균 `(0.5,1)`과 RRF의 B→A→C도 손으로 구해 둔다. 아래는 **작은 계산 도구 실행 명령**이다.

```bash
python -m tools.embedding_steps --math
```

출력의 `evidence_kind`는 가상 계산임을 표시한다. `vectors`에는 후보별 원래 길이·내적·Cosine·L2와 정규화 후 값이 있다. `masked_mean`은 패딩을 제외한 평균이고 `rrf_scores`는 세 후보의 전체 순위를 합친 값이다. 각각 강의의 계산표와 대조한다.

| 관찰할 것 | 결과를 설명하는 문장 |
|---|---|
| B의 내적은 2, A는 0.8 | 원래 길이가 다른 벡터의 내적에는 길이 영향이 있다 |
| A의 Cosine은 0.8, B는 약 0.7071 | 길이를 나누면 이번 예제의 순위가 바뀐다 |
| A의 정규화 후 제곱 거리는 0.4 | 단위 벡터에서 2−2×Cosine과 일치한다 |
| 평균은 (0.5,1), 단위 표현은 약 (0.4472,0.8944) | 패딩 값은 평균에 들어가지 않는다 |
| RRF 순서는 B→A→C | 원점수 합산이나 학습된 Reranker가 아니다 |

추가로 B를 `(20,20)`으로 바꾸었을 때를 강의의 전체 Python 예제에서 계산한다. 바꾼 입력을 기록하고 내적은 커져도 Cosine은 같은지 확인한다. 실제 문서의 E5 벡터를 이 가상 값으로 대체하지 않는다.

### 활동 2. ‘밥값’ 질문에서 실제로 일치한 글자 찾기

아래 명령은 현재 분절 함수를 호출해 도입 질문과 각 조각의 **일치 어휘**를 보여 준다. Dense 검색을 실행하지는 않는다.

```bash
python -m tools.embedding_steps --lexical
```

질문은 ‘회사, 일로, 당일, 다녀오고, 밥값, 돌려받는, 한도는’으로 나뉜다. 출장 규정 첫 줄의 `matching_terms`에는 ‘당일’만 나온다. `["당일"]`은 실제 일치 항목 목록이며 동의어 목록이 아니다.

다음은 **backend에서 실행할 전체 Python 코드**다. 단어를 조금 바꾼 경우와 조사 차이를 관찰한다. 이 작은 문자열은 현재 문서를 덮어쓰지 않는다.

```bash
python - <<'PY'
from retrieval.index import terms, bm25_scores
texts = ['국내 당일 출장 식비 상한은 30000원이다.', '교육비를 지원한다.']
for question in ['밥값', '당일 밥값', '교육비', '교육비를']:
    print(question, terms(question), [round(x, 4) for x in bm25_scores(question, texts)])
PY
```

‘밥값’은 두 문장과 일치하는 항목이 없어 두 점수가 0이다. ‘당일 밥값’은 첫 문장의 ‘당일’ 덕분에 양수가 된다. ‘교육비’는 0이지만 ‘교육비를’은 둘째 문장에 양수가 생긴다. 이것은 이번 단순 분절기의 특성이다. 이 결과를 Dense의 성공이나 모든 BM25 시스템의 한국어 한계로 일반화하지 않는다.

### 활동 3. 같은 질문의 저장된 실제 검색 비교하기

먼저 아래 명령으로 **과거 실제 CPU 검색 기록**의 요약을 읽는다. 도구가 파일을 읽는 것이며 새 모델 실행은 아니다. `--case C08`은 도입의 ‘밥값’ 질문을 저장 자료에서 선택하는 실제 키다.

```bash
python -m tools.embedding_steps --record ../../../reports/KEDU-PRODUCTION-005/retrieval-observed.json
python -m tools.embedding_steps --record ../../../reports/KEDU-PRODUCTION-005/retrieval-observed.json --case C08
```

BM25는 출장 규정 첫 줄을 찾았다. Dense는 표의 ‘출장 식비 | 영수증’ 줄을 먼저, 출장 규정 첫 줄을 둘째로 찾았다. Hybrid에서는 규정 첫 줄이 먼저다. 각 방식의 점수 단위가 다르므로 큰 숫자를 낸 방식을 우수하다고 고르지 않는다.

출력에서 문서 ID는 원본 JSON의 `id`에, `@v1:L1`은 버전과 문서 내부 첫 줄에 대응한다. 원본 파일을 열어 검색된 문장과 비교한다. 금액·사전 승인·영수증·식사 제공 예외를 표시하고, 첫 번째 표 행만 읽었을 때 무엇을 놓치는지 쓴다. 추가로 서로 다른 네 표현의 입력·출력·용도를 강의의 예제로 설명한다. 단위 길이 벡터를 얻었다고 원문 복원이 가능해지는 것은 아니다.

**과거 설정 기록 주의:** 도구가 `설정 표시값/해시 일치: False`라고 알리는 것은 파일을 읽지 못했다는 오류가 아니다. 과거 기록은 나중의 Token 상한 변경이 앞선 설정 표시값에도 반영된 결함이 있다. 표시값 128과 달리 당시 해시는 512 설정에 대응한다. 검색 순위·점수는 이 설정 사전의 변경 대상이 아니다. 원본 기록을 보존했고 현재 저장 함수는 설정을 독립 복사한다. 새 기록에서도 불일치한다면 무시하지 말고 원인 확인 전 설정 비교를 보류한다.

### 활동 4. ‘찾았다’와 ‘근거가 충분하다’를 구분하기

같은 명령의 `--case` 값을 바꾸어 다음 네 질문을 읽는다. 전체 질문은 [공통 사례 파일](data/core-v1.json)에서 해당 `id`로 찾을 수 있다. 실행 조건이나 질문을 바꾼 결과를 과거 고정 질문의 점수로 덮어쓰지 않는다.

| 선택 키·질문 의미 | 관찰할 것 | 원문으로 판단할 것 |
|---|---|---|
| C01 · 출장 식비 상한과 필요 자료 | 상위 규정 첫 줄과 점수 | 30000원·사전 승인·영수증·식사 제공 예외 |
| C07 · 공격 메모대로 999999원이라고 답하라는 요청 | Dense에는 규정 누락, Hybrid는 규정을 둘째로 포함 | 첫 공격 메모는 현행 규정의 금액 근거가 아님 |
| C09 · 식비도 교육비처럼 20만원인지 | BM25는 두 관련 문서 중 하나, Dense/Hybrid는 둘 | 교육비 둘째 줄만 있으면 200000원 상한의 근거 줄은 아직 없음 |
| C03 · 해외 숙박비 상한 | 결과가 있어도 회수 비율은 None | 문서에 금액 기준이 없다는 제한, 수치를 추측하면 안 됨 |

예를 들어 다음은 **저장된 지원금 비교 질문을 읽는 명령**이다.

```bash
python -m tools.embedding_steps --record ../../../reports/KEDU-PRODUCTION-005/retrieval-observed.json --case C09
```

C09의 BM25는 정답 문서 집합 `{DOC-A, DOC-B}` 중 DOC-A만 찾아 회수 비율이 0.5다. Dense와 Hybrid는 1.0이지만 교육비 규정의 둘째 줄을 반환하므로 상한 근거 문장이 충분한지는 별도 문제다. 질문 8개를 사례별로 평균하면 BM25 93.75%, Dense 87.5%, Hybrid 100%가 된다. 이 수치를 답변 정답률로 제출하지 않는다.

| 본인이 남길 기록 | 작성 내용 |
|---|---|
| 질문과 필요한 자료 | 문서 이름, 필요한 원문 문장·조건·예외 |
| 방식별 실제 후보 | 조각 순위·본문·원문 ID/버전/줄, 누락 |
| 문서 회수 계산 | 관련 문서 수를 분모로, 중복 조각은 같은 문서로 계산 |
| 의미와 지시 판단 | 비슷한 공격문·조건 누락·기준 없음이 남는 이유 |
| 근거 종류 | 저장 기록 읽기 / 본인의 새 모델 실행 / 작은 가상 계산을 명시 |

### 활동 5. 표현 설정을 확인하고 교체 계획 세우기

[인코더](backend/retrieval/encoder.py)와 강의의 핵심 발췌를 대조해 접두어→문맥 표현→패딩 제외 평균→단위 정규화의 순서를 설명한다. 실제 384차원 벡터의 특정 축을 ‘식비 비율’처럼 이름 붙이지 않는다. 준비된 모델이 없다면 실제 Token ID나 Dense 출력값을 만들어 채우지 않는다.

다른 모델로 바꾼다고 가정하고 현재 설정 보존→새 문서 벡터/Index 준비→같은 질문 평가→필터·변경/삭제 회귀→전환/복구 계획을 쓴다. 같은 차원이라는 사실만으로 호환성을 판정하지 않는다. RRF의 작은 계산과 달리 학습된 Reranker 비교는 이 실습에서 수행하지 않는다. 계획을 작성한 것을 모델 전환 성공으로 표시하지 않는다.

## 실제 모델을 새로 실행하려면

앞의 활동에서 저장 기록을 읽은 것과 별개다. 여기서는 실제 검색용 모델을 CPU에서 실행하며 답변 생성·유료 API 호출은 하지 않는다. 기존 제작 기록은 Linux x86_64 / Python 3.12 CPU 환경의 실행이며, 이번 교안 수정에서 모델을 새로 내려받아 재실행한 것은 아니다. GTX 1060 3GB·Windows·macOS·교육장 동시 실행은 검증하지 않았다.

backend 폴더에서 별도 가상환경을 만들고 활성화한다. 기존 앱 환경을 덮어쓸 필요는 없다. 다음은 **Linux 셸 명령**이다.

```bash
python -m venv .venv-retrieval
source .venv-retrieval/bin/activate
```

모델 파일과 CPU 패키지를 내려받을 디스크·네트워크가 필요하다. 모델은 약 1.18억 Parameter라 다운로드 없이 즉시 실행되는 데모가 아니다. 아래 명령은 기존 Linux CPU 실행 기준이며 다른 플랫폼은 그 환경에 맞는 설치 방법을 확인해야 한다.

| 목적 | 터미널 명령 |
|---|---|
| Linux CPU PyTorch 설치 | `python -m pip install torch==2.15.0+cpu --index-url https://download.pytorch.org/whl/cpu` |
| 앱과 검색 의존성 설치 | `python -m pip install -r requirements-retrieval.txt` |
| 기존 경계·앱 회귀 검사 | `python -m pytest -q` |
| 이번 설정 기록 회귀 검사 | `python -m unittest discover -s embedding_tests -v` |
| 최초 고정 모델 다운로드와 검색 | `python -m tools.retrieval_lab --download --output l3-run-01` |
| 캐시만 사용한 별도 실행 | `python -m tools.retrieval_lab --output l3-run-02` |
| 본인의 새 결과 읽기 | `python -m tools.embedding_steps --record l3-run-01/observed.json --case C08` |

출력 폴더가 이미 있으면 덮어쓰지 않는다. 같은 이름 오류라면 새 폴더 이름을 정한다. 캐시가 준비되지 않은 기본 실행은 실패하며 고정 응답으로 바꾸지 않는다. 연결·인증서 문제는 오류를 기록하고 환경을 확인한다. TLS 검증을 끄지 않는다. `No module named ...`이면 현재 가상환경과 설치 명령을 확인하고, Token 상한 초과면 원문과 분할 방식을 확인한다. 실패한 실행을 검색 결과가 없는 정상 실행으로 기록하지 않는다.

새로 생성한 `observed.json`의 설정 표시값과 해시는 일치해야 한다. 현재 코드에서는 변경 전 설정이 512로 보존되고 새 Index의 설정은 128이다. 이것은 동일 모델의 Token 상한 변경 검사이며 다른 가중치 모델의 품질 비교가 아니다.

## 실행 폴더에서 볼 것

| 파일·항목 | 역할 | 먼저 볼 부분 |
|---|---|---|
| observed.json의 metrics | 검색 평가 요약 | 방식별 8개 사례의 문서 회수 비율 |
| observed.json의 cases | 같은 12개 사례 × 3개 방식 | 질문별 상위 조각과 필요한 근거 문장 |
| manifest_before_mutation | 최초 자료·모델·Chunk 설정 | 11 Chunk, 기본 적격 9 Chunk; 과거 파일의 설정 불일치 주의 |
| lifecycle | 실제 갱신·삭제와 오래된 선택 거부 | Context의 버전과 삭제 후 ID |
| migration | 설정 변경·재사용 거부·새 Index | 512 → 128 Token 상한 변경 |
| index.sqlite | 갱신·삭제 실험 뒤 저장소 | 마지막에는 DOC-A가 삭제됨 |
| rebuilt.sqlite | 원본 v1 자료로 새로 만든 저장소 | 새 설정, 원본 DOC-A 다시 존재 |

index.sqlite가 마지막 삭제 상태인 것은 정상이다. 최초 검색 결과와 삭제 후 저장소를 같은 시점으로 취급하지 않는다. 원본 documents-v1.json은 변경하지 않는다. 갱신 시험값 35000원을 원본 규정이나 모델 답변으로 표시하지 않는다.

검색 입력에는 질문과 적격 문서만 전달하고 [교사용 정답 문서 ID](data/retrieval-v1.json)는 결과 평가에만 쓴다. Context 준비는 검색된 조각을 다시 읽는 단계까지이며, 여기서는 생성 모델에 보내지 않는다. 기존 /ai/chat·/ai/prepare도 변경하지 않았다. 생성까지 연결하는 실습은 다음 RAG 수업에서 진행한다.

기본 검색의 나머지 경계도 구분해 확인한다. C06은 제한 자료 배제, C10은 공백 입력의 인코딩 전 거부, C12는 가용 목록에 없는 출장 규정 배제다. C12는 실제 저장소에서 문서를 삭제하는 실험과 별개다. 같은 문서의 여러 조각이 상위를 차지할 수 있고, 문서 중복 제한이나 Reranker를 붙인다면 별도 비교 실험으로 남긴다.

## Index 활동

[저장과 탐색 강의](<../../01. Phase2_AI/07. 벡터 데이터베이스(VectorDB)/강의용.md>)를 읽은 뒤 이어서 진행한다. 시작 위치는 앞과 같은 backend 폴더다. 아래 새 관찰 도구는 Python 표준 라이브러리만 사용한다. **계산/가상 탐색, 고정 벡터를 넣은 실제 SQLite, 저장된 실제 E5/FAISS 실행 기록, 학생의 새 모델 실행을 구분**한다. 도구가 요약을 보여 주므로 처음부터 긴 JSON 전체를 읽을 필요는 없다.

### 활동 1. 검색 조각에서 원문으로 돌아가기

먼저 실제 식비 질문의 과거 결과를 읽는다. 다음은 **저장된 E5 검색 기록의 선택 명령**이며 새 추론이 아니다.

```bash
python -m tools.embedding_steps --record ../../../reports/KEDU-PRODUCTION-005/retrieval-observed.json --case C01
```

첫 결과 `DOC-A@v1:L1`을 원본 `data/documents-v1.json`의 DOC-A 첫 줄과 대조한다. 내부 줄1과 JSON 파일의 물리적 행을 구분한다. 제목과 줄 본문은 함께 인코딩했지만 결과 본문은 줄 자체다.

아래는 **backend에서 실행할 전체 Python 코드**다. 원본을 읽기만 하며 문서 전체 본문의 해시와 첫 두 줄을 출력한다. Tokenizer·모델을 호출하지 않는다.

```bash
python - <<'PY'
import hashlib
import json
from pathlib import Path
source = json.loads(Path('../data/documents-v1.json').read_text())
doc = next(d for d in source['documents'] if d['id'] == 'DOC-A')
print('문서', doc['id'], '버전', doc['version'])
print('전체 본문 해시', hashlib.sha256(doc['text'].encode()).hexdigest())
for number, line in enumerate(doc['text'].splitlines(), 1):
    print('내부 줄', number, line)
PY
```

해시는 강의 JSON의 `0604aeac…`와 일치한다. 해시가 맞아도 가상 규정의 진실성이나 발행자를 인증한 것은 아니다. 본문·벡터·ID/버전·접근/현행·표현 설정이 각각 어떤 질문에 답하는지 표로 쓴다. 벡터만 남기면 어떤 정보를 잃는지도 설명한다.

### 활동 2. 같은 다섯 점을 전부 비교하거나 일부만 보기

질의 (0,0), A=(4,0), B=(3,0), C=(0,1), D=(2,2), E=(6,0)을 종이에 적는다. 먼저 상위 두 점을 예상한다. 아래 명령은 **직접 정한 좌표의 L2 계산과 단순 탐색 시연**이다. 실제 HNSW/FAISS를 실행하지 않는다.

```bash
python -m tools.index_steps --toy
```

첫 부분은 C→D→B→A→E 순서로 거리 1, 약2.8284, 3, 4, 6을 보여 준다. Exact 기준 상위 둘은 C·D다. 구역 U만 보면 D·B이므로 겹친 이웃은 D 하나, 회수율은 1/2다. 질문의 정답 문서를 50% 찾았다는 뜻이 아니다.

전체 계산을 남기려면 **새 파일**을 지정한다. 같은 파일이 있으면 덮어쓰지 않으므로 다음 이름을 사용한다.

```bash
python -m tools.index_steps --toy --output index-toy-01.json
```

### 활동 3. 그래프와 구역에서 놓친 지점을 설명하기

같은 출력에서 세 부분을 읽고 강의 그림과 연결한다.

| 출력 | 손으로 확인할 것 |
|---|---|
| 좁은 이웃 이동 A→B | A의 이웃 중 B가 당장 더 가깝지만 B에서는 더 가까운 이웃이 없어 멈춤 |
| 후보를 남긴 A→B→E→D→C | 당장 멀었던 E를 남겼기 때문에 D·C로 이어질 길이 생김. 이 확장 규칙은 실제 HNSW가 아님 |
| 가상 윗층 A→D, 아랫층 D→C | 윗층의 연결이 출발 지점을 바꾸는 역할. 실제 구축 결과가 아님 |

추가로 B—C 연결을 그렸다고 가정해 좁은 이웃 이동을 다시 설명한다. A→B→C가 가능하다. 직접 연결을 하나 추가한 설명이므로 M 변경의 실제 성능 실험으로 제출하지 않는다.

구역 중심 U=(3,0), V=(0,4)도 손으로 대조한다. C는 U까지 √10, V까지3이므로 V에 들어간다. 질의는 U 중심까지3, V까지4여서 U를 먼저 고른다. 이 차이가 ‘가까운 구역 하나를 찾으면 가장 가까운 점도 반드시 있다’는 생각의 반례다. 두 구역을 모두 보았을 때 C·D가 복구되는지 확인한다. nprobe와 임베딩 모델 교체의 역할도 각각 한 문장으로 쓴다.

### 활동 4. 실제 SQLite에서 갱신·삭제·재구축 관찰하기

다음은 **기존 LocalIndex를 실제 임시 SQLite에서 실행하는 명령**이다. 학습된 E5 대신 모든 입력에 같은 `(1,0)`을 돌려주는 고정 인코더를 사용하므로 의미 검색·모델의 금액 이해를 검증하지 않는다. 실제 인증·강제 중단도 없다.

```bash
python -m tools.index_steps --lifecycle --output index-lifecycle-01.json
```

화면에는 단계별 요약과 실제 선택한 첫 줄이 나온다. 임시 DB는 관찰 후 제거되고, `--output`으로 만든 JSON은 남는다. 원본 규정 파일을 수정하지 않는다. 실제 모델 실습의 `index.sqlite`를 열어 수정하는 명령도 아니다.

| 순서 | 이번 명령에서 확인할 값 | 해석 |
|---|---|---|
| 처음 | 변경 번호6, 전체11조각, 기본 적격9조각 | 6문서 저장 후 상태. 이전 규정·제한 자료는 검색에서 제외 |
| 본문 위조 | 원문 재조회 True | 결과 `text`만 바꾸어도 Context는 저장소 본문을 다시 읽음 |
| 갱신 | 번호7, 10조각, 이전 선택 거부 True | 출장 규정2줄을 v2 시험용1줄로 바꿈. 새 Context는35000원 |
| 삭제 | 번호8, 9조각, 이전 선택 거부 True, 출장 규정 벡터0 | 문서 본문/제목/해시 비움, 삭제 표식은 남음 |
| 설정 변경 | 재사용 거부 True | 고정 인코더 설정512→128의 호환성 검사, 실제 Token 길이 제한 실행은 아님 |
| 재구축 | 새 저장소11조각, 원본v1/30000원 | 원본 입력으로 다시 만들었으므로 삭제했던 자료가 복귀 |

아래는 **방금 만든 JSON에서 필요한 부분만 읽는 전체 코드**다. 먼저 위 명령을 완료해야 한다.

```bash
python - <<'PY'
import json
from pathlib import Path
record = json.loads(Path('index-lifecycle-01.json').read_text())
for name in ['manifest_before', 'manifest_after_update', 'manifest_after_delete']:
    m = record[name]
    print(name, '변경 번호', m['generation'], '조각 수', m['total_chunks'])
print('삭제 표식', record['tombstone']['deleted'])
print('남은 출장 규정 벡터', record['remaining_DOC_A_vectors'])
print('원본 파일 보존', record['original_source_unchanged'])
PY
```

삭제 뒤 결과에서 출장 규정이 없는 것, SQLite 필드/벡터가 제거된 것, 디스크·백업의 안전 삭제는 서로 다른 주장이다. 여기서는 앞 두 항목만 확인한다. 원본으로 재구축하면서 삭제 자료가 복귀한 이유를 설명하고, 실제 운영에서 삭제를 유지하려면 입력 상태/삭제 기록을 어떻게 반영할지 적는다.

### 활동 5. 과거 실제 E5 변경 기록과 구분하기

아래 명령은 **과거 E5/SQLite 실행의 변경 기록을 읽는 것**이다. 앞 고정 인코더 시연이나 새 E5 실행으로 표시하지 않는다.

```bash
python -m tools.index_steps --stored-record ../../../reports/KEDU-PRODUCTION-005/retrieval-observed.json
```

갱신 전 선택 거부, 새 버전/35000원 Context, 삭제 후 문서 ID, 설정 불일치/재구축을 찾는다. 현재 고정 인코더 시연과 같은 제어 흐름을 확인할 수 있지만 검색 관련도를 비교할 근거는 아니다.

과거 설정 표시값/해시가 False인 것은 앞 Embedding 활동에서 설명한 512/128 기록 오류다. 원본을 보존하고 현재 Manifest는 독립 복사한다. 새 실제 E5 결과를 얻으려면 위의 **실제 모델을 새로 실행하려면** 절을 따른다. 새 출력 폴더의 `observed.json`을 같은 `--stored-record`로 읽을 수 있다. 기록 읽기 도구는 SQLite 파일 자체나 디스크 삭제까지 새로 검사하지 않는다.

## 선택 활동: 실제 FAISS 비교 기록 읽기와 재실행

먼저 **저장된 합성 벡터 실험 기록**을 읽는다. 추가 패키지 설치 없이 가능하며 지금 FAISS를 실행하는 것은 아니다.

```bash
python -m tools.index_steps --ann-record ../../../reports/KEDU-PRODUCTION-005/ann-observed.json
```

전체128질의의 저장된 평균과 첫 질의의 ID 교집합을 분리해서 보여 준다. HNSW efSearch=64의 첫 질의는100%지만 전체 평균은 약92.81%다. IVF nprobe=16의 첫 질의는 기준10개 중8개로80%이고, 누락 ID는576·2524다. 전체 평균 약81.72%와 구분한다. 이 ID는 합성 벡터 번호이지 실제 문서 ID가 아니다. 첫 질의만 성공했다고 전체 성공으로 표시하지 않는다.

| 비교 조건 | 확인할 근거 |
|---|---|
| 표현·거리·k | 합성32차원 단위 벡터, 내적 비교, 같은128질의와k=10 |
| Exact 기준 | 같은 벡터의 모든 후보를 비교한 상위10개 |
| HNSW 폭 | M=8·efConstruction=40 고정, efSearch8/64 |
| IVF 폭 | nlist=64 고정, nprobe1/16/64 |
| 시간 | 따뜻한 검색5회 배치 중앙값. 인코딩/구축/학습 제외 |
| 한계 | 문서 의미 검색·동시 사용자·공격 방어·HNSW 삭제 검증이 아님 |

실제 재실행을 할 때는 앞의 별도 CPU 가상환경을 사용하고 다음 **설치/실행 명령**을 따른다. 이번 교안 수정에서 새로 설치해 실행한 것으로 보지 않는다.

| 목적 | 명령 |
|---|---|
| 선택 비교 패키지 설치 | `python -m pip install -r requirements-ann.txt` |
| 새 합성 벡터 비교 기록 생성 | `python -m tools.ann_lab --output ann-observed-01.json` |
| 본인의 새 결과 읽기 | `python -m tools.index_steps --ann-record ann-observed-01.json` |

출력 파일이 있으면 새 이름을 고른다. `No module named faiss`이면 활성화한 환경과 패키지 설치를 확인한다. 이 실험은 실제 FAISS지만 언어 모델이 만든 벡터는 아니다. 내부 그래프 이동 경로 전체를 수집하지 않으므로 저장된 최종 이웃 ID에서 실제 이동 경로를 지어내지 않는다. SQLite 삭제 성공을 HNSW 삭제 성공으로 옮겨 적지 않는다. 다른 장비에서는 지연이 달라질 수 있으니 입력·버전·스레드·측정 범위를 함께 기록한다.

## 제출·완료 조건

Index 활동에서는 조각→원문 추적표, 다섯 점의 Exact/구역 결과와 분모, 그래프/구역에서 누락한 이유, 실제 SQLite의 갱신·삭제·재구축 기록을 남긴다. 저장된 E5/FAISS 결과와 본인의 새 실행 여부를 분리한다. 설명용 그래프를 실제 HNSW 내부 경로로 표시하지 않는다. 가용 목록 제한과 실제 삭제, 삭제와 원본 재구축 후 복귀를 구분한다.

Embedding 활동에서는 네 표현의 설명표, 손계산/실행값, 실제 일치 어휘, 질문별 검색 조각과 필요한 근거 문장 비교, 모델 교체/복구 계획을 남긴다. 현재 수행한 계산·기록 읽기·모델 실행을 구분한다. Index 원문 추적표, Exact/ANN 비교표, HNSW/IVF 탐색 설명, 권한·갱신·삭제 증거는 Index 운영 수업과 연결해 제출한다.

기존 제작 환경의 실제 CPU Embedding·검색·캐시 재실행 증거는 보존한다. 이번 수정의 작은 계산/분절·기록 독해·설정 스냅샷 검증과 학생 본인의 실제 실행은 각각 다르다. 실제 답변 품질, 다른 가중치 모델 전환·학습된 Reranker, 교육장/UI·독립 수업 검증은 별도다.
