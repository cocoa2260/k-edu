# 도구 요청을 검사하고, 관찰을 돌려주는 실습

[강의](<../../01. Phase2_AI/09. AI 에이전트(Agent)/01. Single-Agent/강의용.md>)의 검색→원문 읽기→최종 제출을 고정 응답과 실제 모델 기록으로 나누어 관찰한다. 도구를 불렀는지뿐 아니라 무엇을 읽었고 어디서 멈췄는지 설명하는 것이 목표다. 강사 해설은 [별도 파일](<../../01. Phase2_AI/09. AI 에이전트(Agent)/01. Single-Agent/강사용.md>)에 있다.

저장소 최상위의 터미널에서 아래 **이동 명령**을 실행한다. 이후 상대 경로는 backend 기준이다.

```bash
cd "academy/00. 교육과정(curriculum)/02. 실습/document-assistant/backend"
```

기록 읽기는 Python 표준 라이브러리만 사용한다. 현재 제어 코드 실습은 기존 Backend의 Pydantic 환경이 필요하다. 실제 E5/Qwen과 Framework 실행은 뒤의 별도 준비를 따른다. 세 근거를 서로 대신했다고 표시하지 않는다.

## 활동 1. 완주한 고정 응답과 실제 모델 비교

먼저 **과거 고정 행동 실험**의 A02를 읽는다. A02는 검색→원문 읽기 경계를 관찰하기 위한 사례 키다.

```bash
python -m tools.agent_steps --record ../../../reports/KEDU-PRODUCTION-007/fixture-observed.json --case A02
```

검색으로 A@v1:L1 발견, 원문 읽기, 근거 초안 제출을 찾는다. 결정 3회·도구 처리 2회·함수 진입 2회다. cap 30000이라는 영어 가상 원문을 사용한 고정 실험이며 실제 모델이 계획한 결과가 아니다.

이어서 **과거 실제 모델**이 같은 목적의 요청에서 무엇을 했는지 읽는다.

```bash
python -m tools.agent_steps --record ../../../reports/KEDU-PRODUCTION-007/observed.json --case A02 --raw
```

실제 모델은 검색을 반복해 도구 상한으로 끝났다. 원문 읽기 0개·최종 초안 없음이다. 네 번째 요청은 행동 기록에 있지만 처리/함수 진입은 세 번이다. raw는 저장된 모델 문자열이고 새로운 모델 실행이 아니다. 가이드 프롬프트에 행동 예시가 있었다는 조건도 함께 적는다.

## 활동 2. 현재 실행기로 요청·검사·함수 진입 구분

아래는 **backend에서 실행하는 전체 Python 코드**다. 임시 SQLite와 의미 없는 고정 벡터, 교사가 정한 응답을 사용한다. 모델·LangChain·MCP·외부 쓰기를 실행하지 않는다. 종료와 카운터를 관찰한다.

```bash
python - <<'PY'
import json
import tempfile
from pathlib import Path
from app.agent import Registry, Policy, run_agent
from retrieval.index import LocalIndex
from tools.index_steps import FixedEncoder
from tools.harness_demo import ScriptedProvider

def action(name, **arguments):
    return json.dumps({'kind': 'tool', 'name': name, 'arguments': arguments})
doc = {'id': 'A', 'version': 'v1', 'access': 'staff', 'current': True,
       'title': 'meal', 'text': 'cap 30000'}
final = json.dumps({'kind': 'final', 'draft': {'outcome': 'answer', 'answer': 'cap 30000',
    'claims': [{'text': 'cap 30000', 'source_id': 'A@v1:L1', 'quote': 'cap 30000'}]}})
scripts = {
    '검색-읽기-제출': [action('search_documents', query='meal'),
                      action('read_evidence', source_id='A@v1:L1'), final],
    '잘못된 정수': [action('search_documents', query='meal', k=True)] * 2,
    '미발견 출처': [action('read_evidence', source_id='NOT-FOUND')] * 2,
}
with tempfile.TemporaryDirectory() as folder:
    index = LocalIndex.create(Path(folder) / 'index.sqlite', FixedEncoder(), [doc])
    try:
        for name, script in scripts.items():
            result = run_agent(Registry(index, Policy()), ScriptedProvider(script), 'meal cap')
            print(name, result['stop_reason'], '결정/처리/함수 진입',
                  result['decisions'], result['tool_attempts'], result['tool_dispatches'],
                  '읽은 원문', len(result['sources']))
    finally:
        index.close()
PY
```

첫째는 final_review_required, 3/2/2, 읽은 원문 1개다. 둘째는 repeated_failure, 2/2/0이다. 셋째는 같은 종료지만 2/2/2, 읽은 원문 0개다. 읽기 함수에 들어간 것과 원문을 반환한 것은 다르다. 이 실험의 ‘초안’도 자동 의미 검증이나 품질 승인이 아니다.

추가로 첫 스크립트에서 읽기를 빼고 검색 뒤 바로 final을 제출하도록 바꿔 본다. 읽은 출처가 없어 최종 근거 검사가 실패하는지 확인한다. 정해 둔 응답이 소진될 수 있으므로 실패 뒤의 stop 행동도 명시적으로 준비한다. 임의 실패를 실제 모델 생성 오류라고 기록하지 않는다.

## 활동 3. 승인·오류·재시도의 위치 찾기

첫 명령에서 사례 키를 바꿔 아래 고정 실험들을 읽는다. 모두 fixture-observed.json을 선택한다.

| 키 | 관찰 | 확인할 의미 |
|---|---|---|
| A03 | 없는 도구 요청, 함수 진입 0 | 등록 이름 검사 |
| A04 | approved 추가 인수 거부, 함수 진입 0 | 인자 모양과 실행기 승인 분리 |
| protected_without_grant | 올바른 저장 인자라도 승인 없어 진입 0 | 모의 승인 필요 |
| A05 | 검색 일시 오류 주입·같은 요청 재시도, 최종 초안 | 도구 시도 3/결정 3, 전체 재시도 1 |
| successful_repeat_cap | 반복 검색 상한 | 네 번째 행동이 있어도 도구 처리 3에서 종료 |

실제 모델 observed.json의 A04는 저장 대신 미발견 출처 읽기에 실패했다. 이 기록으로 승인 위조 거부를 검증했다고 하지 않는다. 실제 A05는 검색을 요청해 실험 장치의 오류가 주입됐지만, 재시도 후에도 과제는 완료하지 못했다.

승인 모의 검사는 실행 ID·이름·인자에 묶인 실행기 값이며 메모리 내 저장 한 번만 다룬다. 사용자 승인 UI·지속 권한·다른 프로세스의 재사용 방지는 별도다. 원문 속 명령도 Observation 데이터이지 신뢰할 실행 지시가 아니다.

## 활동 4. State와 종료 이유 설명

각 사례의 선택·관찰·실패·종료를 표로 남긴다. 발견한 ID와 실제 읽은 원문을 구분하고 다음 프롬프트에 무엇이 들어갈지 설명한다. 전체 Trace나 내부 추론을 다음 입력에 복사하는 구조로 가정하지 않는다.

| 항목 | 적을 것 |
|---|---|
| 행동 요청 | 실제 파싱된 행동과 원응답 구분 |
| 검사와 실행 | 실패 ID, 처리 시도/함수 진입, 반환한 원문 |
| 상태 변화 | 발견 ID·읽은 자료·최근 관찰·누적 예산 |
| 종료 | 최종 초안/되묻기/모델 중단/상한/실패를 분리 |
| 품질 | 근거·금액·조건·예외 검토 또는 답변 미완료 |

모델 결정 4회·전체 도구 처리 3회·읽기 재시도 1회·같은 오류 2회가 기본 실험 예산이다. 각 도구에 새 예산을 주지 않는다. 180초는 호출 전후 확인이며 실행 중 강제 취소가 아니다. 행동 출력 192 Token과 입력 1536 Token/2000문자의 제한도 각각 확인한다.

## 활동 5. Framework·MCP 범위와 비교 기준

기존 [실행 검토](https://github.com/cocoa2260/k-edu/blob/work/curriculum-production-001/curriculum-work/reports/KEDU-PRODUCTION-007/REVIEW.md)의 마지막 Framework 절은 StructuredTool.invoke와 같은 Registry 결과의 일치, 추가 인수 거부를 확인한 기록이다. Framework Agent Loop나 MCP 서버/전송을 실행한 기록은 아니다. 현재 읽기 도구도 이를 새로 실행하지 않는다.

같은 과제를 다른 실행기로 옮길 때 이름/인자·권한/승인·발견/읽은 출처·재시도/전체 예산·종료를 누가 검사할지 적는다. core-v1 사실 6개·경계 6개와 agent-v1 경계 6개를 유지해 비교하고, 다른 역할을 붙였다는 이유로 품질 통과로 바꾸지 않는다.

## 실제 모델·Framework를 새로 실행하려면

L3/L4와 같은 Linux x86_64 Python 3.12 CPU 패키지를 사용하되 Framework 연결 확인을 위해 별도 가상환경을 권장한다. 먼저 [L3](L3.md)의 CPU PyTorch를 설치하고 아래를 실행한다. 모델 파일 캐시는 재사용할 수 있다. 다른 운영체제·교육생 GPU·동시 수업 성능은 검증하지 않았다.

다음 표는 **터미널에 입력할 명령**이다. backend 폴더에서 실행한다. 프로그램 출력 예시가 아니다.

| 목적 | 입력할 명령 |
|---|---|
| L5와 Framework 연결 패키지 | `python -m pip install -r requirements-agent.txt` |
| 기존·새 경계 검사 | `python -m pytest -q` |
| 모델 없이 경계·StructuredTool API 실행 | `python -m tools.agent_fixture_lab --output l5-fixtures.json` |
| 실제 모델로 한 사례 | `python -m tools.agent_lab --output l5-single --cases A02` |
| 같은 설정으로 18개 이어서 실행 | `python -m tools.agent_lab --resume --output l5-single` |

캐시가 없으면 최초 한 번 download 옵션을 붙여 고정 모델을 내려받는다. 기본 실행은 캐시만 읽으며 유료 API로 전환하지 않는다. 결과 폴더·파일을 덮어쓰지 않고, resume은 완료 사례를 재사용한다. 기록한 코드·자료·모델 설정이 바뀌면 새 폴더를 사용한다.


위 전체 fixture 실행에는 LangChain Core 환경도 필요하다. 현재 활동 2의 직접 Runtime 코드는 Framework를 불러오지 않는다. 이번 교안 수정에서 모델/Framework를 새로 설치해 실행한 것으로 표시하지 않는다. 기존 CPU 패키지와 고정 모델을 재사용하며, 재개는 완료 사례의 재사용이다. 모든 코드/환경을 완전히 고정하는 Lock은 아니므로 변경한 환경도 함께 기록한다.

새 agent_lab 결과는 개별 사례 파일이고 읽기 도구는 과거 합본 형식을 받는다. 새 A02.json은 필요한 필드를 직접 확인한다. generation_observations의 원응답/출력 상한, trace, sources, tool_attempts/tool_dispatches와 종료를 대조한다. 오류 시 가상환경·캐시·입력/설정·새 폴더 여부를 확인하고 TLS 검증을 끄거나 고정 응답으로 몰래 대체하지 않는다.

## 제출과 미완료

Workflow/Agent 책임 비교, 실제/고정 행동의 추적표, 인자·승인·출처 거부, 종료와 과제 미완료, Framework/MCP 범위표를 제출한다. 실제 모델을 실행했다면 본인 파일/환경을 붙이고 미실행이면 준비/오류를 남긴다. 기록 읽기와 고정 응답 제어 검증으로 모델 품질·독립 수업·인증/운영 승인 완료를 표시하지 않는다.
