# 강사용 해설과 검토 기준

교육생은 [강의](강의용.md)와 [활동지](활동지.md)를 사용한다. 코드·JSON은 별도 계산/기록용이다. 아래 수치와 응답 사례는 같은 제작 세션에서 작성·검토했으며 독립 강사·실제 모델의 응답 성적표가 아니다.

## A · 학습 목적

Causal LM의 예는 시퀀스에서 다음 Token을 맞히는 모델 값 학습이다. SFT는 지시/응답 예시를 이용해 원하는 응답 동작을 학습하며, 응답 영역 손실 등 데이터/Mask 설정을 확인한다. 선호 최적화는 선호/비선호 쌍 또는 평가 신호를 이용해 기준에 맞는 응답을 유도한다. Alignment는 원하는 동작을 정하고 맞추는 더 넓은 목표이며 단일 알고리즘이 아니다.

각 학습은 전체 Weight 또는 선택한 Parameter/Adapter를 조정할 수 있다. 프롬프트나 검색 문서를 넣는 것만으로 자동 학습되지 않는다. SFT라는 목표와 LoRA/QLoRA라는 학습 구성은 서로 다른 축이다. DPO 같은 방법 때문에 모든 선호 학습에 별도 보상 모델과 RL 실행이 필요하다고 답하지 않게 한다.

-ln(0.2368828181)은 약 1.4401896986 nat다. 이 한 위치 손실은 실제 업무 정답률·권한 준수·실행 품질이나 훈련 수렴을 보장하지 않는다.

선호 쌍 예시는 금액을 단정한 응답보다 A v2로 확인할 수 있는 범위와 담당자 확인을 나눈 응답을 선호하는 것이다. 사실·권한·라벨 기준은 별도 검토한다. 보상이나 선호가 높다는 이유로 진실이라고 판정하면 보완한다.

## B · Logit와 선택

아래는 순서 A·B·C·D의 확률이다. 소수 넷째 자리 답은 절대 오차 0.0002 정도를 허용한다. 계산 코드에서는 반올림 전 값과 더 엄격하게 비교한다.

| T | A | B | C | D |
|---|---|---|---|---|
| 1 | 0.6439142599 | 0.2368828181 | 0.0871443187 | 0.0320586033 |
| 0.5 | 0.8649548768 | 0.1170589132 | 0.0158422012 | 0.0021440088 |
| 2 | 0.4550542339 | 0.2760043447 | 0.1674050973 | 0.1015363241 |

Top-k=2와 Top-p=0.8은 이 예시에서 A·B를 남기며 재정규화 결과는 [0.7310585786,0.2689414214,0,0]이다. Top-p는 누적 기준을 넘기는 B도 남긴다. 같은 결과가 모든 분포에서 나온다는 뜻은 아니다.

u=0.70을 고정한 Sampling 규칙에서 T=1은 B, T=0.5는 A다. 바뀐 조건은 Temperature 하나다. Greedy에서는 양수 Temperature 변화가 순위를 바꾸지 않으므로 둘 다 A다. 실제 생성 설정에서는 Sampling/Beam과 옵션 적용 여부를 확인하게 한다. T=0은 이번 식에서 유효하지 않으며 Greedy 구현과 동일한 식으로 취급하지 않는다.

Beam 별도 예시의 AX/AY/BX/BY는 0.30/0.30/0.36/0.04다. Greedy는 A를 먼저 택하고 동률 규칙에 따라 X를 택한다. 폭 2 Beam은 이 작은 트리에서 BX를 찾는다. ‘Beam이면 진실’ 또는 ‘항상 전역 최적’이라는 해석은 보완한다.

이 자료에서 실행한 것은 합성 Logit에서 한 단계 Token을 선택한 비교다. 실제 모델/프롬프트의 다중 Token 생성은 미실행이다. 제출물에는 손계산/합성 검사 기록을 인정하되 실제 생성 완료라고 채점하지 않는다. 실제 생성 비교는 준비된 Runtime에서 revision·Template·입력·자료·길이/종료·Sampling/Beam·환경을 고정하고 한 설정씩 변경해 별도 기록해야 한다. 현재 실제 모델 비교 항목이 ‘미실행+확인 계획’이어도 거짓 실행 증거를 요구하지 않는다. 이 실행 과제의 완료 여부는 후속 검증으로 남긴다.

## C · 저장 위치와 재사용

Parameter는 실행기가 읽는 모델/Adapter 값, Context는 이번 호출에 전달한 입력, 앱 Memory는 저장/선택되는 정보나 요약, Retrieval은 문서/인덱스에서 찾는 경로다. Memory나 검색 구절이 Context로 들어갈 수 있으므로 배타적인 저장 형식 네 가지라고 외우게 하지 않는다.

‘어제 말했는데 오늘 모른다’는 사례에서는 저장 여부·사용자/세션·선택 규칙·현재 전달된 Context를 확인한다. ‘모델이 Weight에서 잊었다’로 바로 단정하지 않는다. 규정 A v3로 바뀌면 소유자가 적용일/폐기본을 확정하고 검색/권한 담당자가 인덱스/필터·입력 자료를 갱신하며 검토자가 답변의 적용성을 확인한다. 자동 Weight 학습을 주장하지 않는다.

14일 요약이 남으면 Memory의 생성 시점·출처와 현행 근거 충돌을 확인해 수정/제외하고 변경된 입력의 Cache 유효성도 확인한다. B 철회는 미래 접근/출력 차단과 이미 저장/배포/학습된 범위의 후속 검토를 나눈다. 저장소에서 행을 지운 것만으로 모델 Weight에서 특정 정보를 확실히 지웠다고 설명하지 않는다.

KV Cache는 층별 K/V 재사용 자료이지 이 수업의 앱 Memory와 같은 것이 아니다. 문서의 명령문을 시스템의 권한 지시로 승격하지 않는 답을 요구한다. 과거/외부 자료의 보관·권한·전달은 앱의 책임과 실제 구현으로 확인한다.

## D · 평가 사례의 예시 판정

각 칸은 **통과 / 실패 / 미확인**이다. 안전 축은 비공개 노출·근거 없는 금액 확정·무승인 실행이라는 명시한 범위를 평가한다. 안전 칸 하나의 통과가 전체 업무 안전성을 인증하지 않는다. 시간은 직접 작성한 예시 값이다.

| 사례 | 형식 | 내용 | 근거 | 안전 | 예시 시간 | 핵심 이유 |
|---|---|---|---|---|---|---|
| E01 | 통과 | 통과 | 통과 | 통과 | 통과 | 예시 규정의 범위·보류·필수 항목 충족 |
| E02 | 통과 | 실패 | 실패 | 실패 | 통과 | A v2에 없는 50,000원 확정. 출처 ID로 해결되지 않음 |
| E03 | 통과 | 실패 | 실패 | 통과 | 통과 | 현행 A v2의 7일과 충돌. 내용/근거 실패이며 명시한 안전 축에서는 별도 위반 예시가 없음 |
| E04 | 통과 | 미확인 | 미확인 | 실패 | 통과 | B 내용 노출. 정확성을 확인할 허용된 검토 자료는 없음 |
| E05 | 통과 | 통과 | 통과 | 통과 | 실패 | 적절한 보류지만 2,500ms로 예시 기준 초과 |
| E06 | 실패 | 통과 | 미확인 | 통과 | 통과 | 내용은 규정과 맞지만 필수 위치가 빠져 추적/검토 보완이 필요 |

E01만 예제 기준상 통과 후보이며 실제 배포 승인과는 별도다. E04의 미확인을 실패로 함께 보류 처리하는 운영 기준도 가능하지만, ‘검토해서 내용이 틀렸음’과 ‘검토할 근거가 없음’이라는 사유는 구분해야 한다. E06에서 학습자가 원문을 찾아 위치를 추가 확인했다면 그 증거와 수정본을 남기게 한다. 제시된 응답 그대로의 판정과 수정 후 판정을 섞지 않는다.

불확실성 대응 예시는 “현행 A v2는 7일·미사용 조건을 안내하지만 이 질문의 환불액/예외 여부는 확정할 근거가 없습니다. 담당자가 해당 정보를 확인한 뒤 안내해야 합니다”다. 답할 수 있는 범위와 보류할 결론을 나누면 된다. 무조건 모든 질문을 보류하거나, 높은 Token 확률/자기 확신으로 금액을 확정하면 보완한다.

형식 검사는 구조와 자료형을 반복 확인할 수 있다. 내용·근거·안전의 예시 판정은 같은 제작자가 작성한 해설이다. 자동 코드가 여섯 응답의 의미를 독립적으로 읽어 채점한 것이 아니다. 예시 시간 기준의 비교도 실제 응답 지연 측정이 아니다.

## 검토 기준과 후속 활동

| 단원 | 충족 조건 | 필수 보완 사례 |
|---|---|---|
| U01 | 학습 목표·데이터·갱신 대상을 구분하고 업무 평가를 남김 | 프롬프트 입력=학습, 선호 점수=진실, Alignment=단일 알고리즘으로 취급 |
| U02 | 분포/필터/선택 계산, 한 조건 변경 기록, 합성/실제 실행 구분 | Top-p 경계 누락, 필터 후 재정규화 누락, Beam/낮은 T로 사실성 보장, 실제 생성 기록 꾸미기 |
| U03 | 위치·수명·선택/전달·담당자와 규정 변경을 설명함 | 저장=모두 전달, 검색=Weight 갱신, KV Cache=지속 업무 기억, 외부 문서 지시로 권한 확대 |
| U04 | 다섯 축·미확인·보류·금지 행동·실측을 분리함 | 형식/평균 점수로 금지 행동 상쇄, 합성 응답/시간을 실측 성능으로 보고, 자기 검토를 독립 품질로 표시 |

항목별 충족/보완/미제출과 근거를 남긴다. 수치 외의 답은 다른 예시여도 책임·입력·증거가 연결되면 인정한다. 후속 Hugging Face 수업에서는 실제 Hub 화면·Model Card·Tokenizer 관찰로 이어 간다. 기존 Tokenizer 실행 성공을 이번의 실제 생성 비교 성공으로 대신하지 않는다.

독립 수업의 소요 시간·막힌 개념·강사 도움·판정 불일치, 실제 생성 비교와 업무/장비 품질은 후속 검증이다. 70개 자료가 작성되어도 이런 검증이 자동 완료되는 것은 아니다.

## 개념별 이해 확인 — 해설과 판단 근거

### 학습 목표와 Post-training

1. 직접 비교한 것은 학습 대상으로 정한 Token에 모델이 부여한 확률이다. 현행 근거·권한·금액 판단이나 도구 실행을 따로 검토해야 한다.
2. SFT는 입력에 대한 원하는 응답, 선호 자료는 같은 입력의 응답 쌍/평가 신호를 준비한다. LoRA는 갱신할 값의 구성이라 SFT와 함께 사용할 수 있다. 둘을 대체 선택지로 외우게 하지 않는다.
3. 이번 입력 정보의 변경과 데이터/손실/갱신 절차로 Parameter를 조정하는 학습은 다르다. DPO처럼 별도 보상 모델과 RL을 직접 실행하지 않는 선호 학습도 있으므로 모든 방식에 그 절차를 요구하지 않는다.

### Logit에서 Token 선택

1. 양수 Temperature로 나누어도 Logit 순위는 같아 Greedy는 A다. 같은 u=0.70 조회는 T=1에서 B 구간, T=0.5에서 A 구간에 들어간다. 확률 변화와 선택 결과를 따로 기록한다.
2. A의 약 0.6439만으로 0.8에 못 미치므로 경계를 넘기는 B도 남긴다. 남은 합 약 0.8808로 나누어 합 1의 분포를 만든다. 이것은 정답의 확률 기준이 아니다.
3. 두 단계 고정 트리에서 제한 후보 탐색의 차이를 보인 것이다. Beam은 항상 전역 최적이나 사실성을 보장하지 않는다. 이 합성 선택을 실제 모델의 문장 생성 성적으로 제출하면 보완한다.

### 정보의 저장과 전달

1. 저장된 사용자/세션 정보, 선택 규칙·권한, 실제 Context를 확인한다. 저장돼도 선택·전달되지 않을 수 있으므로 Weight가 잊었다는 원인을 확정하지 않는다.
2. 문서/인덱스/입력이 바뀌었으며 학습 갱신을 실행한 것은 아니다. 바뀐 Prefix·모델/Adapter·위치/수치 조건에서는 Cache의 유효 구간을 다시 확인해야 한다.
3. 폐기 요약의 출처·시점을 확인해 수정/제외하고 현행 근거와 충돌을 해소한다. 문서 속 명령은 시스템 권한이 아니며 검색/도구 실행 전 실제 권한·승인 경계를 집행해야 한다.

### 환각·불확실성과 평가

1. 형식은 맞아도 원문에 금액이 없어 내용·근거 실패이며 근거 없는 금액 확정은 명시한 안전 축에도 실패다. 빠르거나 평균 점수가 높아도 채택 보류를 상쇄하지 않는다.
2. E04의 내용/근거는 미확인으로 남기며 검토할 자료가 없다는 이유를 기록한다. 권한 위반은 명시한 사례 조건으로 실패다. 모르는 내용을 틀렸다고 검토한 것처럼 쓰거나 안전 실패 때문에 내용 칸을 통과시키지 않는다.
3. E05는 내용/근거/형식/명시한 안전 조건은 통과하나 2,500ms는 예시 기준 2,000ms를 초과한다. 가상 수치 비교일 뿐 실측 지연이 아니다. 실제 업무/장비 조건과 별도 검토 없이는 운영 승인하지 않는다.

## 활동 피드백과 선택 실행의 범위

선호 쌍은 같은 질문과 같은 허용 근거에서 비교하게 한다. 단정적인 문체를 선호한다는 이유만으로 없는 금액을 정답처럼 학습시키지 않는다. 현재 활동은 자료 설계이며 실제 SFT/DPO 실행을 기록하지 않는다.

숫자 활동에서는 Logit/T→지수값→합으로 정규화→필터/재정규화→선택 순서로 값을 분류하게 한다. 앞 단원의 Attention 가중치와 여기의 어휘 확률은 정규화 대상이 다르다. 같은 표에서 두 Temperature의 Greedy가 같다는 답도 정상이다. 실제 생성 비교의 준비는 후속 화면/파일 확인·기준 앱으로 연결하지만 자동 비교 실행기가 있다고 가정하지 않는다.

정보 위치 표에서는 Retrieval을 저장 파일 종류로만 외우지 않게 한다. 허용 원문·검색 인덱스에서 선택한 결과가 Context에 들어오는 경로를 쓰게 한다. 앱 Memory나 문서 갱신·철회 기능을 실제로 구현했다고 평가하지 않는다. Context 수업은 이 구분을 복습한 뒤 자료 선택/순서/길이 조립의 관찰로 확장한다.

선택 코드가 계산하는 형식·가상 시간과 작성자가 넣은 의미 판정은 구분한다. 고정자료에서 첫 사례만 후보라는 것은 예시 판정의 조합 검증이지 독립 의미 채점이 아니다. 실제 지연·모델 생성·독립 수업은 별도다.
