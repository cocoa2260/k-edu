# 강사용 진행·평가 안내

첫 제작 묶음 KEDU-PRODUCTION-001. 이 강의는 PRE-HF와 K2-03.U05~07의 공통 원본이다. PRE-HF에서는 첫 모델 사용 전에 화면 탐색·Card 활동을 하고, K2-03에서는 Tokenizer·Template 관찰까지 심화한다. 같은 화면 설명을 두 강의에 복사해 따로 수정하지 않는다.

## 진행 원칙

학생에게 먼저 ‘모델을 골라서 답변을 생성하라’고 요구하지 않는다. 검색 목적과 페이지를 읽는 순서를 알려주고 파일·리비전·실행 경로를 찾게 한다. Python을 아직 배우지 않은 학생은 화면 활동을 완료하고, Python 선수학습 뒤 실행 활동으로 돌아온다.

교사는 시연 전에 선택 리비전 접근·필요 파일·Python 설치/의존성·실제 관찰·캐시 재실행을 확인한다. 의존성이 없는 상태의 preflight나 계약 테스트를 실제 Tokenizer 실행 결과로 제시하지 않는다. 강의 제작 기록에 미검증이면 교실 시연 전 검증이 필요하다.

화면은 2026-10-30의 실제 캡처다. 최신 UI와 다르면 학생에게 위치 암기를 요구하지 말고 Model card·Files·실행 도구라는 정보의 의미를 기준으로 안내한다. 이후 검색 Filter·Files/History·Dataset Viewer 화면을 추가할 때도 날짜/URL·보는 이유·확인 질문을 함께 작성한다.

## 완료 판단

| 영역 | 확인할 근거 | 부족한 경우 |
|---|---|---|
| 메뉴 선택 | 목적에 맞는 Models/Datasets/Spaces/Docs 선택 이유 | 단어의 뜻과 실제 자료를 연결해 재탐색 |
| 모델 판단 | 두 Card/파일에서 Task·언어·License·실행 경로 근거와 미확인 조건 | 모델 인기/크기만으로 고르면 근거 보완 |
| 입력 이해 | 실제 IDs/decode·길이·Padding·Template 관찰값과 해석 | 예상 숫자를 적으면 실제 실행 상태부터 재확인 |
| 재현 | 동일 Revision·입력·옵션의 캐시 재실행 비교 | 시각만 다른 것과 관찰값 차이를 구분 |

점수를 임의로 고정하지 않았다. 과제의 필수 증거를 충족하는지 판정한다. 환경 준비 때문에 실행하지 못한 경우 개념 활동과 실행 상태를 별도로 기록한다. 개념을 설명한 사실을 실행 완료로 대체하지 않는다.

## 예상 답의 핵심과 오답 처리

- Model Card에 정보가 없으면 ‘미확인 + 확인 방법’도 올바른 답이다. 모델 이름 하나를 정답으로 고정하지 않는다.
- Token 수는 Tokenizer와 입력에 따라 달라진다. 한국어/영어 예문 길이 차이와 의미 차이도 있어 몇 문장만으로 언어 전반의 효율/품질 순위를 만들지 않는다.
- 내부 Token 표시와 전체 decode를 함께 본다. Token 표시가 자연어처럼 보이지 않는다는 이유만으로 실행 실패로 채점하지 않는다.
- 입력 ID의 의미는 해당 Tokenizer의 어휘 규칙 안에서 해석한다. 다른 모델의 동일 숫자 ID에 같은 의미를 부여하지 않는다.
- 잘림은 모델에 들어가는 정보 자체를 바꾼다. 규정의 예외 조건이 잘리는 예를 학생의 문장으로 만들어보게 한다.
- Padding mask의 0은 패딩 위치다. SFT 정답 부분을 선택하는 Loss mask는 후속 [미세조정 데이터 준비](<../../10. 미세조정(Fine-tuning)/강의용.md>)에서 별도 확인한다.
- Template 결과는 모델 입력이다. Qwen의 enable_thinking 옵션에 따른 문자열을 실제 생성/추론의 증거로 해석하지 않는다.
- 특수 Token 재추가의 영향은 Tokenizer 설정에 따라 다르다. 변화가 없다는 관찰도 틀린 답이 아니며 이유를 확인하게 한다.
- 설치한 도구가 없거나 캐시가 없을 때 종료 코드 2가 나온 사실은 준비 필요를 정확히 알린 것이다. 실제 관찰의 통과 여부와 분리한다.

## 후속 연결

후속 수업은 [기준 앱](<../../12. AI Integration/강의용.md>)에서 실행 준비를 확인하고 [Prompt](<../../05. 프롬프트 엔지니어링(Prompt Engineering)/강의용.md>)·[Context](<../../05. 프롬프트 엔지니어링(Prompt Engineering)/Context Engineering/강의용.md>)·[Harness](<../../05. 프롬프트 엔지니어링(Prompt Engineering)/Harness/강의용.md>)로 연결한다. 이번에 확인한 모델 ID·리비전·Tokenizer·Template·입력 길이를 기준 정보로 재사용한다. 실제 생성 모델의 한국어 품질·메모리·지연과 Tool 출력 적합성은 G-MODEL에서 새로 검증해야 한다.

PEFT 계열별 비교와 Dataset 제작은 이번 강의에서 이름과 역할만 안내한다. 실제 LoRA/QLoRA·선택 IA3/DoRA 비교는 K2-12에서 같은 데이터/평가·학습량·메모리/시간을 기록하는 별도 실습으로 수행한다.

## 개념별 이해 확인의 해설

### 첫 방문

1. Hub의 Datasets는 데이터 저장소/목록을 찾는 곳이고 Docs의 Datasets는 코드로 자료를 다루는 라이브러리 설명이다. 이번에는 Transformers의 Tokenizer 안내로 입력 변환을 확인한다. 모든 Docs 항목을 선행 암기시키지 않는다.
2. AutoTokenizer는 입력 변환 도구, AutoModelForCausalLM은 생성 모델을 준비하며 generate는 새 Token 생성이다. 이번 실습은 첫 도구만 사용한다. 화면에 모든 줄이 있다고 그대로 전부 실행하게 하지 않는다.
3. 이름과 역할을 기준으로 찾고 확인 날짜/페이지를 기록한다. 예전 캡처·현재 텍스트 확인·새 화면 촬영을 구분한다. 데모의 실행 환경과 교육생 PC는 별도다.

### Model Card·파일·실행 경로

1. 영어 중심이라는 Card 설명은 한국어 업무의 추가 검증 필요 근거다. 한국어 절대 불가능이나 실제 업무 채택 완료로 확대하지 않는다. 허용 질문/판정 기준/실제 생성 시험 계획이 연결되면 인정한다.
2. Tokenizer 파일·실행만으로 가중치 로드나 답변 생성이 확인되지 않는다. 모델 파일과 Tokenizer 파일, 실제 호출한 함수를 나누어 설명한다.
3. 현재 웹 페이지의 revision과 실습 models.json의 고정 revision을 각각 적고 섞지 않는다. 파일 크기는 Weight 저장량의 단서이며 Context·Cache·동시 실행 등의 전체 메모리 측정과 다르다.

### Tokenizer·Template

1. 입력 변환/복원 관찰이다. ID 조각 표시가 낯설어도 전체 decode와 원문을 대조한다. 복원 성공을 모델 답변 정확도로 평가하지 않는다.
2. 고정 Qwen 기록의 16자리 중 내용 2/패딩 14다. 실제 자기 실행의 mask·padding_side·ID를 확인한다. Attention mask는 조회 입력 위치이고 Loss mask는 학습 손실 대상으로 역할이 다르다.
3. preflight는 의존성 메타데이터와 입력/설정의 준비 검사다. 실제 관찰 파일은 Tokenizer 실행/내부 검사 증거다. assistant 제어 문자열은 생성 시작을 위한 입력 형식이지 모델이 새로 쓴 답변이 아니다.

## 활동 피드백과 현재 검증 상태

화면 활동은 모델 후보 발견→설명서→실제 파일→실행 예제 순서로 안내한다. Smol Card 완성 예에서 문장 근거를 찾게 한 뒤 다른 항목은 학습자가 판단하도록 한다. 특정 모델 이름을 정답으로 고정하지 않는다. 현재 main을 읽은 근거와 고정 리비전 실습의 관찰을 섞지 않는다.

부분 코드는 원문→ID 목록→복원문을 설명하는 발췌이고 전체 실행 명령과 구분한다. 본문의 30문자/16 Token과 다른 짧은 시연 문장의 숫자를 같다고 요구하지 않는다. 기존 Qwen의 KO/EN/SHORT 16/13/2, Smol 64/13/2는 보존된 과거 관찰이며 학생의 새 관찰을 대신하지 않는다.

앞선 설명 정비 당시에는 Python 3.12.14 환경에 네 직접 의존성이 없어 실제 Tokenizer/캐시 실행을 하지 못했고, 계약/저장 관찰 회귀 17개와 입력/리비전 대조만 수행했다. 이후 [2026-11-04 실행 재검증](https://github.com/cocoa2260/k-edu/blob/work/curriculum-production-001/curriculum-work/reports/KEDU-RUNTIME-REVALIDATION-001/RESULT.md)에서 새 격리 환경·고정 파일을 준비해 Qwen/Smol 실제 관찰 6회, 세 조건의 캐시 반복/과거 기록 대조, 빈 캐시 거부를 확인했다. 관찰의 ID·Padding·Template·파일/입력 해시는 같았다. 직접 의존성은 같고 filelock의 간접 버전 차이는 새 실행 기록에 남겼다.

그림 두 장은 보존된 2026-10-30 캡처이며 이번 실행 작업에서도 새 화면 촬영이나 바이너리 시각 검토를 수행하지 않았다. 학생이 이 환경을 사용할 수 있다는 보장이 아니므로 실제 수업 전 교사가 준비/관찰 명령을 실행하는 원칙은 유지한다. 모델 생성·다른 OS/교육장·독립 수업은 별도 검증이다.
