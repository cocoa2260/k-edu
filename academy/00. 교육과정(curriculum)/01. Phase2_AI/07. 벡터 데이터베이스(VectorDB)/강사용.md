# 저장·탐색·변경 수업의 해설과 관찰 기준

[학생 강의](lesson.md)와 [Index 연결 활동](../../practice/document-assistant/L3.md#index-활동)에 대응한다. 같은 작성자가 문서와 실행 동작을 대조한 해설이다. 독립 강사·교육생의 수업 검증은 아니다. 결과표를 복사했는지보다 출발 자료·계산 범위·원문 상태를 근거로 설명하는지 확인한다.

## 1장: 저장과 원문 추적

1. **벡터와 ID만 저장:** 벡터는 원문 복원 파일이 아니다. 조각 본문·버전·내부 위치와 원본 자료, 접근/현행 상태가 없으면 당시 어떤 조건·예외를 근거로 삼았는지 재현하기 어렵다. ID만으로 항상 최신/과거 모두 복원된다는 답은 부족하다.
2. **L1의 뜻:** DOC-A의 `text`를 줄바꿈으로 나눈 첫 줄이다. JSON 파일의 물리적 행과는 다르다. `origin_path`는 최초 입력 경로, `source_locator`는 SQLite의 문서/버전/줄을 가리킨다. 임시 v2를 최초 JSON에서 찾게 안내하지 않는다.
3. **해시 공유:** `content_sha`는 문서 전체 본문에 대한 값이라 같은 문서의 조각들이 공유한다. 해시는 변경 대조용이며 발행자 인증·사실성·근거 적합성을 보장하지 않는다. 원문 줄 해시라고 잘못 설명하지 않았는지도 본다.

## 2장: Exact와 ANN의 평가

1. **Exact의 누락:** 모든 적격 벡터를 비교해도 표현/순위·조각 구성·질의·필터 때문에 필요한 문서가 상위 k에 없을 수 있다. 실제 과거 C07 Dense 누락은 ANN 탐색 누락이 아니다. 사용한 구현과 후보 집합부터 확인한다.
2. **이웃 회수:** 기준 `{C,D}`와 결과 `{D,B}`의 교집합은 D 하나이므로 1/2이다. 같은 벡터/질의/거리/k의 Exact 이웃 기준이며 정답 문서 또는 답변 정답률로 바꾸지 않는다. 첫째를 못 찾았으니 무조건0이라는 답도 분모가 다르다.
3. **첫 질의와 전체:** 다르다. 저장된 HNSW efSearch64는 첫 질의100%이나 128개 평균은92.8125%다. 기록의 첫 질의 ID로 전체 평균을 독립 재계산했다고 하지 않는다. 지연 역시 배치 중앙값이며 학생 장비의 처리량이 아니다.

## 3장: 연결과 구역의 탐색

1. **좁은 이동:** A에서는 B3이 E6보다 가깝고 A4보다도 가까워 B로 간다. B에서는 이웃 A4가 더 멀어 멈춘다. C1은 연결된 다른 경로 너머에 있다. 후보 유지·윗층 연결의 필요를 보여 주는 직접 구성한 예이며 실제 HNSW 알고리즘/FAISS 경로가 아니다. B—C를 추가하면 A→B→C가 가능하지만 M 변경의 실제 성능 결과는 아니다.
2. **구역 누락:** q에서 U중심까지3, V까지4라 U를 먼저 고른다. 그러나 C는 U까지√10≈3.1623, V까지3이어서 V 소속이다. 중심과 개별 자료점까지의 거리는 다른 비교다. U만 보면 D·B, 둘 다 보면 C·D다. 중심은 손으로 정한 값이지 학습된 FAISS 중심이 아니다.
3. **폭과 표현:** efSearch/nprobe는 같은 표현에서 탐색 범위를 바꾼다. 모델 교체는 좌표 표현을 바꾸므로 문서 벡터/Index를 새로 준비하고 고정 평가가 필요하다. 폭을 늘리면 항상 지연 없이100% 또는 정확히 efSearch개를 비교한다는 설명은 틀리다.

## 4장: 필터·갱신·삭제

1. **나중에 제거:** 전체 Top1이 제한 문서라면 이를 빼고 결과가 비게 된다. 허용 집합에서 먼저 고르면 허용 자료가 남는다. 현재 Exact는 접근·현행·미삭제·가용 목록을 먼저 적용한다. 이를 ANN 전체의 필터 동작 보장으로 일반화하지 않는다. 공격 메모는 허용된 현행 자료라 이 필터만으로 배제되지 않는다.
2. **갱신 전 선택:** 저장소 변경 번호가 달라 이전 선택은 거부된다. 새 검색으로 새 본문·버전·벡터를 연결한다. Context는 선택의 text 대신 저장소를 다시 읽으므로 text만 바꾸어도 위조문이 그대로 들어가지 않는다. 다만 선택 전체의 서명/인증·여러 서버 동시 변경 보장까지 검증한 것은 아니다.
3. **재구축:** 원본 JSON에는 v1 출장 규정이 남아 있으므로 새 Index에 다시 들어온다. 운영에서 삭제를 유지하려면 재구축의 입력에도 삭제 상태·권한·현행 정책을 반영해야 한다. 삭제 후 복구 시험과 운영 삭제 유지 증거를 구분한다. 디스크/백업 안전 삭제도 별도다.

## 활동에서 받을 근거와 피드백

| 활동 | 충분한 설명과 관찰 | 보완해야 할 답 |
|---|---|---|
| 원문 추적 | 실제 첫 결과→문서ID/버전/내부줄→원본, 전체본문해시 대조 | L1을 JSON 첫 행으로 읽음, 해시로 규정의 진실성 증명 |
| 다섯 점 | C→D→B→A→E와 k=2, U만 D·B의1/2 | 가상 L2좌표를 실제 E5 벡터로 표시 |
| 그래프/구역 | A→B의 막힘, E경로/윗층 연결, U중심과 C의 소속 거리 대조 | 내부 FAISS 경로를 지어내거나 중심을 실제 학습값으로 표시 |
| 현재 SQLite | 6/11→7/10→8/9, 이전선택거부·원문재조회·벡터0·본문비움·v1복귀 | 고정벡터로 의미 품질 검증, 재구축 후에도 삭제 유지 주장 |
| 저장 E5 기록 | 과거 실제 모델 변경과 현재 고정 인코더 제어 실습을 구분 | 기록 출력이 새 모델 실행이라고 주장, 과거128표시를 초기설정으로 인용 |
| 저장/새 FAISS | 전체평균/첫질의/측정범위·버전·새실행 여부를 구분 | 첫질의100%로 전체 성공, 배치ms를 동시접속 성능으로 표시 |

현재 SQLite 시연은 원본6문서를 저장하므로 변경 번호6에서 시작한다. 이 값은 문서 버전이 아니며 새 Index에서도6이 나올 수 있다. 벡터는 모두 `(1,0)`이라 내적이 같고, 실제 코드의 조각ID 동점 정렬을 따른다. 관련도 순위를 해석하게 하지 않는다. 숫자512/128도 이 고정 인코더에서는 설정 호환성 시연일 뿐 실제 Tokenizer가 길이를 재는 검사가 아니다.

실제 의미 검색·FAISS 재실행은 기존 환경 준비에 따라 별도 수행한다. 이번 추가 도구의 기본 출력은 요약이고, `--output`으로 전체 관찰 JSON을 새 파일에만 남긴다. 덮어쓰기 거부를 ‘검색 실패’로 해석하지 않게 안내한다. 저장된 기록을 읽을 때 새 DB나 모델을 검사한 것으로 표현하지 않는다.

과거 E5 Manifest의 512/128 표시값·해시 불일치는 [앞 수업의 해설](../embedding/teacher-guide.md)에 설명돼 있다. 원본은 보존했고 현재 Manifest의 독립 복사는 유지한다. 이 수업 수정으로 과거 파일을 고쳐 쓰지 않는다.
