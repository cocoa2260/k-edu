# Harness 강사용 해설과 실습 판정

학생은 [강의](강의용.md)와 [연결 실습](<../../../02. 실습/document-assistant/L2.md>)을 사용한다. 이 문서는 개념별 질문 해설·활동 피드백·관리 매핑용이다. 같은 작성자의 검수이며 독립 강사/교육생 수업을 수행한 결과는 아니다.

## 진행 원칙

처음부터 실험 이름과 실패 코드를 외우게 하지 않는다. 식비 질문의 원문·원하는 답을 확인하고, 요청 하나의 준비→호출→검사→초안 반환을 읽는다. 그 뒤 통신 실패와 도착한 응답의 계약 실패를 분리한다.

기본 식비 시연은 사람이 작성한 충실한 답을 고정 반환한다. 기존 `harness_demo`의 정상/보완 성공 고정 문장은 일반적인 검토 안내다. 두 내용이 다르다는 점을 설명하고 구조 통과와 내용 적합성을 분리하는 데 쓴다. 모델이 지시를 이해해 고친 성적으로 채점하지 않는다.

횟수 3/1/1과 90초는 이 실습의 작은 정책이다. 첫 호출과 두 종류의 추가 시도를 설명하기 위해 사용하는 값이며 모든 운영 서비스의 최적값은 아니다. 코드·숫자 암기보다 시작 조건·입력 변화·공유 예산·종료 증거를 말하게 한다.

## 1장 해설 · 실행기의 책임

1. **문자열과 의미:** 문자열이 반환되거나 JSON 구조를 통과해도 금액·조건·예외가 맞는지 별도 검토가 필요하다. 첫 식비 시연은 사람이 원문으로 대조할 수 있지만 실행기가 의미를 검증한 것이 아니다. 결과의 `factuality_verified`는 계속 거짓이다.
2. **최종 입력 길이:** 준비 입력 뒤에 출력 계약·보완 지시가 추가된다. 추가 후의 실제 최종 입력에 문자 검사를 적용해야 한다. 이전 준비 단계의 통과를 이후 길이 검사의 대체로 쓰지 않는다.
3. **호출의 증거 수준:** 이번 Provider는 미리 정한 응답/오류를 반환하는 `scripted-fixture`이며 모델 이름은 `no-model-executed`다. 메서드 시도 1회를 실제 모델 추론 1회로 기록하면 안 된다.

`draft`는 JSON을 만드는 도구이고 `Draft`는 구조 검사 모델이다. 서로 다른 이름/역할임을 필요한 경우 짚는다. Trace의 사건은 실행기가 기록한 것이며 모델의 숨은 사고 기록이 아니다.

## 2장 해설 · 재시도와 보완

1. **입력 관계:** 연결 실패·시간 초과는 이번 정책에서 같은 입력으로 통신 재시도한다. 응답이 왔지만 출력 계약을 못 지키면 실패 이름을 추가한 입력으로 보완한다. 입력의 해시/문자열 관계와 각 사건을 연결한다.
2. **공유 예산:** 보완 호출이 시간 초과해도 실행 전체의 호출·재시도 수를 초기화하지 않는다. 아직 통신 재시도 예산이 있으면 같은 보완 입력으로 재시도할 수 있지만 전체 상한 안에서만 허용한다.
3. **세 번째 응답:** 상한은 네 번째 호출을 막는 것이지 세 번째 정상 응답의 검사를 무조건 금지하는 것이 아니다. 시간 초과→형식 오류→정상 구조는 calls3/retries1/repairs1로 초안을 반환한다. 실패한 경우에는 실제 소진 순서와 종료 이유를 본다.

보완 입력은 원래 입력/계약에 실패 이름과 안내를 더한다. 잘못된 응답 전문·평가 정답·해설을 되돌려 주지 않는다. 보완 뒤 다시 같은 검사기를 통과해야 한다. 기본 정책에서는 보완을 한 번 쓴 뒤 다시 실패하면 종료하며, 별도로 동일 실패 ID의 반복을 탐지하는 무제한 Loop가 아니다.

기록 표시의 “첫 입력”과 “직전 호출” 비교 기준을 구분한다. 보완 뒤의 통신 재시도는 첫 입력과 다르지만 직전 보완 입력과는 같다. 모든 오류를 재시도하지 않으며 현재 원격 상태/Provider 해석 오류는 즉시 종료한다. 예상 밖 프로그래밍 오류는 모델의 정상 실패로 숨기지 않는다.

## 3장 해설 · 구조와 내용

1. **ID 검사의 한계:** 제공 문서 목록에 출처가 있다는 것은 본문 내용이 주장을 뒷받침한다는 뜻이 아니다. 현행 버전·조항·숫자·적용 범위·조건·예외를 확인한다. 제공 ID 검사만으로 의미를 읽는 평가를 완료하지 않는다.
2. **두 실패:** 미제공 ID는 `CITATION_NOT_SUPPLIED`로 거부된다. DOC-A를 붙인 틀린 999999원은 구조/제공 ID를 통과하지만 원문 30,000원과 불일치한다. 식비 예외 누락도 별도로 보완해야 한다.
3. **수신 후 크기:** 응답을 모두 받은 뒤의 크기 검사는 이미 발생한 생성/전송·과금을 제한했다는 증거가 아니다. 사용량을 반환하지 않는 공통 Provider 계약의 Token·비용은 `None`이며 측정 0이 아니다.

출력 계약은 `outcome/answer/citations`이며 추가 필드·중복 ID·빈 답·답변 상태의 인용 부재 등을 검사한다. 세 필드가 있다고 모든 답이 좋은 것은 아니다. 제한 ID를 거부한 것을 실제 로그인·권한 체계나 공격 저항성 전체의 완료로 설명하지 않는다.

## 4장 해설 · 회귀와 채택

1. **합계와 개별 실패:** 전체 구조 통과가 9→10으로 늘어도 C07 승인 필드 회귀가 있다. 개선 두 사례와 악화 한 사례를 함께 기록하고 바로 채택하지 않는다. 공백 C10은 양쪽 모두 호출 전에 거부되며 답변 오답률에 섞지 않는다.
2. **적절한 보류인지:** 근거가 충분한 식비 질문에 자료 부족이라고만 해도 구조는 통과할 수 있다. 실제 내용/경계 행동 평가는 이 보류가 적절한지 원문으로 판단해야 한다.
3. **고정 출력과 모델 비교:** 이 실험은 응답 A/B를 주입한 도구 비교다. 실제 모델·Prompt를 바꾼 생성/의미 평가가 아니다. 실제 모델/설정·원응답·사람 판정이 없으면 그 정답률을 보고할 수 없다.

A/B는 최대 한 번의 최초 시도, 재시도/보완 0으로 비교한다. 열 가지 경계 실험의 기본3/1/1 정책과 구분한다. 최초 구조 통과와 보완 후 통과도 구분해야 같은 조건의 비교가 된다. 실제 비교에는 정상 사실 여섯 개와 경계 행동 여섯 개, 조건·예외·출처의 의미 판정을 이어받는다.

출력 B의 추가 승인 필드는 응답 버전의 계약 회귀다. 실행기가 이를 거부하는 것은 정상적인 검사 동작이다. 이 회귀 표를 검사기가 새로 승인 위조를 허용했다는 뜻으로 설명하지 않는다.

## 5장 해설 · 승인·시간·기록

1. **경과시간 검사와 강제 중단:** 호출 전후 90초 검사는 동기 Provider의 진행 중 실행을 끊지 못한다. 가짜 시계를 91초로 바꾸면 반환 직후 초안을 버리고 `elapsed_limit`로 끝난다. 실제 91초의 지연 성능 시험은 아니다.
2. **신뢰 측 상태:** 모델의 승인 문장이나 추가 필드가 정책을 바꾸지 않는다. 호출자 설정과 바깥 취소 신호를 읽는다. 호출 중 신호가 설정되면 반환 후 초안을 버린다. 이 결과도 실제 사용자 인증·승인 저장소·작업 실행의 검증은 아니다.
3. **해시와 보관:** 해시는 입력 동일성/변경 비교에 쓸 수 있지만 원문 복원·암호화 보관을 대신하지 않는다. 기본 Trace에 원문이 없어도 결과의 초안에는 답변이 남는다. 실제 산출물의 보관·공유·민감 내용 범위는 별도로 판단한다.

`boundary_runs`는 동일 실행기에 가짜 시계/신호를 주입한다. 시간/취소 결과는 각각 `elapsed_limit`/`cancelled`, 호출 1회·초안없음이다. 벽시계 강제 취소·원격 작업 중단이나 분산 취소까지 검증한 것으로 표시하지 않는다.

## 활동 피드백과 완료 범위

| 활동 | 충족 근거 | 보완이 필요한 해석 |
|---|---|---|
| 한 요청·책임 분담 | 실제 준비/호출/검사/종료, Provider 종류와 내용 검토 구분 | 메서드 호출을 모델 추론으로, 구조 통과를 업무 승인으로 처리 |
| 재시도/보완 | 같은/달라진 입력·실패 안내·동일 검사 재실행 | 보완에서 전체 예산 초기화, 실패 응답 전문을 다음 지시로 신뢰 |
| 상한 | 혼합3회 초안 반환과 재실패2회 종료의 실제 이유 | 총 횟수만 보고 성공/실패 단정, 계속 호출해서 맞히기 |
| 구조/근거 | 제공 ID와 틀린 금액의 다른 판정 | 출처 이름만 채점, `None`을 측정 0으로 보고 |
| A/B 회귀 | 개선/회귀·공백 거부·최초/보완 구분 | 전체 구조 수로 회귀 상쇄, 고정 출력을 모델 성적으로 보고 |
| 신뢰 경계 | 추가 승인 필드 거부·반환 후 시간/취소·초안 폐기 | 실제 인증·강제 취소·보안 체계 전체 완료로 주장 |

각 답에 **충족 / 보완 / 미제출**과 실제 이유를 남긴다. 같은 표현 복사보다 조건·입력·관찰·판정의 연결을 본다. 실제 모델 생성·의미 채점이 없으면 미실행으로 남긴다. 독립 수업의 이해도·시간·도움 횟수는 아직 측정하지 않았다.
