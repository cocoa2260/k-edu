# Context 강사용 해설과 실습 판정

학생의 기본 자료는 [강의](강의용.md)와 [Context 실습](<../../../02. 실습/document-assistant/CONTEXT.md>)이다. 이 문서는 장별 질문의 해설과 진행·관리 매핑용이다. 같은 작성자의 검수이며 독립 강사/교육생 수업을 수행한 결과는 아니다.

## 진행에서 지킬 구분

식비 질문의 범위·조건·예외를 먼저 읽게 한다. Prompt에서 배운 작성 지시를 다시 요약하는 수업으로 만들지 말고, 같은 지시에서 어떤 자료를 제공하고 보존하는지에 집중한다. 질문이 달라지면 필요한 근거도 달라진다는 비교까지 진행한다.

입력 준비·문자 수·자료 목록은 현재 실행으로 확인할 수 있다. 기존 Token 관찰로 하는 산술, 새 입력의 Tokenizer 실행, 모델 생성·품질은 서로 다른 증거다. 새 순서의 입력에 기존 657 Token을 복사하지 않게 한다.

실행 도구는 기존 `prepare`와 자료·입력 계약을 재사용한다. 실제 검색·로그인 권한·지속 Memory·삭제 서비스·Handoff 검증기를 구현하지 않는다. 현재 단계의 설명용 상태를 후속 구현 완료로 보고하지 않는다.

## 1장 해설 · 출처와 신뢰

1. **접근과 현행성:** 이전 규정은 읽을 수 있어도 폐기본이다. 현행 식비 상한의 근거로 쓰면 안 된다. 이전/현행 비교 질문에는 명시적으로 비교할 수 있다. 현재 코드의 `allowed`는 역할·가용 목록 검사이며 현행 문서 필터가 아니다.
2. **문서 속 명령:** 참고 문서의 명령을 실행 권한으로 승격하지 않는다. 앱이 신뢰 측 정책으로 접근·도구 실행을 검사해야 한다. 문서나 모델이 `approved`라고 적었다고 그 권한이 생기지 않는다. 입력 문구의 요구와 실제 강제 검사를 구분한다.
3. **이름과 본문:** 질문에 제한 문서 이름이 있을 수 있다. 제공 문서 ID/본문에 제한 자료가 포함되는지는 별도로 본다. C06의 질문에는 DOC-R이 보이지만 준비 문서 목록에는 없다. 이름을 모두 지웠다는 이유만으로 보안 검증을 완료했다고 하지 않는다.

C07의 공격 문장이 자료에 있다는 것은 해당 경계를 평가할 입력을 준비했다는 뜻이다. 실제 모델이 그것을 무시했다는 결과는 아니다. 기준 Token 계산은 준비 문자열 전체를 하나의 사용자 메시지 내용으로 변환하며 제목·JSON 포장을 실제 시스템 역할과 동일시하지 않는다.

## 2장 해설 · 선택·순서·형식

1. **질문별 필요한 자료:** 단순 식비 질문은 현행 출장 규정 하나에 필요한 근거가 있다. 식비와 교육비 한도를 비교하는 C09는 두 규정을 함께 읽는 편이 비교 근거를 명확히 한다. 문서 개수를 최소화하는 것 자체가 목표는 아니다.
2. **여러 조건 변경:** 자료 선택·순서·지시를 동시에 바꾸면 최종 구성 차이는 볼 수 있지만 한 원인으로 귀속하기 어렵다. 지시/질문/예시를 고정한 선택 비교, 같은 자료·본문을 고정한 순서 비교로 나눈다.
3. **형식과 내용 손실:** 표로 옮기며 식사 제공 예외를 누락하면 내용도 바뀐 것이다. 같은 사실·부정·적용 범위·출처를 보존했는지 원문으로 확인한다. 학생의 표 표현은 제안이며 실제 입력·Token·생성으로 자동 채택된 결과가 아니다.

C01은 기본 문서5개·1151문자, 선택1개·398문자다. C09 선택은 DOC-A/DOC-B 두 개다. 선택 ID는 교사가 미리 정한 자료이며 검색 모델의 회수 성능이나 학생의 독립 발견 능력을 평가한 것은 아니다. 읽기 쉬운 예제와 실제 자동 검색 검증을 혼동하지 않게 한다.

순서 활동의 `True`는 실제 직렬화된 입력에서 문서별 내용·지시·질문이 유지된다는 뜻이다. 역순으로 바꾼 결과를 모델에 보내지 않았으므로 품질 향상을 채점하지 않는다.

## 3장 해설 · 길이와 출력 여유

1. **단위:** 398문자에서 264 Token이 나온 것은 해당 입력/Tokenizer/Template의 관찰이다. 문자 수에 고정 비율을 곱해 다른 입력의 정확한 Token 수를 알 수 없다. 문자 계약과 모델 입력 Token 계산을 따로 확인한다.
2. **합계:** 가상1900 + 여유256 = 2156이며 기준2048보다108 크다. 실제 입력1900을 측정한 것이 아니다. 측정하지 않은 수치를 실측 칸에 쓰면 보완한다.
3. **계산과 실행:** 657+256=913, 잔여1135이고 264+256=520, 잔여1528이다. 이는 수업 기준 계산이다. 실제 Provider의 모델/Template·출력 길이 설정·전체 메모리·생성/업무 품질은 별도로 확인해야 한다.

2048은 이 실습의 기준 상한이며 해당 Qwen의 실제 최대 문맥 길이라는 답은 보완한다. 256은 확보하려는 출력 여유이며 실제 생성량이 아니다. 계산 도구가 실행기의 출력 상한까지 설정한 것으로 설명하면 안 된다.

예산 도구는 현재 고정 다섯 입력의 파일 SHA256을 기존 관찰 대상과 대조한 뒤 기록을 읽는다. 새 순서/형식·자체 수정 지시는 이 고정 입력의 관찰을 재사용할 대상이 아니다. 기존 입력과 다르면 계산을 거부하고 새 실제 Tokenizer 검증을 남긴다. 예산 단계에 다른 사례를 지정해도 임의의 과거 수치로 대신하지 않는다.

줄일 때는 중복·불필요한 자료를 우선 검토한다. 문장의 뒷부분을 잘라 식사 제공 예외가 사라졌다면 길이는 맞아도 근거가 불완전하다. 필요한 근거를 보존할 수 없으면 호출 보류/범위 조정과 재검증이 합리적인 답이다.

## 4장 해설 · State·Memory와 현재 입력

1. **과거 기록과 현재 가용성:** 어제 원문을 사용했다는 기록은 현재 사용 권한·버전을 보증하지 않는다. 현재 제공 목록·권한·원문을 다시 확인한다. C12의 현재 제공 목록에는 DOC-A가 없으므로 과거 식비 답으로 보충하지 않는다.
2. **선호 저장과 반영:** 선호가 저장됐는지, 현재 사용자/세션과 맞는지, 선택됐는지, 실제 입력에 들어갔는지를 확인한다. 현재 실습은 지속 선호 저장과 자동 입력 반영을 구현하지 않는다.
3. **비어 있는 현재 근거:** 과거 답을 복사하면 현재 근거의 존재·가용성·버전 검사를 건너뛴다. 현재 질문·문서/버전·선택 방식과 미확인 범위를 전달하고 부족한 자료 요청/보류를 판단한다.

강의의 단순 딕셔너리와 모델용 `message`는 다른 자료다. `dataset_version`은 데이터 묶음 기준이며 개별 원문의 `version`을 대신하지 않는다. 실습 도구의 C12 전달에는 출처가 없고, C01로 바꾸면 DOC-A/v1이 나온다. 그 결과도 실제 지속 Memory나 전달 권한 검증기의 증거는 아니다.

## 활동 판정과 후속 확인

| 활동 | 충족을 판단할 근거 | 보완이 필요한 해석 |
|---|---|---|
| 자료 선택 | 같은 지시/질문/예시수와 다른 자료, 질문별 선택 이유 | 짧아서 품질 통과, 교사 선택을 자동 검색 성공으로 발표 |
| 신뢰/제한 | 접근·현행·근거 적합성, 문서 이름과 본문 제공 구분 | 문서 명령을 실행 권한으로 수용, 입력 제외를 실제 모델 공격 저항성으로 발표 |
| 순서/형식 | 문서·본문·조건 보존과 실제 변경을 구분 | 예외 삭제를 형식 변경만으로 처리, 새 입력에 과거 Token 수 복사 |
| 예산 | 문자/Token·입력/출력 여유·가상/실측 구분, 축소/중단 이유 | 2048을 실제 모델 최대 길이로 단정, 계산 통과를 실행/품질 승인으로 처리 |
| 현재 전달 | 현재 문서·버전·가용성, 과거 답/저장 선호와 실제 전달 구분 | 과거 문서 이름만으로 현재 원문 재사용, 메모리 서비스 구현 완료로 표시 |

각 답은 **충족 / 보완 / 미제출**과 이유로 남긴다. 생성 환경이 없어도 입력·산술·판단 활동은 수행할 수 있지만 실제 모델 응답 평가는 미실행이다. 동일 작성자의 시연과 학생 자신의 관찰도 구분한다.

독립 수업에서는 신뢰 경계·직렬화·문자/Token·과거/현재 정보 중 막힌 지점, 소요 시간, 도움 횟수, 판정이 갈린 이유를 기록한다. 현재 그 측정은 없다.
