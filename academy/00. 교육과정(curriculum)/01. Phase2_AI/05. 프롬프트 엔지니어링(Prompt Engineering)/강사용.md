# Prompt 강사용 해설과 실습 판정

학생의 기본 읽기는 [강의 본문](강의용.md)과 [연결 실습](<../../02. 실습/document-assistant/L1.md>)이다. 이 문서는 진행·피드백·관리 매핑용이다. 같은 작성자의 설명 검토이며 독립 강사/교육생의 수업 결과가 아니다.

## 수업 진행에서 먼저 구분할 것

처음에는 현행 출장 규정과 식비 질문을 소리 내어 읽는다. 30,000원이라는 숫자부터 맞히게 하지 말고 적용 범위·상한·승인·증빙·예외를 찾게 한다. 상한을 실제 지급 확정액으로 쓴 답을 수정한 뒤 작성 지시 비교로 넘어간다.

준비 입력을 읽는 활동은 모델 없이 진행할 수 있다. `prompt_inputs`는 기존 `prepare` 함수를 호출해 표시할 뿐이며 답변 생성·성능 채점 도구가 아니다. 출력 안의 도서 시범 답안을 실제 모델 응답으로 읽으면 입력/생성 구분부터 다시 설명한다.

학생이 지시를 추가할 때에는 변경 이유와 고정 조건을 말하게 한다. “상한과 지급액 구분” 문장을 추가한 뒤 자료·질문이 같은지 확인하고, 효과는 실제 응답 평가 전까지 미확인으로 둔다. 동일 작성 지시에서 예시 수를 바꾸는 활동으로 돌아올 때는 방금 만든 사용자 지시가 자동 반영되지 않는다는 점을 짚는다.

현재 관찰한 수업 시간·강사 도움 횟수·학습자 이해도는 없다. 독립 시범 수업에서 기록해 난이도와 시간을 조정한다. 작성 분량이나 코드 검사 개수로 이를 대신하지 않는다.

## 1장 해설 · 지시와 출력 조건

1. **상한과 지급액:** 규정은 사전 승인된 국내 당일 출장에 적용하고 영수증을 요구한다. 식사가 제공되면 지급하지 않는다. 모든 사람에게 30,000원을 지급한다고 하면 조건을 없애고 상한을 확정액으로 바꾼 것이다. 개인별 지급액을 묻는 경우 필요한 조건·실제 지출 등 이 자료로 확인할 수 있는 범위를 따로 판단해야 한다.
2. **둘 이상의 변경:** 지시와 참고 문서를 동시에 바꾸면 최종 구성의 차이는 관찰할 수 있지만 원인을 지시 하나에 귀속할 수 없다. 같은 자료를 유지한 지시 비교 또는 지시를 유지한 자료 선택 비교로 나눈다.
3. **출처와 의미:** 문서 ID가 실제로 제공되었는지, 현행본인지, 조항이 숫자·조건·예외를 뒷받침하는지 확인한다. “[DOC-A] 식비는 50,000원”은 식별자만 맞고 내용은 틀렸다.

강의의 충실한 답안은 교사 작성 예시다. 구체적인 지시가 그 응답을 실제로 생성했다는 결론은 인정하지 않는다. 짧은 지시도 좋은 답을 낼 수 있으므로 길이 자체로 우열을 채점하지 않는다.

코드에서는 두 `prepare` 호출이 서로 다른 모델을 실행하는 것이 아님을 확인한다. 같은 식비 질문과 다섯 자료, 예시 0개를 유지하고 첫 지시만 바꾼다. 자료에 이전 규정과 공격 메모가 포함되는 이유는 같은 비교 조건을 보존하기 위해서다. 현재 코드는 모의 staff 범위로 제한 자료를 제외하며 실제 인증을 구현한 것은 아니다.

## 2장 해설 · 예시를 추가할 때

1. **시범과 대상 질문:** 10일은 도서 대출 규정의 답이며 식비 질문의 사실이 아니다. 작업의 패턴과 그 사례의 사실을 구분한다. 시범 근거 ID도 현재 출장 문서와 구분한다.
2. **평가 답의 노출:** 같은 식비 질문의 정답을 보여주고 그 질문을 다시 맞힌 결과로 처음 보는 문제의 능력을 입증할 수 없다. 실제 사용에서는 예시와 평가 질문의 역할·유사성·개발 사용 이력을 확인한다.
3. **응답 악화의 원인 후보:** 시범의 잘못된 답, 특정 행동의 과도한 유도, 현재 과제와의 불일치, 충돌, 순서·길이와 잘림, 생성 변동 등을 확인할 수 있다. 후보 원인을 실제 입력/응답 없이 확정하면 보완한다. 이번 고정 실험만으로 수·선택·순서 각각의 독립 효과를 입증했다고 하지 않는다.

실제 시범은 대출 기간과 벌금 기준 부재 두 개다. One-shot에서 10일·출처가 보이는 이유는 입력의 시범이기 때문이지 생성이 성공했기 때문이 아니다. Few-shot은 이번에 두 개로 정한 조건이며 일반 정의를 두 개로 고정하지 않는다.

문자 수 1151/1272/1403과 기준 Token 657/723/793을 구분한다. Token 값은 2026-10-31 고정 Qwen 리비전과 사용자 대화 Template의 관찰이다. 현재 문자 재확인과 새 Tokenizer 실행은 다른 증거다. 예시 추가량은 이 조건에서 66/70 Token이다. 다른 모델의 길이·전체 용량·품질로 일반화하지 않는다.

## 3장 해설 · 후보와 도구

1. **검색 증거:** 모델 문장만으로 검색 완료를 인정하지 않는다. 실제 도구 요청, 이름/인수·허용 검사, 실행 여부, 반환된 결과/원문과 다음 입력 연결이 필요하다. 실패·거부도 기록해야 한다.
2. **실행 주체:** 여러 후보는 실행기가 모델 생성을 반복하고 결과를 집계한다. 도구 실행은 모델이 요청한 동작을 실행기가 검사한 뒤 도구에 넘기고 관찰을 돌려주는 것이다. 호출 수와 종료는 각 흐름에 맞게 관리한다. 이번 준비 도구는 두 흐름을 구현하지 않는다.
3. **같은 오답의 다수결:** 모든 후보가 잘못된 근거를 읽었다면 일관성만으로 현재 규정이 되지 않는다. 실제 조항·적용 시점·범위와 대조해야 한다. 금액이 같은 후보도 조건 누락 여부가 다를 수 있다.

Self-Consistency는 여러 추론 경로 샘플링 뒤 답을 집계하는 원 연구의 방법이다. “마음에 드는 후보 선택”과 동일시하지 않는다. 강의의 최종 후보 표는 개념을 읽기 위한 단순화이며 원 논문 재현 로그가 아니다. 내부 사고 전문을 제출받는 대신 최종 답·짧은 근거·원문 대조로 활동을 진행한다.

ReAct 설명은 행동과 관찰이 다음 판단에 연결되는 원리에 초점을 둔다. 이후 Single-Agent의 요청 Schema/Registry와 연결하되, 현재 문자열 준비 코드를 ReAct 실행기로 부르지 않는다. 검색을 여러 번 반복할 수 있으므로 무조건 일정한 총 호출 수로 외우게 하지 않는다.

## 4장 해설 · 평가와 회귀

1. **준비 수와 정답 수:** 55는 만들어진 입력 수이고 다섯 거부는 같은 공백 질문의 다섯 조건이다. 모델 응답·채점이 없으므로 정답률의 분자가 아니다. 사실 여섯 사례와 경계 행동 여섯 사례도 따로 평가한다.
2. **개발에 사용한 평가:** 같은 사례를 계속 보고 고쳤다면 공개 개발 회귀 집합으로 표시한다. 최종 구성 고정 뒤 별도로 마련한 미사용 질문과 독립 검토가 필요하다. 기존 집합도 과거 실패 재발을 확인하는 데 계속 쓸 수 있다.
3. **조건 누락:** 이 식비 질문의 필수 기준에 식사 제공 예외가 있으므로 금액·출처가 맞아도 그 항목은 보완 필요다. 키워드 존재만으로 전체 의미를 통과시키지 않는다.

전후 예의 식비 답은 필요한 조건을 추가해 개선되었지만 해외 숙박비는 없는 기준을 식비로 대체해 회귀했다. 변경 후 버전의 즉시 채택은 보류하고 자료 부족 지시·실제 입력/응답을 확인한 뒤 같은 사례와 정상 사실 사례를 다시 비교한다. 설명용 답안이므로 실제 지시 변경의 인과적 원인을 측정한 기록은 아니다.

## 실습 피드백과 완료 범위

| 활동 | 확인할 실제 기록 | 보완이 필요한 답 |
|---|---|---|
| 지시 비교 | 같은 질문/다섯 자료/예시0, 실제 지시 전후와 의미 | 구체적 지시가 더 길어서 품질 통과라고 단정 |
| 한 문장 추가 | 추가 이유·실제 변경 입력·본문 동일 True·문자 수 | 입력 검사를 답변 정답 검사라고 설명, 여러 조건 함께 변경 |
| 시범 비교 | 대출/벌금 시범·동일 실제 질문·길이/미확인 구분 | 시범의 10일을 현재 답으로 사용, 시범 답을 모델 응답으로 제출 |
| 답안/전략 판단 | 원문·누락/회귀 이유·다음 확인, 후보/도구의 증거 | 출처 이름만 채점, 식비로 숙박비 확정, 설명용 표를 실측으로 제출 |

학생의 각 개념 답에 **충족 / 보완 / 미제출**과 이유를 남긴다. 같은 표현을 복사했는지보다 설명·입력·관찰·판정이 연결되는지 확인한다. 실제 생성 환경이 없으면 입력 활동과 개념 판단의 완료를 인정하되 생성 비교는 미실행으로 남긴다. 최종 모델 품질이나 수업 전체 완료를 인정한 것이 아니다.

실제 생성이 준비되면 정상 사실 C01/C02/C05/C08/C09/C11과 나머지 경계를 분리한다. 실제 모델/리비전·Template·생성 설정·길이·질문/문서 버전과 원응답을 보존하고, 근거·조건·예외·불필요한 보류를 사람이 검토한다. 계약 데모나 후속 RAG의 다른 조건 결과를 이 비교에 섞지 않는다.

## 제작 관리 매핑

이 표는 학생용 학습 제목에 관리 ID를 다시 넣지 않고 기존 70개 성과를 연결하기 위한 것이다.

| 기존 단원 | 현재 본문 | 연결 실습 |
|---|---|---|
| K2-04.U01 지시·요청·제약·출력 계약 | 1장·규정/입력 전후/답안·코드·질문 | 활동1·활동2 |
| K2-04.U02 Zero/One/Few-shot 비교 | 2장·실제 시범/조립/길이·질문 | 활동3 |
| K2-04.U03 추론 기법과 실행 전략 | 3장·후보 판단/ReAct 흐름·질문 | 활동4의 전략 판단 |
| K2-04.U04 Golden Dataset과 회귀 | 4장·전후 답안/사실과 경계·질문 | 활동4·실제 생성 후 평가 표 |

원문·고정 자료·기존 Backend 계약과 입력 생성 코드는 보존한다. 현재 수업 방식은 대표본의 동일 작성자 검수이며, 후속 과목에는 실제 설명/예제의 연결 방식을 주제에 맞게 적용한다. 같은 표·문구를 일괄 복제하지 않는다.
