# PDF 추출·OCR·원문 대조 수업 해설

[본문](lesson.md)과 [연결 실습](../../practice/document-assistant/L8.md)의 질문·활동을 해설한다. 같은 작성자의 설명 검수와 실제 수업·독립 채점은 다르다. 문서 형식/코드 검사를 학생의 이해도 점수로 쓰지 않는다.

## 페이지 경로 선택

1. **직접 추출이 비었다는 것은 사용할 텍스트 층이 없다는 관찰이다.** 픽셀에는 글자가 있어 OCR이 읽을 수도 있다. 스캔을 보기 전에 ‘내용 없음’이나 ‘OCR 불가능’으로 끝내지 않는다. 반대로 텍스트 층이 있어도 이미지와 내용이 맞는지는 화면 대조가 필요하다.
2. **첫 장은 직접 추출되지만 두 번째 스캔 장을 놓칠 수 있다.** 이번 mixed.pdf는 실제로 직접 추출/OCR 경로가 나뉜다. 문서 전체에 하나의 분기를 쓰지 않고 페이지별 route와 결과를 확인한다. 같은 페이지의 이미지 영역 처리는 또 다른 문제다.
3. **현재 분기는 문자가 있으면 직접 추출하고 이미지도 있으면 시각 검토 표시를 붙인다.** 머리말만 추출해 놓고 본문 처리가 끝났다고 판단하면 안 된다. 영역별 OCR 합성·깨진 텍스트 층 판정·일반 페이지 구조 분석은 구현/검증하지 않았다. 직접 추출과 OCR의 입력을 구분해 설명하는지 본다.

실습에서 copy/paste 결과나 chars가 0이라는 관찰을 OCR 정답성과 동일시하지 않게 한다. 디지털과 스캔 예제는 전체 내용이 같지 않다. OCR 품질 비교는 동일 네 줄을 가진 scan/degraded 사이에서 한다.

## 읽기 순서와 표

1. **저장 순서·좌표 정렬·사람의 문단 읽기는 서로 다르다.** B1/B2를 먼저 쓴 PDF와 A1/B1/A2/B2로 합쳐진 줄을 보여준다. 수동 열 영역은 A1/A2와 B1/B2를 나눌 수 있지만 자동 단 검출이 아니다. 무엇을 기준으로 묶었는지 설명해야 한다.
2. **미사용 행의 부담금은 0원이고 15000원은 사용 이력 행의 부담금이다.** 숫자 문자열이 원문에 있다는 사실은 그 질문에 적용된다는 증거가 아니다. 머리글·행 조건·금액·표 영역/셀 좌표가 함께 필요하다. ‘기한 7일’을 모든 행으로 복사하는 식의 오류도 확인한다.
3. **단어 상자는 글자 위치이며 행·열 관계를 보장하지 않는다.** OCR가 모든 글자를 맞혀 CER=0이어도 열 순서가 섞일 수 있다. 이번 3×3 표 한 개의 일치를 병합 셀·여러 쪽 표·선 없는 표의 정확도로 확대하지 않는다. 줄 단위 검색과 표 별도 기록의 한계도 남긴다.

본문의 세 필드 JSON은 표에서 사람이 정리한 설명용 표현이다. 학생이 현재 normalize 출력이라고 말하면 실제 줄 출력과 다시 대조한다. ‘이 JSON을 만들면 모든 표 문제 해결’이라고 가르치지 않는다.

## OCR와 다른 시각 경로

1. **제목과 금액 오류는 같은 CER라도 실패 비용이 다르다.** 공백 제외 40문자에서 환→완 치환이나 15000→1500 한 자리 삭제 모두 1/40=2.5%다. 금액·기한·번호와 적용 조건을 별도로 확인해야 한다. Critical field 문자열 존재도 올바른 행/조건 연결 검사가 아니다.
2. **열화본에서 CER가 낮았다는 한 관측으로 흐림/회전을 권장할 수 없다.** 고정된 작은 합성 네 줄과 해당 엔진/언어/PSM의 결과다. 전처리는 같은 정답/평가 영역·조건으로 비교하고 원본 해상도에서 잃은 정보를 확대만으로 복원한다고 설명하지 않는다. Threshold 175에서 지표가 같았다는 사실도 그대로 남긴다.
3. **CLIP은 이미지/텍스트 표현의 매칭, 생성형 VLM은 시각 입력을 이용한 응답 생성, OCR-free 문서 모델은 별도 OCR 없이 문서 작업 출력을 만드는 경로다.** OCR 단계가 없다고 인식/관계/출력 오류 검수까지 없어지지 않는다. Layout-aware 모델은 문자·위치·이미지 입력과 Processor/좌표 규칙을 확인해야 한다. 이번에는 이 모델들을 실행하지 않았다.

CER는 NFC 뒤 공백 제외 한글 음절 문자, WER는 공백 토큰 편집이다. 한국어 형태소 오류율이나 의미 점수가 아니다. 엔진 Confidence도 정답 확률로 보정된 값이 아니다. 원문·정답 영역을 고정한 뒤 산출했고 정답을 OCR에 주지 않았음을 구분한다. 삽입이 많으면 편집 비율이 1을 넘을 수도 있다.

## 권한·지시문·원문 추적

1. **추출기는 문자열을 자료로 보존했고 LLM을 호출하지 않았다.** 이 사실은 후속 LLM의 Prompt injection 저항을 증명하지 않는다. 문서 안 지시로 권한·도구 실행 정책을 바꾸지 않으며 신뢰할 등록 정보의 권한과 문서 데이터를 구분한다.
2. **과거 검색이 허용됐어도 현재 파일/권한이 바뀌면 근거가 무효일 수 있다.** 원본 SHA·버전·Parser·현재 상태를 확인하고 바뀌면 재추출/재색인한다. 실습의 staff는 고정 교사 역할이며 실사용자 인증은 아니다. 거부가 파일 접근 전에 일어나는지도 확인한다.
3. **현재 Locator는 정규화 블록 전체의 위치다.** 서로 다른 열을 합친 줄도 같은 bbox로 돌아간다. 따라서 물리 위치가 있다고 문단 관계·의미가 맞거나 단어별 정확한 하이라이트까지 구현된 것은 아니다. PDF 물리 페이지와 인쇄 쪽 번호, OCR 줄 번호와 정규화 줄도 구분한다.

좌표 예는 595×842point→1785×2526픽셀로 가로·세로 비율이 각각 3이다. 픽셀 [135,240,435,300]은 point [45,80,145,100]이다. 회전/Crop/원점/UserUnit이 다르면 이 단순 비율을 그대로 쓰지 않는다. 현재 코드는 그 변형을 지원한다고 가정하는 대신 거부한다.

## 활동별 피드백

| 활동 | 충분한 근거 | 보완할 오해 |
|---|---|---|
| 유형과 경로 | 각 페이지의 텍스트/이미지·경로·누락 위험 설명 | 첫 장만 보고 전체 처리 성공으로 판정 |
| 표와 순서 | 미사용/0원 관계, B→A 저장과 수동 열/합쳐진 줄 대조 | 숫자만 발견하면 근거라고 주장 |
| OCR 오류 계산 | 같은 CER의 제목/금액 오류 영향 구분, 필드/관계 별도 확인 | Confidence나 평균 점수 하나로 승인 |
| 원문과 거부 | 현재 코드로 거부·정규 Locator·변경 감지 확인 | 저장 JSON 읽기를 현재 파일/권한 확인으로 표시 |

현재 직접 추출·저장 OCR 대조·새 OCR 실행을 제출물에서 구분한다. OCR 실행 환경이 없으면 저장 기록을 읽었다고 적게 하고 실제 OCR 과제 완료로 세지 않는다. 원본의 한글·표·배치를 화면과 대조하고 오류를 무조건 전처리나 모델 탓으로 단정하지 않는다.
