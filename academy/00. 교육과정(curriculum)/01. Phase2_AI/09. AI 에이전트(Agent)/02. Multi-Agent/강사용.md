# 역할 전달과 전체 예산의 해설

[강의](강의용.md)와 [실습](<../../../02. 실습/document-assistant/L6.md>)에 대응한다. 같은 작성자의 설명/코드/관찰 대조이며 독립 강사·교육생 수업 검증은 아니다.

## 개념별 질문 해설

### 1장

1. 호출 횟수만 늘린다고 역할 분리가 되지 않는다. 목표·필요 정보·허용 도구/행동·상태와 전달 책임이 달라야 한다. 같은 가중치를 순차 재사용할 수 있으며 별도 서버/독립 지능을 가정하지 않는다.
2. 검색의 검색/읽기/전달 3, 작성 1, 검토 1로 모델 5회다. 함수는 검색/읽기 2회다. Handoff 검증은 실행기 작업이며 별도 모델/도구 호출로 세지 않는다.
3. 과제를 못 끝냈다면 조기 중단/되묻기로 호출이 적어진 것이다. 품질·과제 완료를 확인하기 전 효율 향상으로 평가하지 않는다.

### 2장

1. 읽은 근거라도 수신 역할 허용 목록 밖이면 거부한다. M01은 작성자 범위가 비어 있어 HANDOFF_SCOPE를 반복하고 writer 호출 전에 끝난다.
2. 모델은 kind/handoff와 근거ID·부족정보 코드를 요청한다. 실행기가 실행/질문/역할·원문 상태/근거·실패·예산 기록을 만든다. 모델이 주장한 승인이나 예산으로 덮어쓰지 않는다.
3. 요약에 제한 본문/정보가 남을 수 있다. ID 필터만으로 자유 문자열 누출이 해결되지 않는다. 이번 구성은 허용ID로 원문을 확인하고 정해진 부족정보 코드를 사용한다.

### 3장

1. 공통 보완 1회를 썼다면 검토자에게 새 보완을 주지 않는다. 출력/전달 실패도 같은 보완을 쓴다. 역할별 새 예산을 주는 정책과 다르다.
2. 첫 빈 전달 1회에 재진입 후 검색/읽기/전달 3회를 더해 검색 4회다. 작성도 근거요청/초안 2회, 검토 1회로 총 7회다. 초기 호출을 지우면 실제 비용과 상한이 달라진다.
3. partial_draft는 진단용 부분 결과이고 정상 전달은 draft다. M03의 반복 검토 실패에서는 draft가 None이다. 검토 pass도 사용자 승인이나 독립 의미 검증을 뜻하지 않는다.

### 4장

1. 전체 8과 역할 4/2/3을 함께 검사한다. 역할 합 9를 전체 9로 바꾸지 않는다. 재시도 역시 실제 모델/도구 카운터에 들어가고 전체 재시도 1회를 공유한다.
2. A02는 실제 원문을 전달했지만 작성이 부적절하게 보류했고 검토가 기각해 최종 답을 못 냈다. 역할 도달·전달 경계 실행과 과제 성공이 다르다.
3. Probe는 Runtime이 별도로 준비한 근거를 쓴 개별 호출이다. 실제 검색자의 전달을 거친 통합 실행이 아니므로 통합 성공 수에 더하지 않는다.

## 활동 피드백

| 활동 | 충족 근거 | 보완이 필요한 해석 |
|---|---|---|
| Control | 검색 3/작성 1/검토 1, 도구 2, 승인false·사람 검토 초안 | 고정 응답을 모델 계획/품질로 표시 |
| M01/직접 코드 | 실제 읽은 ID와 수신 범위 비교, writer 호출 0 | 우선 넘기고 나중 필터, ID만 확인하면 요약 안전 |
| M02/M03/M04 | 재진입 누적 7/1, 반복 실패의 부분/최종 분리, 상한/가짜시계 구분 | 역할마다 새 보완/예산, 실제 240초 장애시험 주장 |
| 실제 C01/A02 | 도달한 역할과 실제 초안/원문·기각을 구분 | 빠른 되묻기를 품질 개선으로 평가 |
| Probe/비교 | 같은 18개 분모·다른예산/지시·개별호출 범위 | 역할 수만의 인과 효과나 독립 평가 주장 |

응답 전체가 정확히 하나의 JSON 코드 블록일 때 포장만 벗기고 같은 역할 Schema를 검사한다. Python·앞뒤 설명·여러 JSON의 임의 추출/실행이 아니다. 원응답과 파싱 후 행동을 구분한다.

직접 코드의 probes는 기존 경계 실험을 현재 Runtime/임시 SQLite/고정 벡터로 실행한다. 실제 모델·의미 검색·학습 증거가 아니다. 실제 모델 기록의 42호출·부분 6/전달 0은 과거 관찰이며 이번에 새로 생성한 수치가 아니다. 보조 Pydantic2.14.1과 고정 요구 2.14.2, 미실행 전체 Pytest/HTTP·교육장/독립 수업을 구분한다.

## 관리 연결

| 기존 단원 | 학생 장·활동 |
|---|---|
| K2-11.U01 역할 분리가 필요한 문제 | 1장 Control·역할 비용/목표 |
| K2-11.U02 역할별 상태·Tool·입출력 | 2장 수신 범위·Handoff·M01 |
| K2-11.U03 검토와 한 번의 보완 | 3장 M02/M03·부분 초안 |
| K2-11.U04 실패 전파와 동일 조건 비교 | 4장 M04·실제 18개/Probe |

관리ID는 이 표에 두고 학생 설명은 의미로 시작한다. 기존 품질 채택 보류·미완료 게이트를 설명 검수로 바꾸지 않는다.
