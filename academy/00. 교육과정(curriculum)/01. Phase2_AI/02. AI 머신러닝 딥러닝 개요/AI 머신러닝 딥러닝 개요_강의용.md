
# Phase 2 — 02. AI / 머신러닝 / 딥러닝 개요

## 개요

이 과목은 Phase 2에서 앞으로 배우게 될 Transformer, LLM, Fine-tuning을 이해하기 위한 **학습의 언어**를 만드는 과정이다. AI·Machine Learning·Deep Learning의 포함 관계만 외우는 것이 아니라, `Dataset → Training → Model → Inference → Evaluation`의 전체 흐름을 하나의 시스템으로 이해한다.

## 학습 목표

- AI, Machine Learning, Deep Learning의 포함 관계를 자신의 말로 설명한다.
- Sample, Feature, Label, Model, Parameter, Hyperparameter를 구분한다.
- Training과 Inference의 차이를 설명한다.
- Classification과 Regression의 대표적인 문제를 구분한다.
- Train/Validation/Test의 역할과 Data Leakage 위험을 설명한다.
- Loss, Optimization, Overfitting, Generalization의 관계를 설명한다.
- Precision, Recall 등 평가 지표를 업무 위험과 연결한다.

## Why

앞으로 Transformer와 LLM을 배울 때 `학습`, `Parameter`, `Loss`, `Pre-training`, `Evaluation`이라는 단어가 계속 등장한다. 이 기본 용어가 불명확하면 모델 구조를 배워도 각각의 단계가 왜 필요한지 연결하기 어렵다.

## Concept

핵심 개념은 `AI ⊃ Machine Learning ⊃ Deep Learning`의 포함 관계와, 머신러닝이 **데이터를 이용해 Model Parameter를 학습하고 새로운 입력에 일반화하려는 과정**이라는 점이다.

## Architecture

```text
문제 정의
→ Dataset 설계
→ Train / Validation / Test 분리
→ Training
→ Validation으로 선택
→ 잠근 Test로 최종 평가
→ Deployment
→ 새로운 입력에 Inference
→ Monitoring
```

## Example

아파트 가격 예측과 고객 문의 분류를 사용해 Sample, Feature, Label, Classification, Regression을 구분한다. 같은 원본의 복사본이 Train과 Test에 함께 들어가는 Data Leakage 사례도 분석한다.

## Practice

작은 Dataset에서 Feature/Label을 직접 구분하고, Rule-Based 방식과 Machine Learning 방식의 차이를 설계한다. 마지막에는 전체 학습·평가 Pipeline을 직접 만든다.

## Summary

이 과목의 목적은 알고리즘 목록을 외우는 것이 아니라 **데이터가 어떻게 Model의 Parameter 변화로 이어지고, 그 Model이 처음 보는 데이터에서도 잘 작동하는지 어떻게 검증하는가**를 이해하는 것이다.

## 실무 팁

분리 단위와 Seed를 학습 전에 고정하고 Test를 튜닝에 쓰지 않는다.

## 주의사항

점수는 독립 데이터와 실제 사용 조건을 함께 보고 해석한다.

뒤의 Transformer와 LLM도 규모와 구조는 훨씬 커지지만, 결국 이 학습·평가 흐름 위에서 이해할 수 있습니다.

## ① 문제 이해 (Why)

### 왜 AI, 머신러닝, 딥러닝을 구분해서 배워야 할까?

많은 사람들이 다음과 같이 말합니다.

> "AI랑 머신러닝이 같은 거 아닌가요?"
> 
> "딥러닝도 AI 아닌가요?"
> 
> "ChatGPT는 AI인가요, 딥러닝인가요?"

이 질문이 나오는 이유는 **세 용어가 서로 포함 관계**에 있기 때문입니다.

예를 들어,

사람에게 이런 질문을 해보겠습니다.

> 자동차는 탈것인가?

→ 맞습니다.

그렇다면

> SUV는 자동차인가?

→ 맞습니다.

그러면

SUV = 탈것일까요?

맞기도 하지만 정확하지는 않습니다.

왜냐하면

```text
탈것
 ├── 자동차
 │      ├── SUV
 │      ├── 세단
 │      └── 트럭
 ├── 비행기
 └── 배
```

SUV는 자동차의 한 종류이고,

자동차는 탈것의 한 종류입니다.

---

AI도 완전히 같습니다.

```text
AI
 └── 머신러닝
       └── 딥러닝
```

즉,

**딥러닝은 머신러닝의 한 종류이고,  
머신러닝은 AI의 한 종류입니다.**

---

### 왜 이런 기술이 필요했을까?

컴퓨터는 원래 스스로 배우지 못했습니다.

예를 들어

"사과를 찾는 프로그램"을 만든다고 생각해봅시다.

예전에는

```text
빨간색이면 사과

동그라면 사과

꼭지가 있으면 사과
```

처럼 사람이 규칙을 하나하나 만들어 주었습니다.

하지만 문제가 있습니다.

사과는

- 초록색도 있고
    
- 노란색도 있고
    
- 반쯤 가려질 수도 있고
    
- 밤에는 어둡게 보일 수도 있습니다.
    

규칙이 너무 많아집니다.

결국

> **사람이 모든 규칙을 만드는 것은 현실적으로 불가능하다.**

이것이 AI 발전의 출발점입니다.

---

## ② 개념 이해 (Concept)

### AI란 무엇인가?

AI(Artificial Intelligence)는

> **인간의 지능적인 작업을 컴퓨터가 수행하도록 만드는 기술의 총칭**입니다.

여기서 중요한 것은

AI는 **하나의 기술 이름이 아니라 큰 분야**라는 점입니다.

예를 들어

```text
운동
 ├── 축구
 ├── 야구
 ├── 농구
```

처럼

```text
AI
 ├── 규칙 기반 AI
 ├── 머신러닝
 ├── 딥러닝
 ├── 생성형 AI
 ...
```

입니다.

즉,

AI는 가장 큰 우산입니다.

---

### 머신러닝(Machine Learning)

머신러닝은

간단히 말하면

> **데이터를 이용해 예측이나 판단에 필요한 패턴을 모델의 Parameter로 학습하는 방법**입니다.

입문 단계에서는 이것을 “컴퓨터가 데이터에서 규칙을 찾는다”라고 표현해도 좋습니다. 다만 실제 구현에서는 사람이 작성한 `if` 문장 형태의 규칙이 생성되는 것이 아니라, **모델 내부의 Parameter가 데이터에 맞게 조정**됩니다.

여기서 가장 중요한 변화가 있습니다.

예전에는

```text
사람

↓

규칙 작성

↓

컴퓨터
```

였습니다.

머신러닝은

```text
데이터

↓

컴퓨터

↓

규칙 발견
```

입니다.

즉,

사람이 규칙을 만드는 것이 아니라

컴퓨터가 데이터를 보고 규칙을 학습합니다.

---

#### 예제

고양이 사진 100만 장을 줍니다.

컴퓨터는

처음에는 아무것도 모릅니다.

하지만

많은 데이터를 보면서

조금씩

"고양이의 공통점"

을 찾습니다.

이것이 머신러닝입니다.

---

### 딥러닝(Deep Learning)

딥러닝은

> **여러 층의 인공신경망을 이용해 데이터의 복잡한 표현(Representation)을 학습하는 머신러닝 접근**입니다.

`Deep`이라는 이름은 단순히 층 개수가 많다는 사실만 뜻하는 것이 아니라, 여러 단계의 변환을 거치며 **낮은 수준의 입력에서 작업에 유용한 내부 표현을 학습할 수 있다**는 점과 연결됩니다.

즉,

```text
AI

↓

머신러닝

↓

딥러닝
```

입니다.

딥러닝은 머신러닝에 포함되는 접근이며, 여러 층의 인공신경망을 이용해 복잡한 표현을 학습합니다. 모든 머신러닝 문제에 딥러닝이 더 좋은 것은 아닙니다. 데이터의 양, 문제의 복잡도, 설명 가능성, 계산 비용에 따라 전통적인 머신러닝이 더 적합할 수도 있습니다.

---

비유하면

초등학생에게 문제를 푸는 방법을 알려주는 것과 같습니다.

머신러닝은

> 중요한 특징을 사람이 어느 정도 알려줄 수도 있습니다.

딥러닝은

> 사람이 특징을 하나씩 지정하는 대신, 학습 과정에서 작업에 유용한 표현을 데이터로부터 함께 학습할 수 있습니다.

이 차이가 매우 큽니다.

---

## ③ 구조와 원리 (Architecture / Principle)

### 규칙 기반 AI와 머신러닝의 차이

먼저 가장 오래된 방식입니다.

```text
사람

↓

규칙 작성

↓

컴퓨터

↓

결과
```

예를 들어

```text
IF

온도 > 30도

THEN

에어컨 켜기
```

처럼 모든 규칙을 사람이 만듭니다.

이 방식은 단순한 문제에는 효과적이지만 복잡한 현실을 모두 표현하기는 어렵습니다.

---

### 머신러닝의 동작 원리

머신러닝은 흐름이 바뀝니다.

```text
데이터

↓

학습

↓

모델

↓

예측
```

예를 들어

학생의

- 공부 시간
    
- 출석률
    
- 과제 수행
    

데이터를 많이 학습하면

새로운 학생의 데이터를 보고

합격 가능성을 예측할 수 있습니다.

여기서 핵심은 **데이터로부터 패턴을 학습하는 것**입니다.

---

### 딥러닝의 동작 원리

딥러닝도 기본 흐름은 같습니다.

```text
데이터

↓

신경망

↓

학습

↓

모델
```

### 신경망 한 층에서는 무엇이 일어날까?

신경망을 단순히 “층을 많이 쌓은 것”이라고만 외우면 무엇을 학습하는지 알기 어렵습니다. 한 층의 핵심 흐름부터 살펴보겠습니다.

```text
입력값
→ 입력마다 Weight를 곱함
→ Bias를 더해 가중합 계산
→ Activation Function 적용
→ 다음 층으로 출력
```

- **Weight(가중치):** 각 입력을 얼마나 반영할지 조절하는 학습 가능한 값
- **Bias(편향):** 입력이 모두 0이어도 출력 기준을 이동시킬 수 있는 학습 가능한 값
- **Activation Function(활성화 함수):** 단순한 선형 계산을 넘어 복잡한 관계를 표현할 수 있게 하는 함수

예측이 정답과 다르면 Loss를 계산하고, **Backpropagation(역전파)**으로 각 Weight와 Bias가 Loss에 얼마나 영향을 주었는지 Gradient를 구합니다. Optimizer는 이 값을 이용해 Parameter를 조금씩 수정합니다.

```text
Forward Pass
입력 → 예측

Loss
예측 ↔ 정답 비교

Backpropagation
출력 쪽 오차 → 앞쪽 Parameter의 Gradient 계산

Optimization
Loss가 작아지는 방향으로 Parameter 갱신
```

역전파의 수학적 증명은 심화 과정에서 다루지만, 이 과목에서는 **신경망이 정답 문장을 통째로 저장하는 것이 아니라, Loss를 줄이는 방향으로 Weight와 Bias 같은 Parameter를 반복해서 조정한다**는 흐름을 이해하면 충분합니다. 역전파의 수학적 전개는 심화학습에서 다룹니다.

하지만 내부에서는 여러 층(Layer)을 거치며 점점 복잡한 특징을 학습합니다.

예를 들어 고양이 사진을 학습한다고 하면,

```text
입력 이미지
      │
      ▼
선(Line) 인식
      │
      ▼
모서리(Edge) 인식
      │
      ▼
눈·코·귀와 같은 부분 인식
      │
      ▼
얼굴 형태 인식
      │
      ▼
"고양이"로 판단
```

여기서 중요한 점은 **"눈을 찾아라", "귀를 찾아라"와 같은 규칙을 사람이 직접 작성하지 않는다는 것**입니다. 적절한 데이터와 학습 목표가 주어지면 신경망은 작업에 도움이 되는 표현을 학습할 수 있습니다. 다만 그림의 `선 → 모서리 → 부분 → 얼굴`은 이해를 위한 대표적 직관이며, 모든 신경망의 각 층이 사람이 이름 붙일 수 있는 특징을 정확히 하나씩 학습한다는 뜻은 아닙니다.

### AI는 왜 계속 새로운 기술이 등장했을까?

지금까지 우리는

AI,

머신러닝,

딥러닝의 차이를 배웠습니다.

그렇다면 하나의 질문이 생깁니다.

> 이미 머신러닝이 있었는데 왜 딥러닝이 등장했을까요?

그리고

> 딥러닝이 있었는데 왜 Transformer가 등장했을까요?

AI의 역사는

새로운 기술이 기존 기술을 완전히 없애는 과정이 아닙니다.

기존 기술이 해결하지 못했던 문제를 해결하기 위해

새로운 기술이 계속 등장하는 과정입니다.

---

### Rule-Based AI의 한계

초기의 AI는

사람이 직접 규칙을 만들었습니다.

예를 들어

```text
IF

비가 온다

THEN

우산을 추천한다.
```

또는

```text
IF

온도 > 38도

THEN

고열이다.
```

와 같이

모든 규칙을 사람이 작성했습니다.

이런 방식을

Rule-Based AI라고 합니다.

---

처음에는 잘 동작했습니다.

하지만 문제가 생기기 시작했습니다.

예를 들어

사람의 얼굴을 인식하려고 한다면

규칙을 어떻게 만들 수 있을까요?

```text
눈이 두 개이다.

↓

코가 가운데 있다.

↓

입이 아래 있다.
```

이런 규칙만으로는

수천만 명의 얼굴을 모두 구분할 수 없습니다.

규칙이 너무 많아지고

예외도 계속 생기게 됩니다.

---

결국

사람이 모든 규칙을 만드는 방식에는 한계가 있었습니다.

그래서 등장한 것이

Machine Learning입니다.

---

### 머신러닝은 규칙을 사람이 만드는 것이 아니라 AI가 학습한다.

Machine Learning에서는

사람이 규칙을 만드는 대신

데이터를 제공합니다.

예를 들어

수천 장의 고양이 사진과

수천 장의 강아지 사진을 보여주면

AI가 스스로

두 동물의 차이를 학습합니다.

즉,

```text
Rule-Based

사람

↓

규칙 생성
```

에서

```text
Machine Learning

데이터

↓

AI가 규칙 학습
```

으로 바뀐 것입니다.

이 변화는 AI 역사에서 매우 중요한 전환점이었습니다.

---

### 그런데 머신러닝도 한계가 있었다.

Machine Learning에서는

어떤 특징(Feature)을 사용할지

사람이 직접 결정해야 했습니다.

예를 들어

얼굴 인식이라면

사람이

```text
눈의 위치

코의 길이

입의 위치

얼굴 비율
```

같은 특징을

직접 설계해야 했습니다.

이 과정을

Feature Engineering이라고 합니다.

문제는

좋은 특징을 만드는 것이 매우 어렵다는 것입니다.

---

그래서 등장한 것이

Deep Learning입니다.

---

### 딥러닝은 특징까지 스스로 학습한다.

Deep Learning은

정답만 제공하면

어떤 특징을 사용할지도

AI가 스스로 학습합니다.

즉,

사람이

"눈의 위치"

"코의 길이"

를 알려주지 않아도 됩니다.

수많은 데이터를 학습하면서

AI가 가장 중요한 특징을 자동으로 찾아냅니다.

이 Representation Learning 능력은 이미지·음성·언어처럼 고차원 데이터에서 딥러닝이 강력한 성능을 보인 중요한 이유 중 하나입니다. 다만 모든 문제에서 딥러닝이 전통적인 머신러닝보다 항상 우수한 것은 아닙니다.

---

### 머신러닝에는 여러 학습 방법이 있다.

입문 강의에서는 머신러닝의 학습 방식을 **지도학습, 비지도학습, 강화학습**으로 자주 구분합니다. 이 구분은 큰 그림을 이해하는 데 유용하지만, 실제 연구와 실무에서는 경계가 더 복잡합니다.

예를 들어 Self-supervised Learning은 Label을 사람이 직접 붙이지 않지만 데이터 자체에서 학습 신호를 만들어 사용합니다. Semi-supervised Learning처럼 Label이 있는 데이터와 없는 데이터를 함께 쓰는 방법도 있습니다.

따라서 아래 세 가지를 “머신러닝의 유일한 세 종류”로 외우기보다 **대표적인 학습 패러다임**으로 이해합니다.

---

#### 지도학습(Supervised Learning)

가장 많이 사용하는 방식입니다.

정답(Label)이 함께 제공됩니다.

예를 들어

```text
사진

↓

고양이
```

```text
사진

↓

강아지
```

처럼

입력과 정답을 함께 학습합니다.

대표적인 활용 사례는

- 이미지 분류
    
- 스팸 메일 분류
    
- 가격 예측
    
- 수요 예측
    

등입니다.

---

#### 비지도학습(Unsupervised Learning)

이번에는

정답이 없습니다.

AI는

데이터의 패턴을

스스로 찾아야 합니다.

예를 들어

쇼핑몰 고객 데이터를 분석하여

비슷한 고객끼리 그룹을 만드는 것이 대표적인 사례입니다.

기업에서는 대표적으로 **고객 군집 분석**이나 데이터 구조 탐색에 사용할 수 있습니다. 이상 탐지와 추천 시스템도 비지도·자기지도·지도학습 등 여러 방식으로 구현될 수 있으므로, 특정 문제 영역을 한 학습 방식에만 고정해서 외우지는 않습니다.

---

#### 강화학습(Reinforcement Learning)

강화학습은

정답 대신

보상(Reward)을 받습니다.

예를 들어

로봇이

넘어지지 않고 걷는 방법을 학습한다고 생각해 봅시다.

성공하면

보상을 받고

실패하면

보상을 받지 못합니다.

이 과정을 반복하면서

가장 좋은 행동을 학습합니다.

대표적인 사례는

- 게임 AI
    
- 로봇 제어
    
- 자율주행
    
- 최적화 문제
    

등입니다.

---

### 딥러닝도 하나의 모델만을 의미하지 않는다.

딥러닝에는 문제에 따라 여러 **신경망 구조와 생성 방법**이 사용됩니다. 아래 CNN, RNN, Transformer, Diffusion을 완전히 같은 분류 기준의 형제 기술로 외울 필요는 없습니다.

- CNN, RNN, Transformer는 대표적인 신경망 Architecture 계열로 볼 수 있습니다.
- Diffusion은 데이터를 점진적으로 노이즈화하고 그 과정을 거꾸로 학습하는 **생성 모델링 접근**이며, 내부 신경망으로 U-Net이나 Transformer 계열이 사용될 수 있습니다.

이 과목에서는 “서로 다른 문제를 해결하기 위해 다양한 구조와 학습 방법이 발전했다”는 큰 그림을 잡습니다.

---

#### CNN

이미지를 잘 처리하기 위해 등장했습니다.

사진에서는

가까운 픽셀끼리

강한 관계를 가지고 있습니다.

CNN은

이러한 특징을 이용하여

이미지 인식 성능을 크게 향상시켰습니다.

대표적인 활용은

- 얼굴 인식
    
- 의료 영상
    
- 제조 불량 검출
    

등입니다.

---

#### RNN

문장을 처리하기 위해 등장했습니다.

문장은

순서가 중요합니다.

예를 들어

```text
나는

학교에

간다.
```

에서는

앞의 단어를 기억해야

다음 단어를 이해할 수 있습니다.

RNN은

이전 정보를 기억하면서

문장을 처리하려고 했습니다.

하지만

문장이 길어질수록

앞의 정보를 잊어버리는 문제가 있었습니다.

---

#### Transformer

이 문제를 해결하기 위해

Transformer가 등장했습니다.

Transformer의 핵심인 Self-Attention은 각 Token이 다른 Token들과의 관계를 직접 계산할 수 있게 합니다.

RNN처럼 이전 Hidden State를 한 단계씩 전달하는 구조와 달리, 학습 시 많은 Token의 관계 계산을 병렬화하기 쉽고 먼 위치의 Token 사이 관계도 직접 연결할 수 있습니다.

다만 Transformer가 **단어의 순서를 무시한다는 뜻은 아닙니다.** 위치 정보는 Positional Encoding 또는 RoPE 같은 위치 표현을 통해 모델에 전달됩니다.

이것이 바로

다음 시간에 배우게 될

Attention의 시작입니다.

---

#### Diffusion Model

최근에는

이미지를 생성하는 AI도 등장했습니다.

Diffusion Model은

무작위 노이즈에서 시작하여

조금씩 노이즈를 제거하면서

새로운 이미지를 생성합니다.

대표적인 이미지 생성 AI들이

이 방식을 사용하고 있습니다.

오늘 강의에서는

전체 흐름만 이해하면 충분합니다.

---

## 핵심 흐름 다시 정리

AI의 주요 발전 흐름을 학습용으로 단순화하면 다음처럼 볼 수 있습니다.

```text
Rule-Based System
      ↓
Machine Learning의 확산
      ↓
Deep Learning의 발전
      ↓
CNN / RNN 등 다양한 Architecture
      ↓
Transformer의 등장과 확산
      ↓
대규모 사전학습 모델 / LLM
      ↓
RAG · Tool Use · Agent 등 Application Architecture
```

이 그림은 **기술이 완전히 교체된 연대표가 아닙니다.** 오늘날에도 Rule-Based System, 전통적인 머신러닝, CNN, RNN은 문제에 따라 계속 사용됩니다.

핵심은 새로운 기술이 등장할 때마다 이전 기술을 없앴다고 보는 것이 아니라, **더 큰 데이터·더 복잡한 표현·새로운 문제를 다루기 위한 선택지가 늘어났다**고 이해하는 것입니다.

## ③-1. Training과 Inference를 구분하자

초보자가 가장 많이 섞어 쓰는 두 단어가 `학습(Training)`과 `추론(Inference)`입니다.

### Training

```text
Dataset
  ↓
Model이 Prediction 생성
  ↓
정답 또는 학습 목표와 비교
  ↓
Loss 계산
  ↓
Parameter 수정
  ↓
반복
```

Training에서는 모델의 Parameter가 바뀝니다.

### Inference

학습이 끝난 모델에 새로운 입력을 넣어 결과를 얻는 과정입니다.

```text
새로운 입력
  ↓
학습된 Model
  ↓
Prediction / Generated Output
```

일반적인 Inference에서는 모델의 Parameter를 다시 학습하지 않습니다.

예를 들어 ChatGPT에 질문을 입력해서 답을 받는 행위는 기본적으로 **Inference**입니다. 사용자가 채팅을 한 번 보냈다고 해서 그 순간 모델 전체가 다시 Training되는 것은 아닙니다.

### 왜 이 구분이 중요한가?

앞으로 다음 용어를 이해할 때 계속 등장하기 때문입니다.

```text
Pre-training      → Training
Fine-tuning       → 추가 Training
Prompt 입력       → Inference 때 제공하는 입력
RAG 검색 결과     → Inference Context 보강
Model 응답 생성   → Inference
```

## ③-2. Classification과 Regression

지도학습 문제는 처음에는 두 가지 대표 형태로 구분해 두면 이해하기 쉽습니다.

### Classification(분류)

정해진 Category 중 하나 또는 여러 개를 예측합니다.

```text
메일 → 스팸 / 정상
사진 → 고양이 / 강아지
문서 → 계약서 / 보고서 / 회의록
```

### Regression(회귀)

연속적인 숫자 값을 예측합니다.

```text
아파트 정보 → 예상 가격
과거 수요 → 다음 달 수요량
센서 정보 → 예상 온도
```

여기서 `회귀`라는 단어를 “과거로 돌아간다”는 일상어 뜻으로 이해하면 안 됩니다. 머신러닝에서는 **연속적인 수치 값을 예측하는 문제**를 뜻합니다.

이후 실제 모델과 Loss를 배울 때 Classification과 Regression에 따라 적절한 출력과 평가 지표가 달라진다는 점을 다시 보게 됩니다.

## ③-3. 가장 중요한 목표: Generalization

머신러닝이 잘되었다는 것은 Train Set을 외웠다는 뜻이 아닙니다.

```text
Train에서 잘 맞음
        +
처음 보는 현실 데이터에서도 잘 작동함
        =
좋은 Generalization
```

예를 들어 고양이 사진 1,000장을 정확히 외운 모델은 새로운 고양이 사진에서 실패할 수 있습니다. 우리가 원하는 모델은 **학습한 Sample 자체가 아니라, 새로운 Sample에도 적용되는 패턴**을 배운 모델입니다.

그래서 뒤에서 배우는 Train/Validation/Test, Overfitting, Data Leakage, Metric은 모두 결국 하나의 질문으로 연결됩니다.

> 이 모델이 실제로 처음 보는 데이터에서도 잘 작동한다고 믿을 수 있는가?

## ④ 관계 이해 (Relation)

지금까지의 관계를 하나의 그림으로 정리하면 다음과 같습니다.

```text
AI
│
├── 규칙 기반 AI
│
└── 머신러닝
      │
      ├── 지도학습
      ├── 비지도학습
      ├── 강화학습
      │
      └── 딥러닝
             │
             ├── CNN
             ├── RNN
             ├── Transformer
             └── Diffusion
```

여기서 앞으로의 커리큘럼과 연결하면,

- **Transformer**는 딥러닝 모델의 한 종류입니다.
    
- **LLM**은 Transformer를 기반으로 만들어진 대규모 언어 모델입니다.
    
- **RAG**, **Agent** 등은 LLM을 활용하는 응용 기술입니다.
    

즉, 앞으로 배우게 될 내용은 모두 이 구조 위에 쌓여 갑니다.

## ⑤ 적용 예시 (Example / Application)

AI, 머신러닝, 딥러닝은 각각 활용 범위가 다릅니다.

|분야|활용 예시|
|---|---|
|AI|게임 NPC, 전문가 시스템, 규칙 기반 자동화|
|머신러닝|스팸 메일 분류, 수요 예측, 추천 시스템, 이상 탐지|

예를 들어 이메일 서비스에서,

- 간단한 규칙으로 특정 문구를 차단하는 것은 **규칙 기반 AI**에 가깝습니다.
    
- 사용자의 행동 데이터를 학습해 스팸 여부를 예측하는 것은 **머신러닝**입니다.
    
- 이메일 내용과 문맥을 깊이 이해해 분류하거나 요약하는 것은 **딥러닝**이 사용될 수 있습니다.

## ⑤-1. Practice — 같은 문제를 Rule과 Machine Learning으로 설계해 보기

### 실습 목표

같은 업무라도 Rule-Based 방식과 Machine Learning 방식의 설계가 어떻게 달라지는지 구분합니다.

### 실습 환경

코드 없이 종이 또는 Markdown 표로 진행합니다.

### 문제

회사에 들어오는 이메일을 `긴급 / 일반`으로 분류한다고 가정합니다.

### 실습 절차

1. Rule-Based 방식으로 사용할 규칙을 세 개 작성합니다.
2. 규칙만으로 처리하기 어려운 예외를 세 개 작성합니다.
3. Machine Learning을 적용한다면 Sample, Feature, Label이 무엇인지 적습니다.
4. 새로 들어온 이메일을 분류하는 단계가 Training인지 Inference인지 판단합니다.

### 예상 결과

예를 들어 다음처럼 정리할 수 있습니다.

```text
Rule
- 제목에 [긴급]이 있으면 긴급
- 발신자가 대표이사이면 긴급

예외
- [긴급]이라는 단어가 인용문 안에만 있는 경우
- 대표이사가 단순 참고용 자료를 전달한 경우

Machine Learning
Sample = 이메일 한 통
Feature = 제목, 본문, 발신자, 시간 등의 입력 정보
Label = 긴급 / 일반
```

### 실습 확인

- Feature와 Label을 뒤바꾸지 않았는가?
- 실제 예측 시점에 알 수 없는 정보를 Feature로 넣지 않았는가?
- 새 이메일 분류를 “Training”이라고 잘못 부르지 않았는가?

# [보강 학습] “학습한다”는 말을 실제 데이터와 평가 과정으로 이해하기

앞에서는 머신러닝을 “데이터에서 규칙을 학습하는 방법”이라고 설명했습니다. 이 정의는 맞지만, 실제로 모델을 만들려면 더 구체적인 질문에 답해야 합니다.

- 데이터 한 건은 무엇인가?
- 모델은 데이터의 어떤 부분을 보고 무엇을 맞히는가?
- 틀렸다는 사실을 어떻게 숫자로 표현하는가?
- 이미 본 문제를 외운 것과 새로운 문제를 푸는 것을 어떻게 구분하는가?
- 좋은 모델이라는 판단은 무엇으로 내리는가?

이 질문을 이해하면 이후 Transformer와 LLM의 학습 과정도 훨씬 명확해집니다.

## 1. Sample, Feature, Label

아파트 가격을 예측하는 모델을 만든다고 생각해 보겠습니다. 데이터의 한 행에는 아파트 한 채에 관한 정보가 들어 있습니다.

| 면적 | 방 개수 | 건축 연도 | 역까지 거리 | 실제 거래 가격 |
|---:|---:|---:|---:|---:|
| 84㎡ | 3 | 2018 | 500m | 9억 원 |

이때 용어를 다음과 같이 구분합니다.

- **Sample:** 모델이 학습하거나 예측하는 한 개의 사례입니다. 위 표에서는 아파트 한 채가 Sample입니다.
- **Feature:** 예측에 사용되는 입력 정보입니다. 면적, 방 개수, 건축 연도, 역까지 거리가 Feature입니다.
- **Label:** 모델이 맞혀야 하는 정답입니다. 실제 거래 가격이 Label입니다.

스팸 메일 분류에서는 이메일 한 통이 Sample, 제목과 본문의 표현이 Feature, 스팸인지 아닌지가 Label이 됩니다. 생성형 AI의 사전학습에서는 문맥에 주어진 Token들이 입력 역할을 하고, 이어질 다음 Token이 정답 역할을 합니다.

Feature가 많다고 무조건 좋은 것은 아닙니다. 미래의 실제 예측 시점에는 알 수 없는 정보를 Feature로 사용하거나, 정답을 직접 드러내는 값을 포함하면 모델은 현실에서 사용할 수 없는 방법으로 답을 맞히게 됩니다. 이것이 뒤에서 다룰 Data Leakage와 연결됩니다.

### 질문 보강: Machine Learning, 지도학습, Dataset·Feature는 어떻게 연결되는가

입문 수업에서 자주 나오는 혼동을 하나의 아파트 가격 예제로 다시 정리한다.

```text
Dataset = 여러 Sample을 모은 자료
Sample = 한 채의 아파트에 대한 한 행
Feature = 예측 시 사용할 면적·방 수·위치 등의 입력 특성
Label = 학습 때 알려주는 실제 거래 가격
```

**Machine Learning**은 개발자가 `면적 1㎡당 얼마`라는 판단 규칙을 직접 고정하는 대신, 여러 Sample의 Feature와 Label에서 예측에 유용한 패턴을 학습하게 하는 접근이다. 학습되는 것은 소스 코드의 문장이 아니라 모델의 Parameter다. 데이터에 없는 새로운 아파트에도 이 패턴이 어느 정도 통하는지를 별도 Test에서 확인해야 한다.

**지도학습(Supervised Learning)**은 각 학습 Sample에 정답 역할의 Label이 있는 경우다. 가격 예측의 Label은 숫자이고, 스팸 분류의 Label은 `스팸/정상`과 같은 범주다. `Feature`와 `Dataset`은 같은 말이 아니다. Feature는 **한 Sample을 설명하는 입력 항목**, Dataset은 이런 Sample을 **여럿 모은 전체 자료**다. 학습 전에 Label을 모르거나 입력 Feature에 정답이 섞이면 문제 정의와 평가가 달라진다.

| 혼동하기 쉬운 문장 | 바로잡기 |
|---|---|
| “Dataset은 Feature 하나다.” | Dataset에는 여러 Sample이 있고 각 Sample은 여러 Feature를 가질 수 있다. |
| “지도학습은 사람이 `if` 규칙을 써 주는 것이다.” | 사람은 Label과 학습 절차를 제공하고 모델이 Parameter를 조정한다. |
| “Feature가 많으면 늘 더 정확하다.” | 누수·잡음·편향이 있으면 실제 예측 성능이 떨어질 수 있다. |

전통적인 머신러닝에서는 사람이 입력 Feature를 설계할 수 있고, 딥러닝에서는 신경망이 입력에서 유용한 내부 **Representation(학습된 특징 표현)**을 만들기도 한다. 어느 경우든 Dataset은 학습·평가에 쓰는 Sample의 모음이며, Feature 하나와 같은 뜻이 아니다.

이 관계를 이해한 다음 `Train/Validation/Test`와 `Data Leakage`를 읽으면, 왜 “학습 데이터에서 높은 점수”만으로 서비스 성능을 판단할 수 없는지도 설명할 수 있다.

## 2. Train, Validation, Test를 왜 나누는가?

학생에게 문제집 100문제를 주고, 시험에서도 똑같은 100문제를 낸 뒤 “이 학생은 새로운 문제도 잘 푼다”라고 판단할 수 있을까요? 학생이 풀이 원리를 배운 것이 아니라 답을 외웠을 수도 있습니다.

머신러닝도 같은 문제가 생깁니다. 따라서 일반적으로 데이터를 역할에 따라 나눕니다.

```text
Train Set
모델의 Parameter를 실제로 학습하는 데이터

Validation Set
학습 중 설정을 비교하고 모델을 선택하는 데이터

Test Set
모든 선택을 마친 뒤 최종 성능을 확인하는 데이터
```

Train Set은 문제집, Validation Set은 모의고사, Test Set은 최종 시험에 가깝습니다. Validation 결과를 보며 모델 구조나 Learning Rate를 계속 바꿀 수 있지만, Test Set까지 반복해서 확인하며 선택하면 Test Set도 사실상 학습 과정에 사용한 셈이 됩니다. 그러면 최종 점수는 새로운 현실 데이터에서의 성능을 정직하게 보여주지 못합니다.

데이터 분할은 무작위로만 하면 되는 것도 아닙니다. 시간에 따라 미래를 예측하는 문제는 과거 데이터로 학습하고 미래 구간으로 평가해야 합니다. 같은 사용자의 거의 동일한 문서가 Train과 Test에 동시에 들어가면 모델이 사용자의 표현을 외워 높은 점수를 받을 수 있습니다. 따라서 실제 서비스에서 만날 상황을 반영해 분할 기준을 설계해야 합니다.

## 3. Loss와 Optimization: 틀린 정도를 이용해 조금씩 고치기

모델은 처음부터 정답을 알지 못합니다. 처음에는 거의 무작위에 가까운 예측을 만듭니다. 학습이 가능하려면 예측이 정답과 얼마나 다른지 숫자로 계산해야 합니다. 이 숫자가 **Loss(손실)**입니다.

아파트 가격의 실제 정답이 9억 원인데 모델이 6억 원이라고 예측했다면 오차가 큽니다. 다음 예측이 8억 8천만 원이라면 오차가 작아졌습니다. 분류 문제에서는 정답 클래스에 얼마나 낮은 확률을 주었는지를 Loss로 표현할 수 있습니다.

학습의 전체 흐름은 다음과 같습니다.

```text
입력 데이터
→ 모델의 예측
→ 정답과 비교하여 Loss 계산
→ 어떤 Parameter가 오차에 영향을 주었는지 계산
→ Loss가 작아지는 방향으로 Parameter를 조금 수정
→ 많은 Sample에 대해 반복
```

Loss를 작게 만드는 Parameter를 찾는 과정을 **Optimization(최적화)**이라고 합니다. Gradient Descent는 현재 위치에서 Loss가 증가하는 방향을 계산한 뒤 반대 방향으로 조금 이동하는 대표적인 최적화 아이디어입니다.

여기서 **Parameter**와 **Hyperparameter**를 구분해야 합니다.

- Parameter는 모델이 데이터로부터 학습하는 값입니다. 신경망의 Weight가 대표적입니다.
- Hyperparameter는 학습 과정을 설계하는 사람이 정하거나 탐색하는 설정입니다. Learning Rate, Batch Size, Epoch 수 등이 대표적입니다.

Learning Rate가 너무 크면 최적 지점을 지나치며 학습이 불안정할 수 있고, 너무 작으면 학습이 지나치게 느리거나 좋지 않은 위치에서 멈출 수 있습니다.

## 4. Overfitting과 Underfitting

### Underfitting: 충분히 배우지 못한 상태

모델이 너무 단순하거나 학습이 부족해 Train Set에서도 성능이 낮은 상태입니다. 학생이 문제의 기본 개념조차 이해하지 못해 문제집과 시험을 모두 틀리는 상황에 가깝습니다.

### Overfitting: 학습 데이터를 지나치게 외운 상태

Train Set에서는 매우 높은 성능을 보이지만 새로운 Validation 또는 Test 데이터에서는 성능이 크게 떨어지는 상태입니다. 문제집의 답과 순서를 외웠지만 숫자나 표현이 달라진 문제는 풀지 못하는 상황과 비슷합니다.

```text
Underfitting
Train 성능 낮음 + Validation 성능 낮음

적절한 학습
Train 성능과 Validation 성능이 함께 개선되고 차이가 관리됨

Overfitting
Train 성능은 계속 좋아지지만 Validation 성능은 정체되거나 악화됨
```

과적합을 줄이기 위해 더 다양하고 대표성 있는 데이터를 사용하고, 모델 복잡도를 조절하고, Regularization을 적용하고, Validation 성능이 악화되기 전에 학습을 멈추는 Early Stopping 등을 사용할 수 있습니다. 어떤 방법이든 핵심은 “학습 데이터를 더 잘 외우는 것”이 아니라 “처음 보는 현실 데이터에서도 유효한 규칙을 배우는 것”입니다.

## 5. Data Leakage: 시험 답안이 학습 과정으로 새어 들어간 경우

Data Leakage는 모델이 실제 예측 시점에는 사용할 수 없는 정보나 평가 정답에 관한 정보를 학습 과정에서 보게 되는 문제입니다. 점수가 매우 높게 나오기 때문에 오히려 발견하기 어려울 수 있습니다.

예를 들어 퇴사 가능성을 예측하면서 Feature에 `퇴사 처리 완료일`을 넣었다면 모델은 미래를 예측한 것이 아니라 이미 일어난 결과를 읽은 것입니다. 문서 분류에서 원본과 거의 같은 복사본이 Train과 Test에 나뉘어 들어가도 Test 정답을 미리 본 것과 비슷한 효과가 생깁니다.

생성형 AI 평가에서도 Leakage는 중요합니다. 평가 문제와 정답이 모델의 학습 데이터에 포함되어 있었다면 Benchmark 점수가 실제 추론 능력을 과대평가할 수 있습니다. RAG에서는 평가 질문의 정답 문장을 사람이 검색 상위에 직접 고정해 두고 검색 성능이 좋다고 판단하는 것도 공정한 검증이 아닙니다.

Leakage를 예방하려면 다음을 확인합니다.

1. 각 Feature가 실제 예측 시점에 존재하는 정보인가?
2. 같은 사람·문서·사건의 유사한 Sample이 Train과 Test에 동시에 들어가지 않았는가?
3. 데이터 전처리 기준을 전체 데이터에서 먼저 계산해 Test 정보가 Train에 반영되지 않았는가?
4. Test 결과를 보며 모델을 반복 선택하지 않았는가?
5. 평가 문제와 정답이 모델이나 검색 시스템에 미리 노출되지 않았는가?

## 6. Accuracy 하나만 보면 왜 위험한가?

질병 환자가 100명 중 1명인 데이터를 생각해 봅시다. 모델이 모든 사람을 “정상”이라고 답하면 Accuracy는 99%입니다. 숫자만 보면 훌륭해 보이지만 환자를 한 명도 찾지 못하므로 실제 목적에는 실패했습니다.

분류 문제에서는 다음 지표를 함께 봅니다.

- **Precision(정밀도):** 모델이 양성이라고 판단한 것 중 실제 양성의 비율
- **Recall(재현율):** 실제 양성 중 모델이 찾아낸 비율
- **F1 Score:** Precision과 Recall을 함께 고려한 조화평균

스팸함으로 정상 메일을 보내는 피해가 크다면 Precision을 중요하게 볼 수 있습니다. 암 환자를 놓치는 피해가 크다면 Recall을 더 중요하게 볼 수 있습니다. 어느 지표가 항상 최고인 것이 아니라, 어떤 실수가 더 위험한지에 따라 기준이 달라집니다.

생성형 AI는 정답 하나와 정확히 일치하는지만으로 평가하기 어렵습니다. 같은 의미를 여러 표현으로 답할 수 있고, 내용이 자연스러워도 사실은 틀릴 수 있습니다. 그래서 이후 강의에서는 다음처럼 평가를 여러 층으로 나눕니다.

```text
모델 평가
답변의 정확성, 관련성, 안전성

검색 평가
필요한 근거 문서를 찾았는가?

시스템 평가
응답 시간, 비용, 오류율, 권한 준수

사람의 평가
실제 업무에서 유용하고 신뢰할 수 있는가?
```

## 7. Self-supervised Learning과 Transfer Learning

대규모 언어 모델은 사람이 모든 문장에 정답 Label을 붙여 학습시키기 어렵습니다. 대신 원래 데이터의 일부를 정답처럼 활용합니다. 문장의 다음 Token을 예측하거나 가려진 Token을 맞히는 방식이 대표적입니다. 이렇게 데이터 자체에서 학습 신호를 만드는 방식을 **Self-supervised Learning**이라고 합니다.

그렇게 넓은 데이터로 기본 능력을 배운 모델을 특정 작업에 재사용하는 것이 **Transfer Learning**입니다. 이미 언어 패턴을 배운 모델에 소량의 업무 데이터로 Fine-tuning을 수행하거나, Prompt와 RAG로 특정 업무에 적용할 수 있습니다. 처음부터 모든 언어 능력을 다시 학습하지 않고 기존 능력을 새 문제로 옮겨 쓰는 것입니다.

이 흐름은 다음 강의들과 직접 연결됩니다.

```text
Self-supervised Pre-training
→ 넓은 언어 능력을 가진 Foundation Model
→ SFT·Alignment 또는 Fine-tuning
→ Prompt·RAG를 이용한 업무 적용
→ 실제 데이터로 Evaluation
```

## Practice — 작은 Dataset의 책임 나누기

- **실습 목표:** Sample, Feature, Label과 Train/Validation/Test의 역할을 실제 표에서 구분한다.
- **실습 환경:** 위 아파트 표를 확장한 종이 표 6행. 실행 코드 불필요.
- **실습 절차:** 각 행을 Sample로 표시하고 Feature/Label 열을 구분한다. 같은 아파트의 복제 행이 Train과 Test에 동시에 들어갈 때 왜 문제가 되는지 설명한다.
- **예상 결과:** Dataset 전체와 개별 Feature를 구별하고, 복제 행은 Test 점수를 과대평가할 수 있다고 답한다.
- **실습 확인:** “가격”이 예측 입력에 섞여 있지 않은지, Test를 반복적으로 조정에 사용하지 않는지 확인한다.
- **응용 과제:** 시간 순서가 중요한 가격 예측이라면 무작위 분할 대신 어떤 평가 구간을 선택할지 제안한다.

## Practice 2 — 학습 파이프라인 전체 설계하기

### 실습 목표

하나의 머신러닝 문제를 `문제 정의 → Dataset → 학습 → 평가`의 전체 흐름으로 설계합니다.

### 실습 주제

`고객 문의를 환불 / 배송 / 상품문의 / 기타로 자동 분류한다.`

### 실습 절차

다음을 순서대로 작성합니다.

1. **Sample**: 데이터 한 건은 무엇인가?
2. **Feature**: 모델에 어떤 정보를 입력할 것인가?
3. **Label**: 정답 Category는 무엇인가?
4. **Train / Validation / Test**: 어떤 기준으로 나눌 것인가?
5. **Leakage 위험**: 실제 분류 시점에 존재하지 않는 정보가 들어가지는 않는가?
6. **Metric**: Accuracy만 보면 충분한가?
7. **Failure Cost**: 어떤 오분류가 업무에 가장 큰 피해를 주는가?
8. **Inference**: 운영 중 새로운 문의가 들어오면 어떤 흐름으로 처리되는가?

### 예시 흐름

```text
과거 고객 문의 + 사람이 확정한 문의 유형
        ↓
중복 제거 / 개인정보 처리
        ↓
Train / Validation / Test 분리
        ↓
Model Training
        ↓
Validation으로 설정 비교
        ↓
잠근 Test로 최종 평가
        ↓
배포
        ↓
새 고객 문의
        ↓
Inference
        ↓
예측 Category + Confidence
        ↓
불확실하면 사람에게 전달
```

### 예상 결과

교육생은 “모델 하나를 선택하는 것”보다 **데이터 정의와 평가 설계가 머신러닝 시스템의 핵심 일부**라는 점을 설명할 수 있어야 합니다.

### 실습 확인

- 같은 문의의 복사본이 Train과 Test에 동시에 존재하지 않는가?
- 상담사가 처리한 최종 결과처럼 미래에만 알 수 있는 정보가 Feature에 포함되지 않는가?
- Test 결과를 보며 계속 Hyperparameter를 수정하지 않는가?

### 응용 과제

이 분류기를 딥러닝 또는 LLM 기반으로 바꾸더라도 **변하지 않는 부분**과 **달라지는 부분**을 나눠 적어 봅니다.

## 보강 핵심 정리

1. Sample은 한 개의 사례, Feature는 입력 정보, Label은 맞혀야 할 정답이다.
2. Train은 학습, Validation은 선택과 조정, Test는 최종 검증에 사용한다.
3. Loss는 틀린 정도이고 Optimization은 Loss를 줄이도록 Parameter를 조정하는 과정이다.
4. Underfitting은 충분히 학습하지 못한 상태, Overfitting은 학습 데이터를 지나치게 외운 상태다.
5. Data Leakage는 현실에서 알 수 없는 정보나 평가 정답이 학습 과정에 들어가는 문제다.
6. 평가 지표는 업무에서 어떤 실수를 더 위험하게 보는지에 따라 선택해야 한다.

## 자신의 말로 답해 보기

1. Train, Validation, Test를 한 데이터로 사용하면 왜 모델 성능을 믿기 어려운가요?
2. Loss와 Accuracy는 각각 무엇을 말하며 왜 같은 개념이 아닌가요?
3. Train 성능은 계속 좋아지는데 Validation 성능이 나빠진다면 어떤 문제를 의심해야 하나요?
4. 퇴사 예측에 퇴사 처리 완료일을 사용하는 것이 Data Leakage인 이유는 무엇인가요?
5. 환자가 매우 적은 질병 예측에서 Accuracy 99%가 실패일 수 있는 이유를 Precision과 Recall 관점에서 설명해 보세요.

## 짧은 확인 활동

스팸 메일 분류 모델을 만든다고 가정하고 다음을 직접 적어 보세요.

1. Sample 한 개는 무엇인가?
2. 사용할 수 있는 Feature 세 개와 Label은 무엇인가?
3. 같은 사람이 보낸 거의 동일한 메일이 Train과 Test에 동시에 들어가면 왜 문제인가?
4. 정상 메일을 스팸으로 보내는 실수와 스팸을 놓치는 실수 중 어느 쪽이 더 위험한가?
5. 그 판단에 따라 Precision과 Recall 중 무엇을 더 우선할 것인가?

## 실무 팁

- 모델 구조보다 먼저 **무엇을 예측할지**, Sample의 단위와 실제 예측 시점에 알 수 있는 Feature를 정한다.
- Train/Validation/Test 분리는 모델을 만든 뒤가 아니라 **학습 전에 설계**한다.
- 같은 사용자·같은 문서·같은 사건에서 나온 거의 동일한 Sample은 그룹 단위 분리를 검토한다.
- 정답이 희귀한 문제는 Accuracy 하나만으로 성공을 판단하지 않는다.
- Offline Test 점수가 좋아도 실제 서비스 입력 분포가 달라질 수 있으므로 배포 후 Monitoring이 필요하다.
- 딥러닝이 가능하다는 이유만으로 항상 딥러닝을 선택하지 않는다. 데이터 양, 비용, 설명 가능성, Latency와 유지보수까지 함께 본다.

## 주의사항

- `Parameter`는 개발자가 직접 작성한 `if` 규칙과 같지 않다.
- “AI가 스스로 학습한다”는 표현은 사람이 아무 설계도 하지 않는다는 뜻이 아니다. 데이터, 목표, 모델, Loss, 평가 과정은 사람이 설계한다.
- “딥러닝은 Feature Engineering이 필요 없다”라고 단정하지 않는다. 입력 전처리와 데이터 표현 설계는 여전히 중요할 수 있다.
- Transformer가 순서를 무시한다고 설명하지 않는다. 위치 정보는 별도로 모델에 전달된다.
- Dataset 분할은 행 수만 맞추는 작업이 아니라 실제 서비스에서 만날 입력을 재현하는 설계다.
- Benchmark나 Test 점수는 데이터 누출과 분포 차이를 확인하지 않으면 실제 성능을 과대평가할 수 있다.
