# 강사용 해설 · 데이터 설계와 평가

교육생의 기본 읽기는 [강의](강의용.md) → [활동지](활동지.md)다. CSV·검사 코드·제작 JSON은 필수 선행 자료가 아니다. 이 문서는 같은 제작 세션의 예시 답안과 검토 기준이며 독립 강사/교육생 수업을 수행한 결과가 아니다.

## 진행과 피드백

1. ‘환불 승인’과 ‘전문 담당자 추가 확인’을 구분하게 한다. Label 0도 상담 직원의 검토용 초안임을 확인한다.
2. 예측 시점에서는 먼저 예측 시점을 말하게 하고, 그 시점에 없는 열을 지우게 한다. 학습용 Label 사용과 평가 입력의 정답 노출을 구분한다.
3. 데이터 제작에서는 실제 수집 대신 합성 사례로 라벨 지침·출처/분리·증강을 설계하게 한다. G01-a/b를 다른 분리에 배치하는 반례와 G05/G11의 의미상 유사성을 비교한다.
4. Loss 해석에서는 최저 Train Loss가 아니라 Dev와 업무 목표에 근거해 선택 후보를 설명하게 한다. 실제 실험과 가상 표를 구분하게 한다.
5. 지표 계산은 양성 정의 → 네 칸 집계 → 식 → 업무 영향 순서로 진행한다. 계산기를 사용해도 된다. 점수 합계로 금지 행동을 상쇄하지 않는다.

현재 측정한 학습 시간이나 도움 횟수는 없다. 독립 수업에서 막힌 용어·작성 시간·판정 불일치·보완 횟수를 기록한다.

## A · 입력 시점표의 예시 답

예측은 질문 접수 후 전문 담당자 검토 전이다. Sample은 질문 한 건이며 Label 1은 추가 확인 필요, 0은 허용 규정 안내 초안 가능이다.

| 항목 | 판단 |
|---|---|
| 질문 본문 | 현재 이용 가능한 입력. 불필요한 식별정보를 제거한다 |
| 허용된 현행 규정 | 권한·버전·적용 시점을 확인한 입력 맥락 |
| 아직 확인하지 않은 사용 여부 | 실제 값을 지어내지 않는다. 미확인으로 두고 필요한 경우 추가 확인 |
| 확정 금액·연결 완료 | 판단 뒤의 결과이므로 현재 입력에서 제외 |
| needs_escalation·label_basis | 목표·해설. 학습에서 목표를 이용할 수 있지만 평가 입력에 함께 보여주지 않는다 |
| root_group·split | 관리·분리용이며 모델 입력에서 제외 |

다른 업무에서는 입력의 생성 시각이 달라질 수 있다. 그 업무의 예측 시점과 생성 절차를 일관되게 설명하면 다른 답을 인정한다. ‘파일에 있는 값이므로 쓸 수 있다’는 이유만으로 인정하지 않는다.

## B · 라벨과 분리·증강의 예시 답

| 질문 | 예시 판정 |
|---|---|
| 일반 기간·미사용 조건만 요청 | 0. 허용된 A v2에 명시된 조건을 안내한다 |
| 4일·미사용이지만 정확한 금액 확정 요청 | 1. 기간 조건과 별개로 금액 근거가 없다 |
| 권한 없는 B 본문 요청 | 1. 추가 확인 경로로 보내되, 본문은 분류 결과와 무관하게 접근 차단 |
| 빈 입력 | 제작 단계에서는 라벨 보류/사용 제외 후 재수집. 실제 서비스에서는 재질문·중단 등 사전에 정한 처리가 필요하다. 빈 입력을 조용히 0으로 넣지 않는다 |

G01-a/b는 원본 계보를 공유하므로 같은 분리에 둔다. 새 문서 성능을 보고 싶다면 PDF 원문·조각·개정본을 같은 계열로 묶는다. G05/G11처럼 다른 계보지만 의미가 비슷한 경우는 자동 그룹 검사만으로 해결되지 않는다. 새 문의 유형 평가가 목적이면 유사성 검토 후 병합/제외하고 분포·그룹 배치를 다시 확인하는 답을 인정한다. 현재 12/6/6행 수를 억지로 유지할 필요는 없다.

모든 업무가 무조건 문서 ID만으로 분리되어야 하는 것은 아니다. 같은 규정을 아는 상태의 새로운 문의와 새로운 규정 문서를 읽는 능력은 평가 목적이 다르다. 고객/시간 의존성도 목적에 따라 반영한다. 여기의 작은 예제를 일반화 성능 입증으로 채점하지 않는다.

Test를 보고 수정하는 것은 허용하되 이제 개발 판단에 사용된 자료임을 기록해야 한다. 새 구성의 독립 평가에는 별도로 분리한 자료가 필요하다. 평균/특징 선택처럼 자료에서 배우는 전처리는 Train에 맞추고 Dev/Test에는 같은 변환을 적용한다.

증강은 그룹·분리를 정한 뒤 Train에서 추가한다. 부모/그룹·변형 방법·검토를 남긴다. 정확한 환불액 요구를 말만 바꾸면 Label 1 유지 후보지만, 일반 조건 문의에 금액 확정/승인 요구를 추가하면 Label을 다시 판정해야 한다. 모델 생성 문장을 자동 정답으로 받지 않는다. 독립 정보가 늘었다고 행 수만으로 판단하지 않는다.

카드 요약에는 과제·언어·출처/사용 범위·입력/Label·지침/보류·계보/분리·품질/편향·버전/담당/제외를 확인한다. 실제 고객 자료를 수집하지 않았고 독립 라벨 일치도도 미측정이라고 적은 답은 미실행을 정확히 구분한 것이다.

## C · Loss 해석과 통제

가상 표에서는 2회차가 Dev Loss 기준 후보가 된다. 3회차의 Train 감소/Dev 증가가 과적합 징후지만 원인을 확정하지 않는다. 데이터 누수·분포/라벨 문제·평가 코드/조건 변화·작은 표본의 변동 등을 추가 확인할 수 있다. 실제 서비스 채택에는 업무 오류와 금지 행동 검토가 남는다.

높은 경계 기준 조건과 낮은 경계 비교 조건은 같은 가상 Dev 점수·목표·입력·정답·평가 지표·오류 가중치를 고정하고 임계값만 0.70에서 0.30으로 바꾼다. 실제 모델 학습은 없다. 여러 조건을 함께 바꾼 비교는 최종 구성의 차이를 관찰할 수 있지만 특정 변경 하나의 효과로 귀속하기 어렵다. 원본 조건으로 돌아가 한 조건씩 비교하거나 설계된 다중 조건 실험이 필요하다.

시드 고정 외에도 데이터/분리·모델/코드 버전·설정·장비·실행 상태를 기록하는 답을 인정한다. 시드 하나로 모든 실행의 완전 동일성을 주장하면 보완한다.

## D · 계산 해설

예측 1은 가상 점수 ≥ 임계값이다. 양성은 추가 확인 필요다. 0.30에서 D04도 양성으로 들어간다. 혼동행렬의 행/열을 바꿔 그려도 의미와 집계가 명확하면 인정한다.

| 결정 | TP | FP | FN | TN | Accuracy | Precision | Recall | F1 | 10FN+FP |
|---|---|---|---|---|---|---|---|---|---|
| 항상 0 | 0 | 0 | 4 | 16 | 16/20 = 80% | 0/0 · 미정의 | 0/4 = 0% | 0/4 = 0% | 40 |
| 0.70 | 2 | 1 | 2 | 15 | 17/20 = 85% | 2/3 ≈ 66.7% | 2/4 = 50% | 4/7 ≈ 57.1% | 21 |
| 0.30 | 4 | 4 | 0 | 12 | 16/20 = 80% | 4/8 = 50% | 4/4 = 100% | 8/12 ≈ 66.7% | 4 |

F1 식은 2TP/(2TP+FP+FN)이다. 항상 0에서 Precision은 미정의지만, 정답 양성 4개가 있으므로 F1의 분모는 4이고 F1=0이다. 정답·예측에 모두 양성이 없는 별도 사례라면 이 식의 분모도 0이어서 미정의로 기록한다. 정의되지 않은 값을 무조건 좋은 성적으로 바꾸지 않는다.

높은 Recall을 우선하고 예시 가중치를 받아들이면 0.30은 추가 비교 후보가 된다. 실제 인력 부담이나 오류 영향이 다르면 선택이 달라질 수 있다. 어떤 임계값이든 Dev 예시로 고른 결정을 고정한 뒤 새로운 평가와 업무 검토가 필요하다고 설명해야 한다. ‘더 낮은 임계값이 항상 좋다’는 답은 보완한다.

금지 행동의 예는 B 본문 노출, 근거 없는 금액 확정, 승인/송금/고객 발송의 무검토 자동 실행이다. 표의 분류 지표와 별도 기준으로 두고 발생 시 보류·수정·재검증한다. 분류 정답과 실제 응답 안전성이 다를 수 있음을 확인한다.

## 제출물 검토 기준

항목별 **충족 / 보완 / 미제출**과 근거를 기록한다. 동일 문구가 아니라 의미·조건·증거의 연결을 본다. 자신의 업무로 바꾼 설계는 시점·권한·목표가 일관되면 인정한다. 수치 표 D의 입력은 동일하므로 계산 결과는 위와 일치해야 한다.

| 단원 | 충족 조건 | 필수 보완 사례 |
|---|---|---|
| 예측 시점 | 예측 시점과 입력/Label/관리용 열을 구분하고 미확인을 처리함 | 미래 결과나 Label 해설을 평가 입력에 포함 |
| 데이터 제작 | 출처·지침·보류·계보/분리·증강·카드·제외/변경을 연결함 | 원본/변형을 다른 분리에 두고 독립 성능 주장, 권한 없는 자료 사용, Test 조정 뒤 최종 성적 주장 |
| Loss 해석 | Loss와 업무 목표를 구분하고 고정/변경 조건·미실행을 기록함 | 낮은 Train Loss만으로 품질 채택, 여러 변경의 효과를 하나로 단정 |
| 지표 계산 | 양성을 정의하고 네 칸·지표·분모 0·오류 영향·금지 행동을 설명함 | Accuracy만으로 채택, F1을 산술평균으로 계산, 가상 점수를 실제 성능으로 주장 |

이번 자료는 같은 제작 세션에서 검토했다. 자동 검사는 수량·계보·계산 오류를 찾는 보조이며 교육생의 업무 설계나 정답 라벨의 의미를 독립적으로 판정하지 않는다. 독립 강사 검토·학습자 이해도·교육장 실행·실제 모델 품질은 후속 검증이다.

## 이해 확인의 해설 — 판단 이유를 확인한다

### 예측 시점과 입력

1. 확정 금액은 예측 뒤에 생긴 결과라서 실제 예측 때 이용할 수 없다. 과거 파일에 존재한다는 사실과 현재 판단에서 사용할 수 있다는 것은 다르다.
2. 질문·그때 허용된 현행 규정만 입력에 넣고 정답과 해설은 비교용으로 분리한다. 학습에서 Label로 오차를 계산하는 것은 정상이며, 정답을 평가 입력에 보여주는 누수와 구분한다.
3. 사용 여부를 추정해 사실처럼 넣지 않는다. 결론에 필요한 정보가 빠졌다면 미확인으로 남기고 추가 질문·담당자 확인으로 처리한다. 단순 일반 조건 안내와 개인별 결론 요구도 구분한다.

### 데이터 제작과 분리

1. 표현은 달라도 같은 원본의 변형이다. 둘을 같은 원본 가족/같은 분리에 둔다. 정확히 같은 문장만 제거하는 검사로는 충분하지 않다.
2. 현재 자료는 같은 A v2에 대한 문의 분리다. 새 문서 성능을 입증하지 않으며 G05/G11 등의 유사 질문도 남아 있다. 계보 검사와 의미 검토의 범위를 구분한다.
3. Test를 개발 판단에 사용했다고 남긴다. 수정 구성을 고정하고 목적에 맞는 별도 평가 자료를 준비한다. 같은 Test를 새 독립 성적으로 재사용하지 않는다.

### 일반화와 통제

1. Train은 0.18 감소했지만 Dev는 0.23 증가했다. 과적합 징후를 의심하되 작은 가상 표에서 원인은 확정할 수 없다. 오류 사례·라벨/분포·평가 조건을 확인한다. 2회차는 Dev Loss 기준 비교 후보이며 운영 승인과 다르다.
2. 학습이나 점수 산출은 하지 않았다. 같은 가상 점수에서 예측 0/1을 나누는 경계만 바꿨다. 점수·정답은 그대로이고 판정 규칙이 달라진다.
3. 여러 조건이 함께 달라져 특정 변경 하나의 효과로 귀속할 수 없다. 원래 조건에서 한 조건씩 비교하거나 설계된 다중 조건 실험이 필요하다.

### 지표와 영향

1. ≥ 규칙이므로 점수 0.30은 임계값 0.30에서 예측 1, TP다. >로 바꾸면 이 행을 놓쳐 TP 3·FP 4·FN 1·TN 12, Recall 75%, 오류 가중 합 14가 된다. 이는 오산의 결과이지 새로운 모델 성능이 아니다.
2. 정답 0이 16개라 모두 0으로 답해도 정확도 80%다. 필요한 확인 네 개는 모두 놓친다. Precision은 0/0으로 미정의지만 F1 식의 분모에는 FN 4가 있어 0/4=0이다. 지표별 분모를 따로 확인한다.
3. 같은 가상 Dev에서만 FN 0이다. 검토가 3건에서 8건으로 늘고 실제 처리량은 미측정이다. 새로운 평가·권한/내용/금지 행동 검토가 남는다. 작은 표의 Recall 100%를 실제 무누락 보장으로 해석하면 보완한다.

## 활동 피드백과 선택 코드 확인

Sample·Feature·Label을 서로 다른 파일 이름으로만 설명하면 한 질문에서 입력과 목표를 다시 짚게 한다. 문의 내용보다 G01 같은 표식을 먼저 외우게 하지 않는다. 실제 열 이름은 CSV를 찾아 대조할 때 의미와 함께 사용한다. 원본과 변형을 같은 분리에 두어도 평가 목적·의미 유사성의 한계가 남는지 확인한다.

계산이 틀리면 전체 합 20·TP+FN=4·FP+TN=16을 먼저 확인하고 경계와 행별 예측을 되짚는다. 검토량 증가는 총5건이며 TP는2건, FP는3건 증가했다. 오류 가중치 10과1은 가정값이므로 실제 비용으로 설명하지 않는다.

선택 명령은 표준 라이브러리 검사기이며 고정24행 계보·20행 산술·메모리 오류 변형을 검사한다. JSON 통과를 모델/권한 구현·의미 독립 검수나 학습자 수업 통과로 채점하지 않는다. 실행하지 않아도 손계산과 판단 근거로 필수 활동을 수행할 수 있다.
