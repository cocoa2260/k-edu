# Day 2 - 7교시. Ollama로 Local LLM 직접 실행하기 실습

## 개요 — 이번 교시는 설계도가 아니라 실제 실행 상태를 확인한다

6교시에서는 애플리케이션이 모델을 직접 실행하는 방식과 별도의 Runtime이 모델을 제공하는 방식을 비교했습니다. 이번 교시는 그 설명을 다시 하는 시간이 아닙니다. **학생 PC에 Ollama를 준비하고, 승인된 모델 하나를 다운로드·실행한 뒤, 저장 상태와 실행 상태를 직접 확인**합니다.

이번 교시의 실습 기록은 다음 질문에 답할 수 있어야 합니다.

- `ollama --version`이 동작하면 모델까지 설치된 것인가?
- 모델을 `pull`한 직후와 `run`한 직후, `ls`·`ps` 출력은 어떻게 달라지는가?
- 채팅 화면을 나간 뒤에도 모델 파일과 실행 상태가 항상 같은가?
- 모델을 메모리에서 내리는 것과 저장소에서 삭제하는 것은 어떻게 다른가?
- 동일 모델을 사용하더라도 현재 대화 Context에 따라 어떤 차이가 생길 수 있는가?

**오늘의 경계:** Terminal에서 Ollama의 상태와 Local Inference를 관찰하는 데 집중합니다. Python의 HTTP 요청 작성, FastAPI Route, Ollama API의 요청·응답 JSON 구현은 **8교시**에서 진행합니다. Model Serving의 구조적 장단점은 **6교시**에서 이미 다뤘으므로 여기서는 실제 명령의 결과로만 확인합니다.

> **실습 전제:** 아래 `MODEL_NAME`은 명령어에 그대로 입력할 문자가 아니라 **강사가 교육장 장비에서 검증하여 공지할 실제 Ollama 모델 태그**를 의미합니다. 강사는 모델 이름뿐 아니라 버전/태그와 테스트 장비를 고정해야 합니다. 이 문서는 원본 교육과정 자료를 근거로 작성했으며, 실제 서비스·모델의 시점별 지원 상태를 새로 확인한 문서는 아닙니다.

## 1. 학습 목표와 완료 기준

학생은 실습 종료 시 다음을 수행하고 **관찰한 근거**를 남깁니다.

1. Ollama CLI가 설치되어 있고 실행 가능한지 확인한다.
2. 강사가 지정한 모델을 받아 Local Storage에 존재하는지 확인한다.
3. 지정한 모델로 Local LLM 대화를 시작하고 두 차례 이상 Prompt를 보낸다.
4. 독립된 새 대화에서 Context의 영향을 비교한다.
5. `ollama ls`와 `ollama ps`의 출력 목적을 구분한다.
6. `stop`, `rm`, `/bye`가 무엇을 종료하거나 제거하는지 구별한다.
7. Local Inference 전후의 CPU·Memory·GPU 상태를 관찰한다.
8. 실패 시 설치·모델 다운로드·모델 로딩·대화 단계 중 어디에서 문제가 생겼는지 판단한다.
9. 8교시에서 사용할 모델을 **삭제하지 않고 보존**한다.

**완료의 증거:** 실행한 명령, 명령의 출력 또는 상태, 관찰 시점, 오류가 있었다면 원인 판단을 기록한 실습표입니다. AI의 설명이 유창한지만 보고 실습 완료로 판정하지 않습니다.

## 2. 수업 시작 전에 준비해야 할 환경

### 학생 PC 준비 조건

- Windows, macOS 또는 Linux 중 Ollama 설치가 가능한 운영체제
- Terminal/PowerShell 실행 권한
- 수업 모델 파일을 저장할 여유 Disk Space
- 해당 모델을 실행할 수 있는 RAM 및 CPU, 필요한 경우 GPU
- **최초 모델 다운로드**에 사용할 인터넷 연결
- 강사가 결정한 실제 Ollama 모델 이름과 태그

GPU가 없다고 모든 실습이 실패하는 것은 아닙니다. 다만 CPU로 실제 실행할 수 있는지는 선택한 모델의 요구 자원과 교육장 환경에 달려 있습니다.

### 강사가 수업 전에 고정할 값

| 항목 | 강사 기록 | 학생에게 중요한 이유 |
|---|---|---|
| 운영체제 및 Ollama 버전 | `________` | 명령과 화면 차이를 확인하기 위해 |
| 실습 모델 이름/정확한 태그 | `________` | 학생마다 다른 모델을 내려받지 않도록 |
| 모델 다운로드 크기 | `________` | 저장 공간과 시간을 예측하기 위해 |
| 최소 확인 RAM/권장 실행 장비 | `________` | 실행 가능 여부를 미리 판정하기 위해 |
| 모델 License 및 사용 조건 확인 | `________` | 교육 목적으로 이용 가능한지 확인하기 위해 |
| 한국어 Prompt 응답 사전 검증 | `________` | 수업 활동이 가능한지 확인하기 위해 |
| `pull`·`run`·`ps`·`stop` 시연 검증 | `________` | 학생에게 전달할 실행 순서를 확인하기 위해 |
| 다음 8교시에서 사용할 모델 보존 | `예 / 아니오` | 불필요한 재다운로드를 방지하기 위해 |

4교시에서 수행했던 Model Card·License·자원 검토를 **다시 이론으로 설명하지 않습니다**. 이미 선정된 모델과 그 판단 근거를 이번 실습의 입력으로 사용합니다.

**사전 점검이 불가능한 경우:** 모델 실행 성공을 전제로 수업을 진행했다고 기록하지 않습니다. 모델을 선정하지 못했다면 설치 확인·명령 체계 읽기·예상 상태표를 먼저 연습하고, 실제 모델 실습은 미완료로 표시합니다.

## 3. 준비 상태 확인 — Terminal에서 Ollama가 보이는가?

### 3.1 설치

Ollama는 강사가 안내하는 **공식 설치 배포 경로**를 통해 설치합니다. 원본 강의에서는 Windows·macOS·Linux 설치를 대상으로 안내합니다. 운영체제별 설치 화면과 방법은 달라질 수 있으므로 임의의 오래된 명령이나 비공식 파일로 대체하지 않습니다.

설치 완료 후에는 **새 Terminal**을 열고 다음을 실행합니다.

```bash
ollama --version
```

정상이라면 버전 정보가 표시됩니다. 숫자나 문구는 설치 버전에 따라 다릅니다. `command not found` 또는 명령을 찾을 수 없다는 메시지가 나온다면 먼저 설치·PATH·새 Terminal 적용 여부를 점검합니다.

일부 Ollama 버전에서는 인자 없이 `ollama`를 실행하면 도움말 또는 대화형 메뉴가 나타날 수 있습니다. **그 동작 자체를 이 강의의 완료 기준으로 삼지는 않습니다.** 버전을 확인하는 명령이 더 명확합니다.

### 3.2 현재 모델 목록 확인

```bash
ollama ls
```

- 이미 받은 모델이 있으면 해당 목록이 표시될 수 있습니다.
- 처음 설치한 PC라면 목록이 비어 있을 수 있습니다.
- **목록이 비었다고 Ollama 설치 실패를 뜻하지 않습니다.**

이 시점의 학생 기록:

| 실행 명령 | 관찰할 항목 | 기록 |
|---|---|---|
| `ollama --version` | CLI 실행 및 버전 | `________` |
| `ollama ls` | 다운로드된 모델의 존재 여부 | `________` |

**이 단계의 합격 기준:** CLI 실행 가능 여부와 로컬 모델 존재 여부를 서로 다른 상태로 기록했다.

## 4. 모델 이름을 정하고 다운로드하기

다음 명령 형식의 `<MODEL_NAME>`은 **자리표시자**입니다. 실제 Shell에 꺾쇠까지 복사하면 운영체제에 따라 다른 의미로 해석되거나 실패할 수 있습니다. 반드시 강사가 공지한 모델 태그로 **문자열 전체를 교체**합니다.

```text
ollama pull <MODEL_NAME>
```

예를 들어 강사가 공지한 태그가 `승인된-모델-태그`라면 문서의 `<MODEL_NAME>` 자리에 **그 정확한 태그를 넣는 방식**입니다. `승인된-모델-태그` 자체는 실제 모델 이름이 아닙니다.

### 다운로드에서 관찰할 것

`pull`은 모델 데이터를 **다운로드하여 Local Storage에 준비**하는 명령입니다. 모델이 이미 준비되어 있다면 버전과 상태에 따라 추가 다운로드가 없을 수 있습니다.

다운로드 진행 중에는 다음을 확인합니다.

- 요청한 태그가 정확한가?
- 파일을 받는 데 필요한 네트워크가 정상인가?
- 진행률과 모델 크기가 수업에서 예상한 범위인가?
- Disk Space가 충분한가?
- 명령이 정상 완료되었는가?

모델 다운로드에 걸리는 시간은 파일 크기·네트워크·저장 장치에 따라 달라질 수 있습니다. 완료되지 않았다면 실행 단계로 넘어가지 않습니다.

다운로드 완료 후 다시 실행합니다.

```bash
ollama ls
```

**비교할 관찰값:** 다운로드 전 목록과 다운로드 후 목록. 모델 이름·태그·크기 등이 나타난다면 그대로 기록합니다. Ollama 버전에 따라 표시 열과 형식은 달라질 수 있습니다.

> 이 교시는 모델 파일의 비트 표현이나 Quantization을 설명하는 시간이 아닙니다. 다운로드 크기가 다를 수 있다는 점만 관찰하고, 자세한 원리는 후속 과정에서 학습합니다.

## 5. `ls`와 `ps`를 먼저 나란히 비교하기

다운로드한 모델을 실행하기 전에 다음 두 명령을 실행합니다.

```bash
ollama ls
ollama ps
```

| 명령 | 질문 | 해석 |
|---|---|---|
| `ollama ls` | 이 컴퓨터의 Local Storage에 어떤 모델이 준비되어 있는가? | 다운로드된 모델 확인 |
| `ollama ps` | 지금 Ollama가 어떤 모델을 실행 상태로 유지하고 있는가? | 현재 로드된 모델 확인 |

예를 들어 **`ls`에는 모델이 나타나는데 `ps`는 비어 있는 경우**가 있을 수 있습니다. 이것은 실패가 아니라 **파일은 저장되어 있지만 현재 실행 중인 모델은 없는 상태**입니다.

다음과 같이 기록합니다.

```text
다운로드 전:  ls [________] / ps [________]
다운로드 후:  ls [________] / ps [________]
```

이번 교시에서 외워야 할 것은 약어가 아니라 **같은 PC를 두 관점에서 바라보는 방법**입니다. 저장된 모델과 실행 중인 모델은 반드시 같은 목록일 필요가 없습니다.

## 6. 모델 실행 — 첫 번째 Prompt

이제 강사가 검증한 정확한 모델 태그를 넣어 실행합니다.

```text
ollama run <MODEL_NAME>
```

모델이 정상 준비되면 대화형 입력을 받는 화면으로 들어갑니다. 실행 후 다음 Prompt를 입력합니다.

```text
이 컴퓨터에서 실행하는 AI에게 원하는 대답을 얻기 위해
어떤 종류의 질문을 할 수 있는지 세 가지 예를 보여줘.
```

이 Prompt의 목적은 이전 교시의 AI 정의를 다시 설명시키는 것이 아닙니다. **실제로 학생 PC에서 모델이 문장을 생성하고 입력을 기다리는지** 확인하는 것입니다.

### 정상 실행인지 판단하는 기준

1. `ollama run` 뒤에 즉시 종료되는 오류가 아니라 입력 가능한 대화 상태가 나타난다.
2. 입력 Prompt를 제출했을 때 생성된 응답이 나타난다.
3. 응답이 끝난 뒤 추가 Prompt를 입력할 수 있다.
4. 강사가 준비한 모델과 학생이 실행한 모델 태그가 일치한다.

응답 문구는 모델·설정·환경에 따라 다를 수 있습니다. 따라서 **특정 문장을 출력해야 정상**이라는 방식으로 채점하지 않습니다.

### 별도 Terminal에서 실행 상태 확인

대화 Session을 유지한 상태에서 **새 Terminal 창**을 열어 실행합니다.

```bash
ollama ps
```

모델이 실행 상태로 유지되고 있다면 목록에 표시될 수 있습니다. 화면이 비어 있다면 명령 실행 시점·모델 로드 여부·Runtime 오류를 먼저 확인합니다. 모델을 로드하지 못했는데도 응답이 생성되었다고 단정해서는 안 됩니다.

## 7. 대화 Context가 결과에 주는 영향 관찰

앞 교시에서 Context와 Training의 정의를 배웠으므로 이를 반복하지 않고 **실제 대화 Session을 이용한 비교 실험**만 수행합니다.

### 실험 A — 같은 Session의 후속 질문

현재 실행 중인 대화에서 순서대로 입력합니다.

**첫 질문**

```text
세 가지 과목을 기억해줘: Python, React, FastAPI.
```

**두 번째 질문**

```text
방금 내가 말한 세 가지 과목만 다시 적어줘.
```

두 번째 답변이 첫 번째 질문에 의존하는지 관찰합니다. 모델이 반드시 정확히 기억한다고 보장할 수 없으며, 관찰한 실제 출력을 그대로 기록합니다.

### 실험 B — 새 Session에서 후속 질문만 하기

기존 채팅에서 다음을 입력해 나갑니다.

```text
/bye
```

다시 같은 모델을 실행해 새 대화를 시작하고 **두 번째 질문만** 입력합니다.

```text
방금 내가 말한 세 가지 과목만 다시 적어줘.
```

이 새 Session에는 이전 대화 내용을 직접 전달하지 않았습니다. 그렇다고 응답이 반드시 "모르겠습니다"로 고정되는 것은 아닙니다. 모델은 새로운 입력만으로도 추측하거나 다른 답을 할 수 있습니다. 학생은 **관찰한 응답과 그 근거**를 구분해 기록합니다.

| 비교 항목 | 같은 Session | 새 Session |
|---|---|---|
| 첫 질문의 내용이 전달되었는가? | 동일 대화의 이전 입력으로 제공 | 별도 전달하지 않음 |
| 두 번째 질문의 실제 응답 | `________` | `________` |
| 모델이 세 과목을 정확히 답했는가? | `________` | `________` |
| 결과로 단정하면 안 되는 것 | 현재 응답만으로 Parameter 학습 여부 확정 | 추측 답변만으로 이전 Session 접근 여부 확정 |

**학습 포인트:** Session 단위의 입력이 답변에 미치는 영향을 확인하는 것이지 모델 학습이나 메모리 구현을 증명하는 실험이 아닙니다.

## 8. `/bye`·`stop`·`rm`은 서로 다르다

실습 중 가장 중요한 운영 차이를 표로 확인합니다.

| 조작 | 수행 대상 | 실행 후 반드시 확인할 것 |
|---|---|---|
| `/bye` | 현재 대화형 Chat Session 종료 | Terminal 대화가 끝났는가? |
| `ollama stop <MODEL_NAME>` | 현재 실행 중인 해당 모델 중지 | `ollama ps`에서 상태가 바뀌었는가? |
| `ollama rm <MODEL_NAME>` | Local Storage의 해당 모델 제거 | `ollama ls`에서 없어졌는가? |

**명령 대상이 다르기 때문에 `/bye`를 입력했다고 모델 파일이 지워지지 않습니다.** 또한 `/bye` 이후에 모델이 메모리에 계속 유지되는지는 Runtime 상태나 유지 정책에 따라 달라질 수 있습니다. `/bye`와 `stop`을 동일한 조작으로 판단하지 않습니다.

### 모델을 실행 상태에서 중지하기

먼저 `ollama ps`를 확인합니다. **해당 모델이 실행 목록에 나타날 때만** 다음 형식으로 중지합니다. 이미 목록에 없다면 `stop`을 억지로 실행하지 않고 **중지 대상 없음**으로 기록합니다.

```text
ollama stop <MODEL_NAME>
```

그런 다음 상태를 확인합니다.

```bash
ollama ps
ollama ls
```

**기대하는 구분:** 실행 목록에서는 중지된 모델이 사라질 수 있지만, 로컬 목록에는 파일이 남아 있어야 합니다. 상태는 명령 수행 결과를 기준으로 판단합니다.

### 모델 삭제는 여기서 실행하지 않는다

```text
ollama rm <MODEL_NAME>
```

은 삭제 명령의 **형식만 알아둡니다.** **7교시 정규 실습에서는 실행하지 않습니다.** 다음 8교시에서 같은 모델을 재사용할 예정이기 때문입니다. 이 명령을 실제로 사용하는 것은 별도의 강사 승인과 모델 백업/재다운로드 가능성 확인 후로 미룹니다.

> **안전 규칙:** 실습용 모델을 삭제하거나 다른 모델로 바꾸는 작업은 강사의 공통 실습 환경을 확인한 후에 수행합니다. 특히 `rm`으로 제거한 모델은 다음 시간에 다시 다운로드해야 할 수 있습니다.

## 9. Ollama Server는 언제 확인하는가?

원본 강의에 있는 Server 시작 명령은 다음과 같습니다.

```bash
ollama serve
```

하지만 학생은 **이 명령을 무조건 먼저 실행하면 안 됩니다.** 운영체제와 설치 방식에 따라 Ollama Server가 이미 Background에서 실행 중일 수 있습니다. 같은 포트로 여러 Server를 시작하려다 충돌이 날 수 있습니다.

수업 중에는 다음 순서로 판단합니다.

1. 설치 확인 명령이 동작하는가?
2. `ls`와 `run` 명령이 정상 처리되는가?
3. 실제로 Server가 실행되지 않는 상황인가?
4. 강사가 확인한 환경에서만 필요한 경우 `ollama serve`를 사용한다.

현재 교시의 목표는 직접 CLI를 통한 모델 실행입니다. Server를 별도 Service로 운영하는 세부 설정을 새로운 실습 과제로 만들지는 않습니다.

## 10. Local API는 존재만 확인하고 구현은 다음 시간에

원본 강의에서는 Ollama Local API의 기본 주소를 다음과 같이 안내합니다.

```text
http://localhost:11434/api
```

이번 교시에서는 이 주소를 **같은 PC에서 실행되는 Ollama의 API 위치를 나타내는 정보**로만 확인합니다. 기본 포트는 `11434`이지만 설정에 따라 달라질 수 있습니다.

- Terminal의 `ollama run`은 사람이 CLI로 모델과 대화하는 방법입니다.
- Local API는 프로그램에서 Ollama의 기능을 사용할 수 있는 인터페이스입니다.
- 동일 모델에 접근하더라도 **누가 요청을 보내는가**에 따라 인터페이스가 다릅니다.

다음 8교시에서 Python·FastAPI로 요청을 작성할 때 이 정보를 실제로 사용합니다. **이번 문서에는 HTTP 요청 Body, Python Client 코드, FastAPI Route, JSON Response 처리를 수록하지 않습니다.** 해당 구현의 첫 학습 위치를 유지하기 위해서입니다.

## 12. 선택 실습 — 인터넷 연결 없이 같은 모델 실행하기

이 활동은 **강사가 수업 네트워크 정책과 로컬 환경을 확인한 경우에만** 진행합니다. 공유 네트워크 장비의 연결을 임의로 끊거나 다른 학생의 작업을 방해하지 않습니다.

사전 조건:

1. Ollama가 이미 설치되어 있다.
2. 지정한 모델 다운로드가 정상 완료되었다.
3. 실행에 필요한 모델 파일과 설정이 Local에 준비되어 있다.
4. 외부 검색·Cloud Model·원격 Tool 호출이 포함되지 않은 **Local Inference**를 대상으로 한다.

실험:

1. 네트워크가 연결된 상태에서 동일 모델에 Prompt를 보내 정상 응답을 확인합니다.
2. 강사가 허용한 방식으로 학생 PC의 외부 네트워크를 차단합니다.
3. 같은 모델에 간단한 Prompt를 보내 정상 응답 여부를 확인합니다.
4. Network를 복구한 뒤 결과를 기록합니다.

**해석:** 성공하면 해당 조건에서 Local Model Inference가 외부 네트워크 없이 수행된 것입니다. 실패하면 아직 필요한 파일이 준비되지 않았거나 실행 구성이 영향을 받는지 조사해야 합니다. 한 번 성공했다고 **모든 Ollama 기능과 모든 모델이 영구히 오프라인에서 동작한다**고 일반화하지 않습니다.

## 13. 자주 발생하는 실패와 확인 순서

오류를 만났다면 무조건 재설치하지 않습니다. **마지막으로 성공한 단계와 처음 실패한 단계**를 먼저 찾습니다.

| 발생 위치 | 관찰되는 증상 예 | 먼저 확인할 것 | 다음 단계 |
|---|---|---|---|
| CLI 실행 | `ollama` 명령을 찾지 못함 | 설치 여부, 새 Terminal, PATH | 설치 상태 정리 후 재시도 |
| 모델 목록 | `ls`가 비어 있음 | 다운로드 이력 | 첫 다운로드라면 정상 상태 가능 |
| `pull` | 다운로드 지연·실패 | 모델 태그, Network, Disk Space | 같은 태그로 상태 확인 후 재시도 |
| `run` | 모델을 찾을 수 없음 | `ollama ls`와 실행한 태그 일치 | 필요한 모델을 준비 |
| `run` | Memory 부족 또는 실행 중단 | 현재 여유 RAM, 모델 크기, 다른 App | 강사가 검증한 더 작은 모델/환경 검토 |
| `run` | Runtime 연결 불가 | Ollama 실행 상태, 설치별 Server 동작 | 필요하면 강사에게 Server 상태 확인 요청 |
| 대화 | 응답이 느림 | CPU/GPU, 로드 상태, 모델 크기 | 실행 자원 관찰표와 연결 |
| `ps` | 모델이 보이지 않음 | 요청 시점, Load 성공 여부, 유지 상태 | `ls`와 혼동하지 않기 |
| Local API(다음 교시) | 기본 포트에 연결할 수 없음 | Server 실행·Port 설정 | 8교시에서 통신 계층 진단 |

### 실패를 분류하는 학생 연습

다음 상황을 읽고 어디를 확인할지 답합니다.

**상황 1:** `ollama --version`은 정상인데 `ollama ls`에 아무 모델도 없다.

- 확인: **모델 미다운로드 가능성**. 설치 성공과 모델 준비는 별개입니다.

**상황 2:** 다운로드는 완료됐고 `ls`에 모델이 있는데 `run`에서 Memory 오류가 발생한다.

- 확인: **다운로드는 성공, 실행 자원 문제**. 무조건 다시 `pull`하는 것은 올바른 첫 조치가 아닙니다.

**상황 3:** 대화 화면을 `/bye`로 나왔지만 `ls`에는 모델이 남아 있다.

- 확인: **정상일 수 있는 상태**. 대화 종료와 파일 제거는 다릅니다.

**상황 4:** `stop`을 실행했더니 `ps`에서는 모델이 사라졌지만 `ls`에는 남아 있다.

- 확인: **중지는 됐지만 삭제되지는 않은 상태**. 다음 실습에서 재사용할 수 있습니다.

## 14. 강사 시연 — 상태 변화만 따라가기

강사는 모델 선택 기준을 다시 강의하지 않고, 준비한 모델로 **한 번의 완전한 실행**을 보여줍니다.

| 순서 | 강사의 조작 | 학생이 눈으로 확인할 결과 |
|---|---|---|
| 1 | `ollama --version` | CLI 버전 표시 |
| 2 | `ollama ls` | 로컬 모델 목록 확인 |
| 3 | `ollama pull <MODEL_NAME>` | 정확한 태그를 사용한 다운로드/준비 |
| 4 | `ollama ls` | 다운로드 전후 목록 변화 |
| 5 | `ollama ps` | 실행 전 상태 확인 |
| 6 | `ollama run <MODEL_NAME>` | 대화 시작 및 응답 생성 |
| 7 | 별도 Terminal에서 `ollama ps` | 로드된 모델 상태 확인 |
| 8 | 같은 Session의 후속 질문 | 현재 Context를 이용한 응답 관찰 |
| 9 | `/bye` 후 새 Session | 이전 Context를 자동 전달하지 않은 비교 |
| 10 | `ollama ps` 확인 후 실행 중이면 `ollama stop <MODEL_NAME>` | 실행 중지 또는 중지 대상 없음 기록 |
| 11 | `ollama ps`, `ollama ls` | 실행 상태와 저장 상태 비교 |

`<MODEL_NAME>`은 설명용 자리표시자이므로 **강사는 시연 때 모든 명령을 검증된 실제 태그로 바꿉니다.**

시연 중 학생에게 세 번 질문합니다.

1. 지금 바뀐 것은 **파일 상태**인가, **실행 상태**인가, **대화 상태**인가?
2. 어떤 명령의 출력으로 그 판단을 확인할 수 있는가?
3. 다음 단계에서 같은 모델을 다시 쓸 수 있는가?

이 세 질문이 본 교시의 핵심 확인입니다.

## 17. 학생 실습 ③ — 답변 검수와 환경 비교

원본의 반복 Prompt 실습을 이번 교시의 고유 목표에 맞게 바꿉니다.

### 활동 A. 같은 질문 두 번 실행

```text
Local AI 모델을 실행할 때 저장 상태와 실행 상태를 구분해야 하는 이유를 한 문장으로 답해줘.
```

같은 Session에서 질문을 두 번 입력하고 **응답이 동일한지와 다른지를 그대로 기록**합니다. 정답은 반드시 같거나 반드시 달라지는 것이 아닙니다. 모델 출력의 변동 가능성을 이미 배웠으므로, 여기서는 **같은 모델을 실제로 재호출했음을 확인**하는 데 집중합니다.

### 활동 B. 잘못된 설명 검토

```text
"ollama ps에 아무것도 없으면 이 PC에 모델 파일이 존재하지 않는다."
이 문장의 어떤 부분을 확인해야 하는지 말해줘.
```

학생이 직접 `ollama ls`와 `ollama ps`의 결과를 다시 확인한 뒤 모델 응답의 옳고 그름을 판단합니다. AI가 말했다는 이유로 그 답을 정답으로 처리하지 않습니다.

### 활동 C. 다른 PC에서는 결과가 같을까?

두 학생이 같은 모델 태그를 사용하더라도 다음 항목을 비교합니다.

- 실제 설치한 Ollama 버전
- CPU 또는 GPU 실행 환경
- 모델 실행 시 Memory 사용량
- 응답까지 걸린 체감 시간
- 대화 응답의 표현

**주의:** 속도·품질 비교만으로 어느 모델이나 하드웨어가 절대적으로 우수하다고 결론 내리지 않습니다. 이번 활동은 **동일 명령의 실행 결과가 환경의 영향을 받을 수 있음**을 관찰하는 것입니다.

## 18. 흔히 혼동하는 문제 — 관찰 결과로 답하기

**Q1. Ollama만 설치하고 `ls`에 아무 모델도 없으면 오류인가요?**  
반드시 그렇지는 않습니다. CLI 설치와 모델 다운로드는 별도 단계이며, 첫 설치라면 목록이 비어 있을 수 있습니다.

**Q2. `pull`을 끝냈으니 지금 AI 모델이 Memory에서 실행 중인가요?**  
아닙니다. `ls`와 `ps`로 각각 저장 상태와 실행 상태를 확인해야 합니다.

**Q3. `run`에서 모델이 대답했으니 학습이 완료된 것인가요?**  
이번 실습은 준비된 모델의 응답을 얻은 것이며 Training을 수행한 것이 아닙니다. 학습/추론 원리는 앞 교시에서 다뤘으므로 추가 설명하지 않습니다.

**Q4. `/bye`를 누르면 메모리에서 모델도 반드시 사라지나요?**  
보장할 수 없습니다. `/bye`는 대화형 Session 종료입니다. 모델 실행 상태는 `ollama ps`로 확인하고, 중지하려면 적절한 `stop` 명령을 사용합니다.

**Q5. `ollama ps`가 비어 있는데 `ollama ls`에 모델이 있으면 무엇이 남은 건가요?**  
저장 장치에 모델이 준비되어 있으며 명령 확인 시점에 실행 중인 모델은 보이지 않는 상태입니다.

**Q6. `ollama rm`을 이용해 Disk 공간을 정리해도 되나요?**  
명령 자체는 있지만 다음 8교시에서 동일 모델을 사용하므로 이번 시간에는 실행하지 않습니다. 강사 승인 없이 삭제하지 않습니다.

**Q7. 인터넷 연결 없이 모델이 답했으면 다른 설정이 모두 안전하다는 뜻인가요?**  
아닙니다. 확인한 Local Inference의 실행 위치를 보여줄 뿐이며 파일 권한·접근 제어·로그 등의 안전 설정을 증명하지 않습니다.

**Q8. Ollama Server가 이미 실행 중인데 `ollama serve`를 또 입력해야 하나요?**  
아닙니다. 중복 실행이 충돌을 일으킬 수 있으므로 설치별 Service 상태를 강사 지침에 따라 확인합니다.

## 19. 학습 확인 문제와 답안

1. **질문:** 모델을 다운로드한 직후 실제 저장 여부는 어떤 명령으로 확인하나요?  
   **답:** `ollama ls`.
2. **질문:** Model 파일은 있지만 지금 실행 중인지 모르겠습니다. 어떤 명령을 확인하나요?  
   **답:** `ollama ps`.
3. **질문:** 대화만 종료하고 모델 파일은 유지하는 입력은 무엇인가요?  
   **답:** 대화형 Session에서 `/bye`.
4. **질문:** 실행 중인 모델을 중지하지만 다운로드 파일을 삭제하지 않는 조작은 무엇인가요?  
   **답:** `ollama stop <MODEL_NAME>`에 실제 태그를 사용합니다.
5. **질문:** 모델 파일을 삭제하는 명령은 무엇이며 이번 교시에서 실행하나요?  
   **답:** `ollama rm <MODEL_NAME>`이며 **이번 정규 실습에서는 실행하지 않습니다.**
6. **질문:** 같은 Session에서는 이전 입력을 활용했는데 새 Session에서는 답이 달라졌습니다. 무엇을 관찰한 건가요?  
   **답:** Session에 포함된 대화 입력의 차이가 결과에 영향을 줄 수 있음을 관찰했습니다. Parameter 학습 여부를 증명한 것은 아닙니다.
7. **질문:** Ollama 실행 상태를 관찰할 때 모델 이름만 보면 충분한가요?  
   **답:** 아닙니다. 모델 태그, 실행 성공 여부, `ps` 상태, 실제 CPU/Memory 상태도 함께 확인합니다.
8. **질문:** 다음 8교시로 넘어가기 전에 반드시 보존해야 하는 것은 무엇인가요?  
   **답:** 강사가 검증한 정확한 모델 태그와 **로컬에 다운로드된 모델 데이터**입니다.

## 20. 실습 완료 체크리스트

- [ ] 강사가 지정한 모델 이름·태그를 정확하게 기록했다.
- [ ] `ollama --version`으로 CLI 실행을 확인했다.
- [ ] 다운로드 전 `ollama ls` 상태를 기록했다.
- [ ] 지정 모델의 `pull` 성공 여부를 확인했다.
- [ ] `ollama ls`에서 모델 준비 상태를 확인했다.
- [ ] `ollama run`으로 실제 Local Model 응답을 확인했다.
- [ ] 다른 Terminal에서 `ollama ps`를 실행했다.
- [ ] 같은 Session과 새 Session의 결과를 구분해 기록했다.
- [ ] `/bye`를 사용해 채팅 Session을 종료했다.
- [ ] `ollama ps`로 중지 대상을 확인한 뒤 실행 중이면 `ollama stop`을 사용했다(없으면 중지 대상 없음 기록).
- [ ] 중지 후 `ollama ls`와 `ollama ps` 상태를 비교했다.
- [ ] System Monitor로 CPU/Memory 사용을 관찰했다.
- [ ] 실패한 단계가 있다면 원인 후보와 실제 확인 결과를 작성했다.
- [ ] **다음 교시를 위해 Model 파일은 삭제하지 않았다.**

**완료 판정:** 체크 항목을 실제 수행한 경우에만 체크합니다. 설치 또는 모델 다운로드가 실패해 후속 활동을 수행하지 못했다면 미완료를 유지하고 강사가 제공한 실습 환경에서 재검증해야 합니다.

## 21. 이번 교시에서 확보한 결과와 다음 교시 연결

이번 교시의 결과물은 **Ollama CLI의 상태를 읽을 수 있고, 강사가 지정한 Local Model을 실행한 기록**입니다.

```text
[학생 PC]
Ollama 설치 확인
    ↓
실습 모델 다운로드
    ↓
Local Storage의 Model 확인
    ↓
대화형 실행 및 응답 확인
    ↓
Running Model 상태 확인
    ↓
실행 중지
    ↓
Model 파일 유지
```

**8교시에서는** 같은 Local Model을 사람이 Terminal에서 직접 호출하는 대신, Python·FastAPI 프로그램에서 Ollama API를 이용해 호출합니다. 현재 교시에서는 그 구현을 하지 않았으므로 **첫 학습 순서가 유지됩니다.**

학생은 다음 항목을 8교시 시작 시 전달합니다.

```text
Ollama CLI 정상 실행 여부:
실습 Model 정확한 Tag:
Model 파일 Local 보존 여부:
최근 실행 성공 여부:
실습 중 발생한 오류/제약:
```
