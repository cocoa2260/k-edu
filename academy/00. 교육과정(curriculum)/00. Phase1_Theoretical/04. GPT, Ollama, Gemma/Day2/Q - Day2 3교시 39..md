# Q. 간단하게 설명해줘


# A.
이 부분은 **`train()`과 `eval()`이 학습을 시작/종료시키는 명령이 아니다**라는 점을 먼저 잡아주면 됩니다. 현재 강의안에서도 이 구분이 핵심입니다.

### `model.train()`과 `model.eval()`은 무엇인가?

PyTorch Model 안에는 **Training할 때와 Inference할 때 다르게 동작해야 하는 Layer**가 있을 수 있습니다.

그래서 Model에게 현재 상황을 알려주는 것입니다.

```python
model.train()
```

> "지금부터 Training 상황에 맞게 동작해."

```python
model.eval()
```

> "지금부터 Evaluation/Inference 상황에 맞게 동작해."

즉 **Model의 동작 Mode를 변경**합니다.

---

### 왜 Mode를 나눠야 하는가?

대표적인 예가 `Dropout`입니다.

Dropout은 Training 중 일부 값을 의도적으로 제외하면서 학습하는 기법입니다.

개념적으로:

```text
Training

[10, 20, 30, 40]
      ↓
   Dropout
      ↓
[10,  0, 30,  0]
```

반면 실제 Inference에서는 이렇게 일부 값을 무작위로 계속 제외하면 안 됩니다.

```text
Inference

[10, 20, 30, 40]
      ↓
Dropout 비활성화
      ↓
결과 계산
```

그래서:

```python
model.train()
```

상태에서는 Dropout이 Training 방식으로 동작하고,

```python
model.eval()
```

상태에서는 Evaluation 방식으로 동작합니다.

강의안에 있는 `Batch Normalization`도 Training/Evaluation Mode에 따라 동작이 달라지는 대표적인 Layer입니다.

---

### 가장 중요한 오해

```python
model.train()
```

한다고 **Training이 자동으로 시작되는 게 아닙니다.**

Training은 여전히 우리가 직접:

```python
prediction = model(x)
loss = loss_function(prediction, y)

loss.backward()
optimizer.step()
```

같은 과정을 수행해야 합니다.

마찬가지로:

```python
model.eval()
```

한다고 자동으로 Inference 결과가 생성되는 것도 아닙니다.

보통:

```python
model.eval()

with torch.no_grad():
    prediction = model(test_input)
```

처럼 사용합니다.

따라서 학생들에게는 이렇게 설명하면 충분합니다.

```text
model.train()
→ Model을 Training에 적합한 동작 Mode로 변경

model.eval()
→ Model을 Evaluation/Inference에 적합한 동작 Mode로 변경
```

그리고 바로 앞 #38의 `torch.no_grad()`와도 반드시 구분해야 합니다.

```text
model.eval()
→ 일부 Layer의 동작 방식을 Evaluation Mode로 변경

torch.no_grad()
→ Gradient 계산 추적을 비활성화
```

즉 **`eval()`과 `no_grad()`는 서로 다른 역할**을 합니다.

한 문장으로 정리하면:

> **`model.train()`과 `model.eval()`은 학습을 실행하거나 중단하는 명령이 아니라, 현재 Training인지 Evaluation/Inference인지 Model 내부 Layer들에게 알려주는 Mode 설정입니다.**


# Q. Dropout 학습 기법은 언제 사용하는 거야?

Dropout은 주로 **Neural Network가 Training Data에 너무 맞춰지는 Overfitting을 줄이기 위한 정규화(regularization) 기법**으로 사용합니다.

현재 강의안에서는 `model.train()`과 `model.eval()`의 동작 차이를 보여주는 대표적인 예로 Dropout이 등장한 것입니다.

### 왜 Dropout이 필요한가?

Neural Network가 Training을 계속하다 보면 특정 Parameter나 특정 Neuron들의 조합에 지나치게 의존할 수 있습니다.

```text
Training Data
     ↓
Neural Network
     ↓
Training Data에서는 매우 잘 맞음

그런데

새로운 Data
     ↓
성능 저하
```

이런 문제와 관련해서 **Overfitting**을 생각할 수 있습니다.

Dropout은 Training 중 일부 Neuron의 출력을 **확률적으로 0으로 만들어 사용하지 않도록** 합니다.

예를 들어:

```text
원래

Neuron A ─┐
Neuron B ─┤
Neuron C ─┤ → 다음 Layer
Neuron D ─┘
```

Training 중에는 일부가:

```text
Neuron A ─┐
Neuron B ─X   ← 이번 계산에서 Dropout
Neuron C ─┤ → 다음 Layer
Neuron D ─X   ← 이번 계산에서 Dropout
```

처럼 빠질 수 있습니다.

다음 Training Step에서는 또 다른 출력이 빠질 수 있습니다.

```text
Step 1
A  X  C  X

Step 2
X  B  C  D

Step 3
A  B  X  D
```

이렇게 함으로써 Model이 특정한 일부 활성값에 지나치게 의존하는 것을 줄이고, **더 잘 일반화하도록 유도하는 정규화 효과**를 얻는 것이 목적입니다.

### PyTorch에서는

예를 들어:

```python
dropout = nn.Dropout(p=0.5)
```

여기서 `p=0.5`는 Training 중 각 요소를 0으로 만들 확률입니다.

그리고 앞에서 배운 Mode가 여기서 중요합니다.

```python
model.train()
```

Training Mode에서는 Dropout이 활성화됩니다.

```text
Input
↓
Dropout 적용
↓
일부 값이 확률적으로 0
↓
Training
```

반면:

```python
model.eval()
```

Evaluation Mode에서는 Dropout이 비활성화됩니다.

```text
Input
↓
Dropout으로 값을 무작위 제거하지 않음
↓
Prediction
```

실제로 `nn.Dropout`은 Training 중 남은 출력에 적절한 스케일링도 적용하기 때문에, 단순히 "몇 개를 삭제한다" 정도의 구현으로만 이해하면 안 됩니다.

### 그러면 언제 쓰는가?

모든 Neural Network에 무조건 넣는 것은 아닙니다. **Overfitting을 완화하기 위한 정규화가 필요하고, 사용하는 Architecture와 학습 방법에서 Dropout이 적절할 때** 사용합니다.

특히 지금 수업에서는 Dropout 자체를 깊게 배울 필요는 없습니다.

학생들에게는 다음 정도면 충분합니다.

> **Dropout은 Training 중 일부 출력을 확률적으로 사용하지 않게 하여 Model의 Overfitting을 줄이는 데 사용되는 정규화 기법입니다. Training에서만 이러한 확률적 동작이 필요하고 Evaluation/Inference에서는 비활성화되어야 하기 때문에 `model.train()`과 `model.eval()`에 따라 동작이 달라지는 대표적인 Layer입니다.**

그래서 지금 교시에서 Dropout을 소개하는 진짜 목적은 **Dropout 학습법을 가르치는 것보다 "왜 PyTorch에 Training Mode와 Evaluation Mode가 따로 필요한가?"를 보여주는 것**이라고 잡으시면 됩니다.
