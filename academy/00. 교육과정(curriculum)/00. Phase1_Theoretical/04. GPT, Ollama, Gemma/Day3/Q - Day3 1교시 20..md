지금 시점인 **2026년 9월 기준으로 다시 공식 문서를 확인해보면**, 강의안의 방향은 맞지만 **내용은 최신 상태로 수정하는 게 좋습니다.** 가장 큰 이유는 현재 **Gemma 4가 이미 공개되어 있기 때문**입니다. ([Google AI for Developers](https://ai.google.dev/gemma/docs/releases?hl=en&utm_source=chatgpt.com "Gemma releases  |  Google AI for Developers"))

### Gemma는 현재 어떻게 되어 있나?

현재 Google 공식 문서상 Gemma는 세대가 발전하면서 확실히 멀티모달 방향으로 확장됐습니다.

특히 Gemma 3만 봐도 Variant별 차이가 명확합니다.

```text
Gemma 3 270M → Text → Text
Gemma 3 1B   → Text → Text

Gemma 3 4B   → Text + Image → Text
Gemma 3 12B  → Text + Image → Text
Gemma 3 27B  → Text + Image → Text

Gemma 3n E2B → Text + Image + Audio → Text
Gemma 3n E4B → Text + Image + Audio → Text
```

Google 공식 문서에서도 이렇게 구분하고 있습니다. 즉 **같은 Gemma 3라는 세대 안에서도 1B와 4B의 Modality가 다릅니다.** ([Google AI for Developers](https://ai.google.dev/gemma/docs/get_started?utm_source=chatgpt.com "Get started with Gemma models  |  Google AI for Developers"))

그리고 2026년에는 **Gemma 4**까지 나왔습니다. Google의 release 기록에는 2026년 3월 Gemma 4가 공개되고, 6월에는 Gemma 4 12B Unified가 추가된 것으로 나옵니다. Gemma 4 역시 하드웨어와 목적에 따라 여러 아키텍처/Variant로 구성됩니다. ([Google AI for Developers](https://ai.google.dev/gemma/docs/releases?hl=en&utm_source=chatgpt.com "Gemma releases  |  Google AI for Developers"))

따라서 강의안의 이 문장은 **정확합니다.**

> Gemma라는 Family 이름만 보고 입력 Modality를 단정하면 안 된다.

오히려 학생들에게 보여주기 아주 좋은 사례입니다.

```text
Gemma
 ├─ 세대가 다름
 │   ├─ Gemma 2
 │   ├─ Gemma 3
 │   └─ Gemma 4
 │
 └─ 같은 세대에서도 Variant가 다름
     ├─ Parameter Size
     ├─ Architecture
     ├─ Input Modality
     └─ Capability
```

즉 **Family → Generation → Variant까지 내려가야 실제 기능을 알 수 있다**는 게 #20의 핵심입니다.

## 그러면 GPT Family도 똑같은가?

**큰 개념에서는 그렇습니다.**

GPT도 하나의 모델을 의미한다기보다 여러 세대와 Variant가 존재하는 **Model Family 관점으로 이해할 수 있습니다.**

예를 들어 역사적으로 보면:

```text
GPT Family

GPT-1
 ↓
GPT-2
 ↓
GPT-3
 ↓
GPT-3.5
 ↓
GPT-4
 ↓
GPT-4o
 ↓
GPT-5 계열
```

그리고 현재 API에서도 하나의 GPT 세대 안에 여러 Variant가 존재합니다. 예를 들어 현재 공식 API 문서에는:

```text
GPT-5.4
GPT-5.4 mini
GPT-5.4 nano
GPT-5.4 Pro
...
```

처럼 목적·비용·성능 특성이 다른 모델들이 존재합니다. ([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-5.4?utm_source=chatgpt.com "GPT-5.4 Model | OpenAI API"))

GPT-5.4만 보더라도 공식 API 문서상:

```text
Text  → Input / Output
Image → Input
Audio → 지원하지 않음
Video → 지원하지 않음
```

입니다. 즉 **"GPT니까 모든 Modality를 직접 처리한다"라고 판단하면 안 됩니다.** ([OpenAI Developers](https://developers.openai.com/api/docs/models/gpt-5.4?utm_source=chatgpt.com "GPT-5.4 Model | OpenAI API"))

여기서도 결국 같은 원칙이 적용됩니다.

```text
GPT라는 이름만 확인
        ↓
       X

정확한 Model 확인
        ↓
지원 Modality 확인
        ↓
Context 확인
        ↓
Tool 지원 확인
        ↓
Cost / Latency 확인
        ↓
Project 적합성 평가
```

### 그래서 #20은 이렇게 고치면 더 좋습니다

현재 문장은 Gemma에만 초점이 맞춰져 있는데, **Gemma에서 배운 개념을 GPT로 확장**해주면 학생들이 "아, 이게 Gemma만의 이야기가 아니구나"를 이해하기 좋습니다.

```markdown
# 20. Model Family의 세대와 Capability 변화

Model Family는 새로운 세대와 Variant가 등장하면서
지원하는 Capability가 달라질 수 있습니다.

Gemma를 예로 들어보겠습니다.

Gemma 3에서는 같은 세대 안에서도 Variant에 따라
지원하는 Input Modality가 다릅니다.

예를 들어:

Gemma 3 1B
→ Text Input

Gemma 3 4B / 12B / 27B
→ Text + Image Input

Gemma 3n
→ Text + Image + Audio Input

또한 현재는 Gemma 4까지 공개되어
새로운 Architecture와 Multimodal 구성이 추가되었습니다.

따라서:

Gemma
→ Family만 확인하면 부족

Gemma 3
→ Generation만 확인해도 부족

Gemma 3 4B
→ 정확한 Variant까지 확인

해야 실제 Capability를 판단할 수 있습니다.


이 원칙은 GPT와 같은 다른 Model Family에도 적용됩니다.

예를 들어 GPT 계열 역시:

GPT-4
GPT-4o
GPT-5 계열

등 여러 세대와 Model이 존재하며,
각 Model마다 지원하는 Modality, Context,
Tool 지원, 성능과 비용 등이 다를 수 있습니다.

따라서:

Model Family
↓
Generation / Model
↓
Variant
↓
Model Card / 공식 문서
↓
Capability 확인

순서로 확인하는 것이 중요합니다.
```

이렇게 바꾸면 #20이 단순히 **"Gemma가 이미지도 받습니다"**를 가르치는 부분이 아니라,

> **같은 Model Family라도 세대와 Variant에 따라 Capability가 다르므로 정확한 모델 사양을 확인해야 한다.**

라는 **Model Selection의 일반 원칙**을 가르치는 부분이 됩니다.

Google의 최신 Gemma 공식 문서는 [Gemma 모델 개요](https://ai.google.dev/gemma/docs/core?hl=ko&utm_source=chatgpt.com), OpenAI의 현재 GPT 모델 사양은 에서 확인할 수 있습니다.
