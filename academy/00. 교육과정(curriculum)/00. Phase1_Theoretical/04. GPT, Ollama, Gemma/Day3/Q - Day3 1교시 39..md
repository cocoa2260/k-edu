쉽게 말하면 **AI Model도 소프트웨어 라이브러리처럼 버전을 바꾸면 기존 서비스의 동작이 달라질 수 있다**는 이야기입니다. 강의안에서는 이를 `Output Style`, `Accuracy`, `Latency`, `Memory`, `Prompt Compatibility`, `Safety Behavior` 변화로 설명하고 있습니다.

예를 들어 기존에 `Model v1`으로 문서 요약 서비스를 만들었다고 해보겠습니다.

```text
사용자
↓
"다음 문서를 3줄로 요약해줘"
↓
Model v1
↓
항상 3줄 정도로 안정적으로 요약
```

새로운 `Model v2`가 나왔다고 바로 교체했는데 결과가 이렇게 달라질 수도 있습니다.

```text
Model v1
→ 짧고 간결한 3줄 요약

Model v2
→ 더 자세하게 설명
→ 5~6줄을 생성하는 경우 발생
```

새 모델의 전체적인 성능이 더 좋아졌더라도 **기존 서비스 입장에서는 문제가 생긴 것**입니다.

각 항목을 보면:

```text
Output Style
→ 답변의 문체, 길이, 형식 등이 달라질 수 있음

Accuracy
→ 특정 Task의 정확도가 좋아지거나 나빠질 수 있음

Latency
→ 응답 속도가 달라질 수 있음

Memory
→ 필요한 RAM / VRAM이 달라질 수 있음

Prompt Compatibility
→ 기존에 잘 동작하던 Prompt가
   새로운 Model에서는 다르게 동작할 수 있음

Safety Behavior
→ 어떤 요청을 허용하거나 거절하는 방식 등이 달라질 수 있음
```

그래서 **"새 버전 = 무조건 기존 버전보다 우리 서비스에 좋다"**라고 생각하면 안 됩니다.

### 그래서 Regression Evaluation을 한다

`Regression`은 쉽게 말하면 **기존에 잘 되던 것이 변경 후에도 여전히 잘 되는지 확인하는 것**입니다.

기존 모델에서 테스트했던 항목이 있다고 해보겠습니다.

```text
Test 1 → 한국어 문서 요약 잘 됨
Test 2 → 3줄 요약 형식 잘 지킴
Test 3 → 핵심 내용 잘 보존함
Test 4 → 평균 5초 이내 응답
```

Model을 업데이트한 다음 **같은 테스트를 다시 수행**합니다.

```text
Model v1
   ↓
Model v2로 변경
   ↓
기존 Evaluation 다시 실행
   ↓
품질은 유지되는가?
형식은 유지되는가?
속도는 괜찮은가?
Memory는 괜찮은가?
   ↓
문제없음
   ↓
Deployment
```

그래서 강의안의

```text
Model Update
↓
Regression Evaluation
↓
Deployment
```

는 결국 다음 의미입니다.

> **새 Model이 나왔다고 바로 운영 서비스에 적용하지 말고, 기존 서비스에서 잘 되던 기능과 품질이 그대로 유지되는지 다시 평가한 후 배포해야 한다.**

특히 학생들에게는 **`pip install`로 라이브러리 버전을 올렸더니 기존 코드가 깨지는 것과 비슷하다**고 설명하면 이해하기 쉽습니다. AI에서는 코드가 안 깨지더라도 **출력 결과와 품질이 깨질 수 있다는 점**이 차이입니다.
