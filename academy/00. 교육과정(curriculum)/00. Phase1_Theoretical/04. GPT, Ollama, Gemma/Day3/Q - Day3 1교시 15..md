쉽게 말하면 **Parameter가 많아질수록 모델의 규모가 커진다**고 이해하면 됩니다. 현재 강의안의 설명처럼, 모델이 커질수록 일반적으로 메모리와 연산 자원을 더 요구할 수 있습니다.

예를 들어:

```text
작은 Model
→ Parameter 적음
→ 상대적으로 적은 메모리
→ 상대적으로 빠른 실행 가능

큰 Model
→ Parameter 많음
→ 더 많은 메모리와 연산 필요
→ 실행이 느려질 가능성
→ 더 복잡한 Task를 잘 처리할 가능성
```

여기서 중요한 건 **Parameter가 많다고 무조건 더 좋은 모델은 아니라는 것**입니다.

예를 들어 문서 요약이라는 작업에서:

```text
4B Model  → 품질 90, 실행 3초
27B Model → 품질 92, 실행 15초
```

라고 나온다면, 실제 서비스에서는 **4B가 더 적합할 수도 있습니다.**

그래서 이 부분의 핵심은 이렇게 설명하면 됩니다.

> **Parameter가 많아지면 모델의 표현 능력이나 Task 수행 능력이 높아질 가능성이 있지만, 그만큼 메모리·연산량·실행시간도 증가할 수 있다. 따라서 크기만 보고 선택하지 않고 실제 Task로 평가해야 한다.**

바로 다음의 **#16 Model Size 선택은 Trade-off**로 자연스럽게 연결되는 내용입니다.
