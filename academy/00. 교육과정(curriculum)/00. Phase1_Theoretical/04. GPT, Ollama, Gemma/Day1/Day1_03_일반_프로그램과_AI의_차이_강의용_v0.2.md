# Day 1 - 3교시. 일반 프로그램과 AI는 무엇이 다른가

> **수업 핵심 질문**  
> 일반 프로그램과 AI Model은 모두 입력을 받아 결과를 만드는데, **판단하는 방식을 어떻게 마련하는가**는 무엇이 다를까?

## 개요

2교시에서는 AI가 하는 일과 AI·Machine Learning·Deep Learning의 관계를 **전체 지도**에서 살펴보았습니다. 이번 시간에는 그 지도를 다시 그리지 않고, 개발자가 실제로 프로그램과 모델을 만들거나 사용할 때 부딪히는 차이를 살펴봅니다.

핵심은 **일반 프로그램은 규칙을 쓰고 AI는 코드를 쓰지 않는다**는 식의 단순한 구분이 아닙니다. 머신러닝도 코드로 구현됩니다. 차이는 해결하려는 문제의 판단 기준을 사람이 명시적으로 작성하는지, 데이터를 통해 모델 내부의 값을 학습하도록 하는지에 있습니다.

오늘은 한 가지 작은 수치 예제로 `Data → Feature·Label → Training → Model → Inference`를 끝까지 연결합니다. 이후에는 실제 AI Application에서 **어떤 작업은 코드가, 어떤 작업은 모델이 담당해야 하는가**를 판단해 봅니다.

## 1. 학습 목표

이번 교시를 마치면 학생은 다음을 설명하거나 구분할 수 있어야 합니다.

1. 명시적인 규칙 기반 프로그램과 Machine Learning 방식의 차이를 사례로 설명한다.
2. `Dataset`, `Data`, `Feature`, `Label/Target`, `Model`, `Parameter`의 역할을 구별한다.
3. `Training`과 `Inference`에서 어떤 입력을 사용하고 무엇이 달라지는지 설명한다.
4. 짧은 Python 코드에서 학습(`fit`)과 추론(`predict`)이 실행되는 위치를 찾아낸다.
5. AI Model의 확률적 판단과 프로그램의 명확한 업무 규칙을 혼동하지 않는다.
6. NumPy·scikit-learn·PyTorch가 서로 같은 도구가 아닌 이유를 구별한다.
7. AI Application에서 모델의 책임과 Application 코드의 책임을 나눌 수 있다.

## 2. 명확한 규칙은 프로그램으로 직접 표현할 수 있다

### 2-1. 개발자가 판단 기준을 이미 알고 있는 경우

예를 들어 쇼핑몰에서 다음 규칙을 정했다고 생각해 봅시다.

> 주문 금액이 30,000원 이상이면 배송비는 0원, 그보다 적으면 배송비는 3,000원이다.

Python에서는 이렇게 구현할 수 있습니다.

```python
def shipping_fee(order_amount: int) -> int:
    if order_amount >= 30_000:
        return 0
    return 3_000

print(shipping_fee(35_000))  # 0
print(shipping_fee(20_000))  # 3000
```

이 코드에서 `30_000`이라는 경계값과 배송비 금액은 **개발자 또는 업무 담당자가 정한 규칙**입니다. 프로그램이 과거 주문을 살펴보고 이 기준을 스스로 알아낸 것이 아닙니다.

```text
입력: 주문 금액
      ↓
개발자가 작성한 조건·계산 규칙
      ↓
프로그램 실행
      ↓
출력: 배송비
```

같은 규칙, 같은 입력, 같은 상태라면 결과도 같습니다. 규칙을 변경하려면 코드나 설정의 기준을 바꿔야 합니다. 이것이 명시적 규칙 기반 처리의 특징입니다.

### 2-2. 같은 방식으로 처리하기 쉬운 업무

- 사용자의 나이가 정해진 기준 이상인지 확인하기
- 요청한 금액이 0보다 큰지 검사하기
- 업로드 가능한 파일 크기를 초과했는지 확인하기
- 관리자 승인이 필요한 금액인지 확인하기
- 필수 입력 항목이 비어 있는지 검사하기

이런 문제는 판단 기준이 이미 정해져 있습니다. **입력을 확인하고 정해진 규칙을 적용**하면 되므로, 반드시 머신러닝 모델을 사용할 이유는 없습니다.

> **강사 질문:** 위 배송비 프로그램에 주문 데이터 10만 건을 주면 배송비 기준이 자동으로 바뀔까요?  
> **예상 답변:** 아닙니다. 데이터의 양이 아니라, **규칙을 학습하도록 설계되어 있는가**가 차이입니다.

## 3. 모든 판단 기준을 사람이 직접 작성할 수는 없다

이번에는 공장에서 생산된 물건의 사진을 보고 외관 불량 여부를 판단한다고 생각해 봅시다.

사람이 규칙을 작성하려고 하면 다음과 같은 조건부터 떠올릴 수 있습니다.

```text
표면에 어두운 선이 있으면 불량인가?
특정 위치에 흠집이 보이면 불량인가?
색깔이 기준보다 다르면 불량인가?
```

하지만 실제 사진에는 조명, 촬영 각도, 배경, 제품의 위치, 그림자, 정상적인 무늬 등의 차이가 있습니다. 이런 경우의 수를 빠짐없이 `if` 문으로 만들기는 어렵습니다. **문제의 판단 기준이 매우 복잡하고 데이터에 패턴이 있는 경우**, Machine Learning을 검토할 수 있습니다.

이때 사람이 아무 일도 하지 않는 것은 아닙니다. 개발자는 어떤 불량을 찾을지 정의하고, 학습에 사용할 사진과 정답을 준비하고, 모델을 선택하고, 오류를 평가합니다. 다만 사진의 특징과 판단 결과를 연결하는 수많은 값을 모두 수작업 조건문으로 작성하지 않습니다.

### 3-1. 두 방식의 출발점을 비교하기

| 질문 | 명시적 규칙 기반 프로그램 | Machine Learning의 대표적인 방식 |
|---|---|---|
| 판단 기준은 어디에서 오는가? | 사람이 작성한 규칙·계산식 | 데이터와 학습 목표를 바탕으로 학습된 모델 값 |
| 개발자가 하는 일은? | 조건, 예외, 계산을 설계 | 문제 정의, 데이터 준비, 학습, 평가, 배포를 설계 |
| 새 사례를 처리하는 방법은? | 작성된 규칙 적용 | 학습된 Model을 새 입력에 사용 |
| 문제가 생기면? | 조건·구현·입력 확인 | 데이터·학습·모델·평가·입력을 함께 확인 |

머신러닝이 언제나 더 정확하거나 더 좋은 것은 아닙니다. **정확한 규칙이 존재하면 그 규칙을 구현하는 편이 단순하고 검증하기 쉬울 수 있습니다.** 반대로 단순한 규칙만으로 필요한 품질을 얻기 어렵다면 학습 기반 접근을 검토합니다.

### 3-2. Supervised Learning(지도학습)의 기본 흐름

**지도학습**은 입력과 그에 대응하는 정답(`Label`)을 함께 제공하여, 새로운 입력의 정답을 예측하도록 모델을 학습하는 머신러닝 방식입니다.

```text
학습용 입력 데이터 + 각 입력에 대한 정답
                   ↓
            Learning Algorithm
                   ↓
            학습된 Model
                   ↓
              새로운 입력
                   ↓
               예측 결과
```

예를 들어 제품 사진에 '정상/불량'이라는 정답을 붙여 학습하면, 학습된 모델을 새 제품 사진의 검사에 사용할 수 있습니다. 이것은 여러 학습 방식 중 **지도학습의 예**입니다. 모든 머신러닝 학습에 사람이 제공한 정답이 반드시 있어야 하는 것은 아닙니다. 정답이 없는 데이터의 구조를 살피는 방식 등도 있으며, 자세한 차이는 이후 과목에서 다룹니다.

## 4. Dataset·Data·Feature·Label을 하나의 표에서 구분하기

용어를 각각 따로 외우기보다, **하나의 Dataset이 어떤 역할의 데이터로 이루어지는지** 확인해 봅시다.

### 4-1. 집값 예측을 위한 작은 Dataset

아래는 개념 설명용 가상 데이터입니다. 가격 단위는 **백만 원**으로 통일합니다.

| 주택 | 면적(㎡) | 방 개수 | 거래 가격(백만 원) |
|---|---:|---:|---:|
| A | 50 | 1 | 200 |
| B | 70 | 2 | 300 |
| C | 90 | 3 | 400 |

- **Dataset(데이터셋)**: 학습 등에 사용할 사례를 모아 놓은 데이터 전체입니다. 여기서는 표의 세 주택 기록입니다.
- **Data(데이터)**: 모델에 사용하는 정보입니다. 숫자, 문자, 이미지, 음성, 문서 등 여러 형태가 가능합니다.
- **Feature(특성)**: 모델이 예측을 위해 **입력으로 사용하는** 값입니다. 이 예에서는 면적과 방 개수를 사용할 수 있습니다.
- **Label / Target(정답·목표값)**: 지도학습에서 맞혀야 할 값입니다. 여기서는 실제 거래 가격이 `Target`입니다.

```text
한 주택의 학습 사례
├── Feature: 면적 = 70㎡
├── Feature: 방 개수 = 2
└── Target: 거래 가격 = 300백만 원
```

**Feature와 Dataset은 같은 개념이 아닙니다.** 표 전체가 Dataset이며 그 안에서 모델의 입력으로 선택한 항목이 Feature입니다. 또한 `Label`은 반드시 '스팸/정상'처럼 글자로 된 범주만 뜻하지 않습니다. 가격처럼 **연속적인 수치**도 Target이 될 수 있습니다.

### 4-2. 분류와 회귀를 구분하는 기준

앞선 2교시에서 '분류'와 '예측'을 AI의 결과 관점으로 살펴봤습니다. 여기서는 학습 문제를 구성할 때의 차이를 봅니다.

- **Classification(분류)**: `정상/불량`처럼 범주를 맞히는 문제
- **Regression(회귀)**: 집값이나 판매 수량처럼 수치 값을 예측하는 문제

둘 다 학습된 모델로 새 입력을 처리하는 **지도학습 문제**가 될 수 있습니다. 'Prediction'은 모델의 예측이라는 넓은 표현이며, 회귀만을 뜻하는 말은 아닙니다.

### 4-3. Deep Learning에서 Feature는 어떻게 달라지나?

이 표에서는 사람이 `면적`, `방 개수`를 입력 Feature로 선택했습니다. 하지만 이미지나 음성처럼 복잡한 데이터에서는 사람이 유용한 특징을 전부 직접 표현하기 어렵습니다. Deep Learning은 입력 데이터에서 필요한 **내부 표현(Representation)**을 학습할 수 있습니다.

이번 교시에서 기억할 것은 **Dataset은 사례의 모음, Feature는 입력에 쓰는 특성, Label은 지도학습에서 목표로 삼는 값**이라는 차이입니다. 내부 표현을 어떻게 학습하는지는 다음 교시와 Phase2에서 더 깊게 학습합니다.

## 5. Model과 Parameter — 무엇이 학습되는가?

### 5-1. Model은 어떤 역할을 하나?

입문 수준에서 **Model(모델)**은 입력을 받아 자신의 구조와 내부 값을 이용해 출력을 계산하는 대상입니다. 머신러닝에서는 학습을 통해 정해진 내부 값을 사용해 새로운 입력을 처리합니다.

```text
새로운 주택의 면적
       ↓
   학습된 Model
       ↓
   예상 거래 가격
```

실제 모델은 문제에 따라 입력·출력·구조가 다릅니다. 집값 예측 모델, 이미지 분류 모델, 언어 모델은 모두 'Model'이라 부르지만 같은 계산을 하는 것은 아닙니다.

### 5-2. Parameter는 단순히 설정 이름일까?

**Parameter(파라미터)**는 모델 내부에 있고, 학습 과정에서 조정되는 값입니다. 이해를 위해 가장 단순한 형태의 식을 봅시다.

```text
y = w × x + b
```

- `x`: 입력값(예: 주택 면적)
- `y`: 모델이 계산한 예측값(예: 예상 가격)
- `w`, `b`: 모델이 학습으로 맞추는 Parameter

처음에는 알맞은 `w`와 `b`를 모릅니다. 학습 과정에서는 입력에 대한 예측값을 구하고, 목표값과의 차이를 살펴보면서 값을 조정합니다.

```text
입력 x → 예측 y → 목표값과 비교 → w·b 조정 → 다시 예측
```

이 예제는 학습의 개념을 보기 위한 단순화입니다. 모든 모델이 직선 하나를 학습하지는 않습니다. 현대 신경망에는 훨씬 많은 Parameter가 있을 수 있습니다. 또한 **Parameter는 개발자가 전달하는 API 요청 옵션과도 다른 의미**이므로, 이 교시에서는 '학습으로 조정되는 모델 내부 값'을 가리키는 말로 사용합니다.

### 5-3. '모델을 학습한다'는 말의 의미

개발자가 과거 데이터의 모든 사례에 대해 `if` 규칙을 새로 작성한다는 뜻이 아닙니다. 학습 절차가 모델의 Parameter를 조정함으로써, **처음 보지 않은 입력에서도 유용한 결과를 얻도록 시도한다**는 뜻입니다.

학습 데이터에서 잘 맞는 것과 새로운 데이터에도 잘 맞는 것은 서로 다른 문제입니다. 이 차이와 과적합(Overfitting), 평가 데이터의 역할은 Phase2에서 자세히 다룹니다.

## 6. Training과 Inference — 만들 때와 사용할 때

### 6-1. Training(학습)

**Training**은 데이터를 이용해 모델의 Parameter를 조정하는 과정입니다. 지도학습 예제에서는 다음과 같이 볼 수 있습니다.

```text
Training Data (Feature + Target)
              ↓
            Model
              ↓
          Prediction
              ↓
    정답과 비교하여 Loss 계산
              ↓
       Parameter Update
              ↓
       여러 번 반복
```

**Loss(손실)**는 예측과 학습 목표 사이의 차이를 학습에서 다루기 위한 값입니다. 왜 Loss가 필요하고 어떻게 Parameter를 갱신하는지는 이후 심화 단원에서 설명합니다. 지금은 '**학습하는 동안 모델 내부 값이 조정된다**'는 흐름만 분명히 이해하면 됩니다.

### 6-2. Inference(추론)

**Inference**는 이미 학습된 모델에 새로운 입력을 제공해 결과를 얻는 과정입니다.

```text
Training을 거쳐 만들어진 Model
               ↓
          저장 / 준비
               ↓
         새로운 입력
               ↓
           Inference
               ↓
          예측 / 생성
```

예를 들어 집값 모델을 학습한 뒤 새로운 집의 면적을 넣어 가격을 예측하는 과정이 Inference입니다. 뒤에서 사용할 GPT나 Gemma 같은 이미 학습된 모델에 사용자가 질문을 넣어 답변을 얻는 것도 Inference입니다. **사용자가 질문할 때마다 대규모 모델을 처음부터 다시 학습하는 것이 아닙니다.**

### 6-3. 둘의 차이를 표로 확인하기

| 구분 | Training | Inference |
|---|---|---|
| 목적 | 모델 내부 값을 학습·조정 | 학습된 모델로 새 입력 처리 |
| 입력 | 학습 데이터와 학습 목표 등 | 새로운 사용자·서비스 입력 |
| Parameter | 일반적으로 조정됨 | 일반적인 추론에서는 고정됨 |
| 작업의 결과 | 학습된 Model | 예측값·분류 결과·생성 결과 |
| 예 | 집값 예측 모델 학습 | 처음 본 집의 가격 예측 |

학습 과정은 많은 계산 자원을 필요로 할 수 있습니다. 그러나 **Inference가 항상 가볍거나 저렴한 것은 아닙니다.** 대규모 모델을 실제 서비스에서 실행하는 일도 GPU 메모리와 계산 자원을 상당히 사용할 수 있습니다.

### 6-4. Prediction과 Generation은 Inference와 어떤 관계인가?

앞 교시에서는 분류·예측·생성을 **AI가 하는 일**의 관점에서 구분했습니다. 지금은 **모델을 실행하는 시점**에 초점을 맞춥니다.

```text
학습된 수치 예측 Model → Inference → 예측 가격
학습된 생성형 Model   → Inference → 생성 텍스트
```

즉, 예측과 생성은 **출력의 성격**을 구분하는 데 유용하고, Inference는 **학습된 모델을 실제 입력에 사용하는 과정**을 나타냅니다. 서로 대립하는 말이 아닙니다.

## 7. 작은 Python 예제로 Training과 Inference 구분하기

이제 집값 데이터의 '면적'만 사용해 작은 **선형 회귀(Linear Regression)** 모델을 학습해 봅시다. 앞에서 표로 소개한 Dataset을 코드로 연결하는 예제이며, 실제 부동산 가격을 예측하기 위한 완성된 모델은 아닙니다.

### 7-1. 실행 전에 알아둘 점

- **필요한 환경:** Python과 `scikit-learn` 라이브러리가 설치되어 있어야 합니다.
- **이번 실습 목표:** 라이브러리 사용법 전체가 아니라 `fit()`과 `predict()`의 역할을 구분하는 것입니다.
- 다음 코드는 원본 강의의 작은 수치 예제를 설명을 보강해 유지했습니다. **이번 편집 환경(Python 3.13.5, scikit-learn 1.8.0)에서 실행해 출력값을 확인**했으며, 교육장 환경에서 동일하게 실행되는지는 별도로 확인해야 합니다.

### 7-2. 코드 읽기

```python
from sklearn.linear_model import LinearRegression

# Training Data: 입력 Feature는 '면적' 하나
x_train = [[50], [70], [90]]

# 지도학습의 Target: 거래 가격(백만 원)
y_train = [200, 300, 400]

# Model 준비
model = LinearRegression()

# Training: 데이터와 정답으로 모델을 학습
model.fit(x_train, y_train)

# Inference: 새로운 면적 80㎡의 예상 가격을 계산
prediction = model.predict([[80]])

print(prediction)
```

코드의 핵심을 한 줄씩 살펴봅니다.

1. `x_train`은 모델의 **입력 Feature**입니다. `[[50], [70], [90]]`처럼 안쪽 리스트로 각 주택의 입력을 나눕니다.
2. `y_train`은 각 입력에 대응하는 **Target**입니다. `50`과 `200`, `70`과 `300`이 순서대로 짝을 이룹니다.
3. `LinearRegression()`은 학습에 사용할 Model 객체를 준비합니다.
4. `model.fit(x_train, y_train)`은 학습 데이터를 이용해 내부 Parameter를 맞춥니다. 이것이 **Training**입니다.
5. `model.predict([[80]])`은 학습에 쓰이지 않았던 입력 `80`을 모델에 넣습니다. 이것이 **Inference**입니다.

이 세 점이 한 직선 위에 있으므로, 학습된 직선 관계로 계산하면 `80㎡`일 때 예상 가격은 `350백만 원`이 됩니다. **이번 편집 환경에서 실제 출력은 `[350.]`이었습니다.** 60㎡로 바꾸어 실행하면 `[250.]`이 출력되는 것도 확인했습니다. 다만 세 개의 단순한 데이터로 실제 부동산 가격 예측 성능을 검증한 것은 아닙니다.

```text
x_train + y_train
       ↓ fit()
 학습된 Model
       ↓ predict([[80]])
    예측 가격
```

### 7-3. 학생 실습과 확인 질문

1. `model.fit(...)`과 `model.predict(...)`에 각각 `Training`, `Inference`라고 주석을 달아 봅니다.
2. 예측할 면적을 `60`으로 바꾸면 어떤 결과가 나올지 **먼저 예상**한 뒤 코드를 실행해 확인합니다.
3. `y_train`의 두 번째 값을 `300`에서 `500`으로 바꾸면, **Training 전 입력 데이터가 바뀐 것**인지 **Inference 입력이 바뀐 것**인지 구분합니다.
4. 이 세 건의 데이터로 실제 모든 지역의 집값을 정확하게 추정할 수 있는지 토론합니다.

**강사용 확인 포인트:** 데이터가 많거나 모델이 복잡하다고 자동으로 정확해지는 것은 아닙니다. 실제 적용에는 데이터 품질과 평가가 필요합니다. 지금은 코드 안에서 **학습할 때와 사용할 때의 경계**를 찾는 것이 합격 기준입니다.

## 8. 결정적 규칙과 확률적 모델을 정확히 비교하기

프로그램에서는 흔히 다음과 같은 **명확한 계산 결과**를 기대합니다.

```python
def add(a: int, b: int) -> int:
    return a + b

print(add(10, 20))  # 30
```

동일한 입력과 실행 조건에서 같은 결과가 나오는 특성을 **Deterministic(결정적)**이라고 합니다. 머신러닝에서는 데이터에서 학습한 패턴을 바탕으로 범주의 가능성이나 수치를 계산할 수 있습니다. 생성형 AI 모델은 여러 가능한 다음 출력의 확률을 다루기도 합니다.

그러나 다음 두 문장은 **틀린 단순화**입니다.

```text
일반 프로그램은 언제나 Deterministic이다.    (X)
Machine Learning Model은 언제나 출력이 달라진다. (X)
```

일반 프로그램도 무작위성·시각·외부 상태에 따라 결과가 달라질 수 있습니다. 반대로 학습된 모델도 같은 설정과 실행 조건에서 **같은 예측값을 일관되게 계산**할 수 있습니다. 확률을 계산하는 모델도 매번 결과가 변한다는 뜻은 아닙니다.

### 실제 서비스에서 왜 중요할까?

어떤 판단은 정해진 규정에 따라 **항상 같은 기준**으로 실행되어야 합니다. 예를 들어 관리자 승인 기준, 권한 검사, 결제 금액 계산은 프로그램에서 명확히 처리하고 테스트하기 좋습니다. 반면 자연어 답변 초안처럼 여러 표현이 가능한 작업은 AI 활용을 검토할 수 있습니다.

> **강사 질문:** “확률적 모델이 분류한 결과가 90%라고 표시되면, 그 결과를 반드시 믿고 승인해도 될까요?”  
> **예상 답변:** 아닙니다. 모델의 수치가 의미하는 바와 실제 오류 가능성을 검증해야 하며, 최종 승인 규칙은 업무 책임에 따라 별도로 정해야 합니다.

확률 분포에서 생성 출력이 선택되는 방식과 비결정성은 생성형 AI 심화 단원에서 다룹니다.

## 9. AI Application에서는 코드와 모델이 함께 일한다

2교시에서는 Model과 Application의 범위를 구분했습니다. 이번에는 개발 단계에서 **누가 무엇을 책임지고 어떤 결과를 검증해야 하는지**를 구체적으로 살펴봅니다.

### 9-1. 코드가 담당하는 것이 적절한 업무

예를 들어 결제 시스템에 다음 규칙이 있다고 합시다.

> 100,000원 이상 주문은 관리자 승인을 거쳐야 한다.

이 조건을 매번 AI에게 질문할 필요는 없습니다.

```python
def requires_approval(amount: int) -> bool:
    return amount >= 100_000
```

승인 기준이 확정된 비즈니스 규칙이라면 직접 코드로 구현하면 됩니다. 테스트 시에도 `99,999`, `100,000`, `100,001`처럼 **경계값을 확인**할 수 있습니다.

그 밖에 다음 책임도 Application 코드 또는 해당 시스템에 남겨 두는 것이 적절합니다.

- 로그인 상태와 권한 검증
- 파일 크기·형식·필수 입력 확인
- 가격·세금·결제 금액의 업무 규칙 적용
- API Key 같은 비밀 정보 관리
- 저장·조회·오류 처리
- AI가 반환한 결과가 필요한 형식과 업무 조건을 만족하는지 확인

### 9-2. AI를 활용해 볼 만한 업무

- 길게 작성된 고객 문의의 의도 파악과 유형 분류
- 상담 기록을 읽고 핵심 쟁점 요약
- 상품 설명 초안이나 안내 문구 생성
- 문서에서 필요한 정보 후보 추출

**AI가 할 수 있는 일**과 **검증 없이 AI에 맡겨도 되는 일**은 같지 않습니다. 예를 들어 문서에서 추출한 금액을 실제 결제에 사용할 때에는 Application이 형식·값·업무 규칙을 검증해야 합니다.

### 9-3. 실제 업무 흐름에서 책임을 표시하기

고객 문의 처리 서비스를 예로 들겠습니다.

```text
사용자 문의 입력
       ↓
[Application] 인증·입력 길이 확인
       ↓
[Application] 문의 내용 전달
       ↓
[AI Model] 문의 유형 분류·답변 초안
       ↓
[Application] 출력 형식 확인
       ↓
[Application] 업무 규칙·권한 검증
       ↓
[필요한 경우] 담당자 확인
       ↓
[Application] 결과 저장·사용자 응답
```

여기서 **모델은 내용 이해와 초안 생성**을 맡을 수 있지만, 입력 허용 여부와 최종 응답 처리 절차를 스스로 보증하지 않습니다. Application은 AI의 결과를 받아 사용하기 전에 필요한 확인을 수행해야 합니다.

## 10. NumPy·scikit-learn·PyTorch: 같은 단계의 이름이 아니다

앞서 Linear Regression 코드에 사용한 `scikit-learn`은 Python에서 널리 쓰이는 **Machine Learning 라이브러리**입니다. 이 시간에 등장한 다른 도구들과 기능을 구별해 봅시다.

| 도구 | 이번 교시에서 알아둘 역할 | 실제로 깊게 배우는 위치 |
|---|---|---|
| **NumPy** | 배열과 수치 계산 | 수치·Tensor 학습 교시 |
| **scikit-learn** | 분류·회귀 등의 모델 학습·평가 도구 | 본 교시 작은 회귀 예제에서 첫 사용 |
| **PyTorch** | Tensor 연산·자동 미분·신경망 학습 Framework | Deep Learning·Tensor 관련 교시 |

### 10-1. NumPy로 데이터 모양 확인하기

아래 코드의 목표는 AI를 만드는 것이 아니라 **여러 숫자가 어떻게 배열로 정리되는지** 살펴보는 것입니다.

```python
import numpy as np

data = np.array([
    [50, 2],
    [70, 3],
    [90, 4],
])

print(data.shape)
```

행은 3개이고 각 행에는 값이 2개 있으므로 `shape`는 `(3, 2)`라는 형태를 나타냅니다. 학생은 **행 하나가 무엇을 뜻하는지, 열 하나가 무엇을 뜻하는지** 설명해 보세요. 숫자를 배열로 다루는 법과 실제 모델의 계산 원리는 뒤에서 더 학습합니다.

### 10-2. PyTorch가 왜 등장할까?

PyTorch는 단순히 외부 AI 서비스에 질문을 보내는 도구가 아닙니다. Tensor 연산, 자동 미분, 신경망 구성, 학습을 지원하는 Framework입니다.

```text
Python 코드
    ↓
PyTorch의 Tensor 연산·자동 미분 등
    ↓
Neural Network 구성·학습
```

여기서는 **도구의 책임**까지만 구분하면 충분합니다. `Transformers`, `OpenAI SDK`, `Ollama`, `FastAPI` 등은 이후 해당 교시에서 기능과 사용법을 다룹니다. 아직 이 이름을 전부 외울 필요는 없습니다.

## 11. 강사 시연 — 명확한 규칙과 AI 작업을 분리하기

**시연 주제:** 고객 문의가 들어오면 문의 유형을 파악해 담당 부서에 전달하고, 필요한 경우 답변 초안을 마련하는 서비스

**학생에게 먼저 제시할 요구사항**

- 입력이 비어 있으면 접수하지 않는다.
- 고객 문의 내용에서 주요 문의 유형을 파악한다.
- 특정 금액 이상의 환불은 담당자 승인을 받아야 한다.
- 답변 문구는 초안으로만 작성하고 최종 전송 여부는 확인한다.

학생과 함께 각각의 책임을 정리합니다.

| 처리 단계 | 누가 담당하는가? | 판단 이유 |
|---|---|---|
| 빈 입력 거부 | Application Code | 명확한 입력 규칙 |
| 문의 유형 분석 | AI Model 활용 가능 | 문장 표현이 다양하며 분류가 필요 |
| 환불 승인 기준 적용 | Application Code | 정확하고 검증 가능한 업무 규칙 |
| 답변 초안 작성 | AI Model 활용 가능 | 자연어 작성 지원 |
| 승인 기록·최종 전송 | Application / 담당자 | 책임·권한·이력 관리 |

학생이 'AI가 문의 내용을 이해하니까 환불 승인까지 하면 되지 않나?'라고 묻는다면, **내용을 이해하는 능력과 조직이 정한 승인 권한은 다른 문제**라는 점을 짚습니다.

이번 시연은 역할 설계 활동이며 실제 문의 분류 모델이나 웹서버를 실행한 실습이 아닙니다.

## 12. 학생 활동 — 어느 단계에서 Training하고, 무엇을 코드로 처리할까?

### 활동 A. 역할 분류

다음 항목을 `Application Code`, `AI Model을 활용할 수 있는 작업`, `추가 검토가 필요한 작업`으로 구분해 보세요.

1. 사용자가 로그인했는지 확인하기
2. 고객 문의를 배송·환불·상품 문의로 분류하기
3. 5MB보다 큰 파일을 거부하기
4. 고객 문의의 핵심 내용을 요약하기
5. 주문 총액과 배송비 계산하기
6. 상품 설명 초안 작성하기
7. 비밀 API Key를 안전하게 보관하기
8. AI가 찾은 계약서의 중요한 조항을 실제 승인 근거로 사용하기

**강사용 예상 답안**

- Application Code: **1, 3, 5, 7**
- AI Model 활용 가능: **2, 4, 6**
- 추가 검토 필요: **8** — AI가 관련 조항을 찾거나 설명할 수는 있지만, 원문 근거와 업무상 승인 절차를 별도로 확인해야 합니다.

8번이 핵심입니다. AI 활용 가능 여부만으로 **최종 판단을 전적으로 맡길 수 있다**고 결론 내리지 않도록 지도합니다.

### 활동 B. 학습과 추론 찾기

다음 문장 중 무엇이 Training이고 무엇이 Inference인지 구분해 보세요.

- A: 과거 생산 사진과 정답을 모아 모델의 값을 조정한다.
- B: 오늘 촬영한 새 제품 사진을 학습된 모델에 넣어 불량 여부를 얻는다.
- C: 학습된 Gemma 모델에 사용자가 질문해 답변을 얻는다.
- D: 이전에 수집한 데이터의 일부 Label을 수정하여 학습 데이터를 다시 준비한다.

**강사용 예상 답안:** A는 Training, B·C는 Inference입니다. D는 Training을 위한 **데이터 준비 작업**이지 그 자체로 Parameter 학습을 실행했다는 뜻은 아닙니다.

## 13. 수업 확인 질문

### Q1. 머신러닝을 사용하면 개발자는 코드를 작성하지 않아도 되나요?

아닙니다. 개발자는 데이터 준비, 학습 절차, 모델 실행, 평가, 서비스 로직을 구현할 수 있습니다. 차이는 **해결하려는 문제의 판단 패턴을 데이터에서 학습**하도록 한다는 점입니다.

### Q2. Dataset과 Feature는 같은 뜻인가요?

아닙니다. **Dataset은 사례의 모음**이고, **Feature는 모델의 입력으로 사용하는 특성**입니다. 집값 표에서 표 전체가 Dataset이고 면적·방 개수는 Feature가 될 수 있습니다.

### Q3. 지도학습에서 Label은 항상 글자로 된 분류 이름인가요?

아닙니다. 분류의 범주도 Label이 될 수 있고 집값처럼 숫자 Target도 있을 수 있습니다. 지도학습은 **입력과 대응하는 학습 목표값**을 이용한다는 점이 중요합니다.

### Q4. Training과 Inference의 차이는 무엇인가요?

Training은 데이터를 이용해 **모델 내부 값을 학습·조정하는 과정**, Inference는 **학습된 모델에 새 입력을 넣어 결과를 얻는 과정**입니다.

### Q5. AI Model이 확률을 계산한다면 같은 입력에 대해 결과가 매번 달라지나요?

반드시 그렇지는 않습니다. 확률을 계산할 수 있다는 것과 무작위로 결과를 선택한다는 것은 다릅니다. 실행 조건과 생성 방식에 따라 결과가 같을 수도, 달라질 수도 있습니다.

### Q6. GPT나 Gemma에 질문을 보낼 때 모델을 처음부터 다시 학습하나요?

아닙니다. 이미 학습된 모델에 새로운 입력을 사용한 **Inference**입니다. 별도의 Fine-tuning 등의 학습 작업과 구분해야 합니다.

### Q7. AI가 문서를 요약할 수 있다면 권한 검사도 AI에 맡기면 되나요?

아닙니다. 권한과 명확한 업무 규칙은 Application이 검증해야 할 책임입니다. 모델의 내용을 이해하는 능력과 시스템에 부여된 **접근 권한**은 다릅니다.

## 14. 핵심 용어 및 오늘 배운 흐름

| 용어 | 오늘 이해할 의미 |
|---|---|
| Data / Dataset | 학습과 처리에 사용하는 정보 / 사례의 집합 |
| Feature | 모델 입력으로 사용하는 속성 또는 표현 |
| Label / Target | 지도학습에서 예측하도록 하는 목표값 |
| Model | 입력으로부터 결과를 계산하는 구조와 학습된 내부 값을 가진 대상 |
| Parameter | Training을 통해 조정하는 Model 내부 값 |
| Training | 데이터를 이용해 Parameter를 학습·조정하는 과정 |
| Inference | 학습된 Model을 새 입력에 사용해 결과를 얻는 과정 |
| Prediction | 모델이 계산한 예측 결과라는 넓은 표현 |
| Classification / Regression | 범주를 예측하는 문제 / 수치를 예측하는 문제 |

```text
[규칙이 명확한 업무]
입력 → 개발자가 정한 규칙 → 결과

[Machine Learning의 지도학습 예]
Feature + Label → Training → 학습된 Model
                                    ↓
새로운 Feature ───────────────→ Inference → 예측 결과

[AI Application]
Application의 규칙·검증 + AI Model의 필요한 기능
                      ↓
              사용자에게 제공할 결과
```

이번 교시의 결론은 세 가지입니다.

1. **Machine Learning도 프로그램을 사용한다.** 다만 판단에 쓰는 모델 값을 데이터로부터 학습하게 한다.
2. **Training과 Inference는 서로 다른 단계다.** 실제 AI 서비스를 만드는 개발자는 이미 학습된 모델의 Inference를 활용하는 경우가 많다.
3. **AI는 Application의 모든 책임을 대신하지 않는다.** 확정된 업무 규칙과 입력·출력 검증은 별도로 설계해야 한다.
