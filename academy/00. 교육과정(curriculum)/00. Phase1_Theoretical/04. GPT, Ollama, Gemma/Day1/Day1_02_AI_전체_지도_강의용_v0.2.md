# Day 1 - 2교시. AI란 무엇인가 — AI 전체 지도

> **수업 핵심 질문**  
> AI는 어떤 기술들을 포함하고 있으며, Machine Learning·Deep Learning·생성형 AI·LLM·GPT·ChatGPT는 서로 어떤 관계일까?

## 개요

1교시에서는 AI가 등장한 배경과 주요 발전 과정을 살펴보았습니다.
이번 시간에는 연도와 역사를 다시 설명하기보다, 앞으로 등장할 기술들이 **AI 전체에서 어디에 속하고 어떤 문제에 쓰이는지** 지도를 그려 봅니다.

처음 AI를 공부할 때 혼동하기 쉬운 이름은 다음과 같습니다.

```text
AI · Machine Learning · Deep Learning · Generative AI
Language Model · LLM · GPT · ChatGPT
```

이 용어들은 같은 대상을 다른 이름으로 부르는 것이 아닙니다.
어떤 말은 **연구 분야**, 어떤 말은 **모델을 만드는 접근 방법**, 어떤 말은 **모델의 종류**, 어떤 말은 **사용자가 이용하는 서비스**를 나타냅니다.
이 차이를 알면 새로운 도구를 만날 때도 이름에 휘둘리지 않고 그 역할을 판단할 수 있습니다.

## 2. AI라는 큰 범위부터 이해하기

### 2-1. Artificial Intelligence란?

**Artificial Intelligence(AI, 인공지능)**는 기계가 학습, 추론, 문제 해결, 인식, 언어 처리 등 지능과 관련된 작업을 수행하도록 만드는 **기술과 연구의 넓은 분야**입니다.

여기서 중요한 말은 **넓은 분야**입니다.
AI는 하나의 알고리즘도, 하나의 프로그램도 아닙니다.
예를 들어 개발자가 지식을 명시적으로 표현하는 방식이 있을 수도 있고, 데이터에서 패턴을 학습하는 방식이 있을 수도 있습니다.

```text
Artificial Intelligence (AI)
│
├── 지식 표현과 추론
├── 탐색과 계획
├── Machine Learning (데이터에서 학습하는 접근)
├── Computer Vision (영상·이미지 관련 문제 영역)
├── Natural Language Processing (언어 관련 문제 영역)
└── Robotics (로봇 관련 문제 영역)
```

위 그림의 가지는 모두 같은 기준으로 나눈 **서로 배타적인 하위 분야**가 아닙니다.
예를 들어 Computer Vision에는 Machine Learning이 사용될 수 있고, Robotics에는 탐색·계획·Machine Learning이 함께 사용될 수 있습니다.
**문제 분야와 문제를 해결하는 방법을 구분**해야 합니다.

### 2-2. 왜 AI를 특정 제품으로 이해하면 안 될까?

ChatGPT를 사용하면서 AI를 처음 접할 수는 있습니다.
그러나 AI의 범위는 대화 서비스 하나보다 훨씬 넓습니다.
스팸 메일을 구분하는 시스템과 공장에서 부품 이상을 찾는 시스템도 AI 기술을 활용할 수 있습니다.

학생에게 질문해 봅시다.

> “채팅 화면이 없고 문장을 만들지 않는 프로그램은 AI가 아닐까요?”

그렇지 않습니다. 어떤 문제를 해결하고 어떤 기술을 사용하느냐가 중요합니다.

## 3. AI가 하는 일을 다섯 가지 대표 작업으로 보기

AI를 처음 배울 때는 모델 이름보다 **입력을 받아 어떤 결과를 만드는가**를 먼저 보면 이해하기 쉽습니다.
아래 다섯 가지는 자주 만나는 대표 사례입니다.
AI의 모든 작업을 다섯 개로 제한한다는 뜻은 아니며, 실제 서비스에서는 여러 작업이 겹치기도 합니다.

### 3-1. 분류(Classification) — 어떤 범주에 속할까?

분류는 입력을 미리 정해 놓은 범주 가운데 하나 또는 여러 범주에 연결하는 작업입니다.

```text
이메일 내용 → 분류 Model → 스팸 / 정상
사진        → 분류 Model → 고양이 / 개
고객 문의   → 분류 Model → 배송 / 환불 / 상품 문의
```

**분류의 결과**는 보통 범주 이름이나 각 범주에 속할 가능성입니다.
따라서 스팸 판정, 문서 종류 구분, 상품 카테고리 분류처럼 결과의 종류가 정해져 있는 업무에 활용됩니다.

학생에게는 “모델이 새로운 글을 지어내는가, 주어진 범주 중에서 고르는가?”를 질문해 보세요.
이 경우 핵심은 **범주를 판단하는 것**입니다.

### 3-2. 예측(Prediction) — 어떤 값이나 결과를 예상할까?

예측은 현재·과거 데이터를 바탕으로 아직 확인되지 않은 값이나 결과를 추정하는 작업입니다.

```text
과거 판매량 + 날씨 + 요일 + 행사 정보
                  ↓
               예측 Model
                  ↓
            다음 주 예상 판매량
```

매출·수요·고장 가능성·고객 이탈 가능성 추정이 대표 사례입니다.
여기서 한 가지 주의할 점이 있습니다.
**분류도 넓은 의미에서는 예측의 한 종류**입니다.
고객이 이탈할지 여부를 두 범주로 판단하면 분류 문제이고, 다음 주 판매 수량처럼 수치를 예상하면 수치 예측 문제로 볼 수 있습니다.

이번 교시에서는 이렇게 결과의 형태를 구분하는 데 집중합니다.
학습 데이터와 예측 모델을 만드는 자세한 과정은 이어지는 교시에서 살펴봅니다.

### 3-3. 추천(Recommendation) — 무엇을 보여주면 좋을까?

추천은 사용자와 항목에 관한 정보를 이용해 관심을 가질 만한 항목이나 적절한 순서를 제시하는 작업입니다.

```text
사용자 시청 기록 + 콘텐츠 정보 + 이용 패턴
                     ↓
                  추천 시스템
                     ↓
                 추천 동영상 목록
```

음악·상품·뉴스·영상 추천이 여기에 해당합니다.
추천은 하나의 모델만으로 이루어질 수도 있지만, 실제 서비스에서는 후보를 찾고 순서를 정하는 등 여러 단계로 구성될 수 있습니다.

**분류**가 범주를 판단하는 일이라면 **추천**은 여러 후보 중 사용자에게 보여줄 항목을 고르는 일에 집중한다는 차이가 있습니다.

### 3-4. 인식(Recognition) — 입력에서 무엇을 알아낼까?

인식은 이미지·음성·문서 같은 입력에서 의미 있는 정보나 대상을 알아내는 작업입니다.

```text
음성                 → Speech Recognition → 문자
스캔한 문서 이미지    → OCR                → 문자
사진                 → Computer Vision    → 물체·특징
```

- **Speech Recognition**: 음성 입력을 분석하여 말한 내용을 텍스트 등으로 변환합니다.
- **OCR(Optical Character Recognition)**: 이미지에 보이는 문자를 인식하여 텍스트로 추출합니다.
- **Computer Vision**: 사진과 영상에서 물체나 특징 등 시각적 정보를 분석합니다.

OCR이 문자 정보를 얻는 단계라면, 추출한 텍스트를 요약하거나 질문에 답하는 일은 다른 작업일 수 있습니다.
후속 OCR·Multimodal 단원에서는 문서의 레이아웃, 여러 입력 형태의 처리 등 더 구체적인 원리를 다룹니다.

### 3-5. 생성(Generation) — 새로운 내용을 만들까?

생성은 입력 조건과 학습한 패턴을 바탕으로 새로운 콘텐츠를 만드는 작업입니다.

```text
사용자 요청
    ↓
생성형 Model
    ↓
새로운 텍스트 / 이미지 / 코드 / 음성 / 영상
```

문장 작성, 요약, 이미지 생성, 코드 작성 등이 익숙한 활용 사례입니다.
다만 한 서비스가 여러 작업을 함께 사용할 수 있다는 점을 기억해야 합니다.
예를 들어 문서 요약 서비스는 먼저 문서에서 글자를 **인식**하고, 그 내용을 바탕으로 설명을 **생성**할 수 있습니다.

### 3-6. 대표 작업 한눈에 비교

| 작업 | 먼저 던질 질문 | 입력의 예 | 결과의 예 |
|---|---|---|---|
| 분류 | 어느 범주인가? | 이메일 본문 | 스팸 / 정상 |
| 예측 | 어떤 값이나 결과가 예상되는가? | 판매 이력 | 예상 판매량 |
| 추천 | 어떤 항목을 보여줄까? | 시청 기록 | 동영상 목록 |
| 인식 | 입력에서 무엇을 알아낼까? | 음성·문서 이미지 | 글자·물체 정보 |
| 생성 | 어떤 새로운 내용을 만들까? | 사용자 요청 | 답변·이미지·코드 |

이 외에도 탐지, 검색 보조, 최적화, 의사결정 지원, 제어 등이 있습니다.
목적을 분류하고 나면 어떤 종류의 AI 기술이 필요한지 더 분명하게 생각할 수 있습니다.

## 4. AI, Machine Learning, Deep Learning의 관계

앞에서는 **AI가 무슨 일을 하는지**를 기준으로 살펴봤습니다.
이제는 **어떤 접근으로 문제를 해결하는지**를 보겠습니다.
두 구분 기준을 섞지 않는 것이 중요합니다.

```text
Artificial Intelligence
│
├── Rule-based / Symbolic Approaches
├── Search / Planning
└── Machine Learning
       └── Deep Learning
```

### 4-1. Machine Learning은 AI의 한 접근이다

**Machine Learning(머신러닝)**은 데이터를 이용해 모델의 동작에 필요한 패턴을 학습하도록 만드는 접근입니다. 개발자가 모든 판단 조건을 하나씩 코드로 작성하는 방식과 대비됩니다.

예를 들어 스팸 분류 시스템에서 개발자가 특정 단어가 나오면 무조건 스팸이라고 직접 정할 수도 있습니다.
반면 머신러닝 방식에서는 여러 메일 데이터와 학습 신호를 이용해 어떤 패턴이 스팸 판정에 도움이 되는지 모델이 학습하도록 할 수 있습니다.

여기서 꼭 기억할 점은 두 가지입니다.

- **AI 전체가 Machine Learning은 아닙니다.** 규칙과 지식을 활용하는 다른 AI 접근도 있습니다.
- **Machine Learning에도 프로그램이 필요합니다.** 데이터 준비, 학습 절차, 실행과 결과 활용은 소프트웨어로 구성됩니다.

`Data`, `Feature`, `Label`, `Parameter`, `Training`, `Inference`가 정확히 무엇인지는 **다음 3교시**에서 별도의 사례와 실습으로 배웁니다.
이번 시간은 그 과정이 AI 전체에서 어디에 위치하는지만 파악합니다.

### 4-2. Deep Learning은 Machine Learning의 중요한 접근이다

>**Deep Learning(딥러닝)**은 여러 층의 인공 신경망(Neural Network)을 이용해 데이터의 복잡한 패턴과 표현을 학습하는 머신러닝 접근입니다.

```text
AI
└── Machine Learning
    └── Deep Learning
        └── 여러 층의 Neural Network를 활용한 모델
```

즉 `AI = Deep Learning`도 아니고 `Machine Learning = Deep Learning`도 아닙니다. 딥러닝은 이미지·음성·언어 등 다양한 분야의 발전에 크게 기여했지만, 모든 문제에서 반드시 딥러닝 모델을 사용해야 하는 것은 아닙니다.

이번 시간에는 신경망 내부 계산을 다루지 않습니다. 왜 신경망이 복잡한 표현을 학습할 수 있는지와 그 한계는 Phase2의 심화 학습에서 다룹니다.

## 5. 생성형 AI, Language Model, LLM, GPT를 같은 말로 쓰지 않기

### 5-1. Generative AI는 생성이라는 목적에 초점을 둔다

> **Generative AI(생성형 AI)**는 새로운 콘텐츠를 만드는 모델과 시스템을 중심으로 사용하는 말입니다. 현대의 대표적인 생성형 AI는 딥러닝을 기반으로 하지만,**
> 
> **생성형 AI를 LLM과 동일시해서는 안 됩니다.**

```text
Generative AI
├── Text Generation
├── Image Generation
├── Code Generation
├── Audio / Speech Generation
└── Video Generation
```

위 항목 역시 서로 완전히 떨어진 영역은 아닙니다. 하나의 모델이나 서비스가 여러 형태의 입력과 출력을 다룰 수도 있기 때문입니다. 핵심은 **생성하는 대상이 텍스트에만 한정되지 않는다**는 점입니다.

### 5-2. Language Model과 LLM

**Language Model(언어 모델)**은 언어의 패턴을 모델링하는 모델입니다. **LLM(Large Language Model, 대규모 언어 모델)**은 대규모 데이터와 많은 Parameter를 이용해 학습한 언어 모델 계열을 가리키는 용어로 사용됩니다.

LLM은 질문 답변, 번역, 요약, 코드 생성, 대화, 문서 변환 등 여러 언어 관련 작업에 이용할 수 있습니다. 그러나 그 출력은 언제나 자동으로 정확한 사실이나 업무상 올바른 판단이 되는 것은 아닙니다.
서비스에서는 필요에 따라 다른 데이터 처리와 검증이 함께 이루어져야 합니다.

이번 교시에는 내부 생성 계산이나 Token의 상세한 동작을 배우지 않습니다. 이 부분은 Day2 및 LLM 심화 단원에 맡깁니다.

### 5-3. GPT는 LLM의 대표적인 모델 계열이다

입문 단계에서는 다음처럼 위치를 이해하면 됩니다.

```text
AI라는 넓은 분야
  └── Machine Learning
      └── Deep Learning
          └── 현대의 언어 모델 계열
              └── LLM
                  └── GPT 계열 모델
```

이 그림은 다양한 접근을 모두 포괄하는 엄밀한 제품 분류표가 아니라 **GPT가 AI 전체보다 훨씬 좁은 개념**임을 나타내는 학습용 지도입니다.

> **GPT는 AI 전체의 다른 이름이 아닙니다.** 특정 계열의 모델을 가리키는 말입니다.

## 6. GPT와 ChatGPT — Model과 Application의 차이

### 6-1. 같은 이름처럼 보여도 역할이 다르다

**Model(모델)**은 입력을 처리하고 결과를 만들어 내는 AI 기능을 담당합니다. **Application(애플리케이션)**은 사용자가 그 기능을 실제 업무에서 이용할 수 있도록 화면과 처리 절차 등을 갖춘 소프트웨어입니다.

- GPT 계열: 주로 **모델 또는 모델 계열**의 관점
- ChatGPT: 사용자가 AI 기능을 이용하는 **서비스·제품(Application / Product)**의 관점

따라서 `GPT = ChatGPT`가 아닙니다. 학생이 보는 대화 화면이 모델 자체는 아니기 때문입니다.

### 6-2. AI Model만 있으면 서비스가 완성될까?

그렇지 않습니다. 예를 들어 사용자가 문서를 올리고 그 내용을 요약 받는 서비스를 생각해 봅시다.
이 서비스에는 AI Model 이외에 다음과 같은 역할이 필요할 수 있습니다.

| 구성 요소 | 사용자가 이용하는 서비스에서 하는 일 |
|---|---|
| Frontend | 사용자가 파일을 선택하고 결과를 확인하는 화면 제공 |
| Backend | 요청 처리와 업무 절차 조정 |
| File Processing | 파일에서 필요한 텍스트와 정보를 추출 |
| AI Model | 요청한 요약 등의 AI 작업 수행 |
| Validation | 입력과 결과가 요구 형식에 맞는지 확인 |
| Authentication / Security | 필요한 경우 사용자 확인과 접근 제한 |
| Database / Storage | 필요한 데이터·파일 보관 |
| Logging / Monitoring | 동작 상태와 오류 등을 파악 |

모든 서비스에 이 요소가 전부 필요하거나 각각 별도 서버에 있어야 하는 것은 아닙니다.
**Model 하나와 실제 Application 하나는 책임의 범위가 다르다**는 뜻입니다.

```text
사용자
  ↓
Frontend (예: React 화면)
  ↓
Backend (예: FastAPI 서버)
  ├── 입력 검증 / 파일 처리
  ├── 필요한 데이터·업무 로직
  └── AI Model 호출 (예: GPT 또는 Gemma)
            ↓
        요약 등 AI 결과
            ↓
      결과 점검·응답 처리
            ↓
       사용자 화면
```

React, FastAPI는 뒤의 개발 과목과 연결될 기술 이름입니다.
**이 교시에서는 사용법을 이미 안다고 가정하지 않고**, 화면·서버·모델의 역할만 구분합니다.

> **모델을 사용할 줄 아는 것과, 그 모델을 활용한 서비스를 설계·구현하는 것은 서로 다른 역량입니다.**

---

## 7. 하나의 AI 서비스에 여러 작업이 결합될 수 있다

앞에서 소개한 다섯 가지 작업은 실제로 분리되어만 등장하지 않습니다.

예를 들어 **문서를 업로드하면 핵심 내용을 요약해 주는 AI 서비스**의 입력이 스캔한 PDF라면 다음과 같이 생각할 수 있습니다.

```text
PDF / Image 업로드
        ↓
문서에서 텍스트 추출 (OCR 또는 Document Parsing)
        ↓
필요한 정보 분류·추출
        ↓
AI Model을 이용한 내용 요약
        ↓
결과 확인과 사용자에게 응답
```

이 흐름에서 **OCR은 인식·추출**, **요약은 생성·변환**과 연결됩니다.
입력이 이미 디지털 텍스트인 문서라면 OCR이 필요 없을 수도 있습니다.
어떤 단계가 실제로 필요한지는 파일의 종류와 서비스 요구사항에 따라 달라집니다.

학생에게 두 가지 질문을 던져 보세요.

1. “이 서비스 전체가 하나의 AI Model일까요?”
2. “모델이 요약을 잘하더라도 업로드한 파일을 처리하지 못하면 서비스가 제대로 동작할까요?”

이 활동의 목적은 코드를 작성하는 것이 아니라 **기술별 역할을 분해해서 생각하는 습관**을 기르는 것입니다.

## 8. 새로운 AI 기술을 만났을 때 사용하는 세 가지 질문

새로운 이름이 나올 때마다 아래 세 질문으로 분류해 보세요.

### 질문 ① 무엇을 해결하는가?

`분류`·`예측`·`추천`·`인식`·`생성`·`검색`·`최적화` 중 어떤 문제가 중심인지 묻습니다.
이는 **문제와 결과의 관점**입니다.

### 질문 ② 어떻게 구현하는가?

> 규칙이나 탐색을 사용하는지,
> 데이터를 학습한 모델을 사용하는지,
> 이미 준비된 외부 AI 기능을 호출하는지,
> 로컬 환경에서 모델을 실행하는지

살펴봅니다.
이는 **방법과 실행의 관점**입니다.

### 질문 ③ Application의 어디에 위치하는가?

`Frontend`·`Backend`·`AI Model`·`실행 환경`·`데이터 처리` 가운데 어떤 역할을 맡는지 살펴봅니다.
이는 **서비스 구조의 관점**입니다.

같은 단어라도 이 세 관점에서 다르게 설명될 수 있습니다. 예를 들어 문서 요약은 **작업**, LLM은 그 작업에 사용할 수 있는 **모델 종류**, ChatGPT는 AI 기능을 제공하는 **제품**입니다.

## 9. 앞으로 배우는 기술과 도구의 위치

이번 시간에는 이름을 외우기보다 위치만 파악합니다. 사용법과 구현은 해당 교시에서 배웁니다.

| 구분 | 대표 이름 | 어디에 쓰는가? |
|---|---|---|
| 데이터·수치 처리 | NumPy, pandas | 데이터를 다루고 계산하는 작업 |
| Machine Learning 개발 | scikit-learn | 머신러닝 모델 학습·활용 |
| Deep Learning 개발 | PyTorch | 신경망 모델 개발·학습 |
| 사전학습 모델 생태계 | Hugging Face Hub, Transformers | 모델을 찾고 불러와 활용 |
| Cloud AI 이용 | OpenAI SDK | 외부 AI API 호출 |
| Local AI 실행 | Ollama | 로컬 모델 실행과 서비스 제공 |
| AI Application Framework | LangChain, LlamaIndex | AI 기능을 애플리케이션 흐름에 연결 |
| Web Backend | FastAPI, Pydantic | 요청 처리와 데이터 검증 등 |
| 화면 구성 | React | 사용자가 AI 기능을 이용하는 화면 |

위 표의 이름은 모두 AI Model이 아닙니다. **Model / Library·Framework / Runtime·Serving / Application**을 구분하는 것이 핵심입니다. 한 제품이나 도구가 여러 성격을 함께 가질 수도 있으므로, 무조건 하나의 칸에만 넣으려 하기보다 지금 어떤 역할로 사용하는지 확인합니다.

### AI 개발자가 하는 일도 서로 다르다

AI 관련 개발이라고 해서 모두 모델을 처음부터 학습시키는 것은 아닙니다.

- **Model Research / Development**: 모델 구조, 학습, 평가 등에 집중합니다.
- **ML / AI Engineering**: 데이터, 학습·추론 실행, 배포 환경과 운영에 집중합니다.
- **AI Application Development**: 이미 제공되는 모델이나 API를 업무 기능, Backend, Frontend와 연결하여 사용자 서비스를 만듭니다.

이 과정에서는 특히 **AI Application Development를 이해하기 위한 기초 지도**를 먼저 만듭니다. 모델의 학습 원리와 실행·도구 사용은 뒤의 각 교시에서 단계적으로 확장합니다.

## 10. 강사 진행 활동 — 하나의 서비스를 분해하기

**상황:** 학생들에게 “문서를 업로드하면 요약해 주는 서비스”를 보여준다고 가정합니다.

**진행 순서**

1. 학생들에게 “화면에서 보이는 부분”과 “실제로 내용을 요약하는 부분”을 구분해 보라고 합니다.
2. 파일을 받을 때, 글자를 뽑을 때, 요약할 때, 결과를 표시할 때 각각 어떤 역할이 필요한지 물어봅니다.
3. 학생의 답을 `Frontend → Backend·파일 처리 → AI Model → 응답 화면`의 흐름에 배치합니다.
4. 마지막으로 “어느 구간이 AI Model이고 어느 구간이 일반 Application 기능인지” 설명하게 합니다.

**강사 확인 포인트:** 학생이 반드시 React나 FastAPI 코드를 알아야 할 필요는 없습니다. 구성 요소가 모두 ‘AI 그 자체’는 아니라는 사실과, **서비스는 여러 역할이 협력해 만들어진다**는 점을 말할 수 있으면 됩니다.

## 11. 학생 활동 — 사례를 AI 전체 지도에 배치하기

다음은 원본 교안의 네 사례입니다. 각 사례를 보고 **어떤 작업인지 / 어떤 방식인지 / 모델 밖에 필요한 것은 무엇인지** 구분해 봅시다.

### 사례 A — 사람이 조건을 작성한 프로그램

```python
if age >= 19:
    result = "adult"
```

질문: 누가 판단 조건을 만들었을까요? 이 한 줄을 보고 바로 머신러닝 모델이라고 할 수 있을까요?

### 사례 B — 고객 이탈 가능성

과거 고객 데이터를 이용해 신규 고객의 이탈 가능성을 추정합니다.

질문: 결과는 분류와 어떤 관계가 있을까요? 데이터를 학습하는 방식이 쓰일 수 있을까요?

### 사례 C — 문장을 입력해 이미지 만들기

사용자가 글로 장면을 설명하면 새로운 이미지를 만듭니다.

질문: 어떤 AI 작업에 해당할까요? LLM처럼 텍스트를 출력하는 작업과 무엇이 다를까요?

### 사례 D — 계약서의 핵심 조항 요약

사용자가 계약서를 업로드하면 핵심 내용을 보여 줍니다.

질문: 문서가 스캔 이미지라면 어떤 처리가 추가로 필요할까요? 하나의 Model이 곧 전체 서비스일까요?

### 강사용 활동 답안

| 사례 | 핵심 판단 | 학생이 놓치기 쉬운 점 |
|---|---|---|
| A | 개발자가 직접 조건을 정한 일반 조건문이며, 이것만으로 학습 모델이라고 볼 수 없음 | **규칙을 썼다는 이유만으로 모든 규칙 기반 AI까지 AI가 아니라고 단정하면 안 됨** |
| B | 이탈 여부는 분류 문제로 다룰 수 있고, 이탈 확률 추정도 가능함 | 넓은 의미의 ‘예측’과 ‘분류’는 완전히 분리되지 않음 |
| C | 이미지 생성이라는 Generative AI 활용 | 생성형 AI는 텍스트 생성에 한정되지 않음 |
| D | 파일 처리, 필요하면 OCR, 정보 추출·요약, 결과 전달 등의 구성 요소가 결합됨 | Model과 Application 전체를 동일하게 보지 않음 |

## 13. 이번 교시 핵심 지도

```text
[기술·접근의 범위]
Artificial Intelligence
├── 지식 표현 / 추론 / 탐색 / 계획 등의 접근
└── Machine Learning
    └── Deep Learning
        ├── 분류·인식 등에 활용되는 모델
        └── 현대의 다양한 생성 모델
            ├── 언어·텍스트 관련 모델 (LLM, GPT 계열 등)
            └── 이미지·음성·영상 등의 생성 모델

[서비스의 역할]
사용자 ↔ Application의 화면·처리 기능 ↔ AI Model
```

이 두 그림은 **같은 것을 다른 방식으로 표현한 것이 아닙니다.** 첫 그림은 기술과 접근의 포함 관계를, 두 번째 그림은 서비스를 이루는 역할을 보여 줍니다.

이번 교시에서 세 가지를 기억하면 됩니다.

- **AI는 특정 모델이나 채팅 제품이 아니라 넓은 분야입니다.**
- **AI를 분류할 때는 ‘무슨 일을 하는가’와 ‘어떤 방식으로 만드는가’를 구분합니다.**
- **AI Model은 서비스의 한 부분이고, AI Application은 여러 기능을 결합한 전체 소프트웨어입니다.**
